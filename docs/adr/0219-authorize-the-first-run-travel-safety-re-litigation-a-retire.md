# Authorize the first-run travel-safety re-litigation: a retire-set reference-closure invariant + a mandated hard CI closure check (engine-template #147 plan-gate travel-safety finding)

*Decided 2026-06-19 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) on explicit operator approval to (a) add a **first-run retirement reference-closure invariant** to the locked [provisioning](../spec/systems/infrastructure/provisioning.md) retire phase, (b) mandate a **hard, CI-suite `custom/script` closure check** that enforces it — coverage named in locked [validation](../spec/systems/guardrails/validation.md), rule-data owned by locked [validators-core](../spec/modules/validators-core.md) — and (c) anchor the invariant with a one-line cross-ref in the locked [repository-topology](../spec/systems/infrastructure/repository-topology.md) "What travels" law — touching **four** locked docs; plus the non-locked [glossary](../reference/glossary.md) (the *travel-safety* term) and [risks](../reference/risks.md) ([R28](../reference/risks.md)). Provisioning is the **definition-of-record**; the other three locked docs reference it, never re-define it (the [D-218](0218-resolve-the-d-217-derived-committed-artifact-reconcile-re-li.md) byte-consistency discipline).

  **The litigation alarm.** The first-run instantiator's `retire()` deletes its first-run assets on a generated repo's first run — `_FIRST_RUN_ASSET_FILES` = `instantiator.py`, `test_instantiator.py`, `operations/first-run.md`, `templates/first-run.md` (`.engine/tools/instantiator.py`, ground-truthed against engine-template `origin/main`). But files that **survive** retirement still statically reference the deleted modules: `.engine/tools/test_security_seed.py` and `test_security_floor.py` import `test_instantiator` (and `test_security_seed.py` also imports `instantiator`), so after retirement a generated repo's `unittest discover -s tools -p 'test_*.py'` aborts at **collection time** and the adopter's **required `engine-ci`** check goes red. Per [constraints](../reference/constraints.md) (a generated repo's committed workflows do not run on the generation commit, only on the next real push/PR), the operator first meets this red X on their **first real PR** — the trust-critical ask-and-walk-away moment — as a Python `ImportError` a non-engineer cannot read and no channel but the AI's reply surfaces. The locked provisioning canon specifies *that* first-run assets self-delete ([D-012](0012-provisioning-is-two-subsystems-on-one-manifest-grammar-modul.md), [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md), [D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md)) but states **no invariant that the surviving set is closed over references to the retired set** — the silence that let the build introduce the defect and would let it recur on the next first-run asset that has a test. engine-template #147's plan-gate cold review surfaced it (out of #147's own LICENSE scope) and parked it for this litigation session.

  **The decision — a property-defined provisioning invariant + a mandated mechanical check, the operator's "invariant + validator" choice.** A four-lens cold plan-audit (adversarial · technical-feasibility · non-engineer-operator · architect) ran against the proposed plan; it found **no fatal flaw** — the feasibility lens re-traced the live `retire()` and the offending imports against `origin/main` and confirmed `custom/script` (precedent: the existing `uv-group-drift.json` hard CI check) can express the closure as pure static analysis — and its blocking/serious findings are folded into the authorized design:
  - **The invariant (provisioning, definition-of-record).** *First-run retirement is reference-closed:* no file that **survives** instantiation may statically reference a **retired** first-run asset — by `import`, `importlib`, a subprocess invocation of its path, or a hard-coded read of a retired file's path. A surviving file that needs such machinery **is itself a first-run asset** (retired in the same pass) or is removed. **No "guard it instead" exemption** — a static check cannot certify that a guarded import keeps a generated repo's first CI green (a top-level `try/except ImportError` still red-fails when a test body later names the absent module), so blessing a guard would be a [§7](../principles.md) overclaim. Membership is **by property, not a frozen list** (the closure spans `import`/`importlib`/subprocess/path-read, not the single `import` symptom observed) — the [D-217](0217-authorize-the-derived-committed-artifact-reconcile-re-litiga.md) define-by-property discipline.
  - **The check (validation coverage + validators-core rule-data).** A **hard**, **CI**-suite `custom/script` check, owned by [validators-core](../spec/modules/validators-core.md) as rule-data (the `uv-group-drift.json` shape — derive-from-source-and-compare, no `pass_token`), listed in [validation](../spec/systems/guardrails/validation.md) "What it covers". It surfaces a finding to the **operator-communication standard** ([D-215](0215-authorize-the-operator-prose-register-re-litigation-sharpen.md)/[D-216](0216-resolve-the-d-215-operator-prose-register-re-litigation-land.md)): the **consequence** ("a leftover engine file points at setup code removed at first run; if shipped, the adopter's first check fails with an unreadable error"), the **concrete file + reference**, and the **disposition** (stop referencing the retired machinery, or retire the file in the same pass) — never "retire-set / closed under import / import graph" engineer shorthand on the surface ([§17](../principles.md) bars resting the maintainer's gate on code-reading).
  - **The anchor (repository-topology "What travels").** One additive cross-ref line: a surviving committed file must not depend on a first-run-retired module, pointing to provisioning's invariant. "What travels" enumerates *what* ships but stated no safety invariant *over* what ships; the closure hazard is precisely a travel hazard, so the law is its right anchor.
  - **Altitude — a provisioning invariant, not a new principle.** The single-instance closure rule does not earn a numbered §20: the structural twin (the [§15](../principles.md) guardrail-weakening guard, also a `custom/script` CI check enforcing a cross-system invariant) is a principle only because guardrail-integrity recurs across many systems; one travel-closure instance does not clear that bar. If a second travel-closure instance appears, *that* mints the principle.
  - **Correction to the #147 framing (confirmed by the audit).** The collection-breaking survivor set is **two** files (`test_security_seed.py`, `test_security_floor.py`), not the three the comment implied: `demo_security_seed.py` dangles but is a `demo_*` file unmatched by `-p 'test_*.py'`, so it breaks `python demo_security_seed.py`, not `unittest discover` — a real but distinct dangling-demo defect the same invariant covers. `test_instantiator.py` self-deletes (it is itself retired), so it is not a survivor. The comment's "#134 marker-guard" precedent citation is spurious — #134 is the marketing-README marker task; "travel-safety" is coined at #147, not settled precedent.

  **Scope. Re-lock set — 4** (all currently locked → re-locked, none added): [provisioning](../spec/systems/infrastructure/provisioning.md), [validation](../spec/systems/guardrails/validation.md), [validators-core](../spec/modules/validators-core.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md). **Carriers (non-locked, authored this pass):** [glossary](../reference/glossary.md) (the *travel-safety* term, pointing at provisioning as definition-of-record), [risks](../reference/risks.md) ([R28](../reference/risks.md) — a surviving engine file dangling on a retired first-run module; partitioned from [R18](../reference/risks.md) first-run-availability and [R5](../reference/risks.md) install-as-surgery as a distinct *reference-survival* failure mode). **Verify-no-edit (confirm at the landed-text audit):** [engine-architecture](../architecture.md) (no system/surface/role added — it carries no exhaustive principle index, the [D-218](0218-resolve-the-d-217-derived-committed-artifact-reconcile-re-li.md) convention), [modules/README](../reference/module-catalog.md) (no module edge/status change — validators-core gains a rule-data file, not a dependency), the [check](../spec/systems/surfaces/check.md) surface (a new check *instance*, not a new kind or grammar). **Build-owes (engine-template, downstream — not authored here):** (1) bring the surviving set into closure — `test_security_seed.py` + `test_security_floor.py` stop importing the retired harness (the two collection-breakers), `demo_security_seed.py` stops referencing `instantiator` (the dangling-demo), each fixed-or-retired after an **AST scan grounds the full surviving-reference set**; (2) **required** — realize the closure check: a **permanent** check callable doing pure static reference-closure analysis (`import`/`importlib`/subprocess-by-path/retired-path-read) that **reads the retired-asset set without statically importing retired machinery** (AST/manifest, never `import instantiator` — else the check is itself the next dangler) and **no-ops gracefully once the first-run machinery is already retired** (the adopter's post-first-run tree); (3) make `_FIRST_RUN_ASSET_FILES` machine-readable from a stable source if the check needs it; (4) the plain-language finding copy (a build-leaf under the operator-communication standard above); (5) regenerate `graph.json` last, full suite + `validate --suite CI` green, one `guardrail-ack` (touches guarded `.engine/tools/`). **Residual (operator-lens, named not built):** an adopter who generated before this ships — or a slip-through — remediates via the **engine-upgrade overlay** (engine code replaced wholesale → the corrected retire-set + the new check) plus boot's plain-language open-findings relay; the template-side hard check is go-forward prevention, the upgrade overlay is the deployed-instance backstop. The re-locks land under the **Resolve** entry ([D-220](0220-resolve-the-d-219-first-run-travel-safety-re-litigation-land.md)) after the mandatory landed-text cold audit.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval, and the gap is real and was hit live: the locked retire model deletes first-run assets but never constrained what the *survivors* may reference, so a non-engineer-hostile red `engine-ci` on a clean first run could (and in three files did) arise. A provisioning-local invariant is the right altitude — single-instance, so below a numbered principle — and the property definition (reference-closure, not the one `import` symptom) plus the strict no-guard semantic make the mandated `custom/script` check honestly enforceable at the [§7](../principles.md) hard tier. The plan-audit's folds — the unenforceable guard escape, the too-narrow "import" word, the imprecise three-file claim, the check-reads-its-own-retired-list trap, the engineer-shorthand message, the topology anchor — are folded into this authorized wording before any edit, which is what makes this a litigated change rather than a session reflex.

## What we ruled out

**Fix only the engine-template build bug, no design change** (rejected — leaves the canon silent, so the defect class recurs on the next first-run asset with a test; the operator chose invariant + validator). **Keep the "OR guard the import" exemption** (rejected — a static check cannot certify a guard yields green first-run CI; it is a [§7](../principles.md) overclaim and readmits the red X). **Word the invariant "closed under import"** (rejected — too narrow; misses `importlib`, subprocess-by-path, and the live `instantiator.TEMPLATE_PATH` retired-path read; define by reference-closure property). **Mint a numbered §20 travel-safety principle** (rejected — single instance; the [§15](../principles.md) twin earned its principle by recurring across many systems; promote only on a second instance). **Scope repository-topology out to keep the re-lock set at three** (rejected — "What travels" is the law this is an instance of; omitting the anchor to spare a lock is dodging a justified edit). **Enumerate the three files as "the breaking set"** (rejected — only two break `unittest discover`; `demo_security_seed.py` is a distinct dangling-demo defect; precision matters for the build-owe). **Put the closure-check's plain-language copy in the locked design** (rejected — the *message standard* is design law, the exact copy is a build-leaf, the [D-218](0218-resolve-the-d-217-derived-committed-artifact-reconcile-re-li.md)/build-spec boundary).
