# Resolve the D-198 standing-situation correction: landed-text cold audit, state + build-orchestration + boot re-locked

*Decided 2026-06-15 in the design workspace.*

## The decision

The [D-198](0198-authorize-correcting-100-where-we-are-is-assembled-read-only.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with four independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written reverts/reframes in [state](../spec/systems/cognitive/state.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [boot](../spec/systems/lifecycle/boot.md) plus the carriers ([glossary](../reference/glossary.md), [risks](../reference/risks.md) [R23](../reference/risks.md), [scenarios/build-session](../architecture.md#build-session-lifecycle), [scenarios/routine-session](../architecture.md#routine-session)). **Outcome: adversarial and architect PASS clean; the technical-feasibility "blocking" findings rejected as a layer confusion and routed to the build-owes; the non-engineer-operator card-rendering laws folded into boot.** Re-lock set: **3**.

  **The audit + dispositions.**
  - **Adversarial — PASS (no blocking/serious/nit).** The revert is complete — no doc still assumes build-orchestration advances the cursor; [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) reads **scar-free** (no orphaned "(below)", no double-blank, no dangling transition where the six [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md) additions were removed); reframed [state](../spec/systems/cognitive/state.md) coheres (the "assembled, not advanced" commitment contradicts neither the malformed-file refusal, the degradation limits, the known-unbounded bound, nor "now and next is surfaced, not stored"); the "debt count's sibling" framing is **honestly qualified** as composite (`phase` strong, `milestone` best-effort with a `none set` fallback), not overclaimed; boot's new subsection preserves the read-only law (derive-for-display ≠ regenerate committed state); no anti-changelog cruft.
  - **Architect — PASS (no blocking/serious).** Revert complete + **re-lock scope correct at exactly three**; boot's touch is **warranted, minimal, and read-only-clean** (the design must require boot to *derive* live, not just read the cache — boot's existing "what just happened" derivation is the congruent pattern); the reframe is [§2](../principles.md)/[§3](../principles.md)/[§16](../principles.md)-clean (canonical truth in GitHub; replaceable offline cache in state; boot owns the read-time assembly; build-orchestration relays by producing the artifacts the projection reads); **[telemetry](../spec/systems/guardrails/telemetry.md), [attention](../spec/systems/cognitive/attention.md), [knowledge](../spec/systems/cognitive/knowledge.md), [modules/core](../spec/modules/core.md), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning) genuinely stay verify-no-edit**; the [D-198](0198-authorize-correcting-100-where-we-are-is-assembled-read-only.md)→[D-199](0199-resolve-the-d-198-standing-situation-correction-landed-text.md) supersession is append-only-correct ([D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md)/[D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md) stay unedited); scope is purely subtractive + reframe (no new field/capability/gate, R6).
  - **Technical-feasibility — "blocking" findings REJECTED as a layer confusion, routed to the build-owes.** The lens ground-truthed (correctly, of the as-**built** repo) that `boot.py` currently *reads* `standing_situation` from the committed file and does **not** derive it, that `telemetry.run()` is not production-wired, and that the repo has **zero** GitHub Milestones. These are true of the **build**, but this is a **design re-litigation authored as current-state target** (the four authoring rules): the design *specifies* that boot **must derive** the standing-situation live (the build owes that realization), not that the build already does. The design closes the hole at the design layer (the explicit "derive live … no session advances a stored marker, so the online card cannot silently rot" law); the build conforms one-way. The feasibility *facts* were **confirmed** — `phase` is derivable from build Issues, `milestone` from the active Milestone when present, and derive-for-display is read-only. Routed to the build-owes (the corrected #100 comment makes explicit: **boot must derive, not read the cache**; wire the cache refresh for **both** fields; the current no-Milestone state is the honest `none set`).
  - **Non-engineer-operator — folded into boot.** The card-rendering **laws** are now pinned in boot: distinguish the live "where we are" from the cached one in plain language (the card shows **one** — live *or* cached, never both); render an **absent `milestone` as an honest normal state**, never an error; carry **no engine jargon** (the [§12](../principles.md) leak guard); and "unreachable" names **outage or expired auth**. The exact wording and the live-vs-cached query/timing mechanism stay build-spec leaves (the law is one-value-per-session-labelled).

The engine-template **#100** build realization (boot's derive-at-orientation step; the both-fields offline-cache refresh; **stop the advance-tool worktree already begun**) is the downstream build-owes, communicated via a corrected #100 comment, not authored here.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran (four lenses), the adversarial and architect lenses passed clean, the operator card-rendering laws were folded into boot, and the technical-feasibility "blocking" findings were ground-truthed as true-of-the-build-but-not-the-design — a design re-litigation specifies the target and the build owes conformance — so they were rejected at the design layer and routed to the build-owes, not silently dropped. The design is faithful to [D-198](0198-authorize-correcting-100-where-we-are-is-assembled-read-only.md): build-orchestration owns nothing about the cursor; the standing-situation is assembled read-only by boot from native sources (`phase` engine-derived, `milestone` operator-Milestone or `none set`), online-live and offline-cached; the honest bounds (composite derivability; the offline cache best-effort/labelled) are named, never over-promised.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Treat the technical "blocking" findings as design blockers** (rejected — ground-truthed as true of the as-built but a layer confusion: the design is authored as the current-state target the build conforms to one-way, so "the build hasn't built it yet" is the build-owes, communicated via the #100 comment, not a design defect; the feasibility facts were confirmed). **Pin the card's exact wording / live-vs-cached timing as locked laws** (rejected — laws-not-leaves: the *laws* (distinguish live/cached, one-value-per-session, `none set` honest, no jargon) are locked in boot; the exact copy and query/timing mechanism are build-spec leaves). **Edit [telemetry](../spec/systems/guardrails/telemetry.md) to own the standing-situation cache refresh** (rejected — telemetry owns the debt register; the standing-situation cache rides the same GitHub-derived-cache pass as a build realization, not a telemetry design responsibility; verify-no-edit holds).
