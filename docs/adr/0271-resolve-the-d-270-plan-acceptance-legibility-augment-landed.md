# Resolve the D-270 plan-acceptance legibility augment: landed-text cold audit clean (design), one serious accept-with-clear-context coverage gap + nits folded, modes + hooks re-locked

*Decided 2026-06-28 in the design workspace.*

## The decision

The [D-270](0270-litigate-engine-template-276-make-the-explore-build-switch-o.md) change-set is landed and **re-locked**. The mandatory **landed-text cold audit** ran with four independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written [modes](../spec/systems/lifecycle/modes.md) acceptance-path paragraphs + plan-acceptance build-spec leaf and the [hooks](../spec/systems/infrastructure/hooks.md) `PostToolUse` owner row, plus [D-270](0270-litigate-engine-template-276-make-the-explore-build-switch-o.md), [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)/[D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md), and the carrier-disposition targets. **The augment cleared on all four lenses** — adversarial traced the resume-safety turn-by-turn and found the three guards (signal-is-sole-record + boot-stance-line-authoritative + kickoff-guarded-by-live-signal-re-read) individually load-bearing and jointly sufficient as worded, every non-superseded [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)/[D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md) guarantee preserved, the supersession surgical and append-only-respecting; architect confirmed the **re-lock set {modes, hooks} complete and correct** with all four verify-no-edit dispositions holding against the text (**the [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md) boot-escalation flag does not trip — boot needs no edit**, its existing reliable-resume + stance-line text fully supports modes' authority assertion, and the authority correctly lives in the modes leaf as the new mechanism's owner); non-engineer-operator confirmed exactly-once announcement, no resume lie, honest tier intact. **Findings resolved before re-lock:**
  - **(serious — technical-feasibility) the accept-with-clear-context non-fire was uncovered.** Per live claude-code [#20397](https://github.com/anthropics/claude-code/issues/20397), `PostToolUse(ExitPlanMode)` does **not** fire when a plan is accepted *with context cleared*, so that accept variant leaves the signal absent. This is **fail-safe** (no false Build — the session stays Explore) and **pre-existing to [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)** (it is the same non-fire class [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)'s mechanism already resolves to the Explore floor), not introduced by D-270; the gap was coverage. **Resolved:** the modes build-spec leaf now **names the accept-with-clear-context non-fire explicitly** (hook does not fire → Explore fail-safe floor, the operator-typed verb the recovery path, best-effort/fail-safe/never-a-false-Build), folding it into the named build-slice conformance set; the law level already covers it ("a hook that never fires … leaves the signal absent → Explore, the fail-safe floor").
  - **(nits, folded)** "stale boot briefing that still reads Explore" → "the start-of-session boot briefing (which always reads Explore by design)" so boot's deliberate every-session reset is not misread as a defect; the bare "(a resume reliably re-renders it)" anchored to the reliable-resume path ([D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)); "≈10,000-character cap" → exact "10,000-character cap."
  - **(nit, dispositioned no-edit)** the "announced kickoff" vocabulary modes uses for build-orchestration's operator announcement is **inherited unchanged from [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)** (build-orchestration's text says "opens a draft PR and shows the headline," never "kickoff") — a pre-existing concept-not-named-thing cross-reference, not introduced here; build-orchestration disposition stays verify-no-edit (any vocabulary alignment is later non-blocking polish).
  **Re-lock set (2):** [modes](../spec/systems/lifecycle/modes.md), [hooks](../spec/systems/infrastructure/hooks.md). **Re-lock:** `python3 lock.py --relock` run on both under this decision; `python3 validate.py` green. **Non-locked propagation — recorded verify-no-edit (the [D-251](0251-reject-engine-template-255-s-explore-gate-memory-carve-out-t.md) discipline):** [R11](../reference/risks.md) (orthogonal — the verb-drop quirk; the accept-with-clear-context non-fire is the same fail-safe entry-miss class R11 already generalizes; its operator-legible-still-in-Explore mitigation stands); [scenarios/build-session.md](../architecture.md#build-session-lifecycle) (the "accepting a plan … the same announced kickoff follows" description stays truthful — the assistant-legibility fix is internal mechanism, not an operator-facing flow change); wbs (no post-M1 acceptance-trigger conformance slice exists — `core-build-roadmap` was retired at completion; the conformance rides the engine-template build-owes, not a planning slice). **Build-owes (engine-template, filed via [`issue_author.py`](https://github.com/StarshipSuperjam/engine-template) + `engine` label, citing [D-270](0270-litigate-engine-template-276-make-the-explore-build-switch-o.md)/[D-271](0271-resolve-the-d-270-plan-acceptance-legibility-augment-landed.md)):** implement the additionalContext injection to the laws; the `modes.py stance` session-id auto-resolution leaf fix; the conformance set (PostToolUse-fires-on-ExitPlanMode-accept + additionalContext-reaches-model re-verify, accept-with-clear-context handling, resumed-session-neither-acts-nor-reports-Build, announce-present-and-singular). **Resolves engine-template #276.**

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran, the design cleared on all four lenses, and the one serious finding *strengthened* the change rather than reversing it — the accept-with-clear-context non-fire is now named coverage (fail-safe, with the verb recovery) instead of an unstated platform surprise, and it confirmed the platform facts the design rests on (additionalContext reaches the model, replayed-not-rerun on resume, SessionStart re-runs reliably on `source:"resume"`). The augment is landed: on plan-acceptance the modes hook sets the stance signal **and** injects an assistant-internal directive that triggers the announced kickoff, the falsified "a PostToolUse hook cannot inject conversational text" claim is corrected with the durable principle in the locked docs and the dated mechanism in the leaf + log, the resume case is inert-by-construction, and the operator-legibility guarantee #276 threatened is restored.

## What we ruled out

**Re-lock without naming the accept-with-clear-context case** (rejected — leaving a known current-platform non-fire unstated would let the build hit it as a surprise; naming it as fail-safe coverage with the verb recovery is the §7/§17 honest posture). **Expand the re-lock set to boot** (rejected — the audit confirmed boot needs no edit; the authority statement lives correctly in the modes leaf, and boot's existing text supports it without contradiction; an unneeded boot re-litigation would churn a doc just re-locked under [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)). **Edit R11 / build-session / wbs** (rejected — each is verify-no-edit against the landed text, recorded above per the [D-251](0251-reject-engine-template-255-s-explore-gate-memory-carve-out-t.md) dispositions-not-skipped discipline). **Defer the re-lock** (rejected — the audit cleared; leaving two locked docs fingerprint-failing is the silent-drift state the lock gate forbids).
