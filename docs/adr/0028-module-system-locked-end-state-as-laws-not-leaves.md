# Module system locked end-state, as laws not leaves

*Decided 2026-05-23 in the design workspace.*

## The decision

Design and lock [module-system](../spec/systems/grammar/module-system.md) to its final current-state, expressed as **laws, not membership**. Six cuts: **(1) Manifest grammar** — one manifest per module at `.engine/modules/<id>/manifest.json` (`id`, `version`, `status`, `provides`, `wires`, `depends`, `migrations`); not a catalog surface; schema-governed via a `check` rule of kind `schema`; `provides` is **file-precise** and every engine file maps to exactly one module. **(2) No separate registry** — the available set is *derived* from the present manifests; the [D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md) **engine manifest** is the installed-set + per-package-version lockfile; **installed ⇔ present** (first-run deletes unselected modules — **fork 1**); the operator sees one engine version, per-package versions are internal bookkeeping (**fork 2**). **(3) Dependency resolution** is presence + acyclicity + topological order + a coherence **range-check**, with **no version solver** (single-release pinning). **(4) The wiring library** (permanent, in `.engine/tools/`, called by both provisioning subsystems) applies/reverses a **closed seam vocabulary** (`hook`, `mcp`, `ontology-entry`, `permission`, `gitignore`) — **no `custom/script` escape hatch** — keyed on **engine-namespaced identity** (never bare content), erring toward leaving unnamespaceable entries rather than mis-removing; **no seam edits product source**. **(5) Coherence** (the locked [validation](../spec/systems/guardrails/validation.md) check-kind, invoked directly post-install) confirms declared ⟺ applied wiring + `depends` satisfied + the one-owner file mapping; suites are derived and ontology coverage is a separate gate. **(6) MCP** definitions live in the root `.mcp.json` (engine-prefixed names, `${CLAUDE_PROJECT_DIR}`, gitignored data); **approval is operator-owned**, not engine wiring. Lifecycle: install / uninstall (manifest-derived reversal) / upgrade (overlay installed packages only, no resurrection) / clean removal (reversal + an operator-privileged control-plane de-bootstrap). Two operator-facing **design laws** are recorded for the [Q4](../reference/open-questions.md) bootstrap-UX session: the loudly-surfaced inactive-substrate message **names the substrate + states the degraded mode + gives the fix command**, and the "what is my engine made of" readout has a **named operator-reachable access path**. Opens [Q10](../reference/open-questions.md). [module-system](../spec/systems/grammar/module-system.md) is set `locked`; [topology](../spec/systems/infrastructure/repository-topology.md) is re-locked separately under [D-027](0027-topology-admits-root-mcp-json-as-a-tool-dictated-slot-re-lit.md).

## Why

The module system is the composability layer that kills the "every feature is a refactor" failure ([R5](../reference/risks.md)) and whose dependency graph's topological sort *is* the build order (WBS), so it must be settled before the build. Locking laws not membership follows the [D-016](0016-repository-topology-as-a-foundational-substrate-product-owns.md)/[D-019](0019-authoring-grammar-locked-end-state-as-laws-not-leaves.md)/[D-022](0022-hooks-locked-as-foundation-11-as-laws-not-leaves.md)/[D-023](0023-check-system-locked-validator-architecture-the-check-surface.md) precedent — the grammar does not depend on which modules ship ([Q1](../reference/open-questions.md)). The forks serve the risk-containment goal: installed-⇔-present means absent code cannot fail, and the closed seam vocabulary plus engine-namespaced-identity keying are the actual contagion firewall ([D-025](0025-fault-containment-is-earned-at-the-seams-not-conferred-by-mo.md) — fault-containment is earned at the seams). The cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran twice — on the plan and again on the authored docs — with four lenses; technical-feasibility verified the platform facts (root `.mcp.json` keyed by name, `${CLAUDE_PROJECT_DIR:-.}`, the settings.json hook schema, template-copies-tree-not-settings, `gh release download --repo`, and the unreported-required-check merge deadlock). Blocking/serious findings were all resolved before the lock: the engine-manifest "thin" idea (adopted the D-024 lockfile instead), the keying collision risk (engine-namespaced identity, not bare content), the overlay resurrecting deselected modules (overlay installed packages only), clean removal's control-plane settings and operator-privilege dependency, the `mcp` enable-flag reverser ambiguity (approval is operator-owned, not engine-cleared), and the operator surfacing/readout reach (recorded as Q4 design laws).

## What we ruled out

A separate hand-authored module registry (rejected — a duplicate that only drifts; the available set is derived and the installed set is the D-024 manifest). A thin engine manifest of only the release tag (rejected — contradicts locked D-024 and drops the non-derivable pre-overlay version state migrations need). A version solver / independent per-module semver resolution (rejected — every module ships from one tagged release; `depends` is a coherence assertion, not a SAT problem). Structural keying on bare content (rejected — would mis-remove an operator's or product's identical-looking entry; key on engine-namespaced identity). A `custom/script` wiring escape hatch (rejected — an irreversible shared-state mutation is the R5 failure). A `master` manifest field classifying who each module serves (rejected — it forces a classification, edges into the deferred cognitive-content scoping, and is unnecessary: asymmetry is enforced mechanically and wiring is master-agnostic). Auto-clearing the operator's MCP approval on uninstall (rejected — approval is the operator's trust decision, not engine wiring).
