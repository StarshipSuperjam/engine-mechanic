# Resolve the D-189 operator-checkout-boundary re-litigation: landed-text cold audit, five docs re-locked

*Decided 2026-06-13 in the design workspace.*

## The decision

The [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with four independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written edits to [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [modules/core](../spec/modules/core.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [boot](../spec/systems/lifecycle/boot.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md) plus the non-locked carriers ([constraints](../reference/constraints.md), [glossary](../reference/glossary.md), [risks](../reference/risks.md) [R20](../reference/risks.md), [scenarios/routine-session](../architecture.md#routine-session)). **Outcome: one serious + two nits folded; one nit rejected with rationale; technical-feasibility and architect lenses PASS.** Re-lock set: **5**.

  **The audit + dispositions.**
  - **Technical-feasibility — PASS.** Every git/platform fact verified empirically (git 2.50.1) and against current Claude Code/GitHub docs: a worktree session resolves the main checkout via `git worktree list`/`--git-common-dir` (local, no network); the lossless predicate `rev-list HEAD --not --branches` empty + `stash list` empty + `status --porcelain` clean is offline-correct **and valid on a detached `HEAD`** (where `@{upstream}` throws — confirming D-189's tool choice and its rationale); rescue-branch-before-switch is non-orphaning and `--ff-only` refuses divergence; gitignoring `.claude/worktrees/` is the platform-endorsed pollution fix (matches the Claude Code worktrees doc verbatim); the constraints auto-worktree facts match current docs near-verbatim (Desktop auto-isolation; `origin/HEAD` base with offline local-`HEAD` fallback; **scheduled tasks do not auto-isolate by default** — the worktree toggle); GitHub offers no server-side gate on Issue *creation* (#74b posture-only confirmed). Version-fragile platform facts are correctly held under the don't-depend posture / build-spec leaves.
  - **Architect — PASS (no findings).** Propagation complete and single-owner-clean: build-orchestration owns the prevention posture and defers the health predicate to provisioning (no restatement); provisioning owns the detector + mechanism + the lossless safety law; boot relays read-only and names provisioning as the actor; modules/core's §16 seam mirrors the existing "provisioning applies / control-plane defines" pattern; repository-topology is one defer-pointer. Counts/tiers/residual-sets reconcile across docs (boot "Five" = five bullets; open-findings tier consistent in boot/risks/core; the residual set identical in build-orchestration/constraints/R20). **[external-contribution](../spec/systems/lifecycle/external-contribution.md) genuinely stays verify-no-edit** — the floor's two-axis scoping (working-location class + the explicit "never to commits reaching the default branch through the reviewed PR" carve-out) does not collide with fork-main substrate commits, whose concrete working location is an external-contribution build-spec leaf. **[modes](../spec/systems/lifecycle/modes.md) and [control-plane](../spec/systems/infrastructure/control-plane.md) verified untouched** (no operator-checkout text gained).
  - **Non-engineer-operator — PASS, one nit (rejected).** Every operator-facing *string* is jargon-clean (boot's "your project folder has drifted into a broken state; … here's how to get it healthy"; provisioning's rescue-then-update consent and the "missing the last weeks of merged work" consequence quote); the present-marker floor was confirmed **not** edited and stays cause-agnostic and jargon-free; the never-strand-main floor is correctly AI-facing (the deployed `CLAUDE.md`, which the AI reads); #74b creates no operator-visible refusal; R20/#80 is honestly tiered, never a blanket "always catch a stale checkout." The lone nit — boot's design-register prose ("re-attach") sitting near the operator quotes could bleed into the build-spec leaf — was **rejected**: provisioning's leaf law already forbids git verbs (detached, fast-forward, rescue branch, `rev-list`) on the operator surface and boot defers operator copy to provisioning, so boot's parenthetical is design-register for the doc reader, not an operator string.
  - **Adversarial — one serious + two nits, all folded.** Folded: **(serious)** the lossless claim was *absolute* while its enumerated predicates (`rev-list HEAD --not --branches` + `stash` + `status`) cannot see commits a *prior* `reset --hard` left reachable only from the reflog — so provisioning's safety law now scopes losslessness to *its own operations* (never discards branch-reachable / detached-`HEAD` / stashed work; a prior reset's reflog-only orphans are neither created nor touched, with git's reflog their backstop), matching the §7 honest tier; **(nit)** build-orchestration's design-commitment "the merge stays the only unbypassable wall" gained the **"for shipped history"** qualifier its siblings carry (R20: the wall does not cover local-checkout integrity); **(nit)** a dropped-word grammar slip in the Routine worktree-toggle sentence was repaired. The adversarial lens confirmed the floor↔fix carve-out is airtight across all three docs, overclaim is otherwise clean, and the behind-ness / double-fault tiers are consistently and honestly stated.

  **Folds applied before re-lock** (two in provisioning's owning docs): the provisioning lossless-scope clause (reflog backstop named); the build-orchestration "for shipped history" qualifier; the build-orchestration grammar repair.

  **Re-lock set (5):** [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [modules/core](../spec/modules/core.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [boot](../spec/systems/lifecycle/boot.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md). **Re-lock:** `python3 lock.py --relock` run on all five under this decision; `python3 validate.py` green. **Non-locked carriers edited:** [constraints](../reference/constraints.md) (the version-contingent auto-worktree quirk), [glossary](../reference/glossary.md) (*operator checkout* + *stranded checkout*), [risks](../reference/risks.md) ([R20](../reference/risks.md)), [scenarios/routine-session](../architecture.md#routine-session) (the worktree-toggle note). **Verified-no-edit (logged):** [external-contribution](../spec/systems/lifecycle/external-contribution.md), [modes](../spec/systems/lifecycle/modes.md), [control-plane](../spec/systems/infrastructure/control-plane.md) (the #74b producer-set note deferred to the #62/#63 follow-up), [engine-architecture](../architecture.md), [state](../spec/systems/cognitive/state.md), [attention](../spec/systems/cognitive/attention.md). **No [open-questions.md](../reference/open-questions.md) opened/resolved; no [deviations](../reference/prototype-deviations.md) entry.** The engine-template **#79/#80/#74** build realizations (the detector + un-stranding fix, the never-strand-main floor, the `/engine-routine` worktree-toggle guidance, the #74b issue-helper binding) are downstream follow-ups filed against the build, not authored here.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran (four lenses), the technical and architect lenses passed, the one serious (an absolute losslessness claim outrunning its predicates) and two nits were folded in the as-written text, and the single operator nit was ground-truthed as already covered by provisioning's leaf law and rejected with rationale. The design is faithful to [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md): recognize native worktree isolation + the never-strand-main posture floor (no bespoke guard, no [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md) re-open), detect a *stranded* (not merely behind) operator checkout, offer a lossless-or-it-does-not-run un-stranding fix owned by provisioning and relayed read-only by boot, all honestly tiered with the merge wall covering only shipped history.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Leave the absolute "lossless / no loss" claim** (rejected — it outran its own enumerated offline predicates for the prior-`reset` reflog case; the §7 honest tier requires scoping the claim to the fix's operations and naming reflog as the backstop, even though the fix creates no loss). **Add a reflog scan to the offline gate** (rejected for v1 — real build complexity for a low-probability, git-recoverable path; the honest scoping plus reflog-as-backstop is the proportionate resolution, with the concrete gate commands a build-spec leaf). **Fold the operator-nit by editing boot's prose** (rejected — no operator string leaks; the leaf law in provisioning already forbids git verbs on the operator surface, and boot's parenthetical is design-register). **Edit [external-contribution](../spec/systems/lifecycle/external-contribution.md), [modes](../spec/systems/lifecycle/modes.md), or [control-plane](../spec/systems/infrastructure/control-plane.md)** (rejected — the floor's location/branch scoping keeps fork-main commits clear; modes' gate is unchanged; the #74b producer-set note is deferred to the #62/#63 follow-up to avoid re-locking a foundation for a provisional one-liner).
