# Comprehensive cold audit of the D-156 tool-runtime change-set; resolve findings; re-lock the eight foundations

*Decided 2026-05-31 in the design workspace.*

## The decision

Ran the operator-chosen **single comprehensive cold-session audit** over the coherent [D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md) change-set (the [D-153](0153-clear-the-deferred-nit-backlog-one-batched-re-litigation-of.md) batched-re-litigation instrument at the scope D-156 authorized, not eight separate per-doc audits): **six independent cold-context lenses** — adversarial/contradiction-with-locked, architect/cross-doc-seam, technical-feasibility (uv facts re-verified against current Astral docs), non-engineer-operator, genesis/build-readiness, and authoring-discipline — over the eight edited locked docs, the eight non-locked edits, and D-156. **Verdict: no blocking finding.** Technical-feasibility re-confirmed every load-bearing uv claim TRUE (PEP 735 dependency-groups are Final; `uv.lock` resolves the full group set while group-scoped `uv sync` installs only the selected groups — *reinforced* by uv's default exact-sync pruning, so *installed means present* is mechanically enforced, not merely by omission; uv-managed standalone interpreter; `UV_NO_MODIFY_PATH`; SHA-pinnable `setup-uv`; per-OS `bin/`÷`Scripts\`; sha256 lock hashes with the index-dependence caveat the docs already state). **Two serious findings, both resolved before the lock:** **(S1)** a code/config contradiction — [topology](../spec/systems/infrastructure/repository-topology.md)'s Law-5 corollary called the lockfiles "committed configuration" while [provisioning](../spec/systems/infrastructure/provisioning.md)'s upgrade step calls them "engine code (replaced wholesale)"; on the overlay axis (code replaced, config preserved) "configuration" would wrongly tell a builder to *preserve* the lockfiles across an upgrade, so topology now calls them **committed engine artifacts replaced wholesale, never preserved like operator config** (the intended behavior was always replace-wholesale; only the word was wrong). **(S2, precision)** D-156's pointer to the genesis dry-run cited dry-run.md §7 (the "what it is not" disclaimer, which carries the re-run *mandate*) rather than §3/§4/§8 (the genesis run-order + protocol); the log is append-only, so the **build-ready re-affirmation entry will cite §3/§4/§8**. **Actionable nits resolved in-doc:** the committed `uv.lock` still *names* a deselected module's deps (resolved-but-not-installed) — provisioning now states the residual is a static lockfile listing, never a live/importable surface; provisioning's illustrative ownership list gained the lockfiles (matching topology + [module-system](../spec/systems/grammar/module-system.md)); stage-0 §4 now pins the bare-seed `pyproject.toml` (stdlib-only validator → no dependency-groups) and names the maintainer's local uv install as the [R15](../reference/risks.md) residual (not a checklist-dischargeable proof); the [first-run](../architecture.md#first-run-provisioning) sequence note was reworded off the literal "install uv" so it cannot be lifted into operator copy. **Nits accepted with rationale (no edit):** D-156's QA-7 citation should have read QA-5/QA-1 (append-only; corrected in future refs); a one-clause §5 acknowledgment of the named inoperable bound is optional (the substance is honored across provisioning/boot/constraints/R18); the boot double-fault floor wording surfaces "did not ground" rather than "runtime needs repair" (loud either way — a build-session enhancement); the seed uv-version-pin source and the per-OS venv-bin-path resolution are build-spec leaves (the latter parenthetically flagged in [hooks](../spec/systems/infrastructure/hooks.md)). **With all blocking/serious resolved, re-locked the eight foundations** under D-156 in seam order — [tools](../spec/systems/surfaces/tools.md), [topology](../spec/systems/infrastructure/repository-topology.md), [module-system](../spec/systems/grammar/module-system.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [control-plane](../spec/systems/infrastructure/control-plane.md), [hooks](../spec/systems/infrastructure/hooks.md), [validation](../spec/systems/guardrails/validation.md), [boot](../spec/systems/lifecycle/boot.md) — via `python3 lock.py --relock <doc> --decision D-156`; `python3 validate.py` green. **Propagation:** the five fix-edits above + this entry. **Build-ready stays provisional** ([D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md)) pending the genesis dry-run re-run (§3/§4/§8) and a clean validate — the next and final step.

## Why

The single comprehensive audit is the operator-chosen proportionate instrument for one coherent change propagated across eight docs (already 5-lens plan-audited), the [D-151](0151-whole-corpus-design-audit-re-litigate-state-af-1-to-fix-the.md)/[D-153](0153-clear-the-deferred-nit-backlog-one-batched-re-litigation-of.md) batched precedent — and it earned its keep by catching S1, a live code/config contradiction on the load-bearing overlay axis that a per-doc audit reading topology alone would have passed. Both serious findings were resolved (S1 in-doc, S2 by deferring to the re-affirmation entry the append-only log requires) before any re-lock, per the HARD cold-session-audit gate; the lenses otherwise confirmed the crux (foundation-artifact lockfiles, group-scoped sync, helper-applied `.venv/` block) sound, the propagation complete, the uv facts true, and the operator surfaces trustworthy and jargon-free.

## What we ruled out

**Eight separate per-doc ≥4-lens audits** (rejected by the operator as disproportionate for one coherent, already-plan-audited change; the single comprehensive audit weighted to the seams covers the cross-doc defect class a per-doc audit cannot, and caught S1 precisely because it read topology and provisioning together). **Re-lock before fixing S1** (rejected — a live contradiction on the overlay axis is exactly the serious-finding class the gate exists to stop; lock discipline and the HARD audit rule forbid locking over it). **Edit D-156 to fix the §7 citation** (rejected — the decision log is append-only; the correction rides the forthcoming re-affirmation entry). **Treat the resolved-but-named-deps point as blocking** (rejected — a static lockfile listing of an uninstalled dependency is not a live surface; the honest clarification suffices, and per-module-derived lockfiles were already rejected at D-156 for re-litigating the closed-seam grammar).
