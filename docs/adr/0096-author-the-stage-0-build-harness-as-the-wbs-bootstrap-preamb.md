# Author the stage-0 build harness as the WBS bootstrap-preamble; split the engine-mechanic out as its own future system (Q20)

*Decided 2026-05-27 in the design workspace.*

## The decision

Author a new maintainer-layer WBS doc, wbs/stage-0-harness.md, specifying the **hand-built governance harness that constructs the engine-template repo before any engine module exists** — resolving the operator's "chicken-and-egg" (you cannot need a finished Engine to build the Engine). The harness ports this workspace's own proven governance *shape* (hard rules + a validator + a durable decision/PR record + a human merge gate + cold multi-agent review) to the build task across three named layers — **L1** workspace design-authoring, **L2** stage-0 maintainer construction, **L3** the deployed engine and the engine-mechanic — and is **scoped to L2**, naming its actor as the **template maintainer, not the non-engineer operator** (the "trusted by a non-engineer" north star governs only the deployed template). Its centerpiece is the **PR contract shipped in the seed commit**: all eight locked [control-plane](../spec/systems/infrastructure/control-plane.md) sections reproduced verbatim (**Purpose · Scope · Out of scope · Risk · Validation · Review · Files of interest · Claude involvement** — `Review` included), the PR-body completeness check (presence/non-emptiness `hard`, truthfulness posture [§7](../principles.md)), and the guardrail-weakening guard per [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md)/[§15](../principles.md) (the guard check **bound in the ruleset by its frozen name** [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) and **evaluated from a trusted source** so a PR cannot disarm its own guard), with [§11](../principles.md) stated precisely — the PR body carries *change-history*; *design decisions* land on the decision/contract surface and are **referenced**, not replaced. The doc also fixes: the **seed (stage 0.0)** as the irreducibly-ungated trust root with a **mandatory** (not optional) cold attestation; the seed validator superseding into [validators-core](../spec/modules/validators-core.md); the ruleset bootstrap (Risk [R1](../reference/risks.md)) in its strong form (the Actions `GITHUB_TOKEN` carries **no `administration` scope at all**); a present-tense **supersession ratchet**; and the **engine == product topology degeneracy** (in the construction repo the engine occupies the root and the [repository-topology](../spec/systems/infrastructure/repository-topology.md) partition is degenerate, so the seed root `CLAUDE.md` is the maintainer-construction file, distinct from the deployed-floor `CLAUDE.md` [boot](../spec/systems/lifecycle/boot.md) specifies — **neither locked doc is edited**). The self-hosting terminus — the **engine-mechanic** (a deployed Engine instance whose *product* is the template repo) and its **self-construction threshold** — is **split out** of this doc into [Q20](../reference/open-questions.md), to be designed as its own deployed-instance system, because it is net-new L3 architecture with unresolved hard problems.

## Why

The operator scoped this session to *spec the stage-0 harness, including the PR template, because an unstructured PR cannot be gate-checked.* Grounding it in the canon dissolved the paradox two ways — the v1 Engine is a *contributor* that builds products with a human in the loop ([§13](../principles.md)), so it need not build itself; and this workspace is itself a working proof that externalized discipline + mechanical checks + a human gate keeps multi-session AI work on the rails. A **four-lens cold multi-agent audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran on the plan **before approval**; its blocking/serious findings were folded: the engine-mechanic was net-new architecture mischaracterized as "no new design" and is now split out to [Q20](../reference/open-questions.md); the plan never named the maintainer-vs-operator actor and now does; the engine == product topology degeneracy was unaddressed and is now stated without editing locked topology/boot; the [§11](../principles.md) "PR body replaces a decision log" over-read was corrected; the guardrail-weakening citation was wrong (D-084) and is corrected to [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md); and the ungated seed's cold review was "optional" and is now mandatory. Technical-feasibility verified every platform fact against current GitHub documentation and the live Paideia reference (ruleset/token-scope asymmetry, "Use this template" copies files not settings, required-check merge gating, PR-template auto-fill) and added the load-bearing `types: [opened, synchronize, reopened, edited]` trigger and the "template generation leaves no git-native template→instance channel" caveat. The doc lands **unlocked** (the `wbs/` group is outside the validator's frontmatter, coverage, and lock gates), so it is fully reversible and the cold-audit lock gate correctly does not fire. Propagation per the matrix: wbs/README.md (pointer added + "not yet authored" status reconciled to "bootstrap-preamble authored; topological module sort pending"), [open-questions.md](../reference/open-questions.md) (Q20 opened), [risks.md](../reference/risks.md) (R6 reconciled — the harness operationalizes the WBS-layering control for the template's *own* construction), [glossary.md](../reference/glossary.md) (*stage-0 harness*, *seed (stage 0.0)*, *supersession ratchet* added). Verified no-change: [engine-architecture.md](../architecture.md) (a WBS detail doc names no new system — true precisely because the mechanic is split to [Q20](../reference/open-questions.md); the master stays a truthful index) and Risks R1/R7 (R1 already specifies the bootstrap contract the seed reuses; R7's reflexive-upgrade facet is parked in [Q20](../reference/open-questions.md) until the engine-mechanic is designed). No locked doc is edited.

## What we ruled out

Treat self-hosting as the build's *starting condition* (rejected — it manufactures the chicken-and-egg; the mechanic is the terminus reached only after a hand-built threshold). Deny self-hosting entirely (rejected — the engine-mechanic is a faithful [§13](../principles.md) application and a real goal; it is deferred to its own design, not dropped). Half-spec the engine-mechanic inside this WBS doc (rejected by the audit — it is net-new L3 architecture with unresolved trusting-trust ([§15](../principles.md) forbids a self-authored guard) and reflexive-upgrade problems; fixing an exit criterion to an undesigned construct is the "defer its own substance" failure). Omit the PR contract or its `Review` section from the seed (rejected — an unstructured PR is ungate-checkable and historyless, and dropping a locked section is a litigation-alarm event, not a quiet trim). Make seed attestation optional (rejected — the seed is the trust root no later rail can recover, so its cold review is mandatory). Fold the harness into a system doc rather than the WBS (rejected — it is build-sequencing that *precedes* the module graph, the same pre-graph build-order role the [repository topology](../spec/systems/infrastructure/repository-topology.md) holds). Edit the locked repository-topology/boot to handle engine == product (rejected — the degeneracy is stated in the harness doc; a topology law change, if ever required, is a litigation alarm, never a silent edit).
