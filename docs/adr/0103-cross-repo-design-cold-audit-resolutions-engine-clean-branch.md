# Cross-repo design cold audit: resolutions (engine-clean branch, build-orchestration close-model, posture honesty, mechanic trust base)

*Decided 2026-05-28 in the design workspace.*

## The decision

The four-lens cold-session design audit of the [external-contribution](../spec/systems/lifecycle/external-contribution.md) `designed` pass ([D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)) ran. The technical lens **verified the platform facts against live GitHub** — the fork-PR trust model holds (a fork pull request runs the *upstream's* own checks in the upstream's context regardless of fork settings, even more generally than [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)'s `pull_request_target`-specific phrasing; the general `pull_request` fork-PR model is the correct framing the system doc/scenario already use) — and the operator lens cleared the narration. The adversarial and architect lenses' blocking/serious findings are **resolved in the docs**: (1) the product-branch knowledge-regeneration "suppression" is **removed** — the product branch is cut from the upstream's *engine-free* default and carries no engine surfaces, so knowledge's regeneration (running in the Engine's fork-main context) produces nothing on it and **no change to the locked [knowledge](../spec/systems/cognitive/knowledge.md) foundation is required**; the [module](../spec/modules/external-contribution.md) accordingly wires **nothing** (any cross-fork `gh` `permission` is a build-spec leaf), and knowledge / hooks / telemetry drop out of the Phase-C seam set; (2) the [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) touch is **reclassified from "a minimal worker-base note" to a substantive close-model re-litigation** — the cross-fork close moves the unbypassable merge wall from the operator's own merge to the *upstream's*, which the locked close model does not currently admit; (3) the upstream-clean check is **named as honest posture, not a "guarantor"** ([§7](../principles.md)) — the branch is engine-clean by origin, the [§6](../principles.md) nudge catches an accidental engine path, and the **upstream's own review is the backstop**; (4) the engine-mechanic's non-reflexivity is **grounded in an independently-trusted human gate** (the engine-template maintainer ratifies every change before release; the mechanic upgrades only to ratified releases) — human-review-grade ([§15](../principles.md)'s *cannot weaken silently* tier), honestly not a falsifiable machine proof. Operator nits folded: the submitted-≠-accepted line is narrated **at submission and on status checks** (not doc-parked), and the working-fork degradation explicitly covers the **declined** case. The **corrected Phase-C seam set** is: provisioning (additive "upstream" disambiguation), control-plane (additive upstream-acceptance note), topology (additive CODEOWNERS-predicate note), and **build-orchestration (substantive close-model re-litigation)** — each gated on operator approval, dependency order, with its own cold audit before any relock.

## Why

The cold-session audit is the CLAUDE.md gate; its blocking/serious findings must be resolved or rejected-with-rationale before the design settles, and my standing finding-disposition rule forbids burying any. The two blocking findings were genuine honesty defects in the authored text: [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)'s framing that the mode "reuses the locked machinery, only a minimal worker-base note" understated the build-orchestration close-model change, and the "wires a hook to suppress knowledge regeneration" framing would have covertly reached into a locked core foundation ([§12](../principles.md)/[§15](../principles.md)). The knowledge-suppression proved **unnecessary**, not merely mis-framed — the engine-free branch origin makes the product branch clean without touching knowledge — so the fix both removes a locked-foundation seam and simplifies the design. The "guarantor"→posture and mechanic-trust-base corrections close [§7](../principles.md)/[§15](../principles.md) honesty gaps. Net: the audit **reduced** the locked-doc footprint (knowledge / hooks / telemetry seams dropped) while **raising** the honesty of the one substantive seam (build-orchestration) — a result the operator should weigh when authorizing Phase C, since that seam is a close-model re-litigation, not a cross-reference. Propagation: [external-contribution](../spec/systems/lifecycle/external-contribution.md) + [module](../spec/modules/external-contribution.md) corrected; [risks](../reference/risks.md) R13 reframed; [engine-architecture.md](../architecture.md) §3 seam list corrected; [scenarios/external-contribution.md](../architecture.md#contributing-to-an-external-repo) corrected; this entry. The design stays `designed`; Phase C remains gated on operator approval.

## What we ruled out

Keep the knowledge-suppression hook and name knowledge a Phase-C re-litigation target (rejected — the engine-free branch origin makes it unnecessary; a module hook overriding a locked foundation's behavior is exactly the covert weakening [§15](../principles.md) forbids). Leave build-orchestration described as "a minimal worker-base note" (rejected — the merge wall moves to the upstream, contradicting the locked close model's "the operator's merge is the wall"; [§7](../principles.md) requires naming it substantive). Keep "the nudge is the guarantor" (rejected — a §6 nudge that blocks nothing cannot guarantee; the honest backstop is the upstream's own review). Assert the mechanic "never self-upgrades to its own output" as the *mechanism* (rejected — unenforced separateness is not a guard; the real, honestly-named base is the human ratification gate on engine-template). Defer these to Phase C (rejected — they are current-truth corrections to the `designed` docs, not locked-doc edits; the docs must be honest now). Append nothing and silently edit [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md) (rejected — the decision-log is append-only; this entry refines D-102's seam-scope and platform-framing claims in the open).
