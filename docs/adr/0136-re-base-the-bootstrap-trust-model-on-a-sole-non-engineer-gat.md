# Re-base the bootstrap trust model on a sole non-engineer gate-holder; one informed-consent-on-evidence model at every layer; specify the build-conformance review

*Decided 2026-05-30 in the design workspace.*

## The decision

Correct a load-bearing error the operator surfaced: the stage-0 harness assumed the construction maintainer is **engineer-grade and "reviews code"** (§1 "engineer-grade work… a non-engineer is not promised"; §7 "in stage 0 it is the maintainer, who reviews code"). The maintainer is a **non-engineer (a project manager), the sole gate-holder from commit #1, with no outside engineer available — confirmed with the operator this session** (extends [D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md)'s confirmed solo-maintainer arrangement). So the bootstrap gets **no engineer-gated exception**: the merge gate is **informed consent on an evidence bundle, never code review**, the same trust bar the deployed template meets, from the seed commit. Five changes realize it. **(1) New principle [§17](../principles.md)** — "One trust gate — informed consent on evidence, never code review" — makes explicit what §6 + §15 only implied. **(2) The five-class evidence bundle** every bootstrap merge rests on (stage-0 §1/§7), only two classes non-AI: mechanical green (deterministic floor); the **build-conformance review** (AI; value = independence + adversarial pressure); **operator-driven behavioral demonstration** (the one class routing around AI, varied by the maintainer, never an AI-scripted happy path); **tests wired *through* the conformance review** (a green test *name* is never trusted alone — the lens attests name↔assertion fidelity + coverage, load-bearing tests get a behavioral demo, the build hands over a behavior→test map); and the honest control-plane **Review record**. **(3) New instrument wbs/build-conformance.md** — the per-non-trivial-PR post-build cold review (conformance reviewer + adversarial divergence-hunter lenses; the dry-run §4 ground-truth-before-recording + re-adjudicate-a-high-confirm-reviewer disciplines inherited **HARD**; PM-legible output, never line-level code). It is the **per-PR catch for a *semantic* misread** — code that builds and passes its own tests but implements the spec wrongly, producing a well-formed input re-grounding cannot catch (small-step + re-grounding bounds only *structural* compounding). It is the **detail home** the stage-0 §2/§7 cold-review invariants now point into, and — because the engine's own `design-review`/`qa-review` lenses are **product-aimed** (a [product-design](../spec/modules/product-design.md) spec referent; a disclosed no-op for a spec-less engine self-build) — it, not those lenses, covers "built engine vs engine-planning design" through **all of v1**. **(4) Honest residuals, named not closed:** the **seed** ([R15](../reference/risks.md)) — a behavioral proof shows a gate *fires*, not that it is bound/trusted/unbypassable, which needs config-reading; with no engineer, minimality + GitHub-native protections + an exhaustive operator-runnable checklist + maximal cold review shrink but do not close it; and **AI-on-AI conformance** ([R16](../reference/risks.md)) — a shared-blind-spot semantic divergence, or a wrong spec reproduced faithfully (a dry-run/design-audit job upstream, never build-conformance). Confidence is **bounded by the share of a change with a non-AI correlate**, stated not dressed as assurance ([§7](../principles.md)). **(5) New scenario [scenarios/genesis-build-conformance.md](../architecture.md#genesis-build-conformance)** proves the model operable. Two seed-machinery precision fixes ride along: stage-0 §3 disentangles the two guards' trigger models (the PR-body completeness check runs on the plain `pull_request` event reading body metadata only — no diff, no elevated perms; only the §15 weakening *classifier* is `pull_request_target`-class, and "reads diff only" is an authoring invariant the trigger does not enforce); and §5 sharpens the protection guard to require the **required-check bindings** (not just "protection on") and corrects that [R1](../reference/risks.md) **bites harder** here — the one-time ruleset application is now a non-engineer admin action, mitigated by the loud guard + a single documented step (a UI toggle by preference). **No locked doc is touched.**

## Why

Origin — the dry-run's "litany of misreads, adjudicated away" pattern raised the build-time question (does the *build* misread the way the audit does?), and the operator then corrected the engineer-maintainer premise. Per the audit-the-plan discipline a **four-lens cold-session design audit** (adversarial · technical-feasibility · non-engineer-operator · architect, cold-context, no shared session) ran against the **plan before any edit**; every blocking/serious finding was ground-truthed by the orchestrator and folded in. Blockers/serious caught and resolved: the draft reserved **D-135** which the concurrent session had just landed (ground-truthed against the live log → D-136); the draft **over-claimed "high confidence"** while four of five evidence classes are unverifiable AI self-report (→ bounded honest thesis, the pseudo-formula dropped); the **behavioral recipe was a deferred promise** (→ specified as substance and made operator-driven/varied); the **seed still needs code-reading** and the genesis paradox was under-stated (→ R15 elevated, not footnoted); **"audit test names" assumes coverage judgment a PM lacks** (→ tests wired through the cold lens + behavioral demo + a behavior→test map); the instrument **overlapped stage-0 §2/§7 and mis-used the "L2" label** (→ build-conformance is the single detail home, §2/§7 are pointers, the operator-facing name is "a second independent check that what got built matches what you approved"); the **dry-run symmetry was overstated** (→ the harsher-regime asymmetry — code artifact, AI adjudicator, gated merge — is stated, the no-behavioral-correlate residual conceded, R16); the **structural/semantic divergence conflation** (→ per-PR review is the semantic catch); **no genesis scenario existed** (→ added). **Technical-feasibility was ground-truthed against the live engine ([Paideia](#)) and current GitHub docs:** the Actions `GITHUB_TOKEN` has no `administration` scope (confirmed; Paideia's protection was applied by the admin maintainer, never a workflow); the evaluated-rules endpoint omits rules in `evaluate`/`disabled` mode (so only protection that bites reads as present); and the empty-PR-body completeness check is **buildable but unbuilt/unproven in the references** (→ the seed attestation must be a *first-exercise proof*, not an assertion). **Matrix obligation discharged — re-examined the decisions citing §6/§13/§15** (a principles change is high blast radius): [§17](../principles.md) **generalizes** [D-073](0073-lock-build-orchestration-wave-3-terminal-and-re-litigate-con.md) (the deployed Review record is "the engine's own account; your approval is the real gate"), [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)/[D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md) (the engine-mechanic's trust base is the maintainer's human ratification gate, never code review), and [D-134](0134-resolve-q22-pin-the-15-weakening-merge-consent-as-a-distinct.md) ("in solo no acknowledgment artifact is AI-proof… no machine detection in solo"); none relied on "maintainer reviews code," so there is no contradiction and no re-litigation. **No litigation alarm:** locks.yaml holds only `systems/` + `modules/core`; the engineer premise lived only in the freely-revisable `wbs/` docs and the editable framing docs (constraints/principles/goals), verified by a leak-check across all locked docs — the locked control-plane already states the deployed operator "cannot review code" (D-134), so the locked corpus is *consistent with* the correction. **Propagation per the matrix:** [constraints.md](../reference/constraints.md) (non-engineer maintainer constraint), [principles.md](../principles.md) (§17), [goals-and-quality.md](../reference/goals-and-quality.md) (maintainer stakeholder + QA-1 spans construction), wbs/build-conformance.md (new), [scenarios/genesis-build-conformance.md](../architecture.md#genesis-build-conformance) (new) + [engine-architecture.md](../architecture.md) scenario index, wbs/stage-0-harness.md (§1/§2/§3/§5/§7), wbs/module-order.md (§4/§5/§6), wbs/dry-run.md (§1 cross-ref + symmetry/asymmetry), wbs/README.md (pointer), [risks.md](../reference/risks.md) (R15, R16), [glossary.md](../reference/glossary.md) (maintainer, build-conformance review, behavioral attestation — with the `spec-conformance` disambiguation), [open-questions.md](../reference/open-questions.md) (Q31), this entry. **Document-map precedent ([D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md)/[D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)):** `build-conformance.md` is a new doc *inside* the existing `wbs/` group and the scenario is indexed in engine-architecture.md, so neither is a new top-level doc or systems group — CLAUDE.md's document map and the top-level README stay untouched. `python3 validate.py` green; lock fingerprints unchanged (no locked doc edited).

## What we ruled out

**Keep the engineer-maintainer / "reviews code" framing** (rejected — an unratified authoring assumption that contradicts [§6](../principles.md)/[§15](../principles.md)/[D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md)/[D-134](0134-resolve-q22-pin-the-15-weakening-merge-consent-as-a-distinct.md); the operator is a non-engineer with no outside engineer, so the premise is simply false). **Claim the machinery makes construction high-confidence / closes the risk** (rejected — over-claim against [R3](../reference/risks.md)/[§7](../principles.md); the seed trust-root (R15) and AI-on-AI conformance (R16) are real and named, and the honest thesis is "materially above blind trust, bounded by behavioral coverage," never airtight). **A separate engineer-gated genesis regime, or borrow an outside engineer for the seed** (rejected — none is available; the design must not assume one, and the residual is accepted knowingly). **Fold the build-conformance review into the dry-run or stage-0 §7 prose** (rejected — it is the post-build twin warranting its own detail home like dry-run.md; §2/§7 point into it to avoid a dual source of truth). **Point the engine's product `qa-review`/`design-review` lenses at the engine-planning workspace** to cover self-build conformance (rejected — breaches the engine/product wall [§13](../principles.md); the lenses are product-aimed and no-op without a product-design referent, so build-conformance covers engine self-construction instead). **Trust test *names* alone as the non-engineer's bridge** (rejected — relocates the truthfulness gap into test bodies a non-engineer cannot read; tests are wired through the cold lens + a behavioral demo). **Reserve the cold conformance review for "foundational" steps only** (rejected — a semantic misread on an ordinary step is invisible to re-grounding; the per-PR cadence is the only catch). **Ship the build-conformance review as an Engine feature** (rejected — maintainer-layer construction tooling that retires at v1; whether the deployed/in-repo engine needs a *standing* self-conformance instrument is parked as [Q31](../reference/open-questions.md), a handoff of the human gate not an orphan). **Re-litigate any locked doc** (rejected — none requires it; the premise was quarantined to revisable docs and the locked corpus already assumes a non-engineer gate).
