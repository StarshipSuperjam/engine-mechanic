# Resolve Q22/Q23: the construction repo carries no CODEOWNERS (no topology law) and a hand-seeded engine manifest handed off to the nascent engine at M1

*Decided 2026-05-29 in the design workspace.*

## The decision

Resolve the two genesis-only foundation-infrastructure gaps the [D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md) dry-run confirmed ([Q22](../reference/open-questions.md), [Q23](../reference/open-questions.md)), both rooted in one fact: in the **template-construction repo the engine *is* the product** and the [provisioning](../spec/systems/infrastructure/provisioning.md) **instantiator — which authors CODEOWNERS at its `apply` step and the engine manifest at its `confirm` step — never runs** (a repo is never generated from itself via "Use this template"). **Q22:** the construction repo carries **no CODEOWNERS**, and this needs **no topology law** (no litigation-alarm against locked [repository-topology](../spec/systems/infrastructure/repository-topology.md)). The engine/product wall is vacuous under engine==product (no "rest" to own); the deployed CODEOWNERS is a *derived* block the instantiator renders, so hand-authoring one would violate [§3](../principles.md) (derive-don't-hand-author); and it is not load-bearing for the construction gate, which is the protected-branch ruleset + required **checks** + the maintainer's review (stage-0 §7) — the L2 analog of the deployed *solo* tier, where a CODEOWNERS-bound required *review* would in any case deadlock a sole owner who cannot approve their own pull request ([constraints](../reference/constraints.md)). The engine still ships the CODEOWNERS *machinery* (built as `core`/provisioning code, traveling in the template to render a block in *generated* repos); the construction repo merely lacks a *rendered instance of its own*, and the derivation is exercised before v1 against a throwaway generated/fixture repo (or the post-v1 engine-mechanic), never by the construction repo self-governing. **Q23:** the genesis engine manifest is **hand-seeded by the maintainer as a stage-0 artifact**, grown **append-as-built** as the M1 subset (`core`, [validators-core](../spec/modules/validators-core.md), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md)) lands, then **inherited by `core`'s permanent module manager at M1** — a **handoff, not a supersession** (the seed-validator-data precedent). Genesis values: an in-development version sentinel (valid semver sorting below any release, e.g. `0.0.0-dev` — the construction repo pulls no releases, it *is* the release source, so the manifest's upgrade-source-of-truth role is dormant), the append-as-built package list, and the **solo** identity tier. The solo-maintainer arrangement and the no-CODEOWNERS choice were confirmed with the operator this session.

## Why

[D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md) logged Q22/Q23 as confirmed genesis-only (core-G: the deployed-instance path has no foundation-infra gap of its own), awaiting this decision; [D-109](0109-tune-the-dry-run-from-the-l0-calibration-a-deferred-disposit.md) first surfaced them and stage-0 §6 had flagged the engine==product CODEOWNERS degeneracy as a litigation-alarm candidate left open. **No locked doc is edited:** the topology CODEOWNERS derivation and provisioning's instantiator authoring are *correct for the instantiated world they govern*; the construction repo is that world's **unmet precondition** (it is never instantiated), an L2/genesis concern — so the resolution lands in the freely-revisable stage-0 §6, and [core](../spec/modules/core.md) (still `designed`, its *deployed* manifest authoring unchanged) is untouched. Declining to bloat the locked deployed-world doc with genesis vocabulary is the legitimate **inverse** of weakening-a-design-to-dodge-a-lock, not an instance of it ([§12](../principles.md) layer discipline). The **§3 carve-out** is stated so the two artifacts' opposite dispositions do not read as inconsistent: hand-seeding the manifest does not breach §3 as hand-authoring CODEOWNERS would — the manifest is a *lockfile that records state* (honest schema fill, the seed-validator-data precedent), not a *derived index of source* that rots; only the derived artifact is §3-barred from a hand stand-in. A three-lens cold audit (adversarial / technical-feasibility / architect-propagation, independent cold-context agents) found **no blocking or unresolved-serious issue**: no mechanism requires a construction-repo CODEOWNERS — coherence's file-ownership leg carves CODEOWNERS out as a named infra artifact (so its *absence* is neither orphan nor double-claim), the [§15](../principles.md)/[D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md) guardrail-weakening guard fires on a weakening *diff* not on never-having-had the file, and the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) frozen check-name + ruleset binding are orthogonal to CODEOWNERS (which powers required *review*, not required *checks*); the manifest M1-handoff has no pre-`core` reader (its consumers — the module manager and coherence — ship *in* `core`); and `0.0.0-dev` is valid semver that trips no migration/version-stamp check (that check fires only on revert-after-upgrade, which never happens during construction). Propagation: wbs/stage-0-harness.md §6 rewritten to settled current-state (the open "requires a topology law?" hedge excised, the two resolutions and the §3 carve-out authored in, CODEOWNERS + manifest noted as non-ratchet-table foundation-infra artifacts); [open-questions.md](../reference/open-questions.md) Q22 + Q23 deleted; wbs/dry-run-ledger.md pointer; this entry. No glossary term is needed (**Engine manifest**, **Self-construction threshold (M1)**, **Supersession ratchet** already carry the vocabulary) and no [engine-architecture.md](../architecture.md) / wbs/README.md edit. `validate.py` green.

## What we ruled out

Add a construction-repo clause / CODEOWNERS law to the locked [repository-topology](../spec/systems/infrastructure/repository-topology.md) (rejected — that would raise a litigation-alarm to import genesis/maintainer-layer vocabulary into a deployed-world law that is *already correct*; its precondition is merely unmet in the construction repo, an L2 concern). Hand-author an engine-fenced CODEOWNERS block in the construction repo to dogfood the wall (rejected — [§3](../principles.md) derive-don't-hand-author; the wall is vacuous under engine==product; a sole-owner required-review deadlocks anyway; the derivation is dogfooded via a throwaway fixture repo instead — the operator chose "none"). An all-maintainer CODEOWNERS (rejected — only non-inert with a ≥2-person team running required review; the maintainer is solo). Run the instantiator once against the construction repo to produce both artifacts (rejected — the repo is never instantiated; the instantiator would derive identity and delete "unselected" modules, nonsensical where every package is being built). Treat the manifest's hand-seeding as a §3 violation symmetric with CODEOWNERS (rejected — the manifest records state and is not derived from source; the seed-validator-data sets the hand-built-then-inherited precedent). Log Q22 and Q23 as two separate entries (rejected — one shared root cause, and the manifest is "the sibling of Q22"; one umbrella matches the [D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)/Q27 precedent against open-questions fragmentation). Defer the resolution to the genesis-sequence build session (rejected — these are decidable design choices now, and leaving them open keeps a known gap in the pre-M1 picture the dry-run assembled; execute-don't-defer).
