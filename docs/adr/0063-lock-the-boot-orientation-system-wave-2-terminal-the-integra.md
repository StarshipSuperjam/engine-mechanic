# Lock the `boot` / orientation system (Wave-2, terminal): the integration point that honors its substrates' deferrals

*Decided 2026-05-25 in the design workspace.*

## The decision

Ratify and lock [boot](../spec/systems/lifecycle/boot.md) — the cognitive substrate's orientation layer — to its end-state, the **last Wave-2 lock** on the [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) runway. Boot is a **family of read-only cognition-refresh moments** ([memory](../spec/systems/cognitive/memory.md)/[knowledge](../spec/systems/cognitive/knowledge.md) regen is never boot's), the cold-start `SessionStart` pack being the heaviest; the per-prompt `UserPromptSubmit` **scent** the lightest; post-compaction re-orient rides the *next* scent (no post-compact hook). It **always grounds** (`SessionStart` unconditional) with a **hook-independent root-`CLAUDE.md` floor** beneath the hook-dependent pack. Because boot is the integration point several already-locked neighbors **deferred operator-facing contracts to**, this lock is mostly boot **honoring** them — it edits only the (designed) boot doc and **no locked doc** (grep-verified across all 20 locked docs: every "boot" reference is a contract pointing *at* boot, so honoring them contradicts none — **no re-lock**). The reconciliations: **(1)** boot receives [attention](../spec/systems/cognitive/attention.md)'s [D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md) degraded-input hand-off — on a [telemetry](../spec/systems/guardrails/telemetry.md)/GitHub debt-register read failure (outage or expired auth) attention ranks over [state](../spec/systems/cognitive/state.md)'s committed count and boot surfaces it with staleness shown ("*N open problems as of <when>, possibly stale*"); **(2)** boot surfaces a **malformed-state refusal** via injected context + a telemetry finding — **never a `SessionStart` exit-code halt** ([D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md) law 1) — and falls through to the floor; the session does not crash; **(3)** the floor carries a **double-fault expectation-setter** ([D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md) law 3) in observable-not-jargon wording, paired with a positive marker on a healthy boot so absence is detectable by contrast; **(4)** boot surfaces [memory](../spec/systems/cognitive/memory.md)'s **reversible-forgetting readout** ([D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)) in plain language with a per-item undo handle (boot owns the wording, memory the mechanism); **(5)** boot continuously surfaces the **unprotected protected branch** ([control-plane](../spec/systems/infrastructure/control-plane.md) D-017's "surface continuously" obligation + Risk [R1](../reference/risks.md)), reading the per-branch evaluated-rules signal and **offering an engine-driven fix** (the engine runs the operator's own `gh` on approval) — never a typed command; **(6)** a **disclosure-priority law** pins governance-critical alarms first and visually distinct so a degraded boot is not a wall of warnings; **(7)** explicit **pure deferrals** to the four `designed` neighbors — [modes](../spec/systems/lifecycle/modes.md) (stance vocabulary + write-gate), [close](../spec/systems/lifecycle/close.md) (the `Stop` turn-close), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (the plan gate + risk assessment; boot **supplies** the degraded readout it consumes but **fixes the disclosure, not the gate**), [telemetry](../spec/systems/guardrails/telemetry.md) (register shape/triage); **(8)** boot's machine-consumed orientation artifacts live under `.engine/boot/` ([topology](../spec/systems/infrastructure/repository-topology.md) law 1); **(9)** a **"Build-spec leaves"** section (no "Open questions" in a locked doc) — concrete pack format, surfaced-item ordering/rendering, and root-`CLAUDE.md` copy are leaves; the laws (moments fire, read-only, unconditional-with-floor, degrade-loud-and-consented, alarms-pinned) are fixed. **Budget non-overlap with [D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md):** boot owns the **event model** (which moments, each event's hook/cadence/cost tier); attention owns the **within-event budget split and its flex** — no "cost ceiling" framing.

## Why

Boot is the correct terminal Wave-2 lock: it reads only **locked** substrates (state, knowledge, memory, attention) and powers orientation downstream; its only churning upstream — attention — locked at [D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md), and its four remaining neighbors are downstream `designed` systems reduced to pure deferrals (the [D-053](0053-procedural-surfaces-reconciled-to-the-merged-claude-code-ski.md)/[D-056](0056-lock-the-tools-surface-wave-1.md)/[D-057](0057-lock-the-agents-surface-wave-1-four-settled-design-forks.md)/[D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md)/[D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md) pattern), so none of their later locks can force a boot change. Most of the lock is *honoring deferrals*, not invention — state/memory/attention/control-plane already named boot as the surface that renders their operator-facing readouts. The four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md): adversarial / technical-feasibility / non-engineer-operator / architect, no shared context) ran against the design before this entry; technical-feasibility returned **no findings** (verified SessionStart context-injection + fail-open and its lack of exit-halt semantics, the hook-independent floor, the FTS5/BM25 scent latency, the session-id-keyed abandoned-delta sweep, the PreCompact-only/next-scent re-orient, and the default-token per-branch evaluated-rules read); its blocking/serious findings were resolved before the lock: **(adversarial, blocking)** a proposed "boot sets the cost ceiling, attention allocates within it" framing **contradicted locked [attention](../spec/systems/cognitive/attention.md)** (which owns the budget flex) → the ceiling framing was **dropped**, replaced by event-model-vs-within-event-split; **(adversarial + non-engineer-operator)** the R1 surfacing must not have boot *originate* a control-plane detection/fix contract and must not strand a non-engineer with a typed `gh` command → reframed as honoring control-plane's locked surfacing obligation with an **engine-driven** fix deferred to provisioning; **(non-engineer-operator, serious)** a degraded boot risked a wall of warnings burying the alarm that matters, and the double-fault floor copy was engineer-shorthand → added the **disclosure-priority law** and rewrote the floor in **observable-not-jargon** terms with a positive healthy-boot marker; **(architect, serious)** the degradation→plan-gate hand-off had to read as a pure deferral → reworded so boot fixes the disclosure and build-orchestration owns the gate. Propagation per the matrix is **empty** (architect-verified): [glossary](../reference/glossary.md) (Boot pack/Orientation event family/Scent/Debt register), [engine-architecture.md](../architecture.md) §4/§6/§7/§8, and [scenarios](../architecture.md#first-run-provisioning) already match; **Risk [R1](../reference/risks.md) stays open** — boot adds the continuous-surfacing nag but the ruleset is applied by [provisioning](../spec/systems/infrastructure/provisioning.md)'s first-run UX (Wave 5) — and **Risk [R5](../reference/risks.md) stays open** (the wiring library); the boot lock firms neither closed.

## What we ruled out

Frame the per-event budget as a "cost ceiling" boot sets while attention allocates within it (rejected — contradicts locked [attention](../spec/systems/cognitive/attention.md) [D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md), which owns the budget split *and its flex*; the honest split is event-model vs within-event-budget). Have boot emit a `gh` command for the operator to run (rejected — strands the non-engineer, the exact [R1](../reference/risks.md) failure; the fix is engine-driven on operator approval). Let boot freeze that the consent happens at the plan gate or define the risk assessment (rejected — that is [build-orchestration](../spec/systems/lifecycle/build-orchestration.md)'s to decide; boot supplies the degraded readout and owns only the disclosure). Hard-halt `SessionStart` on a malformed state file (rejected — `SessionStart` has no safe halt semantics and an exit-halt would strand a non-engineer; surface + finding + fall to floor is fail-loud within fail-open, [D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md) law 1). Leave the degraded notice "loud" but unranked (rejected — a wall of warnings trains the operator to scroll past the governance-critical alarm; alarms are pinned and legible). Keep the double-fault floor copy as "the engine did not fully ground" (rejected — jargon a non-engineer cannot act on; the floor describes the observable and gives a plain action). Originate a control-plane detection/fix contract in boot (rejected — control-plane owns detection and provisioning owns the fix; boot only surfaces + offers). Close [R1](../reference/risks.md) at this lock (rejected — it closes when provisioning's first-run UX applies the ruleset, not when boot adds the nag). Edit or re-lock any locked doc (rejected — every "boot" reference is a deferral *to* boot; honoring them changes none). Lock boot before attention (rejected — boot reads attention's ranking; locking atop a churning upstream is the lock-discipline failure, which is why boot is the terminal Wave-2 lock).
