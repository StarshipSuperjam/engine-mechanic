# Flesh the `memory-substrate-sqlite-fts5` module doc to `designed`: the memory floor, the `search` implementation/contract split, the wired capture substrate

*Decided 2026-05-27 in the design workspace.*

## The decision

Take the [`memory-substrate-sqlite-fts5`](../spec/modules/memory-substrate-sqlite-fts5.md) module doc from `stub` → `designed` (packaging-view depth; **not** locked) — the most substantive module so far, the only one owning real per-instance substrate. It packages the [memory](../spec/systems/cognitive/memory.md) foundation floor: the gitignored append-only **NDJSON ledger** (shipped empty) + its ledger-integrity machinery; the derived **SQLite/FTS5 index** + plain-scan fallback; **capture** (turn-delta append, episodic consolidation, the abandoned-session sweep) + the closed [D-030](0030-memory-ledger-canonical-observe-don-t-predict-capture-lexica.md) role vocabulary; **active forgetting** + its operator-undo handle; the **`search` interface FTS5 lexical-fallback implementation** + the **memory MCP server**; and the **backup/restore mechanism + restore contract**. It is its own `required` package on both [D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md) tests (the non-regenerable ledger needing an owned migration unit; the `search` seam another package binds to), the ledger being decisive. Settled points: **(1) the `search` seam splits implementation-vs-contract** — `memory-substrate` owns the FTS5 fallback *implementation* + the MCP server + the bound recall substrate the semantic module ([engine-knowledge-graph](../spec/modules/engine-knowledge-graph.md)) overrides; the `search` interface **declaration/contract** stays an [interface](../spec/systems/surfaces/interfaces.md)-surface concern in `core`'s grammar ([D-089](0089-flesh-the-core-module-doc-to-designed-the-kernel-partition-t.md) claim **unchanged — no `core` edit**), its v1 schema a build-spec leaf. "Memory owns the `search` seam" ([D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md)) is the *substrate* ownership, and the package status is independently secure on the ledger. **(2) It wires** `mcp` (the memory `search` server, engine-prefixed, data gitignored), `gitignore` (ledger + FTS5 index), and `hook` (memory's **own** `Stop`/`PreCompact`/`SessionStart` capture hooks, keyed distinctly from `core`'s) — the capture hooks are memory-wired because **`core` cannot depend on `memory-substrate`** (graph direction `core → memory-substrate`), so the mechanism rides with its owner; the boot scent reaches recall through the presence-bound `search` interface, and write-safety across the distinct `Stop` hooks is the ledger-integrity law, not hook ordering. **(3) Backup ownership** — memory owns and defines the mechanism + restore contract; [provisioning](../spec/systems/infrastructure/provisioning.md) is a downstream consumer that triggers the pre-migration snapshot ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)) and owns the destination UX but **may not widen** it ([§16](../principles.md)). **(4) Degradation** — MCP-server-down → boot proceeds, scent silent with a notice; FTS5-absent → plain-scan fallback (availability not latency), memory detects and boot renders. `depends: core`; `migrations`: the owned ledger-shape unit, **none in v1** (the module is the home for future ledger migrations; backup/restore routes through it).

## Why

A module doc is the packaging view; the depth lives in the locked [memory](../spec/systems/cognitive/memory.md) + [interfaces](../spec/systems/surfaces/interfaces.md) systems, so the doc *applies* their laws to the bundle and defers the laws'-leaves the memory doc already names (role-vocab schema, ranking, forgetting scores, region-lock impl, MCP roster, backup UX). It runs longer than the `audit-library`/`validators-core` peers because it carries the most substrate, but stays at what/why. A **cold plan-approach audit** (adversarial + architect, plan inlined) ran before approval and **corrected a genuine over-reach in the plan**: the plan had proposed ceding the `search` interface *declaration* from `core` to `memory-substrate` and editing `core`'s `designed` doc. The audit was right to reject it — an interface is a protocol *contract* (a stable interface-surface concern that names its fallback), modules supply *implementations*; memory's package status is secure on the ledger (D-086 test 1) without owning the declaration; and editing a `designed` sibling would break the [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md) precedent (a sibling pass does not edit `core`) and risk contradicting the locked interfaces doc, for no gain. **Corrected: no `core` edit; `core`'s claim stands; memory owns the implementation, the contract stays in the interface surface.** Other audit findings folded: the MCP-server-down degradation mode (distinct from FTS5-absent) was added per the locked memory doc; the backup ownership was made precise (memory owns the mechanism + contract, provisioning consumes — triggers + owns the UX, not "sole owner" unqualified). Rejected-with-rationale: that `core` should invoke memory's capture rather than memory wiring its own hooks (impossible — `core` cannot depend on `memory-substrate`); depth-temptation and role-vocab-evolution nits (folded as deferral instructions). A **second audit on the finished doc + this entry** (adversarial / architect / technical-feasibility, in-tree) ran: the adversarial and technical lenses passed clean (0 blocking/serious; the technical lens confirmed the mcp/gitignore/hook wires, the `PreCompact`/`Stop`/`SessionStart` events with multiple-hooks-per-event, the ledger-integrity-law write-safety, and the two degradation modes against the locked docs). The architect's one "serious" — add a forward-reference in `core`'s doc that the `search` *implementation* lives here — was **rejected with rationale**: it is explicitly not an error (`core`'s protocol claim is correct), it would reopen a `designed` sibling against the [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md) no-edit-core precedent, the other two lenses found no contradiction, and the implementation-ownership is already discoverable via the dependency graph + this doc + the locked interfaces doc; a contract-declaring module need not enumerate its implementors. The phrasing nits (the "owns the seam" line, the backup "may not widen" line) were already substantively addressed in the authored doc (the seam line is qualified "substrate ownership"; the backup line attributes ownership to memory). No doc change resulted from audit 2. Propagation per the matrix: [modules/memory-substrate-sqlite-fts5/README.md](../spec/modules/memory-substrate-sqlite-fts5.md) authored to `designed`; this entry. Verified no-change with rationale: [modules/core/README.md](../spec/modules/core.md) (its `search` interface-protocol claim **stands** — memory owns the implementation, not the contract; the over-read core edit was dropped), [modules/README.md](../reference/module-catalog.md) (catalog row `memory-substrate-sqlite-fts5 | required | core` + the `core → memory-substrate` and three `engine-knowledge-graph` edges already present; design-maturity not catalog-tracked), [glossary.md](../reference/glossary.md) (`Memory ledger`, `Frecency`, `Required package`, the `search` seam already defined; no new term), [engine-architecture.md](../architecture.md) (indexes systems via the catalog; the memory foundation role unchanged), wbs/README.md (unauthored; gates the lock not the `designed` state). No locked system doc edited — the packaging derives from the locked memory/interfaces docs, following their current truth (the [D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md) session-id sweep / no-lease model, not the older [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) "lease-gated" phrasing).

## What we ruled out

**Cede the `search` interface declaration to `memory-substrate` and edit `core`** (rejected — over-reads "owns the seam"; the contract is a stable interface-surface concern, memory's package status is secure on the ledger alone, and editing a `designed` sibling breaks the [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md) precedent and risks the locked interfaces doc, for no gain). **Have `core` wire/own the capture hooks** (rejected — inverts the `core → memory-substrate` dependency; `core` cannot depend on memory). **Fold the ledger migration into a monolithic `core` migration** (rejected — the [D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md) reason this is its own package: the irreplaceable ledger gets a legible owned migration unit). **Let provisioning widen the backup mechanism** (rejected — memory owns the mechanism + restore contract; provisioning is a consume-not-widen downstream, [§16](../principles.md)). **Re-derive the memory laws in the module doc** (rejected — the laws live in the locked system doc; the module applies them and defers the leaves). **Lock `memory-substrate` this pass** (rejected — the WBS + a fresh cold audit gate the lock, in dependency order after `core`).
