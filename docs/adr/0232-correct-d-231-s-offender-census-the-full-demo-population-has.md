# Correct D-231's offender census: the full demo population has 25 showcase demos that cannot fail, not one (engine-template #171)

*Decided 2026-06-22 in the design workspace.*

## The decision

Correct a **factual finding** in [D-231](0231-promote-the-in-tool-demo-subcommand-as-a-governed-ai-run-sta.md) without changing its bar. D-231 recorded that the in-tool demo population "audited healthy … return non-zero on failure (**bar one**)" and named a single non-conformer (`wiring.py demo-gitignore`). A complete AST classification of all **44** dispatched demo subcommands — re-run this session against `origin/main` after engine-template #171's build session flagged the discrepancy, following delegation into `_…_body` helpers and dispatch-level `0 if ok else 1` conversion, and cross-checked by reading the bodies — shows D-231's count was a **substantial undercount**: of the **40** non-construction subcommands, **25 are showcase demos that return `0`/`None` unconditionally and cannot fail** even when the surface they drive is broken (the exact `wiring.py demo-gitignore` defect — they print a finding and exit 0 regardless), and only **15 self-check** (assert the expected outcome and return non-zero on failure). The other **4** are `instantiator.py` construction subcommands that retire with their host file at first run. **Origin of the error:** D-231's technical-feasibility audit lens sampled ~5–6 demos that happened to all be self-checkers (`attention`/`scent`/`close demo-relay`/`compact`/`rollup`) and **over-generalized "healthy" to the whole population**; it never examined the `*_check` family, `knowledge_gen`/`self_map`, `modes`, `telemetry`, et al., which are showcase. **D-231's shape-law bar is correct and unchanged** ("a demonstration must be able to fail"); only its census of which demos meet it was wrong. The 25 showcase demos fail D-231's **existing** bar — including its liberal "can fail via an uncaught raise" reading, because their surfaces *return findings* rather than raise, so they cannot fail at all — this is a census correction, **not** a new or stricter bar. **Conformant target (engine-template #171):** each of the 25 showcase demos is brought to conformance — given a real self-check on the finding it already computes (the in-repo `module_coherence._demo` pattern: `ok = <expected outcome>; return 0 if ok else 1`) **or** demoted/retired — the per-demo fix-vs-demote call a build judgment within the bar; the 15 self-checkers are left untouched; the 4 construction subcommands need no work. With the showcase set fixed, D-231's **optional `custom/script` floor becomes coherent and discriminating** (it flags exactly the no-reachable-failure-path shape and passes the 15 self-checkers), dissolving the build session's "the floor forces all-or-nothing" objection — which rested on the false premise that every demo is structurally identical to `wiring`. The full classification table is posted on engine-template #171.

## Why

The build session correctly ground-truthed D-231's "bar one" claim against the code, but anchored on D-231's *count* as settled truth and built a false dilemma (fix-one-faithfully vs. fix-all-twenty-and-raise-the-bar) around preserving it; reading `module_coherence._demo`'s self-check should have shown the population is **mixed** and prompted a recount rather than a fork. The planning session's complete AST scan settles the census deterministically. Correcting the count honestly — rather than honoring D-231's undercount (which would ship 24 demos that cannot fail) or mis-framing the fix as a bar re-litigation (which it is not) — is the design→build conformance loop working: the build surfaced a real defect in a planning decision, and planning corrects it append-only. **No glossary edit is owed** — [D-231](0231-promote-the-in-tool-demo-subcommand-as-a-governed-ai-run-sta.md)'s [Behavioral attestation](../reference/glossary.md) extension already states a demo "that cannot fail … is reclassified or fixed, never kept"; D-232 corrects how many currently need that, not the rule. **No locked doc is touched** and no new risk/principle/open-question opens.

## What we ruled out

**Honor D-231's "bar one" and fix only `wiring`** (rejected — ships 24 demos that cannot fail, violating D-231's own bar; "discharges #171" only by honoring a factual error). **Treat the fix as a bar-raise needing a re-litigation/amendment** (rejected — the 25 showcase demos fail D-231's *existing* bar, including its liberal reading, since their surfaces return findings rather than raise; this is a census correction, not a bar change). **Fix "all ~20" uniformly** (rejected — the build's Path B over-reaches: 15 demos already self-check and must not be churned; only the 25 showcase ones are non-conformant). **Decline the floor as unbuildable** (rejected — the floor is buildable and discriminating once the showcase set is fixed; the "all-or-nothing" claim was false, resting on mis-classifying `module_coherence` and the other 14 self-checkers as showcase). **Run a full four-lens cold audit before this append** (rejected — D-232 changes no design grammar or bar; it corrects a factual census and updates a build-owe, lower-stakes than a design change; the deterministic AST classification plus body reads are the evidence, posted on #171 for the build to re-verify).
