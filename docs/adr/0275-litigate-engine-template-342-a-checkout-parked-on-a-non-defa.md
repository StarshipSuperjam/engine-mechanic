# Litigate engine-template #342: a checkout parked on a non-default branch evades the strand model; widen the operator-checkout detector to be branch-agnostic (early off-main signal + consequence-gated behind escalation); re-litigate locked [provisioning](../spec/systems/infrastructure/provisioning.md) + [boot](../spec/systems/lifecycle/boot.md) — coupled re-lock lands under D-276

*Decided 2026-06-29 in the design workspace.*

## The decision

A build session in engine-template hit a gap in the locked operator-checkout strand model and correctly stopped at the never-invent-structure wall, routing it back here ([engine-template #342](https://github.com/StarshipSuperjam/engine-template/issues/342), engine-opened). **The gap:** the locked [provisioning](../spec/systems/infrastructure/provisioning.md) strand model catches two binary *broken* states (detached `HEAD`, missing/stale engine files) plus a consequence-gated **behind-origin** tail (built for #335) that fires **only on the default branch**. A top-level checkout **parked on a non-default but fully-merged branch** (not detached, engine files present) is none of these — the detector reads it *healthy* and the behind arm returns `None` off-default — yet that was the **exact shape of the incident that prompted #335** (the operator's checkout sat on a long-merged feature branch, 132 commits behind `main`, reported healthy). A design gap in a locked doc, not an under-build ([§20](../principles.md)); it extends the two-state model fixed by [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)/[D-190](0190-resolve-the-d-189-operator-checkout-boundary-re-litigation-l.md). **This entry is the litigation alarm + operator authorization** (given in-session over a four-lens plan-stage cold audit) **and the design of record**; the **coupled re-lock of [provisioning](../spec/systems/infrastructure/provisioning.md) + [boot](../spec/systems/lifecycle/boot.md) lands under [D-276](0276-resolve-re-lock-provisioning-boot-operator-checkout-detector.md)** after the mandatory landed-text cold audit — the carriers **edited-but-not-relocked** until D-276 (the [D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md) authorize→resolve pattern; `validate.py` flags their lock fingerprints until the relock).

  **The ruling (operator-authorized): widen the existing behind detector to be *branch-agnostic*, as a two-stage hybrid signal — not a third always-on binary alarm.** The harmful essence is "missing your merged main line of work," not "sitting on a branch" (which can be intentional/brief). **Stage 1 — off-main (offline, day-one, [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)-collapsed):** a checkout parked on a non-default branch is surfaced as the gentlest standing signal the moment it happens, collapsing to one line when unchanged — catching the anti-pattern before drift accrues, the cheap-to-fix window the consequence-gated-only design was blind to. **Stage 2 — behind the merged main line (network-gated, consequence-gated):** once that checkout is missing merged work — on the default branch *or* a side branch — the signal escalates to a firm offer naming the felt consequence. The operator chose this hybrid over consequence-gated-only; [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)'s collapse-when-unchanged neutralizes the nag-fatigue [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md) rejected for bare distance, and under Desktop auto-worktree isolation a top-level non-default checkout is genuinely anomalous (low false-positive rate).

  **The laws the carriers settle (a four-lens plan-stage cold audit reshaped the remediation half; the detection spine was sound):** **(1) Branch-agnostic, two-stage detection.** The off-main signal is offline + every-boot (classified against the **persisted derived default-branch name**, not a frequently-unset `origin/HEAD`); the behind escalation is network-gated and **uncomputable-so-silent on a detached, no-remote template-generated repo** (degrade honest, never a false all-clear). The two binary *broken* states stay two — the off-main signal is a new gentle standing detection, not a third broken state. **(2) Losslessness is independent of the merged/unmerged read.** Returning from a *named* branch never orphans committed work (the branch ref keeps pointing at its commits — unlike a detached `HEAD`, where switching away orphans them), so the fix needs no rescue branch there and is structurally lossless for commits; the clean-tree + no-in-progress-op (`MERGE_HEAD` / `rebase-merge` / …) + empty-`stash` (repo-global, fails safe) predicate covers uncommitted work. **(3) Merged-vs-unmerged is advisory tone, never a safety gate — and must use `git cherry`.** `git branch --merged` / `merge-base --is-ancestor` / `rev-list --not` all misclassify a **squash-merged** branch (the #335 shape) as unmerged; only `git cherry <default> <branch>` (patch-id) recognizes a squash-merge. Even it is patch-id-fragile, so there is no certain offline merged check — the read picks only the offer's tone and **errs to the gentle "I'll keep your unfinished work safe" framing whenever the branch is not confidently fully absorbed**, never a breezy catch-up that could move the operator off real work. **(4) One operator decision, no git vocabulary, disclosure-gap owned.** Both broken and off-main cases are worded without git verbs; merged/unmerged reduces to one decision ("yes, fix it" / "no") with the carries-work case reassuring "your unfinished work stays exactly where it is, nothing deleted"; and because the catch is new, the **first full relay owns the gap** ("earlier sessions couldn't spot this; that's fixed now") so a folder reported healthy for weeks is not silently re-cast as freshly broken.

  **Plan-stage cold audit (four independent no-shared-context lenses — adversarial · technical-feasibility · non-engineer-operator · architect): none rejected the ruling; the remediation half was reshaped.** Adversarial BLOCKING — the first-draft "lossless predicate already suffices" was false; `rev-list HEAD --not --branches` is blind to a named branch carrying unmerged commits → folded to laws (2)+(3). Feasibility BLOCKING — the squash-merge defeats ancestry-based merge checks; only `git cherry` works and is fragile → law (3); plus network-gating, detached-repo silence, and the persisted-default-branch resolution → law (1); plus keep the clean-tree gate and add in-progress-state probes → law (2). Operator BLOCKING — no leaky "side branch" copy; merged/unmerged must collapse to one decision → law (4); SERIOUS — own the healthy-then-broken trust gap → law (4). Architect — **boot is a confirmed coupled re-lock** (its "Five" deferred-surfacings count and "ordinary *behind* … is not alarmed — only the stranded states are" sentence are enumerated prose [§16](../principles.md) does not immunize), and [modules/core](../spec/modules/core.md)'s never-strand carve-out is **class-scoped** ("the operator-consented un-stranding correction … scoped to the working-location/strand class") so a consented return-to-default falls inside it — verify-no-edit, confirmed at the landed-text audit.

  **Carriers (coupled, one semantic event — the [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)/[D-264](0264-authorize-git-native-retention-for-the-pre-migration-memory.md)/[D-265](0265-resolve-coupled-re-lock-of-memory-memory-substrate-sqlite-ft.md) coupled-relock precedent):** [provisioning](../spec/systems/infrastructure/provisioning.md) (the branch-agnostic detector, the persisted-default-branch classification, the `git cherry` advisory read, the in-progress-state predicate, the merged/unmerged offer split, the off-main day-one signal — in the *Operator-checkout strand* section, its Design-commitments summary, and its build-spec-leaf law) and [boot](../spec/systems/lifecycle/boot.md) (the expanded fifth deferred surfacing — off-main + behind escalation + disclosure-gap framing, "Five" unchanged); both re-lock under [D-276](0276-resolve-re-lock-provisioning-boot-operator-checkout-detector.md) after the landed-text cold audit. **Recorded verify-no-edit dispositions (no re-lock — to be confirmed against landed text, [D-251](0251-reject-engine-template-255-s-explore-gate-memory-carve-out-t.md) discipline):** [modules/core](../spec/modules/core.md) (never-strand carve-out is class-scoped, covers consented return-to-default; the `provides` strand-detector label is unaffected), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (prevention ≠ detection; its deferral pointer is roster-agnostic), [repository-topology](../spec/systems/infrastructure/repository-topology.md) (one-line pointer), [attention](../spec/systems/cognitive/attention.md) ([§16](../principles.md) — a new boot finding attaches additively, the [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md) precedent), [engine-architecture](../architecture.md) (role label, the [D-190](0190-resolve-the-d-189-operator-checkout-boundary-re-litigation-l.md) precedent), [scenarios/](../architecture.md#routine-session) (no scenario walks strand-granularity detection). **Non-locked propagation (under this entry):** [glossary](../reference/glossary.md) *Stranded checkout* (the three caught conditions; preserve "ordinary behind is never alarmed" — **no new term**, the [R6](../reference/risks.md)/[D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) anti-sprawl precedent), [risks](../reference/risks.md) [R20](../reference/risks.md) (Detection-line mitigation touch — branch-agnostic coverage closes the #342 gap; **no new R-number**). **Build-owe (engine-template #342):** the branch-agnostic `git cherry`-based detector, the persisted-default-branch resolution + network-gating + detached-repo silence, the in-progress-state probes, the merged/unmerged offer split, the felt-consequence boot copy (no git verbs), and the gap-ownership first-relay framing — built as a follow-up against the live engine.

## Why

the gap is real and routed correctly — an engine that reports a 132-behind checkout "healthy" fails the very trust the strand model exists for. The minimal honest fix **realizes the model's own intent** (catch a checkout that drifts off the operator's surface) by widening the *existing* consequence detector rather than bolting on a bespoke always-on guard ([D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)'s rejected v1). Framing it as a *widening* keeps the two binary broken states two and boot's "Five" five — the [§20](../principles.md)-minimal claim is structurally true, not merely asserted. The hybrid two-stage signal closes the cheap-to-fix blind spot the adversarial lens exposed in consequence-gated-only, made nag-free by [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md). The plan-stage audit earned its keep decisively: it caught that the first-draft losslessness claim was false (named-branch unmerged work), that only `git cherry` survives squash-merge, and that the operator copy leaked git vocabulary — all folded before authoring. The authorize→resolve-after-landed-text-audit split keeps the irreversible coupled re-lock behind its own clean gate ([D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md)).

## What we ruled out

**Build it freelance in engine-template** (rejected — it extends a locked spec; the never-invent-structure / stop-and-raise rule routes it here, exactly what the build session did). **A third always-on binary "on a side branch" alarm** (rejected as the *structure* — it would bump the two binary broken states to three and boot's "Five" to six, falsely converting a widening into new always-on machinery, and risks false-positives on intentional brief checkouts; the gentle [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)-collapsed off-main signal + consequence-gated escalation is the right shape). **Consequence-gated-only (no early off-main signal)** (rejected by the operator — silent during the only window the park is cheap to fix; at T0 a side-branch checkout is 0-behind and says nothing, accruing risk until the 132-behind incident; [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md)'s collapse makes the early signal nag-free, so the blind spot is not worth keeping). **"Lossless predicate already suffices; merged/unmerged is messaging not loss" (the first draft)** (rejected — the adversarial lens showed `rev-list HEAD --not --branches` is blind to a named branch carrying unmerged commits, and moving the operator off real work re-creates the harm class; merged/unmerged must be a real `git cherry` read, advisory-only, erring gentle). **`git branch --merged` / `merge-base --is-ancestor` for the merged check** (rejected — all ancestry-based checks call a squash-merged branch unmerged, the literal #335 shape; only `git cherry` patch-id recognizes squash-merge). **Re-lock [modules/core](../spec/modules/core.md) for the return-to-default write** (rejected — the never-strand carve-out is class-scoped, not state-enumerated; a consented un-stranding correction of the working-location class already covers it; the adversarial "branch-switch is forbidden" read is routed to the landed-text audit, not used to widen the blast radius). **Mint a new glossary term or risk entry** (rejected — [R6](../reference/risks.md)/[D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) anti-sprawl; the existing *Stranded checkout* term + R20 carry it, and the gap is being closed). **Write the [D-276](0276-resolve-re-lock-provisioning-boot-operator-checkout-detector.md) resolve entry now** (rejected — it records a landed-text cold audit that runs later; authoring it pre-audit would dress un-audited as audited, the [§7](../principles.md) violation this pattern prevents).
