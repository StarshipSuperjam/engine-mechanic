# Clear the deferred nit backlog: one batched re-litigation of eight cosmetic locked-doc nits from the D-151 corpus audit

*Decided 2026-05-31 in the design workspace.*

## The decision

Clear the eight cosmetic locked-doc nits [D-151](0151-whole-corpus-design-audit-re-litigate-state-af-1-to-fix-the.md) deferred as a logged backlog (the corpus-audit-ledger disposition roster) in **one batched, justified re-litigation**, re-locking the six affected docs — the operator's elected pre-capstone cleanup before the v1 build-ready declaration. Each fix is the corpus audit's own *indicated fix*, converging a divergent `locked` doc *toward* already-canonical truth; **no design law changes**. The eight, by target:
  - **[build-orchestration](../spec/systems/lifecycle/build-orchestration.md)** — **AF-2:** the build-Issue parenthetical attributed issue-template governance to the [templates](../spec/systems/guardrails/templates.md) surface, which templates disowns ("not the GitHub platform files the [control-plane] owns") and control-plane ships as its own scaffolds; reattributed to control-plane. **AF-5:** the plan-gate coverage inputs named [attention](../spec/systems/cognitive/attention.md) as producing "the change's risk/size," an assessment attention does not make (it governs budget allocation, candidate-work ordering, and debt-blocking over *structural neighbors*); retitled to "the work's structural adjacency and debt-proximity" (the orchestrator self-derives risk/size from the visible plan).
  - **[control-plane](../spec/systems/infrastructure/control-plane.md)** — **N-1:** the "travels as files … ship and run automatically" list lumped `CODEOWNERS` with the workflows/templates, but [provisioning](../spec/systems/infrastructure/provisioning.md) **derives-and-renders** the CODEOWNERS engine block at first run (it ships carrying an unsubstituted handle token); softened to carve `CODEOWNERS` out as rendered-at-first-run. One-sided edit — provisioning already states the derive model.
  - **[provisioning](../spec/systems/infrastructure/provisioning.md)** — **AF-9:** control-plane locks the security-scanning-tier *disclosure* invariant and defers its wording + first-run step to provisioning, but provisioning's build-spec leaves never enumerated it; added a seventh "security-scanning-tier disclosure" leaf mirroring the control-plane invariant.
  - **[agents](../spec/systems/surfaces/agents.md)** — **N-2:** the `finding.v1` base was written `{message, location, severity}`, diverging from the canonical [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md) order `{severity, message, location}` ([validation](../spec/systems/guardrails/validation.md):28 / [glossary.md](../reference/glossary.md):91 / [check](../spec/systems/surfaces/check.md)); reordered to canonical (notation only, JSON field order is not semantic). **N-3:** the open `lens` field's worked examples used slugs the v1 roster never consumes (`scope`/`design`/`code-review`/`security`/`qa`); replaced with the real [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) roster (`product-intent`·`architecture`·`feasibility`·`risk-governance` at plan-review; `spec-conformance`·`usability`·`technical-integrity`·`security-governance` at pre-submission; plus the optional `retroactive`), preserving the "open and additive" clause so membership stays open (the lock fixes laws, not lens membership).
  - **[validation](../spec/systems/guardrails/validation.md)** — **N-4:** control-plane names "[validation] owns the guard's check wiring" for the §15 guardrail-weakening guard with no reciprocal anchor in validation; added a one-line anchor naming the guard as a frozen-named `custom/script` instance whose wiring validation owns while control-plane owns its protection-off contract ([D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md)/[D-134](0134-resolve-q22-pin-the-15-weakening-merge-consent-as-a-distinct.md)) — the intended [§14](../principles.md) posture (acknowledged, not enumerated).
  - **[close](../spec/systems/lifecycle/close.md)** — **N-6:** the fail-open "surfaced … in plain language that same turn" notice had no path in an unattended [routine](../spec/systems/lifecycle/modes.md) turn (no operator present); added that it degrades to the already-auto-logged tracked finding, surfaced at next boot, with no consent lost.

  **Verification:** a focused **two-lens cold re-check** (faithfulness + propagation, cold-context, no shared session — the [D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)/[D-147](0147-lock-the-design-review-and-qa-review-suites-the-v1-review-le.md) proportionate instrument for remediating already-audited nits) ran against these exact edits and returned **clean on both lenses**: every edit resolves its nit without a new cross-doc contradiction or a weakened law, and the propagation set is complete with **no edit owed** beyond the batch. **Propagation:** the six re-locked docs + this entry + a one-line "Resolved by D-153" annotation on the corpus-audit-ledger disposition roster. **No edit owed** (cold-confirmed) to [glossary.md](../reference/glossary.md) (no new/renamed term — N-2/N-3 align agents *to* the already-canonical glossary entries), [engine-architecture.md](../architecture.md) (no system role/index change), [risks.md](../reference/risks.md) (no risk opened/closed — N-4/N-6 clarify already-disclosed postures), [modules/README.md](../reference/module-catalog.md), the `scenarios/` walkthroughs, the rest of `wbs/`, or any non-target locked doc (every named counterpart already agrees). `python3 lock.py --relock` for each of the six docs `--decision D-153`; `python3 validate.py` green.

## Why

The corpus audit found the case for change but left the call to the operator ([finding-disposition](../spec/systems/surfaces/policies.md)); the operator elected to clear the backlog to a clean corpus *before* the build-ready capstone rather than carry eight known-but-deferred nits past the v1 line. One batched re-litigation is the lower-churn path the ledger itself prescribed — touching six locked docs once, with one history entry, rather than six. Each fix is cosmetic by construction (the audit downgraded all eight to `nit` precisely because none changes a design law), so the proportionate verification is the focused two-lens re-check the [D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)/[D-147](0147-lock-the-design-review-and-qa-review-suites-the-v1-review-le.md) precedent established for remediating already-audited findings, not a fresh four-lens audit. The edits *reduce* the corpus's cross-doc divergence — every one moves a doc into agreement with a counterpart that was already right — so build-readiness can only rise.

## What we ruled out

**Leave the backlog deferred** (rejected — the operator elected to clear it; carrying known nits past the build-ready line is avoidable debt). **One re-litigation per doc** (rejected — six entries for one coherent cosmetic sweep is needless history churn; the ledger prescribed a single batch). **A fresh four-lens cold audit before re-lock** (rejected — disproportionate for eight nits already produced *and* fix-specified by the 38-agent D-151 corpus audit; the focused two-lens re-check is the precedent for remediating audited findings, [D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)/[D-147](0147-lock-the-design-review-and-qa-review-suites-the-v1-review-le.md)). **Edit the canonical counterpart instead of agents for N-2/N-3** (rejected — `{severity, message, location}` and the D-066 roster are already canonical in validation/glossary/check and design-review/qa-review; agents was the sole divergent doc, so the fix adapts agents, never the settled docs — the lock-discipline default). **Run the full corpus re-run now** (deferred — a clean whole-corpus re-run is warranted after these land, but it belongs to the build-ready capstone as its evidence, not to this scoped cleanup).
