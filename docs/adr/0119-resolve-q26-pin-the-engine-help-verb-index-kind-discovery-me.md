# Resolve Q26: pin the `/engine-help` verb-index + kind-discovery mechanisms as `core` build-spec leaves (no alarm)

*Decided 2026-05-29 in the design workspace.*

## The decision

Resolve [Q26](../reference/open-questions.md) — the unpinned `/engine-help` (and module check-kind) presence-discovery *mechanism* — as **`core` build-spec leaves with no locked-doc edit and no litigation alarm** (the core-lock-closure step-4 "otherwise" branch, [D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md)), clearing the **last Phase-1 blocker** before the `core` lock. **Conception affirmed:** `/engine-help` stays the **verb index** of [D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md) — the operator chose to keep the index over reconceiving it as a state-aware *advisor*; the advisory behaviour ("how do I migrate my database") needs no new surface, since a grounded Explore session already answers it when asked (the index is the floor, the model is the advisor), so D-087's purpose is **not** re-litigated. **The pinned contract** ([modules/core/README.md](../spec/modules/core.md) Build-spec-leaves): (1) the index lists the engine's **operator-typed** verbs — *installed* ones parsed from the committed `.claude/skills/*/SKILL.md` + legacy `.claude/commands/*.md` by real YAML parsing (verb = `name`/dir or command filename; line = frontmatter `description`), the predicate **deferring to the locked [skills](../spec/systems/surfaces/skills.md) invocation axis** rather than hardcoding a flag (in v1 all engine skills are operator-typed, [D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md), so "all-typeable vs operator-typed" is vacuous and the index is engine-verbs-only); *available-but-uninstalled* optional verbs shown as "available if you install X", read from the **committed module catalog provisioning maintains** ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) selection-UX data, which survives deselection) as a [§16](../principles.md) relay (provisioning owns the catalog, `/engine-help` reads it; the catalog's verb+description fields a build-spec leaf); descriptions **guaranteed for engine verbs** by the skills schema + `validators-core` schema-conformance (so the listing never shows a blank); a closing pointer to the operator orientation [doc](../spec/systems/surfaces/docs.md); degradation-proof committed-file/committed-catalog parse, no MCP dependency. (2) The **module check-kind discovery** mechanism — the validation dispatcher discovers a module-provided kind callable **by presence** in a pinned `.engine/tools/` location by a filename↔`kind`-name convention, each conforming to the [D-115](0115-q27-1-re-litigation-the-validation-kind-callable-result-cont.md) result contract, dangling→the locked finding — pinned as the **dispatcher's** build-spec form (the dispatcher rides `core`); **not** a `core`-lock blocker (core's five closed kinds register directly). This is laws-not-leaves ([D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)): the *form* is pinned, concrete directories/strings/fields deferred. **Propagation:** [modules/core/README.md](../spec/modules/core.md) Build-spec-leaves section + tightened `/engine-help` paragraph; no [glossary](../reference/glossary.md) edit owed (the `Derived binding` instance list is illustrative, not exhaustive — `/engine-help`'s §14 nature is recorded here and in core's build-spec); [open-questions.md](../reference/open-questions.md) **Q26 deleted**; wbs/core-lock-closure.md step 4 marked resolved (only Phase 2 — reconcile + lock `core` — remains). **No locked-doc edit, no `lock.py --relock`.** **No `validators-core` edit owed** — correcting the approved plan: `validators-core` ships **zero check-kinds** (data only), so the kind-*discovery* convention is the **dispatcher's** (`core`'s) build-spec, not its; and the engine-skill `description` guarantee already rides its existing schema-conformance corpus (no new rule).

## Why

[D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)'s genesis dry-run found the `/engine-help` discovery mechanism unpinned (a `core`-lock blocker, core-H) and the module-kind file location/naming a coupled nit. The locked [skills](../spec/systems/surfaces/skills.md) doc already fixes the *grammar* (scan dirs incl. the legacy form; `disable-model-invocation` = operator-typed; `engine-` prefix; `description` a routing field), so the residual is purely the `/engine-help` tool's *implementation contract* — a `core` build-spec leaf by the [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md) convention, **not** a grammar change, so no skills/validation alarm is warranted (and none is dodged — there is no grammar edit to make). A **four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect) ran against the plan; its blocking/serious findings reshaped this resolution: the first draft's "list all typeable verbs (incl. `model-auto`) + the operator's own product verbs, grouped" was caught as a **skills-grammar extension** (the locked doc scopes the discovery path to operator-typed) and as wall/legibility scope-creep — dropped, since keeping the D-087 index makes the listing engine-operator-typed-only and the all-typeable fork vacuous in v1; the planned re-pinning of the kind-callable **result contract** in `core` was caught as **duplicating already-locked law** ([D-115](0115-q27-1-re-litigation-the-validation-kind-callable-result-cont.md) + the locked validation/check + the glossary `Check-kind` "bound by presence but not an interface" fence) — reduced to citing D-115 and pinning only the residual location/naming; technical-feasibility **verified against the live Paideia engine** that both skill forms coexist, `description` is reliably present in both, `disable-model-invocation: true` is the real reliably-honoured operator-typed marker, and legacy commands are operator-typed by filename — and found the [skills](../spec/systems/surfaces/skills.md) doc's **`user-invocable: false`** (model-only) key appears in **no** live engine (consistent with "real but unused" — D-087 ships no model-only skill), flagged as a **build-time verification item** that does not block Q26 because the pinned predicate defers to the invocation axis and never touches that key; the operator lens's "(no description)" and "no exit to deeper help" findings were folded (schema-guaranteed descriptions; the orientation-doc pointer). The resolution is now strictly more conservative than the audited draft (no alarm, engine-operator-typed-only), so no re-audit is owed; the full ≥4-lens cold-session audit gates the separate Phase-2 `core` **lock**, not this step. `python3 validate.py` green.

## What we ruled out

Reconceive `/engine-help` as a state-aware **advisor** (thin skill → consultative operation) (rejected by the operator — the advisory capability is largely intrinsic to a grounded Explore session; the verb stays the index, the model advises). List **all-typeable** verbs incl. `model-auto` (rejected — extends the locked skills discovery scope, an alarm; and vacuous in v1 where every engine skill is operator-typed). List the operator's **own product verbs** grouped "Engine/Your commands" (rejected — the audit flagged wall/legibility/scope concerns and D-087's index is engine-verbs-only; deferred, not built). Home the discovery contract in the **locked [skills](../spec/systems/surfaces/skills.md)** doc (rejected — skills already fixes the grammar; the residual is `core`'s implementation contract, a build-spec leaf, no alarm). **Re-pin** the kind-callable result contract / presence-binding / dangling behaviour in `core` (rejected on audit — already locked in [D-115](0115-q27-1-re-litigation-the-validation-kind-callable-result-cont.md)/validation/check/glossary; a second source of truth breaches CLAUDE.md rule 3; cite, don't re-pin). Home the kind-discovery convention or the description guarantee in **`validators-core`** (rejected — it ships zero kinds, so the dispatcher's discovery convention is `core`'s, and the description guarantee already rides its schema-conformance corpus — no edit owed). Hardcode the **`user-invocable`** key in the predicate (rejected — unverified against live Claude Code; defer to the skills invocation axis). Treat the "available if you install X" half as **unbuildable / a new open question** (rejected — its committed source is provisioning's existing selection-UX catalog, read via §16; only the catalog's verb-level fields are a deferred build-spec value).
