# Promote the in-tool `demo` subcommand as a governed, AI-run standing falsification capability (the healthy whole-class promotion; engine-template #171)

*Decided 2026-06-22 in the design workspace.*

## The decision

Exercise the [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md) "promoted by an explicit logged decision to a standing operator capability" lever for the **whole healthy population** of the engine's **in-tool `demo`/`demo-*` subcommand** (~34–35 tools / ~42 subcommands — e.g. `attention.py demo`, `scent.py demo`, `close.py demo`/`demo-relay`, `memory/compact.py demo-trigger`/`demo-erase`, `memory/rollup.py demo-sweep`). These travel into every generated repo automatically because the tool file travels — a subcommand cannot be first-run-walled the way a standalone `demo_*.py` file is ([D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md); engine-template #191) — so [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md)'s travel rule forces an explicit call: promote them, or strip them. The operator chose **govern the whole healthy class**. The convention is pinned in the canonical [Behavioral attestation](../reference/glossary.md) entry (extended **in place** — one home, [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md)) as **the promoted standing class**, characterized honestly: it is **engine machinery, not an operator entry** — tools are Python the operator cannot run ([constraints](../reference/constraints.md); [tools](../spec/systems/surfaces/tools.md): a tool is engine code, "not an operator entry") — so a `demo` subcommand is **AI-run on demand and operator-*relayed*** in plain consequence-language, an **AI-mediated** evidence tier ([§17](../principles.md)-bounded), **weaker** than the non-AI maintainer-run behavioral class, whose value is that the deployed session can back a claim by showing the real surface fail when broken rather than merely asserting it; the genuinely non-AI, operator-weighable form of any behavior remains the **retired regression/CI check** (watched on CI, no AI in the loop). The class is **governed, not accreted**: every member inherits the [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md) **shape law** (drives the real shipped surface, **must be able to fail**, no parallel reimplementation), enforced as **posture** at construction (the build-conformance review and per-PR discipline apply it — there is no standing audits or mechanical demo-shape probe today, and none is added) and **optionally** floored by a `custom/script` [check](../spec/systems/surfaces/check.md) (the existing `self-map-drift` vehicle — check *data*, no new kind) asserting a reachable failure path exists. Non-conformers are **reclassified, not kept**: `wiring.py demo-gitignore` (returns 0 unconditionally — cannot fail) is given a self-check or demoted; the `instantiator.py` `apply-demo`/`finish-demo`/`collision-demo` construction subcommands retire with their host file at first run. This is a **distinct population** from the standalone construction `demo_*.py` files ([D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md)), which stay PR-claim-tied and do not travel unless separately promoted. **Discoverability is AI-facing** (the AI knows the convention and offers to run the relevant demo when the operator asks to see a behavior) — **not** via `/engine-help`, which indexes operator [skills](../spec/systems/surfaces/skills.md), not tool subcommands. Live build-owes are tracked on engine-template #171.

## Why

engine-template #171 surfaced ~42 in-tool demo subcommands traveling into generated repos with no logged decision authorizing them, and asked planning whether they are intended standing capability or construction cruft. Ground-truth (this session, against the built repo) found them **healthy** — real falsifications that drive the real surface and return non-zero on failure (bar one) — a coherent per-tool falsification convention, not junk. They are trust-aligned in the honest, AI-mediated framing: the deployed session can demonstrate any engine behavior on demand to back a claim, the referent for build-conformance §6's "here's how to see that yourself." The operator chose to **govern the whole healthy class** over a bare blessing (which would rubber-stamp the junk drawer #171 exists to bound) and over stripping (~40 edits discarding healthy evidence). The bound on the drawer is **conformance** — every demo must be a real falsification, non-conformers reclassified — not deletion of healthy evidence. The four-lens cold audit against the proposing draft was decisive and is why this entry differs from the draft: it corrected a **mis-attributed trust tier** (the draft pitched these as operator-*run* non-AI evidence; they are AI-run/operator-relayed, the AI-mediated tier — [§17](../principles.md), the [D-225](0225-recenter-the-spec-on-the-ai-is-the-thing-made-trustworthy-re.md)/[D-227](0227-resolve-the-d-226-audits-re-litigation-landed-text-cold-audi.md) do-not-dress-one-tier-as-another discipline), a **theater bound** (a `coherence`-kind check cannot inspect demo source, and "can fail" is the posture the locked [check](../spec/systems/surfaces/check.md) surface excludes; corrected to posture + an optional `custom/script` floor), and **factual errors** (the count; the misclassification of `demo-relay`/`demo-trigger`/`demo-erase`/`demo-sweep` as construction harnesses when they are operator-purposed M1-seam falsifications; a false `/engine-help` discoverability claim; a spurious `_demo`-vs-`demo` naming build-owe). Resolving these before authoring is the audit-before-approval gate working as intended.

## What we ruled out

**Bare promote** (rejected — blesses ~42 ungoverned subcommands; re-opens the junk drawer #171 closes). **Strip / don't-travel** (rejected — a subcommand cannot be cleanly walled from travel without editing each host tool; ~40 edits discarding healthy, trust-aligned evidence that audited clean). **Curate a small set, retire the rest into tests** (considered, rejected by the operator — it discards on-demand AI falsification for most behaviors and converts healthy demos into per-demo curation work now; the whole-class bound is conformance not count, and the demos are engine-namespaced machinery the operator does not browse, so the standing-fixture cost is low). **Frame as operator-run non-AI evidence** (rejected — false; the operator cannot run Python tools and a tool is not an operator entry; dressing an AI-mediated tier as the non-AI class is the [§17](../principles.md)/[D-225](0225-recenter-the-spec-on-the-ai-is-the-thing-made-trustworthy-re.md) anti-pattern). **Bound it with a `coherence`-kind check** (rejected — `kind_coherence` reads only module manifests and cannot inspect demo source; "must be able to fail / no reimplementation" is the posture the locked [check](../spec/systems/surfaces/check.md) surface excludes; the honest bound is the shape law as posture + an optional `custom/script` failure-path floor). **Mint a sibling "Demo subcommand" glossary term** (rejected — two homes for one rule; [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md) deliberately gave the demo shape/lifecycle a single canonical home in [Behavioral attestation](../reference/glossary.md), so the promoted class is a clause there). **Discover via `/engine-help`** (rejected — it indexes operator [skills](../spec/systems/surfaces/skills.md), not tool subcommands; enumerating ~42 tool subcommands there is a [§12](../principles.md) machinery-vocabulary leak; discovery is AI-facing). **Edit the locked [tools](../spec/systems/surfaces/tools.md) or [check](../spec/systems/surfaces/check.md) surfaces** (rejected — no litigation alarm needed: the convention is a behavioral-attestation concept homed in the unlocked glossary, the tools surface's "tests and checks" governance is compatible, and the optional floor is `custom/script` check *data* riding existing kinds, not a new kind or a surface-grammar change). **Open a new risk or resolve [Q31](../reference/open-questions.md)** (rejected — [R6](../reference/risks.md): the capability already exists in the build and governing it serves trustworthiness, not net-new scope creep, so no new risk, consistent with [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md); [Q31](../reference/open-questions.md) is the post-v1 *standing AI self-conformance* instrument and stays open — a traveling AI-run falsification is **adjacent, not a substitute**, mirroring [D-228](0228-pin-the-behavioral-demonstration-shape-and-lifecycle-a-falsi.md)'s "Q31-adjacent" framing).
