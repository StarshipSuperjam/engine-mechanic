# Authorize the `conduct` surface (codes of conduct): a tier-3 prose carrier for the operator's standing behavioral stance, baked in from cold boot and tunable (engine-template #94)

*Decided 2026-06-14 in the design workspace.*

## The decision

Authorize **adding a new tier-3 prose surface — `conduct`, whose instances are *codes of conduct*** — plus a re-litigation wave wiring it into the foundations, to close the real gap behind engine-template **#94**: the operator's standing **behavioral stance** (how the AI engages — dialog, pushback, provenance-first, plain-language, anti-fragmentation) has **no shipped home present at cold boot**. [Memory](../spec/systems/cognitive/memory.md) ships empty ([D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)) so it cannot carry it (it is the right home for *project-learned* enrichment via the `preference`/`lesson` roles, not for the cold-boot floor); the [policies](../spec/systems/surfaces/policies.md) operator-override is numeric-only ([D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)); the root `CLAUDE.md` floor is thin template machinery. The planning workspace's own `## Collaboration stance` is exactly this artifact and had **no deployed-Engine analogue**.

  **The settled design (operator-chosen + four-lens cold-audited).**
  - **A tier-3 prose surface, pure posture.** `conduct` is catalogued (class `prose`; location `.engine/conduct/`; authority **tier 3 — mechanics & guidance**; enforcement **posture**; lifecycle `artifact`; with a `governing_schema` + `template`). A code of conduct *shapes* behavior and **never enforces, blocks, or gates** — so it never collides with a higher tier (whispers, not walls), and the #94 auto-memory *enforcement* items are explicitly **not** conduct.
  - **Two layers, composed by rule-id.** Universal-good **defaults** (`.engine/conduct/defaults.md`) ship as machinery (overlaid on upgrade so the Engine can improve them); the **operator override** (`.engine/conduct/operator.md`) is **operator config** (in no `provides`, preserved across overlay — the [audits](../spec/systems/guardrails/audits.md) three-way split by `provides` membership). Composition is **per-rule-by-`id`** supersession + a disable-list — **not** policy's numeric per-key merge (prose does not merge per-key). File granularity (two layer files vs. per-instance files + a derived fingerprint-gated aggregate) is a build-spec leaf; the `@import` single-file constraint favors the two-file form.
  - **Floor-loaded, hook-independent.** The root `CLAUDE.md` (core/topology-owned) **`@import`s** the two layer files (verified live against current Claude Code docs: imports are "expanded and loaded into context at launch alongside the CLAUDE.md" and survive compaction; ≤4-hop depth; single-file only; in-repo relative paths), so the stance is present **even when the boot hook fails** — the CLAUDE.md floor guarantee, held under the existing "substantially reliable, not airtight" posture. The set is **bounded** (paid every session; rules earn their place; attention-budgeted).
  - **Travel across repos (the operator's goal).** `operator.md` is **seeded at provisioning from a seed the maintainer's template carries**, so the operator's codes of conduct ride every repo generated from their template (no re-teaching); per-deployment tuning is preserved thereafter; an optional command promotes a learned rule back into the template seed. The **public** template's `defaults.md` stays universal (a third party without the seed gets defaults + an empty override) — honoring the operator's "universal defaults + my override" choice.
  - **§15 safety.** Mechanical guardrails (PreToolUse denies, required checks, branch protection, the merge wall) do **not** depend on model compliance, so no prose rule can weaken them; conduct is **committed**, so any change rides a reviewable PR (weakening is merge-visible, never silent); a [validation](../spec/systems/guardrails/validation.md) check flags a code of conduct that purports to instruct weakening a guardrail (reflexive §15 guard, soft-warn).
  - **§12 placement.** `conduct` rides **`core`** (it must be present in every repo — it cannot be optional — and is loaded by the core/topology-owned floor); the addition is **minimal** (a defaults file + two `@import` lines + a small authoring verb), justified per [§12](../principles.md), not a subsystem.
  - **Tuning + visibility.** A prose-aware `core` authoring verb (the policy-tuning-verb precedent adapted for prose) + direct edit; the active stance is committed (readable) and pulled on demand via the [status verb](../reference/glossary.md) — AI-facing behavioral context, not a governance alarm (not must-push).

  **Scope.** **Re-lock (locked) — 3:** [modules/core](../spec/modules/core.md) (the `@import` floor content + `conduct` in `provides` + the authoring verb + the §12 justification), [provisioning](../spec/systems/infrastructure/provisioning.md) (ship defaults, seed `operator.md` from the template seed, the authoring verb, preserve across overlay), [repository-topology](../spec/systems/infrastructure/repository-topology.md) (placement + the preserved-across-overlay category + the CLAUDE.md `@import` infra-artifact). **Additive, no ontology re-lock:** the [ontology](../spec/systems/grammar/ontology.md) **catalog** gains the `conduct` record (surfaces attach additively without a re-lock). **New (`designed`):** [conduct](../spec/systems/surfaces/conduct.md) + its schema + template. **OUT (verify-no-edit):** [boot](../spec/systems/lifecycle/boot.md) (floor-loaded, not pack-injected; the status-verb pull is its existing seam), [memory](../spec/systems/cognitive/memory.md) (the auto-memory boundary is affirmed, not changed), [modes](../spec/systems/lifecycle/modes.md) (conduct is not a stance-axis gate). **Edit (non-locked):** [glossary](../reference/glossary.md), [engine-architecture](../architecture.md), [modules/README](../reference/module-catalog.md), [scenarios/first-run](../architecture.md#first-run-provisioning), wbs, [risks](../reference/risks.md), [validation](../spec/systems/guardrails/validation.md)/[check](../spec/systems/surfaces/check.md); [principles](../principles.md) verified — **no new principle** (covered by [§4](../principles.md)/[§6](../principles.md)/[§7](../principles.md)/[§12](../principles.md)/[§16](../principles.md)), cross-refs only. **#94 secondary (folded):** affirm the auto-memory boundary stays posture + friction; **reject** the operator-proposed audits-`consolidate` pass over auto-memory (audits' read-only "report, never heal" law; never writes `~/.claude`; depends on a harness skill the Engine does not own), the PreToolUse path-block (the invariant is *content*, not *location*; the path is the sanctioned personal notebook), and the provisioning header (never writes `~/.claude`); the pre-M1 **construction promotion sweep** routes stance-class lessons → `conduct`, project narrative → [memory](../spec/systems/cognitive/memory.md), structure → [knowledge](../spec/systems/cognitive/knowledge.md), rationale → eADR canon, governed by a **mis-promotion rubric** (no narrow construction quirk ships as a corpus-wide law). The engine-template **#94** build realizations (the default-stance copy, the maintainer seed, the authoring verb, the generated-`CLAUDE.md` `@import` wiring, and verifying in-repo imports do not trip the external-import approval dialog) are downstream follow-ups filed against the build, not authored here. The re-locks land under the **resolve** entry after the mandatory landed-text cold audit + dry-run (the [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)→[D-190](0190-resolve-the-d-189-operator-checkout-boundary-re-litigation-l.md) pattern).

## Why

The gap is real and operator-confirmed: a non-engineer's Engine must carry *their* operating rules from first boot without re-teaching each repo, and no surface homed them. The design assembles **existing, already-audited patterns** — non-empty config shipping ([D-169](0169-add-the-foundational-eadr-canon-the-engine-ships-its-own-why.md) eADR canon), operator-config-preserved-across-overlay ([D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)/[D-185](0185-authorize-a-two-foundation-re-litigation-ship-a-native-plan.md)), an engine-mediated tuning verb, and CLAUDE.md `@import` (verified live) — rather than new machinery, and the four-lens cold audit's load-bearing findings (§12 not-in-minimal-core, §15 weakening vector, prose-not-numeric composition, the floor-load feasibility, cross-repo travel) are folded. The operator authorized resolving to the optimal design regardless of lock cost; the three re-locks are propagation breadth (wiring a new surface into the floor + the overlay-preserve split), not capability breadth, and the honest tiers (pure posture; floor-load substantially-reliable-not-airtight; mechanical guardrails immune) are named, never over-promised.

## What we ruled out

**Name it `house-rules`** (rejected — `conduct` / "codes of conduct" fits the corpus register). **Inline the stance into the root `CLAUDE.md`** (rejected — conflates operator-tunable config with thin template machinery and inflates the every-session floor; a separate `@import`ed file keeps the floor thin and the layer operator-owned). **A bare textual pointer in `CLAUDE.md`** (rejected — verified live: the model does not follow a textual pointer; only `@import` inlines the file). **Policy-style numeric per-key merge** (rejected — prose does not merge per-key; composition is per-rule-by-`id` supersession + a disable-list). **An optional module** (rejected — it must be present in every repo; an optional package could be deselected, defeating the goal — so a required carrier riding `core` per §12). **Ship the operator's rules as the public `defaults.md`** (rejected — keeps the public template universal; the operator's rules ride the preserved override seeded from the maintainer's template). **Pack-inject the stance at boot** (rejected — floor `@import` is hook-independent; pack-injection vanishes on a hook failure). **Enforce the auto-memory boundary** (rejected per the #94 analysis — audits' read-only law, never-writes-`~/.claude`, harness-skill dependence, content-not-location). **Re-lock [boot](../spec/systems/lifecycle/boot.md)** (rejected — the stance is floor-loaded, not pack-injected; boot's status-verb pull is its existing seam, so boot gains no text).
