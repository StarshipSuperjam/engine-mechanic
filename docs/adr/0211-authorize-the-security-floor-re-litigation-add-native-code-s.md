# Authorize the security-floor re-litigation: add native code scanning (CodeQL), private vulnerability reporting, and a seeded SECURITY.md to the locked floor (engine-template Security Overview gap)

*Decided 2026-06-18 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) on explicit operator approval to extend the locked [security floor](../reference/glossary.md) — its contract in [control-plane](../spec/systems/infrastructure/control-plane.md) and its mechanism in [provisioning](../spec/systems/infrastructure/provisioning.md) — from {secrets, dependencies} to also cover **code scanning** and **vulnerability disclosure**. **The litigation alarm:** the operator, reading the engine-template Security Overview, observed three features unconfigured — **code scanning**, **security policy (`SECURITY.md`)**, and **private vulnerability reporting (PVR)** — and directed that all three be **part of the template, automatic for every product repo, never manual per-repo setup**, with the **drawback disclosed** where a feature cannot apply. Two real gaps: the floor reached secrets + dependencies but never the **code the Engine writes** (the Engine autonomously authors product code a non-engineer cannot review) nor a **vulnerability-disclosure surface**; and the corpus carries **no "security" quality attribute** to anchor either.

  **The decision — extend the floor along its own existing grain (native-where-supported / disclose-never-downgrade), fully native, no bespoke layer.** Three native pillars added, each reusing the operator-privileged `gh` bootstrap the ruleset already runs (no new scope):
  - **Code scanning (native CodeQL).** Provisioning enables **CodeQL default setup** (GitHub-managed, no committed workflow) via `PATCH .../code-scanning/default-setup` where the tier supports it (public, or paid-private); on a **free private** repo it 403s — provisioning detects, **skips, and discloses the drawback** (what's off, what unlocks it), never auto-switching visibility, shipping **no bespoke third-party scanner**. Native code-scanning alerts are **advisory, not a merge gate** — so a finding never blocks the non-engineer.
  - **Vulnerability disclosure.** A **root `SECURITY.md`** seeded as operator-owned config (seed-then-preserve, the conduct-override precedent; at the **repo root** = product territory, preserved by the overlay's product-paths-untouched rule with **no carve-out**), plus native **PVR** enabled on **public** repos via `PUT .../private-vulnerability-reporting`; on private repos PVR is structurally absent (public-only), disclosed, with SECURITY.md the channel.
  - **A first-run disclosure** for the repo-altering toggles + the seed (the native-plan-mode / conduct-seed precedent — nothing lands silent).

  **R6/attribute anchoring:** fold under existing **#1 Trustworthiness** + **#5 Degradability**; **no new "security" attribute** ([goals-and-quality](../reference/goals-and-quality.md) untouched).

  **Reshaped by a four-lens cold plan-audit + the operator's decision.** The audit **killed the original candidate** — a committed **Semgrep OSS SAST workflow as a required, merge-blocking check** over product code — on convergent blocking findings: it contradicts **[D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md)**'s locked altitude (standing product-code analysis is an opt-in *module*, not a foundation floor), violates **[§6](../principles.md)** (hard-gate only governance-critical invariants; a judgment-requiring SAST finding is not one — unlike a leaked secret), **strands the non-engineer** at a greyed merge button they cannot clear (and, as repo-admin, trains ruleset-bypass), and collides with **[dependency-discipline](../spec/modules/dependency-discipline.md)**'s locked "no third-party scanner injected into every repo's CI" stance. **The operator redirected** to **native-only where supported** (CodeQL where the tier allows; **free repos get nothing, disclosed**) — eliminating the bespoke scanner, the disposition machinery, the D-095 altitude conflict, and the third-party-CI collision in one move. The audit also fixed the **SECURITY.md ownership tier** (operator-seeded-and-preserved at the **root**, not an engine-owned `.github/` artifact) and confirmed the **fold-not-mint** attribute call.

  **Scope. Re-lock set — 2** (both currently locked → re-locked, none added): [control-plane](../spec/systems/infrastructure/control-plane.md) (the security-floor contract gains the code-scanning + disclosure pillars) and [provisioning](../spec/systems/infrastructure/provisioning.md) (the CodeQL + PVR toggles branched on tier/visibility, the root-`SECURITY.md` seed, the first-run disclosures, the extended security-scanning-tier build-spec leaf). **Carriers (non-locked, authored this pass):** [constraints](../reference/constraints.md) (the CodeQL/PVR/`SECURITY.md`/template-workflow platform facts), [glossary](../reference/glossary.md) (*Security floor* amended; *Protection floor* cross-ref), [risks](../reference/risks.md) (**R25**), [engine-architecture](../architecture.md) (the bootstrap-settings index line), [scenarios/first-run](../architecture.md#first-run-provisioning) + [scenarios/upgrade-the-engine](../architecture.md#upgrading-the-engine). **Verify-no-edit (confirm at the landed-text audit):** [modules/core](../spec/modules/core.md) (CodeQL is a setting-toggle, **not** a committed workflow, and `SECURITY.md` is operator-seeded at root → core's foundation-artifact inventory is untouched), [dependency-discipline](../spec/modules/dependency-discipline.md) (no third-party scanner → its anti-third-party-CI stance is not implicated), [goals-and-quality](../reference/goals-and-quality.md) + [modules/clean-code](../reference/module-catalog.md) / [D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md) (native security scanning ≠ the bespoke style/lint module; no new attribute), [modules/README](../reference/module-catalog.md), [telemetry](../spec/systems/guardrails/telemetry.md) / [audits](../spec/systems/guardrails/audits.md). **No [deviations](../reference/prototype-deviations.md) entry** (no security-coverage deviation exists); **no wbs slice** (the floor is built as control-plane/provisioning build-spec leaves, not a slice; downstream realization is engine-template conformance issues). **AF-9 is already resolved** ([D-153](0153-clear-the-deferred-nit-backlog-one-batched-re-litigation-of.md)); ## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval. The gap is real — a security floor that scrutinizes secrets and dependencies but never the code the Engine itself writes, on a premise (a non-engineer trusts AI-authored code they cannot review) that makes automated scrutiny of that code load-bearing for trust. Extending the floor along its **own locked grain** (native-where-supported / disclose-never-downgrade) reuses settled grammar and invents no structure; the operator's native-only choice is the minimal, least-bug-surface realization — GitHub-managed CodeQL with a clean detect-and-skip on free-private, no third-party scanner, no disposition layer — which is also why it touches **no** other locked decision (D-095, dependency-discipline, goals-and-quality all stand). Advisory-not-gating keeps [§6](../principles.md) satisfied and the non-engineer un-stranded; the disclose-the-drawback invariant the floor already locks keeps the free-private gap honest rather than silent.

## What we ruled out

**A required, merge-blocking Semgrep OSS SAST check over product code** (the original plan — rejected on the four-lens audit: contradicts [D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md) altitude, violates [§6](../principles.md), strands the non-engineer / trains bypass, collides with [dependency-discipline](../spec/modules/dependency-discipline.md)'s anti-third-party-CI stance). **Any bespoke third-party scanner as a free-private fallback** (rejected — the operator's native-over-bespoke call: another scanner is "another layer to inject bugs"; the free-private gap is disclosed instead). **A committed `codeql.yml` advanced-setup workflow** (rejected — it 403s on free-private and is a maintained file forever; default setup is GitHub-managed, auto-updating, and the API gives a clean detect-and-skip). **`.github/SECURITY.md`** (rejected — `.github/` is the engine namespace; a root `SECURITY.md` sits in product territory, unambiguously operator-owned and preserved with no overlay carve-out). **A new "security/safety" quality attribute** (rejected — the existing floor stands on #1/#5 with none, extending it shares that justification; minting one re-opens locked [goals-and-quality](../reference/goals-and-quality.md) for zero design gain). **Auto-enabling the toggles or seeding `SECURITY.md` silently** (rejected — repo-altering acts get a plain-language first-run disclosure, the native-plan-mode / conduct-seed precedent). **Fire-and-forget toggles** (rejected — provisioning branches on the call's HTTP status, never reporting a feature on when the enable failed — [R25](../reference/risks.md)).
