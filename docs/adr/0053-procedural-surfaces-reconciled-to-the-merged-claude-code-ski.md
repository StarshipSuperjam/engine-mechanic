# Procedural surfaces reconciled to the merged Claude Code skill mechanism (commands ⊂ skills)

*Decided 2026-05-25 in the design workspace.*

## The decision

Reconcile the `designed` procedural-surface docs to a verified current-platform fact: **Claude Code has merged custom slash commands into skills.** A command is realized as a `SKILL.md` carrying **`disable-model-invocation: true`** (operator-only invocation; its description is *not* held resident in context and loads only when the operator invokes it), living in `.claude/skills/` — with the legacy `.claude/commands/<name>.md` form still working identically. A genuine [skill](../spec/systems/surfaces/skills.md) surface instance is the **model-invocable** case (the default), whose name+description *is* permanently resident (the attention cost). **Three reconciliations, all to `designed` docs (no lock, no locked-doc edit, no litigation alarm):** (1) commands — location, class, and framing updated to the skill mechanism + `disable-model-invocation`, legacy path noted; (2) [skills](../spec/systems/surfaces/skills.md) — the always-resident attention cost scoped to *model-invocable* skills, the command-is-the-same-file-format-with-the-flag relationship stated; (3) [tools](../spec/systems/surfaces/tools.md) — the interface-implementation **binding-model** clause neutralized to a pure deferral (`tool` is the code-home; *how* an implementation binds and how a default/fallback is chosen is the still-`designed` [interfaces](../spec/systems/surfaces/interfaces.md) surface's concern), so a future `tools` lock cannot be forced by the interfaces lock. The **engine/product collision** claim in commands and skills is corrected from "never collides" to **convention**: loose project-level `.claude/` files are *not* platform-namespaced (real namespacing exists only for plugin skills, `plugin:name`), and the engine ships as committed files via "Use this template", not as a plugin — so the `engine-` prefix reserves the name by convention, making a collision improbable, not platform-impossible. The locked [ontology](../spec/systems/grammar/ontology.md) D-020 identifier law is unaffected in intent (prefixing is the mechanism; it never claimed platform enforcement). **The operator-typed-vs-model-auto-invoked distinction survives the merge** (it is now `disable-model-invocation: true` vs. the default), so `command` and `skill` remain **distinct catalogued surfaces** and the locked surface set ([D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)/[D-043](0043-surface-set-completion-re-lock-ontology-and-hooks-to-clear-t.md)) is untouched — additive, no re-lock.

## Why

The four-lens cold-session audit of the original "lock the five ready surfaces as one event" plan caught (technical-feasibility lens, verified firsthand against `code.claude.com/docs/en/skills`) that the commands/skills docs encoded a two-distinct-mechanisms / two-locations model the platform had since collapsed, and (adversarial lens) that `tools` made interface-implementation *binding by presence* a defining clause while [interfaces](../spec/systems/surfaces/interfaces.md) — which D-044 already proved has a subtle named-fallback law — is still `designed`. Freezing either drift under a lock would have been exactly the stale-assumption / lock-atop-a-churning-neighbour failures the audit gate and lock discipline exist to prevent. Reconciling the `designed` docs first (no lock) clears the drift cheaply; the surface *distinction* is governance-level (invocation trigger, per the [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md) boundary law), not file-format-level, so the merge does not collapse the catalog. The collision correction keeps the trust story honest — the engine does not over-claim a platform guarantee it does not have.

## What we ruled out

Collapse `command` into `skill` as a single surface (rejected — the operator-typed-vs-auto-invoked distinction is real at the governance layer and survives the platform merge via the invocation flag; the boundary law routes by *who invokes*, not by file format). Lock commands/skills/tools now against the drifted/dependent text (rejected by the audit — a lock would freeze a stale platform assumption and an interfaces-dependent clause). Keep "never collides" (rejected — false for loose `.claude/` files; only plugin skills are namespaced, and the engine is not a plugin). Edit the locked ontology D-020 law (rejected — its prefixing intent stands; "never collides" was a leaf over-claim in the surface docs, not in the locked law). Treat `.claude/commands/` as removed (rejected — the platform states existing command files keep working; it is the legacy form, not a dead one).
