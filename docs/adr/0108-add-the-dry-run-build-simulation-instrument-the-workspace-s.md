# Add the dry-run build-simulation instrument (the workspace's L1 build-readiness gate)

*Decided 2026-05-28 in the design workspace.*

## The decision

Author wbs/dry-run.md as a maintainer-layer, freely-revisable **build-readiness instrument**: cold-context **builder** + **spec-completeness-reviewer** agents simulate constructing each WBS build step *from the design docs alone*, surfacing four gap classes a reader misses but a builder hits — **underspecification, missing-grammar, contradiction, ordering**. It **inverts** the cold-session audit's question (per-system *soundness* → end-to-end *build-readiness*) and complements validate.py (mechanical). It is **read-only/advisory** — a findings ledger tagged blocking/serious/nit, **never** a doc edit — run in build order from the **irreducible M1 genesis** ([repository-topology](../spec/systems/infrastructure/repository-topology.md) → `core` → `validators-core` + `memory-substrate-sqlite-fts5`, plus the stage-0 seed and [control-plane](../spec/systems/infrastructure/control-plane.md) bootstrap) outward. Form: a protocol doc **plus ready-to-run builder/reviewer prompt templates**, executed via the Agent tool — **no script**. It is **L1 planning-workspace tooling**, distinct from the Engine's [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), the stage-0 **L2** cold review of construction, and the deployed **L3** [audits](../spec/systems/guardrails/audits.md) system.

## Why

The workspace had two gates — validate.py (mechanical) and the per-system cold-session audit (soundness) — but neither tests whether the corpus is *buildable*: a design can be internally consistent yet underspecified for a cold builder, and that gap stays silent until construction hits it. The genesis stretch (Builder A, building from docs alone before any engine machinery exists) has the least margin — no validator, orchestration, or substrate to catch a gap — so it is simulated first. **Read-only/advisory is mandatory** because most [systems](../architecture.md) are `locked`: a simulation that edited docs to close its own findings would be exactly the silent drift the lock fingerprint guards. It directly serves [R6](../reference/risks.md) deferral discipline — the end-state must stay *specified*, and this is what tests that the specification is build-complete. Placed under `wbs/` (outside the validator's frontmatter/coverage gates, freely revisable) rather than as a top-level doc, so no resume-order/document-map churn. Propagation: wbs/dry-run.md authored; wbs/README.md pointer; CLAUDE.md "No mechanical enforcement of meaning" section names it as the third gate; this entry. The instrument is **not run** in this pass — building the finder is in scope; launching the simulation and dispositioning findings is the separate, human-gated step. `validate.py` green.

## What we ruled out

Ship a `dryrun.py` harness (rejected — the work is semantic agent-orchestration like the cold-session audit, not mechanical; a script would only aggregate findings, low value for added surface to maintain). Place it as a top-level `build-readiness.md` (rejected this pass — heavier propagation into resume order + document map + `README.md`; the maintainer-layer `wbs/` home fits a freely-revisable instrument that operates on the build steps, and the lighter pointer suffices). Let the simulation edit docs to close gaps (rejected — most systems are `locked`; auto-remediation is the silent drift the lock protocol forbids, so finder and remediation are deliberately separated by a human gate). Fold it into the cold-session audit (rejected — that gate is per-system soundness before a lock; build-readiness is end-to-end across the sequence and asks a different question; conflating them would dull both). Run it now (rejected — the operator scoped this pass to building the instrument, not starting it). Skip this entry as mere tooling (rejected — adding a workspace instrument is a substantive workspace-process change; precedent [D-037](0037-graveyard-exemption-the-append-only-decision-log-may-link-re.md) logs workspace-process decisions, and silent changes are forbidden).
