# Defer the `expression-contracts` design to a dedicated session; correct `core`'s mischaracterizing carve-out

*Decided 2026-05-27 in the design workspace.*

## The decision

**Defer** the design of the `expression-contracts` module to its own dedicated session, and **correct** `core`'s partition line, which mischaracterized it. `expression-contracts` was never actually designed — it is undefined in every canonical/locked doc beyond [`core`](../spec/modules/core.md)'s one-line carve-out, which moreover framed it as tier-1 "lifecycle/expression **contract instances**" when the operator's actual intent is **tier-3, audience-keyed style/voice governance**: tunable instruction sets fixing the *tone, tenor, and organization* of **engine-authored** output — human-facing prose (kinetic, short, no citation-stuffing), AI-facing prose (efficiently organized, no "junk-drawer" dumping), and code (per-language style standards, which make downstream linter/formatter modules less load-bearing) — distinct from the structural [templates](../spec/systems/guardrails/templates.md) foundation. It is a genuine, load-bearing design effort, **not** a packaging-view pass over already-locked machinery, so it gets its own grounded session rather than being reconstructed here. The live design threads are captured in [open-questions.md](../reference/open-questions.md) **Q19**; `core`'s carve-out bullet is corrected to current truth (style/voice governance, **realization deferred** — not pre-committed to a new surface vs. reuse). The stub holds the slot and stays `required` in the catalog (its required-ness is not re-litigated here; only its design is deferred).

## Why

Established during the [D-092](0092-flesh-the-routine-mode-module-doc-to-designed-the-operator-e.md)/[D-093](0093-cut-the-adr-discipline-module-vestigial-its-content-already.md) module pass. Asked to "continue module docs," the author initially planned to flesh `expression-contracts` to `designed` alongside `routine-mode`/`adr-discipline` by inferring its content from the reference-only `Engine_Prototype` ("three-layer code/document/migration contract template"). The operator caught this: the prototype is a reference input, not gospel, and the inferred content did not match intent. On clarification the operator supplied the real intent (audience-keyed style/voice, above; **engine-authored content only** — product output follows the product's own conventions per [asymmetric awareness](../principles.md)/the engine-product wall) and chose to **defer it to its own session** so it can be designed properly rather than guessed. The session plan-audit (architect lens) then established that this deferral is itself a **substantive scoping decision** requiring a log entry (not merely an open-questions note), and that `core`'s carve-out line mischaracterized the module — both folded here. **No cold audit of the expression-contracts *design* runs here, by design**: nothing is designed yet, and auditing a non-design would be theater (the very lesson that opened this exchange — do not plan/audit what is not yet understood); the cold-audit gate fires in its dedicated design session. Propagation per the matrix: [open-questions.md](../reference/open-questions.md) Q19 added; [modules/core/README.md](../spec/modules/core.md) carve-out bullet corrected to current truth (style/voice governance, realization deferred). Verified no-change with rationale: [modules/README.md](../reference/module-catalog.md) (the `expression-contracts | required | core` row + `core → expression-contracts` edge stand — design is deferred, not the package), [glossary.md](../reference/glossary.md) (no `expression-contract` term coined yet — it is deferred with the realization, so coining one now would pre-commit the grammar), [engine-architecture.md](../architecture.md) (indexes via the catalog; the required-stub row is unchanged), wbs/README.md (unauthored). No locked doc edited (`core` is `designed`/editable; the contracts/policies/templates surfaces the future design will weigh are untouched).

## What we ruled out

Reconstruct `expression-contracts` from the reference-only prototype and author it to `designed` this pass (rejected — the prototype's "code/document/migration template" framing is not the operator's style/voice intent; authoring from an unconfirmed reconstruction is the exact intent-gap error this exchange corrected). Leave `core`'s "contract instances" carve-out unchanged (rejected — it mischaracterizes the module as tier-1 contracts; current-truth authoring requires the fix). Capture the deferral only in [open-questions.md](../reference/open-questions.md) with no log entry (rejected — a substantive scoping decision needs a logged entry per the propagation matrix; open-questions holds the *live threads*, not the deferral *decision*). Cut `expression-contracts` like [`adr-discipline`](README.md) ([D-093](0093-cut-the-adr-discipline-module-vestigial-its-content-already.md)) (rejected — unlike adr-discipline, its style/voice function is **not** already shipped by `core`; it is a genuine gap, deferred not removed). Pre-commit the realization to a new tier-3 surface now (rejected — whether it is a new surface or a reuse of an existing one is a real design question with [R6](../reference/risks.md) weight, owned by the dedicated session).
