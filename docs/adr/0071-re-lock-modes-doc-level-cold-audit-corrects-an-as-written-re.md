# Re-lock `modes`: doc-level cold audit corrects an as-written resume-resurrection overclaim and a dangling seam link

*Decided 2026-05-26 in the design workspace.*

## The decision

Re-lock [modes](../spec/systems/lifecycle/modes.md) after a **cold-context audit of the as-written locked document**, not only of the pre-lock plan — the [D-018](0018-cold-session-design-audit-required-before-any-lock.md) gate read literally requires the four lenses to review *the doc being ratified*, and at [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) they reviewed the plan prose while the authored doc (written afterward) went un-cold-read. The doc-level pass found, and this entry resolves: **(1, serious)** the "never persists" justification was **factually wrong** — the doc claimed a fresh session "cannot read a prior session's signal — *the key differs*", but `claude --resume <id>` **reuses** the session id, so a resumed crashed Build session keyed by that id could read its lingering marker and **resurrect as Build**, breaching locked [state](../spec/systems/cognitive/state.md)'s "must not resurrect as Build"; reframed to the honest law — **every session start, including resume, begins in Explore and never inherits a prior stance signal** (the signal is set only by a deliberate in-session entry and cleared at every `SessionStart`, which fires on resume), with that session-start clear added to the build-spec leaves; **(2, serious)** the still-`designed` [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) carried an **inbound `trivial-write fast path` link into `../modes/`** routing the mechanism-noun *into* modes, which no longer defines it ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) drained the circularity but repointed only the scenario link, missing this one) — repointed so build-orchestration owns the term and links to modes only as the entry it keeps proportionate; **(3, serious)** the gate's fail-open was unreconciled with the operator promise — added that a write slipping the gate is **bounded by the merge wall** (it shows in the reviewed change set and cannot reach the protected branch unreviewed), so a fallible gate never silently turns Explore into an unreviewed protected-branch change; **(4, nits)** the denial copy now names the **concrete way forward** rather than "say the word", "PR" is **glossed** ("a pull request, the change I submit for your approval") on operator-facing examples, and Routine's scope-check is **attributed** to build-orchestration (modes' gate is Explore-only and permits writes in Routine). `python3 lock.py --relock` updates the fingerprint; ratified_by D-071. The laws are unchanged from [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) — this corrects their as-written realization.

## Why

A lock fingerprints a specific document, so the cold-audit gate must cover *that document*, not a plan that precedes it — prose authored after the plan can overclaim, contradict, or leak in ways the plan-level pass cannot see, which is exactly what happened (both the resume-resurrection justification and the dangling link were born in the authored text). Re-reading the ratified artifact is therefore part of the lock, not an optional extra. Technical-feasibility confirmed the platform facts the fixes rest on — a `PreToolUse` hook receives `session_id` on stdin, `--resume` reuses it, `SessionStart` fires on resume (so a start-time clear is implementable), `permissionDecision: deny` is honored unevenly for edit tools ([D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md), live), and operator-only invocation maps to a real `disable-model-invocation` skill — and the two remaining platform-reliability quirks (deny-ignored-for-edits; operator-typed-verb honor rate) are already carried honestly by the gate's uniform-fallibility framing and [R11](../reference/risks.md). No locked doc other than modes is touched; build-orchestration is `designed`, so its link repoint is a free reconciliation, not a re-lock.

## What we ruled out

Let the [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) lock stand on the un-cold-read text (rejected — the audit gate exists to catch exactly the as-written overclaim it caught; skipping the doc-level read ranks with skipping the audit). Keep "the key differs" / "cannot resurrect" (rejected — false for `--resume`, which reuses the id, and an overclaim of the kind the doc elsewhere forbids; the honest law is start-clears-and-never-inherits). Soften to "a fresh session boots Explore" and leave resume unaddressed (rejected — locked [state](../spec/systems/cognitive/state.md) requires no-resurrect, so the mechanism must guarantee it across resume, not duck the case). Drop build-orchestration's fast-path link entirely (rejected — loses the navigational seam; the fix is to own the term locally and link to modes as the proportionality principle). Re-open the modes laws (rejected — [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md)'s laws are sound; only their as-written expression needed correction).
