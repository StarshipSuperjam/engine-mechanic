# Re-litigate `attention` (honesty/clarification): reference-time as an explicit determinism input; "right things first" stated unproven-until-fixture

*Decided 2026-05-27 in the design workspace.*

## The decision

Under the litigation-alarm protocol (operator-approved as part of the cognitive-substrate remediation plan), re-litigate [attention](../spec/systems/cognitive/attention.md) with two scorecard-surfaced corrections: **(A3)** name **reference time an explicit, recorded input** to the deterministic ranking function (a single as-of timestamp), so "the same inputs yield the same ordering" includes that timestamp and recency-dependent ordering is reproducible across clock skew and a ledger/host change — a clarification of the existing determinism law that creates no new state ("reads, never owns" is intact); **(A4)** state honestly in *Build-spec leaves* that, until the build-session fixture exists, the claim that prioritization surfaces **the right things first** is **unproven** — the laws fix that the ordering is explicit, deterministic, and debt-blocking-aware, not that its weights are calibrated to a correct priority. **No design law changes.** `python3 lock.py --relock systems/cognitive/attention/README.md --decision D-083`; ratified_by D-083.

## Why

The remediation plan provisionally assigned `attention` a fresh per-system cold audit on two premises the prior audits dissolved: (1) A4 would legislate a new "fixture-before-weights" law — but the plan-level cold audit scoped A4 down to an honesty statement and routed the authoring-order recommendation to the workspace-layer [Q15](../reference/open-questions.md), not the locked doc; (2) the M3-reframe × attention-determinism interaction needed checking — but Step 2's ([D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md)) architect lens already resolved it (frecency is a memory-owned *input*; determinism is "same inputs → same ordering," which a time-varying input does not violate). With both dissolved, A3 (a determinism *clarification* naming an always-implied input) and A4 (an honesty statement) touch **no new design surface** — the same class as [D-080](0080-re-litigate-state-honesty-name-the-floor-s-known-unbounded-f.md)/[D-082](0082-re-litigate-knowledge-honesty-r8-hub-explosion-is-deferred-b.md) — so a fresh four-lens audit is disproportionate under the [D-074](0074-sweep-the-stale-q1-references-resolved-by-d-066-d-068-re-loc.md)/[D-078](0078-citation-accuracy-re-litigation-repoint-stale-q4-references.md) precedent; the rigor is `validate.py` + a current-state self-check + the remediation plan's own 5-lens cold audit, which already vetted both edits. The operator was explicitly flagged of this deviation from the plan's provisional audit assignment. Propagation per the matrix: [attention](../spec/systems/cognitive/attention.md) (re-locked end-state), this entry; [risks.md](../reference/risks.md) R4 extended (closure now requires calibration against the fixture that establishes ordering correctness, not merely an explicit policy); [engine-architecture.md](../architecture.md) D-029/D-030 lineage verified unaffected (no edit); [scenarios/remediation-loop.md](../architecture.md#the-detect-to-remediate-loop) "debt seen first" reflects the debt-blocking *law*, not the unproven general calibration — verified truthful (no edit); [glossary](../reference/glossary.md) "Attention" verified truthful (no edit).

## What we ruled out

**Run the full four-lens per-system audit anyway** (rejected as disproportionate once A4 was scoped to honesty and the M3 interaction was resolved in [D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md) — but flagged to the operator as a plan deviation, reversible on request). **Legislate fixture-before-weights into the locked law** (rejected — collides with laws-not-leaves/[D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md); the authoring-order recommendation lives in the workspace-layer [Q15](../reference/open-questions.md)). **Cite Q15 from the attention doc** (rejected — Q15 is a workspace-process item; citing it from a locked Engine doc breaches layer discipline, so the doc references only the Engine build-session fixture). **Leave "right things first" implicitly proven** (rejected — the scorecard's keystone finding; a locked doc must not imply a calibration it has not earned).
