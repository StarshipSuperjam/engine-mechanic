# Resolve the D-213 front-door re-litigation: landed-text cold audit, two docs re-locked

*Decided 2026-06-18 in the design workspace.*

## The decision

The [D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with **four** independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written edits in [repository-topology](../spec/systems/infrastructure/repository-topology.md) and [provisioning](../spec/systems/infrastructure/provisioning.md) plus the carriers. **Outcome: no blocking on any lens; architect PASS (propagation complete, seams clean, every verify-no-edit target confirmed); two serious folded (the marketing-seed recognizer, the disclosure framing); the rest dispositioned.** Re-lock set: **2**.

  **The audit + dispositions.**
  - **Technical-feasibility — one serious folded; no platform-fact error.** Re-verified: "Use this template" copies the root README ([constraints](../reference/constraints.md)); the instantiator's greenfield/brownfield branch is intrinsic to the delivery model (greenfield runs in the copied tree, brownfield overlays then runs the same instantiator); the `SECURITY.md` seed-if-absent precedent is correctly extended. **Serious (folded):** the "recognizable marketing seed" recognizer was deferred to a build-spec leaf without naming a feasible approach or its safe-failure direction. **Fold:** the provisioning section's first bullet + the build-spec leaf now state the recognizer is **conservative — positive-match-or-preserve**, realized by a recognizable engine marker / content fingerprint the landing seed carries, never replacing operator-authored content (preserve on any doubt); idempotency, brownfield-safety, and upgrade-safety all follow from that one predicate.
  - **Non-engineer-operator — one serious folded; mechanism sound.** The replace mechanism and the never-touch-operator-content guarantee read clean. **Serious (folded):** the disclosure law was too generic beside the security-floor leaf's precision — a bare "the engine set your README" could read as an overwrite. **Fold:** the build-spec leaf's disclosure law now mandates the framing — name *what changed and why it is theirs* (the Engine's landing page was replaced with a starter for *their* project, intentional setup of their repo's front door), never a bare "the engine changed your README". **Dispositioned (no edit):** the deferred marketing *content* is the operator's own explicit "mechanism in design, content as task" scoping ([D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md)) — honored, not re-opened, and legible in [D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md), the [glossary](../reference/glossary.md) term, and [R26](../reference/risks.md); maintainer vocabulary stays in the mermaid/design prose and off the operator surface (the disclosure-copy law governs what the operator sees).
  - **Adversarial — no fatal flaw; two nits dispositioned.** Confirmed the three cases (greenfield replace / brownfield preserve / re-run no-op) are mutually exclusive and exhaustive, the never-replace-operator-content commitment holds, and no contradiction with [topology](../spec/systems/infrastructure/repository-topology.md) law 1, the engine/product wall, the [docs surface](../spec/systems/surfaces/docs.md) "never claims the product's own root README", or the `SECURITY.md` treatment. **Nit (dispositioned):** the CODEOWNERS "product-owned-by-default → no unowned-file hole" claim rests on the wall's **existing** "product owns everything else by default" premise ([topology](../spec/systems/infrastructure/repository-topology.md)) — not a new assumption, already grounded in the same doc, so no new text. **Nit (verified):** "[D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) names no writer" is accurate — D-067 specifies *what* the project README discloses, never *who writes it*; this pass supplies that writer.
  - **Architect — PASS, no blocking/serious; re-lock set = 2 confirmed; propagation complete.** Every verify-no-edit target read and confirmed untouched-and-consistent: [modules/core](../spec/modules/core.md) (the README seed is provisioning mechanism, not a new core `provides` artifact — exactly as the `SECURITY.md` and conduct seeds), [control-plane](../spec/systems/infrastructure/control-plane.md) (the README is product-owned, not a control-plane artifact), [surfaces/docs](../spec/systems/surfaces/docs.md) ("never claims the product's own root README" is *honored* — the README is a product file, not an engine doc). The topology(ownership)/provisioning(mechanism) seam is clean; the carriers (engine-architecture, first-run, glossary, risks) tell one consistent story. A corpus grep for "project README"/"root README" surfaced only [modules/README](../reference/module-catalog.md)'s disclosure-vehicle references, which the new glossary term now defines — no edit. (An architect nit alleging R26 says "opened by D-212" was a misread — R26 carries no such text.)

No fold touched [repository-topology](../spec/systems/infrastructure/repository-topology.md) (the ownership clause stood as landed).

  **Build-owes (engine-template, downstream — not authored here):** the **sequencing gate** — the provisioning root-README replace step ships before the template's marketing landing README ([R26](../reference/risks.md)); the **marketing-seed recognizer** (the marker/fingerprint the landing seed carries + the positive-match-or-preserve check); the **product-starter README content** (the product placeholder + the [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) required-spine disclosure copy in plain operator language); the **first-run disclosure copy** (names what changed and why it is theirs, never a bare "the engine changed your README"); and the go-to-market **content** task (the template's marketing landing README + banner + GitHub description/topics — the operator's, sequencing-gated).

## Why

The lock gate requires a landed-text cold audit with every blocking/serious resolved before re-lock; it ran (four lenses), found no blocking, and the two seriouses (the under-determined recognizer, the under-specified disclosure framing) were folded into provisioning before the re-locks. The landed text is faithful to [D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md): the root README is the `SECURITY.md` product-owned-by-default seeded-root-file model with one new operation — replace-iff-it-is-the-recognizable-marketing-seed — whose conservative positive-match-or-preserve predicate is exactly what keeps it idempotent, brownfield-safe, upgrade-safe, and incapable of touching operator content; the marketing content stays a maintainer task behind the sequencing gate; and the engine/product wall and the locked neighbors stand untouched.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Leave the recognizer's failure direction unstated** (rejected — a recognizer that fails toward *replace* could clobber operator content; the law is positive-match-or-preserve). **Leave the disclosure as a bare "README set"** (rejected — a non-engineer could read it as an overwrite; the law names what changed and why it is theirs). **Re-open the mechanism/content scope split** (rejected — it is the operator's explicit call; the deferral is legible in [D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md)/[glossary](../reference/glossary.md)/[R26](../reference/risks.md), not buried). **Document GitHub CODEOWNERS default-ownership as a new premise** (rejected — it is the wall's existing "product owns everything else by default", already grounded in [topology](../spec/systems/infrastructure/repository-topology.md)). **Edit [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) to add the README writer** (rejected — append-only; the writer is supplied in the landed provisioning text and recorded here).
