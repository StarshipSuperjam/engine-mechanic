# Authorize the audit-over-audit re-litigation: feed the periodic audit its own prior digests (corroboration only) and reconcile the module-fit concern with the function-probe law (re-opens locked [audits](../spec/systems/guardrails/audits.md) D-076 + [audit-library](../spec/modules/audit-library.md) D-148)

*Decided 2026-06-22 in the design workspace.*

## The decision

Authorize re-opening two locked docs to close a latent contradiction the operator surfaced and the running engine then confirmed: the periodic audit is asked to make usage-flavored judgments (module-fit *"installed but never exercised → retire"*) while law 2 (function-probe-not-stats) forbids resting fitness *"on a cached count"* and no trend history is retained. **Four changes.** **(1) [audits](../spec/systems/guardrails/audits.md) — over-time corroboration input:** the audit reads the **git history of its own committed digest path** (the dated digest sequence) as corroboration, bounded by four guardrails — *corroborates, never decides* (the retire/keep call still rests on a fresh function-probe this cycle, law 2 intact, quiet≠dead); *observed conditions only, never the audit's own prior judgment* (resting on a recorded condition, never a prior digest's recommendation — citing its own past leaning would compound single-project bias and feed the warm audit its own priors, against law 3 and the held-out learning ambition); *prioritization computes nothing* (recurrence directs where the persona looks, persists no count/threshold/weight); *honest degradation* (no readable history → point-in-time review, said plainly, never a fabricated trend). It adds **no committed artifact and no ledger** — the durable signal-of-record stays [telemetry](../spec/systems/guardrails/telemetry.md)'s native record + the per-issue first/last-seen markers — so it neither duplicates telemetry's mechanical trend nor touches the judgment ladder, and the digest must present a finding's fresh-probe basis and any corroborating-history note as **distinct**. **(2) [audits](../spec/systems/guardrails/audits.md) — module-fit reconciled:** reword **only** the module-fit seed-concern so absence-of-evidence-of-use is the *trigger to demand the affirmative case* (law 1 retirement-default), never the *proof of disuse*; the call rests on a fresh probe, corroborated not decided by digest-history persistence (raises rigor — retires less, the safe direction). **(3) [audit-library](../spec/modules/audit-library.md) — one realization-grammar bullet:** the scheduled run must put the committed digest's prior history in front of the read-only, GitHub-token-less persona (the same fetch-and-feed seam concern #2's issue backlog uses); the concrete vehicle — the workflow reading that history token-free from a full-history checkout (the default shallow checkout carries none) vs. a `gh`-API read of prior versions — is a build-spec leaf; where a substrate's clone carries no history (the optional Cloud-Routine fresh clone, depth not engine-controlled) the input is absent and the audit degrades. **(4) [audits](../spec/systems/guardrails/audits.md) — operator decline-respect:** a recurring retire-candidate re-presents the case, never escalates the ask; a prior decline stands; the recurrence is never weaponized as pressure (symmetric to the escalate-lane's *"does not return as fresh noise each cycle"*), protecting law 1's *"declining is a real choice."* **Propagation:** [glossary](../reference/glossary.md) (the Audits + Audit-digest entries gain a corroboration clause; the posture-laws gloss stays intact — law 2 unchanged), [risks](../reference/risks.md) R6 (the audit-layer firming gains this mechanism; **no new risk** — the git-history dependence is self-disclosing degradation). The re-lock of both docs lands at the resolving entry after a landed-text cold re-check (the [D-227](0227-resolve-the-d-226-audits-re-litigation-landed-text-cold-audi.md)/[D-230](0230-resolve-the-d-229-audit-auth-correction-landed-text-cold-aud.md) pattern).

## Why

The contradiction is real and pre-existing — the four-lens plan-stage cold audit (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) confirmed Change 2 fixes a genuine locked-text defect, not a design weakened to fit current work (CLAUDE.md justified-re-litigation bar) — and the **running engine confirmed both halves**: engine-template self-review PR #194 (2026-06-22) independently reported *"on module fit, this engine has no usage history yet, so I can't honestly call any installed module 'inert'"* (Change 2 verbatim) and exhibited the fetch-and-feed seam (the GitHub-token-less persona was fed the issue backlog by the workflow's automatic `GITHUB_TOKEN`), so Change 1 fits with **no new operator auth** — the digest is a same-repo read; prior digests ride the workflow's existing token-free local-git checkout. The technical-feasibility lens ground-truthed the substrate against current GitHub docs and locally: `actions/checkout` defaults to `fetch-depth: 1` (shallow — the default cron run would see zero prior digests, so the requirement is **load-bearing grammar, not a leaf**, which is what forces the audit-library re-lit), and `git log -- <path>` returns a same-path file's full per-commit history even under full content replacement (the digest's exact case), surviving an overlay commit. Two build observations the live run surfaced are logged on engine-template as **#198** (attest backlog completeness so the persona stops hedging) and **#199** (decide whether the cron audit is fed the protected-branch signal vs. leaving it to boot's lane) — out of this design's scope, tracked not buried.

## What we ruled out

A committed telemetry history ledger (rejected — [D-040](0040-telemetry-designed-end-state-native-signal-of-record-tracked.md) stands: topology law 5 forbids committing canonical data, and it collides with the overlay; the digest's own git history is the native substrate, no new artifact). The self-tuning/learning loop (rejected — [Q17](../reference/open-questions.md) stays deferred post-v1; re-weighting from a single project's observed usage over-fits and over-weights the contagious core, [§12](../principles.md)). Statistical retirement (rejected — law 2 stands; the trend corroborates, never decides). Editing the judgment-ladder gloss (audits) or any telemetry phrasing (rejected — the architect lens established *"are the signals trending bad?"* is telemetry's correct phrasing, not an audit-law contradiction; touching it would needlessly re-lock telemetry). Re-scoping Change 1 onto telemetry's first/last-seen markers instead of digest history (rejected — the architect lens established the digest is audits-owned and reading one's own prior *observations* at judgment time is a clean different-substrate/purpose read, complementary to, not a duplicate of, telemetry's mechanical trend). Extending the audits never-appears backstage-vocabulary enumeration to the new terms (rejected — the canon forbids banned-word-list growth, [D-225](0225-recenter-the-spec-on-the-ai-is-the-thing-made-trustworthy-re.md)/[D-226](0226-authorize-the-audits-doc-probe-re-litigation-extend-the-oper.md)/[D-227](0227-resolve-the-d-226-audits-re-litigation-landed-text-cold-audi.md); the existing leak-guard is a *category* judgment that already covers "digest history"/"audit-over-audit"/"trend" as backstage vocabulary, and the Change-1 prose requires the over-time finding rendered plainly in the operator-facing digest). Adding a git-history-dependence risk to [risks](../reference/risks.md) (rejected — the degradation is self-disclosing and degradable, not register-worthy; R6 is strengthened, not newly endangered).
