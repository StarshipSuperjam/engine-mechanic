# Correct D-162: S-8 is a build-conformance deviation (fix the build, already done), not a litigation alarm; downgrade the reclustering dry-run output to unverified after ground-truthing

*Decided 2026-06-03 in the design workspace.*

## The decision

[D-162](0162-construction-scaffold-flexibility-for-ai-stepwise-build-fail.md) (relaying the reclustering dry-run's synthesis) mis-framed conformance finding **S-8** as a locked-doc litigation alarm. **Correction:** the locked plan — [policies](../spec/systems/surfaces/policies.md) + [templates](../spec/systems/guardrails/templates.md) + the machine-readable policy-values carrier — *already* requires a governed machine-readable home for the threshold values (slices 12/14 echo it: *"machine-read tuning values … not prose"*). The engine-template slice-14 build shipped a **prose** carrier *in deviation from the plan*; the operator has already remediated it by **converting the values to YAML as the plan defined**. S-8 is therefore a **build-conformance deviation whose fix is to conform the build to the locked plan** — never a plan gap, and the litigation protocol does not apply. The default posture holds: adapt the work to the locked system; a build artifact conforms to the plan, the plan is never bent to match a build mistake. The K1 clustering write-in is **not** gated behind any litigation alarm. **Ground-truthing the rest of the dry-run's headline findings against the locked corpus + this log refuted them:** (a) *"the `operation` frontmatter field set is enumerated nowhere"* is **false** — [operations](../spec/systems/surfaces/operations.md) specifies frontmatter governance, and the field-set-vs-instance question was already settled as the genesis **Q27** over-tagging meta-pattern ([D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md)); (b) *"`/engine-routine` is authored by no slice"* is **false** — it is owned by the **locked** [routine-mode](../spec/modules/routine-mode.md) L2 module ([D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md)/[D-088](0088-justified-re-litigation-name-the-routine-entry-command-engin.md)/[D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md)), built post-`core` and outside this roadmap's `core`-only scope, so slice 26 rightly omits it; (c) the `operation`- and `skill`-grammar slices the dry-run reported as *blocking discoveries* are **already self-flagged** by the roadmap's own *"surfaces that need a grammar slice"* completeness section. The run lacked the **decision-log** and module-order as inputs, and the derivability lens scored against the roadmap's deliberate **pure-pointer** text (non-derivable from itself *by design* — it directs the session to read the locked source in full), so the *"all twelve non-derivable"* headline is largely an **artifact**, not a defect inventory. **Standing:** the three [D-162](0162-construction-scaffold-flexibility-for-ai-stepwise-build-fail.md) scaffold additions (coping-deferral disclosure, dependency preference, grouped fixes) remain valid — operator-approved and independent of the dry-run. The **K1–K12 clustering and any residue from the dry-run are treated as unverified hypotheses**, to be re-vetted finding-by-finding against the locked corpus + decision-log + module-order before any roadmap edit — not relayed or applied. No roadmap clustering was written; no locked doc was touched. `python3 validate.py` green.

## Why

The lock discipline exists precisely to stop "change the locked system to fit what I am doing now," and the S-8 mis-framing inverted it. Relaying a cold-sub-agent synthesis without grounding it against the canonical corpus reproduced the exact over-tagging failure mode the project already caught at [D-123](0123-run-the-l2-dry-run-validators-core-memory-substrate-both-bui.md); the remedy is operator-verified, source-grounded disposition, never workflow output at face value. The two process failures were not seeding the workflow with the decision-log/module-order context a grounded reviewer needs, and relaying rather than verifying.

## What we ruled out

**Re-litigate the locked policies/templates to add a machine-readable carrier** (rejected — the carrier is already required by the plan; the deviation was the build's, already fixed). **Apply the dry-run's fix list to the roadmap** (rejected — its headline findings did not survive ground-truthing; acting on them would encode false gaps). **Edit [D-162](0162-construction-scaffold-flexibility-for-ai-stepwise-build-fail.md) in place** (rejected — the log is append-only; this entry supersedes the mis-framing).
