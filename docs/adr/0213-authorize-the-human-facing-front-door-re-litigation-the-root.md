# Authorize the human-facing front-door re-litigation: the root README as a seeded-then-ceded landing front (engine-template blank-landing-page gap)

*Decided 2026-06-18 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) on explicit operator approval to extend the locked [repository-topology](../spec/systems/infrastructure/repository-topology.md) and [provisioning](../spec/systems/infrastructure/provisioning.md) to give the repo's **root `README.md`** a designed dual life. **The litigation alarm:** the operator, reviewing the engine-template build (mid-M1), observed the engine-template GitHub repo has **no real root README** — its landing page is nearly blank, with no description, banner, or reason a potential adopter would deploy the Engine. Grounding found a real, never-specified gap: the design specifies only the *generated* repo's "project README" as the required-spine **disclosure vehicle** ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md), [D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md); [engine-architecture §3](../architecture.md), [provisioning](../spec/systems/infrastructure/provisioning.md) Gather step) and never the engine-template's **own go-to-market presentation** — and "disclosed in the project README" ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)) names **no writer** for that README. The wrinkle that makes it design, not maintainer copy: the root README is a committed file, so under "Use this template" it **travels** into every generated repo, where [topology](../spec/systems/infrastructure/repository-topology.md) **law 2 reserves the root for the product** — a README that markets the Engine cannot simply sit at the generated repo's root.

  **The decision — frame the root README on the existing seeded-root-file model, no new category.** It is the [D-211](0211-authorize-the-security-floor-re-litigation-add-native-code-s.md)/[D-212](0212-resolve-the-d-211-security-floor-re-litigation-landed-text-c.md) `SECURITY.md` ownership model exactly: **product/operator-owned by default** (the engine never claims it in CODEOWNERS, so law 2's default ownership covers it — no unowned-file hole), **engine-seeded once** at instantiation. Its dual life:
  - *At rest in the template repo* the root README carries the maintainer's **engine-marketing landing page** — engine-authored content occupying a product-owned slot, there to be seen on GitHub and replaced at instantiation (law 2 is not breached: in the template the maintainer owns the root by default).
  - *At first-run instantiation* provisioning's apply phase **replaces the README iff it is still the engine's recognizable marketing landing seed** with a **product-owned starter README** — which is where the writer-less [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) required-spine disclosure is finally written, in plain operator language. The "replace iff it is the marketing seed" predicate generalizes the `SECURITY.md` seed-if-absent rule: a slot holding *the engine's own marketing seed* is free to seed (engine-authored, not operator content), while any **operator-owned** root README — a brownfield product's, or post-seed operator edits — is preserved untouched. So the operation is idempotent (a re-run finds no marketing seed → no-op), brownfield-safe (a product README is not the marketing seed → preserved), and **upgrade-safe (the engine never re-touches the root README after instantiation)**.
  - The seed/replace is **disclosed to the operator at first run** in plain language (the [operator-presentation relay](../reference/glossary.md)) — the visible-file change never surprises them, the same non-weakening posture as the `SECURITY.md` and conduct seeds.

  **Scope of the design vs. the content (per the operator's "mechanism in design, content as task").** This pass specifies only the **mechanism**. The template's actual marketing copy, a banner/logo image, and the engine-template GitHub **description/topics** (settings — they do not travel, [constraints](../reference/constraints.md)) are the operator's (sole-maintainer) **go-to-market task**, drafted with the AI when they choose and **sequencing-gated**: the provisioning replace step must ship before the marketing README lands, or the marketing copy pollutes generated repos.

  **Reshaped by a four-lens cold plan-audit.** The audit's blocking/serious findings reshaped the plan before this entry: the **CODEOWNERS-ownership hole** an earlier "template-distribution artifact" framing risked → resolved by adopting the `SECURITY.md` product-owned-by-default model (no new category, no ontology entry); the **seed-vs-replace imprecision** (an earlier "exactly like SECURITY.md" overclaim) → resolved by the replace-iff-it-is-the-marketing-seed predicate that makes the one new operation idempotent and clobber-safe; the **silent-mutation** trust gap → resolved by the first-run disclosure; and the **propagation** set was completed (the existing [risks](../reference/risks.md) project-README entry reconciled, not merely appended; [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md) left append-only-untouched).

  **Scope. Re-lock set — 2** (both currently locked → re-locked, none added): [repository-topology](../spec/systems/infrastructure/repository-topology.md) (the root README named under the seeded-root-file model — product-owned-by-default, engine-seeded-once, marketing-at-rest) and [provisioning](../spec/systems/infrastructure/provisioning.md) (a root-README seed sub-section paralleling the `SECURITY.md` seed: the first-run replace-iff-marketing-seed, the product-starter content carrying the [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) disclosure, the operator disclosure, the build-spec leaves). **Carriers (non-locked, authored this pass):** [engine-architecture §3](../architecture.md) (the root README seeded/replaced at instantiation), [scenarios/first-run](../architecture.md#first-run-provisioning) (the walkthrough gains the README seed + disclosure), [glossary](../reference/glossary.md) (the landing-front framing of the project README, if warranted), [risks](../reference/risks.md) (reconcile the existing project-README entry; the marketing-pollution-if-the-replace-regresses risk). **Verify-no-edit (confirm at the landed-text audit):** [modules/core](../spec/modules/core.md) (the instantiator-seed enumeration — confirm the README seed is named where the seed list lives; core's foundation-artifact inventory is otherwise untouched), [control-plane](../spec/systems/infrastructure/control-plane.md) (the README is product-owned, not a control-plane artifact), [surfaces/docs](../spec/systems/surfaces/docs.md) (the engine *docs* surface is `.engine/docs/`, distinct from the product root README — its "never claims the product's own root README" line is *honored*, not changed). The re-locks land under the **Resolve** entry ([D-214](0214-resolve-the-d-213-front-door-re-litigation-landed-text-cold.md)) after the mandatory landed-text cold audit.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval. The gap is real and load-bearing for the north star: a non-engineer adopter cannot be *won* by an Engine whose front door is blank, and the design — exhaustively specified for what ships *into* a generated repo — never looked at the template's own front door because that artifact faces outward, before generation. Framing the root README on the **already-locked** `SECURITY.md` seeded-root-file model invents no structure and reuses settled grammar (product-owned-by-default ownership, seed-then-own, brownfield collision, first-run disclosure); the single new operation — replace-iff-marketing-seed — is the minimal extension that lets an engine-authored landing front coexist with law 2's product-owns-root, and its idempotent/clobber-safe predicate is what keeps it from ever touching operator content. Keeping the marketing *content* a maintainer task honors the operator's scope split and the engine/product wall ([§13](../principles.md)): the engine owns the *mechanism* by which the root README transitions to the product; the product (the operator) owns the *words*.

## What we ruled out

**A new "template-distribution artifact" category** (rejected on the plan-audit: it leaves the root README unowned in CODEOWNERS and needs an ontology entry for zero gain; the `SECURITY.md` product-owned-by-default model already fits). **"Replace, exactly like the SECURITY.md seed"** (rejected — `SECURITY.md` is seed-if-absent; an unqualified replace clobbers operator edits on re-run/upgrade; the operation is replace-**iff-it-is-the-marketing-seed**). **A neutral/product-shaped placeholder README in the template** (rejected — it fails the operator's actual complaint; the landing page must be a compelling *Engine* front, which is precisely why it must be replaced at instantiation). **Seeding the marketing copy into the design corpus** (rejected — go-to-market content is the operator/maintainer's, not engine grammar; the corpus specifies the mechanism only). **Authoring the marketing README before the replace step ships** (rejected — sequencing hazard: the marketing copy would travel and land as every generated repo's product README). **Editing [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) to name the README writer** (rejected — the decision log is append-only; the writer is specified now in the landed provisioning text and recorded here). **Silent seed/replace** (rejected — a visible-file change gets a plain-language first-run disclosure, the `SECURITY.md` / conduct-seed precedent).
