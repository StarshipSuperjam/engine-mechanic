# Litigate engine-template #446: incremental consolidation — the boot-time consolidation **sweep** recovers an idle session's un-reflected tail. Re-litigate the locked [memory](../spec/systems/cognitive/memory.md) durability law: the sweep predicate moves from "no consolidation marker" to "genuine conversation **beyond the last marker's watermark**", and the marker form moves from a binary done-flag to a per-session **high-water-mark** — re-lock of memory lands under [D-308](0308-resolve-re-lock-memory-incremental-consolidation-the-waterma.md)

*Decided 2026-07-12 in the design workspace.*

## The decision

A build session opened engine-labeled [engine-template #446](https://github.com/StarshipSuperjam/engine-template/issues/446) and raised the **litigation alarm** (CLAUDE.md §103–107) rather than papering over it. **The residual (the one honest gap disclosed on merged [PR #443](https://github.com/StarshipSuperjam/engine-template/pull/443) / #396 Sub-PR 2):** a session left **running-but-idle** long enough to be tidied mid-run — its liveness lease aged past the small cushion (N=3) while it took no turns — has its **later half never summarized into recall**. The boot-time consolidation **sweep** computes `pending = have − marked` and never re-tidies an already-marked session, so a single early marker permanently excludes the tail. **Content is never lost** (raw turn-deltas are always ledger-resident); only the **reflection** for that later half is skipped — a **recall-quality** gap over a **content-safe** residual, spec-tolerated today by the memory durability note. **The fix (incremental consolidation)** lets the sweep re-tidy a marked session that carries raw notes past its last summary. **This entry is the litigation alarm + operator authorization** (the #446 alarm set the governance parameter "re-open the locked doc first" and the mechanism "an explicit note counter, not the marker's coarse wall-clock `ts`"; direction re-confirmed in-session over `ExitPlanMode` before any locked-doc edit) **and the design of record.** Only [memory](../spec/systems/cognitive/memory.md) is edited; its re-lock lands under **[D-308](0308-resolve-re-lock-memory-incremental-consolidation-the-waterma.md)** after the mandatory landed-text cold audit; it is **edited-but-not-relocked** until then (the [D-296](0296-litigate-engine-template-427-residual-three-l1-l2-l3-audits.md)/[D-298](0298-litigate-the-deployment-eadr-collision-the-operator-s-per-in.md) authorize→resolve pattern; `validate.py` flags its fingerprint until the re-lock).

## Why

the fix invents no new grammar — it reuses the ledger's `seq` (a per-message ordinal already assigned at capture and already the sort key `read_deltas` returns), the existing single-writer flock discipline, and the existing store-time re-check, turning the binary done-flag into a high-water-mark. The **`seq` watermark over the cheaper marker-`ts`-vs-delta-`ts` comparison** (which the built `earned_consolidated_raw` already uses as a "consolidated up to here" boundary) is justified: wall-clock `ts` is coarse — clock skew and same-second ties defer a note's reflection — whereas `seq` is monotonic per session and aligns with the read sort key (the operator's chosen mechanism, feasibility-confirmed buildable). This closes the idle-session gap **without** raising N (which would reintroduce the "sat untidied for ages" passivity the module exists to kill; N is deliberately 3). Framed honestly as a **convenience over the standing recoverable-content guarantee, not a new guarantee** — the operator's real trust anchors (content never lost; capture independent of graceful close) were already whole.

## What we ruled out

**Raise N (the lease cushion)** (rejected — reintroduces the passivity the module exists to kill; N is deliberately small). **Reuse the marker `ts` as the watermark boundary** (rejected — coarse; clock skew and same-second ties defer a note's reflection). **Build now and let the deliverable gate confirm** (rejected — touches the pinned marker form; the litigation alarm is the correct route). **Do nothing / accept the residual** (legitimate — a minor content-safe gap, no urgency — but the operator elected to close it and the fix is clean). **Advance the watermark only past deltas that yielded a record** (rejected — a genuine-but-un-summarizable tail would then re-fire every boot forever; advancement must be examination-based). **Take the *last-appended* marker's watermark** (rejected — non-monotonic under a revival race; the effective watermark is the MAX across markers). **Delete the residual disclosure as fully closed** (rejected — the gap is narrowed-and-deferred, not eliminated; deleting would over-claim completeness, an [§7](../principles.md) defect).

## Further record

### Why this is a law change, not a build-conformance leaf-fill

(the non-engineer-operator lens's crux challenge, answered): the locked predicate's conjunct *"…and has **no consolidation marker** (no lease heartbeat)"* ([memory](../spec/systems/cognitive/memory.md):78) **actively forecloses** re-tidying a marked session — it is load-bearing in the built code (`store_episodic` re-checks `if session_id in marked: return already-consolidated`), not a mere under-implementation of a broader law. And the marker **form** is **pinned** at wbs/dry-run-ledger.md:381 (M2 — *the form is pinned; only the liveness-detection detail is a leaf*). Both pinned pieces must move, so the litigation route is required, not avoidable.

### The amendment (design of record)

(1) **Sweep predicate** → the sweep fires over a non-live session that *carries genuine, un-consolidated conversation **beyond its last consolidation marker's watermark*** (the never-consolidated session is the watermark-at-zero case). (2) **Marker form** → a per-session **high-water-mark** (*summarized through message N*), not a binary flag; multiple markers per session are tolerated (already true in code — orphan retirement keys on the global `batch` id, never one-marker-per-session). The **effective watermark is the MAX across a session's markers** (monotonic — a slow sweep finishing after the session revived-and-self-consolidated can never regress it). (3) **Termination stays structural** — each pass **advances the watermark past every delta it examined**, not only those that yielded an episodic record, so a genuine-but-un-summarizable tail (consolidation is a non-deterministic LLM step that may emit no record) and a purely harness-injected tail both advance the watermark and never re-fire — preserving the §93–95 "the sweep does not loop on it" invariant that the old binary marker guaranteed. (4) **Concurrency** — the store-time re-check generalizes from *"session already marked?"* to *"watermark already covers my span?"*, evaluated under the held ledger lock, so a second boot that consolidated the same span in parallel aborts as a duplicate (the LLM step runs unlocked; the re-check + append run locked). (5) **Compaction carry** — the per-session watermark joins the [memory](../spec/systems/cognitive/memory.md) Compaction §Layer-1 carried-state list (tier / retirement-pending / gist↔raw link): Layer-1 folds the per-session markers into a single current-state MAX-watermark field carried in the ledger, never only in the throwaway index (else a compaction resets watermarks to zero and re-consolidates the whole store — the #446 disease at ledger scale). (6) **Honesty** — incremental consolidation **narrows-and-defers** the residual, it does not eliminate it (a still-live idle session, or one just abandoned, carries an un-reflected tail until a later session boots and sweeps it; during a partial window the `[0,W]` episodic record stands in only for the consolidated-through portion), so the durability note's disclosure is **rewritten to its new true bound — "reflection is deferred to a later session, never lost; content is immediately safe and recoverable" — never deleted and never over-claimed as "no reflection is ever skipped."** The concrete watermark **representation** (`through_seq`) is a build-spec leaf, named in memory's own *Build-spec leaves* section.

### #446 premise corrections (both surfaced by the plan-stage cold audit, recorded per [§7](../principles.md)/[§17](../principles.md) honesty)

(a) the issue body's premise *"the marker already records the point it summarized up to"* is **false** — the built `consolidated` marker records only a wall-clock `ts`, no note counter (which is precisely why the marker-**form** change is required, not optional); (b) the #446 alarm's claim that the fix *"closes the disclosed-residual entry"* in [risks.md](../reference/risks.md) is a **no-op** — grep-confirmed there is **no** `risks.md` entry for this residual; it lives in the memory durability note + PR #443. Neither correction changes the ruling.
