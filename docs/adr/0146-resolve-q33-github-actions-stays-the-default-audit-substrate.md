# Resolve Q33: GitHub Actions stays the default audit substrate, with a delivery-layer reframe and Cloud Routines as a documented option (no locked-doc edit)

*Decided 2026-05-30 in the design workspace.*

## The decision

Resolve [Q33](../reference/open-questions.md) → the recurring self-audit keeps **GitHub Actions as the present-by-default substrate** (the committed `.github/workflows/` `audit-prep` cron — the locked framing), the substrate is made **swappable at the delivery layer**, and an Anthropic **Cloud Routine** is offered as a documented operator option. **No locked-doc edit and no litigation alarm:** because GitHub Actions remains the canonical/default substrate, every locked audit-substrate statement stays true — verified by read across all seven: [audits](../spec/systems/guardrails/audits.md) cadence (the 60-day auto-disable + `gh workflow enable` describe the default), [validation](../spec/systems/guardrails/validation.md) `audit-prep` ("a scheduled (cron) workflow"), [agents](../spec/systems/surfaces/agents.md) (the `--agent` top-level session), [control-plane](../spec/systems/infrastructure/control-plane.md) scheduled-work (the audits system "lands the workflow"), [core](../spec/modules/core.md):68 ("and cron"), [modes](../spec/systems/lifecycle/modes.md):19-22 ("scheduled read-only work runs as GitHub Actions cron, not a Claude session stance" — true for the default, and a Cloud Routine is likewise not a *local* stance, so the fourth-cell-empty argument holds), and [build-orchestration](../spec/systems/lifecycle/build-orchestration.md):287 (Routine *builds* use Local Desktop, "not the cloud Routines product" — true; the read-only audit tolerates a fresh clone where a stateful, scope-locked build cannot). **The reframe is delivery-layer:** the locked digest + the digest-staleness boot signal already key on the committed digest run-date, not on any runner, so the substrate is swappable without touching locked grammar; a future default-switch to Cloud Routines would be a then-justified single-doc decision, never a multi-doc re-litigation. **The substantive work landed in the `designed` [audit-library](../spec/modules/audit-library.md) doc:** the GitHub-Actions realization is pinned (`-p/--print` for the TTY-less runner; `--agent audit` as the top-level session; `CLAUDE_CODE_OAUTH_TOKEN` via `claude setup-token` — a one-year subscription token, no metered key — as the non-engineer default, with the `ANTHROPIC_API_KEY` alternative and the 2026-06-15 Agent-SDK-credit note); the Cloud-Routine option carries a choice-eliminating operator walkthrough (Remote-not-Local, recurring-not-one-off, the right repo, the verbatim persona-loading prompt, a "did it arm?" confirmation) with the paid-plan + Claude-Code-on-web precondition, the research-preview caveat, and the daily cap disclosed plainly; the **local-memory coverage limit** of any cloud/CI substrate (the gitignored ledger is absent from a committed-files-only run) is bridged by a **pure read of memory's existing [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) backup repo** (no memory-side change) with an **honest in-digest disclosure** when no backup is configured; and an [R14](../reference/risks.md)-style un-exercised-at-v1 disclosure. **Propagation:** [risks.md](../reference/risks.md) gains **[R17](../reference/risks.md)** (the optional Cloud-Routine substrate rides a research preview; the default does not, so no core mechanism depends on it); [Q33](../reference/open-questions.md) deleted from open-questions.md (resolution captured here); this entry. **Reviewed, no edit owed (logged no-touch):** [glossary.md](../reference/glossary.md) (the *Audit digest* / *Agent (persona)* / *Derived roster* / *Audit persona* cron/`--agent` terms all stay true under the GitHub-Actions default; "Cloud Routine" is a module-delivery option, not a glossary term), [memory](../spec/systems/cognitive/memory.md) (the backup read is a pure consumer of the existing [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) artifact and widens nothing — the [§16](../principles.md) consume-never-widen discipline), [engine-architecture.md](../architecture.md), [modules/README.md](../reference/module-catalog.md) (catalog row + dependency graph unchanged), [constraints.md](../reference/constraints.md):22 (GitHub Actions remains "the host for periodic audits"), and the seven locked audit-substrate docs above. **This supersedes [D-133](0133-type-the-cron-fired-audit-persona-re-litigate-agents-role-tr.md)'s substrate *assumption* only where it framed the audit purely as a GitHub-Actions cron** — the `audit` role, no-lens, read-only, `output-contract`, and `--agent` top-level-session semantics D-133 settled are unchanged; only "the substrate is swappable, GitHub Actions is the default not the sole option" is added, at the delivery layer. `python3 validate.py` green (lock fingerprints unchanged — the alarm stayed down).

## Why

The operator's initial Q33 choice — Cloud Routines as the *sole* substrate — was put through the mandatory four-lens cold audit, which found it **under-propagated and trust-eroding**: it would re-litigate six locked docs (audits, validation, agents, control-plane, core, **modes**) plus a build-orchestration reconciliation and living `constraints.md`; it created a **"never-armed" silent gap** (a Cloud Routine has no committed correlate, so an operator who never sets one up is silently un-audited with no staleness baseline — violating the *Forgotten setup* quality scenario); it made the audit's **headline "stale memory beliefs" check dark-by-default** on a fresh clone; it put a **core trust mechanism on a research preview**; and it **invalidated audit-library's GitHub-Actions-substrate dry-run precondition**. Re-presented with that evidence, the operator chose the audit's own recommended resolution. Keeping GitHub Actions as the present-by-default substrate keeps every locked statement true (no re-litigation), arms the audit automatically (no silent never-armed gap), and keeps the single-flight concurrency law a live consumer; the durable decoupling win is captured at the delivery layer (the runner-independent staleness backstop + the swappable-substrate documentation); and Cloud Routines is offered as the Claude-native, subscription, laptop-closed *option* the operator valued, without betting a core mechanism on a preview. The burden sat on the current work to fit the locked grammar (lock discipline), which under the GitHub-Actions default it does.

## What we ruled out

**Adopt Cloud Routines as the sole audit substrate** (the operator's initial choice) — rejected on the four-lens cold audit for the reasons above (a six-locked-doc re-litigation, the never-armed silent gap against the *Forgotten setup* scenario, the dark-by-default memory promise, a core mechanism on a preview, an invalidated dry-run); the audit's own recommendation was the design adopted here. **Surgically re-litigate the locked audits/validation/agents grammar now to make the substrate explicitly agnostic** — rejected for v1: a three-locked-doc re-litigation for a decoupling whose practical benefit is already delivered by the runner-independent staleness backstop + the delivery-layer documentation; the explicit-grammar reframe is available later as a small, separately-approvable add-on if a default-switch is ever made. **Use a metered `ANTHROPIC_API_KEY` as the default CI auth** — rejected: it imposes a per-token API account and cost on a non-engineer; the subscription `CLAUDE_CODE_OAUTH_TOKEN` (one `claude setup-token` step) is the non-engineer default, the API key only the alternative. **Disclose the memory-coverage gap without bridging it** — rejected as the sole answer: it undercuts the audit's headline promise by default; the [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) backup read gives full coverage where a backup exists (pure-read, no memory change), with disclosure as the honest fallback when it does not. **Edit a locked doc to mark the substrate change** — rejected: GitHub Actions stays the default, so every locked statement stays true; editing one would be an unjustified re-litigation. **Leave Q33 open** — rejected: the decision is settled and audit-library is now lock-eligible.
