# Authorize flipping the memory-backup default to a shared vault: re-litigate locked [memory](../spec/systems/cognitive/memory.md) D-061 (overturns its shared-as-default anti-choice; re-weighs [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md))

*Decided 2026-06-22 in the design workspace.*

## The decision

Authorize re-opening the locked [memory](../spec/systems/cognitive/memory.md) doc to **flip the backup default** from one-repo-per-project to a **single shared cross-project memory vault**, with a **per-project repo offered at every new project's setup**. The operator runs many projects, and the per-repo default scales friction onto a non-engineer (N consent moments, N private repos to track, N privacy re-checks, N audit-access grants); one vault set up once and reused is the ergonomic fit, and the per-project escape stays one step away for a project that warrants it. This is **default + disclosure + a namespace-identity tightening, not a mechanism redesign**: the export/copy/replace-and-rebuild path, the snapshot manifest, branch-per-namespace concurrency, and the **memory-owns / provisioning-consumes seam** ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)) are unchanged. **Five edits land in the one doc that asserts the default** (a corpus grep confirms it is the only living assertion): **(1)** flip the default to the shared vault, a per-project repo the alternative offered at every setup; **(2)** a **namespace-identity law** — a namespace is a **minted, collision-free, rename-stable, content-free id carried in the committed destination pointer**, bound by backup/restore instead of a runtime-derived name, so a shared store cannot mis-route project A's memory into B's namespace or restore the wrong one (representation a build-spec leaf, mirroring the existing minted stable-record-id); **(3)** floor **(1)** presents the shared-vs-per-repo choice at **every new project's setup** with a **plain-language disclosure** of the trade-off and **why** one would pick per-repo; **(4)** floor **(2)** makes the committed backup README **multi-project-framed** for a shared vault and redirects the dangerous delete-a-folder instinct; **(5)** floor **(3)** offers a **brand-new project reuse of the operator's existing vault** (provisioning selects + writes the pointer; **no new cross-instance discovery mechanism** added to memory). The privacy bullet states honestly that under the shared default the periodic re-check is **more** load-bearing — it detects, it does not prevent — so the **per-project escape, not the re-check**, is the structural bound on the enlarged flip blast radius. **No other locked doc is in the blast radius:** the [memory-substrate module](../spec/modules/memory-substrate-sqlite-fts5.md) asserts per-project *namespacing* + "a private repo" (both true under a vault), and [provisioning](../spec/systems/infrastructure/provisioning.md)'s `:766` leaf lists the shared-vs-per-project choice but is **silent on the default** (the new content rides as a memory floor it consumes) — both stay **unedited**; [risks](../reference/risks.md) R2, [glossary](../reference/glossary.md), wbs, `scenarios/`, and [engine-architecture](../architecture.md) are mode-agnostic and stay unedited (touching any signals over-scope). The plan-stage cold review (adversarial · non-engineer-operator · architect, no shared context) ran against the **bare** flip and the operator weighed its central finding before approving the refined shape; the **four-lens cold audit** (adding technical-feasibility) re-runs against the **landed** remediated text before the re-lock, and **D-238** resolves with the relock (`lock.py --relock`). The engine-template build session is already implementing shared-default; this entry is the **design-side ratification** it aligns to (build-owe filed/cited at D-238).

## Why

This clears the justified-re-litigation bar: not a design weakened to fit current work, but a default re-fit to the operator's real workflow that **directly engages — does not paper over — D-061's recorded grounds**. [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)'s anti-choice rejected shared-as-default because "a shared vault co-locates many projects' memory under one credential against [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)'s leakage concern." That concern is **accepted with eyes open, not dismissed**: **(a)** the canonical store stays the **local gitignored ledger** — [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)'s core (memory is never committed) is untouched; only the off-repo *backup* co-locates, which [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) already permitted as an opt-in; **(b)** the honest scorecard is that for a sole operator the **same single `gh` credential reads every per-repo backup too**, so per-repo never bought read-isolation — its real residual edge is a smaller accidental-public-flip / credential-compromise / erasure unit, *structural* rather than control-dependent; **(c)** the operator, who owns the account and the risk, judged the one-vault ergonomics worth that enlarged unit, and the per-project escape preserves the structural bound for any project that warrants it. The cold review's **central correction is folded into the law**: the periodic privacy re-check is the *same* control in both topologies, so it cannot offset shared's larger blast radius — the doc now says so plainly and names the **per-project escape** (not the re-check) as the bound, honoring [principle §7](../principles.md)'s "do not pretend reporting is remediation." The **mis-routing** failure mode the review surfaced (a shared store promotes namespacing from a free 1:1 repo binding into a load-bearing correctness key) is closed **structurally** by the minted namespace-id, not by disclosure. One ergonomic that also improves and is recorded honestly: a **single audit-access grant** instead of N — though that one grant now exposes every co-located namespace, itself disclosed, with the per-project escape keeping a sensitive project out of it.

## What we ruled out

Keep per-repo the default and only lower the shared opt-in's friction (rejected — the operator runs many projects and wants one consistent default, not a per-project opt-in they must re-pick and might inconsistently click through into a fragmented split across both topologies; the safer-default principle is in part a protect-the-naive-user argument the north star discounts for a capable operator knowingly accepting risk on their **own** account). Treat the flip as a UX-leaf change ridable on provisioning's shared-vs-per-project leaf (rejected — that leaf was delegated the *UX of a choice whose safe default was already fixed* by [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md); flipping the default is a locked-law change, not a leaf). Add an auto-discovery / vault-registry / standing-operator-config so a new project finds the vault automatically (rejected — a new cross-instance mechanism memory would have to own and **widen**, against the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) seam; reuse is realized at the provisioning UX layer writing the existing committed pointer, and any auto-discovery is a separate decision). Build cross-store migration — move a project between shared and per-repo *after* setup — into this change (rejected — out of scope; the choice is made at each new project's setup, and re-peeling later is a separate decision if the operator wants it). Fold the authorize and resolve into one entry (rejected — the authorize/resolve split is the litigation-protocol convention, [D-233](0233-authorize-the-audit-over-audit-re-litigation-feed-the-period.md)/[D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md), [D-235](0235-authorize-the-engine-issue-conformance-reroute-gate-promote.md)/[D-236](0236-resolve-the-d-235-engine-issue-conformance-reroute-gate-land.md)).
