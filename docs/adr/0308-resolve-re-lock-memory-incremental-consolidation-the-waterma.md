## Further record

### Landed-text audit outcome — the two convergent SERIOUS wording findings folded before the re-lock

**(1, adversarial)** the store's double-consolidation guard was first written as a *coverage* test (*"does the watermark already cover this span?"*), which leaves a **prefix** exposed in the contemplated boot-sweep-vs-revived-live-consolidation race (each reads a different span end; the whole-span guard passes and a `[w0,5]` prefix is re-consolidated) → reworded to a **residual recompute under the lock**: a store consolidates only the residual beyond the current effective watermark and appends record+marker in the same held section, so neither a concurrent boot nor a revived session's own consolidation can re-consolidate an already-swept prefix. **(2, adversarial + feasibility, convergent)** the marker was defined as *"summarized through"* but each pass **advances past every delta it examined** — two different watermarks — and *"never stays un-reflected"* over-claimed against the conceded *"consolidation may emit no record"* (a genuine-but-unsummarizable turn is examined but yields no episodic record) → the marker is now *"**swept through** (examined)"*, the bound is *"no genuine later-half is left **un-swept**"* (never "un-reflected"/"complete"), and the injected-tail termination is attributed to its true code cause — **harness-injected deltas are neither fuel nor a pending-detection trigger, so such a session is never pending** — not to the watermark covering injected `seq`s (feasibility ground-truthed that `read_deltas` skips injected records, so "examined" is genuine-only and the watermark never advances over an injected tail). **Feasibility NIT folded:** the Build-spec-leaves illustration names the **existing per-message `seq`** reused as the `through_seq` high-water mark (not a new parallel counter).

### Two operator SERIOUS findings — rejected with rationale (logged, not folded)

**(a)** the deferred-tail window (a just-idled, not-yet-reswept session whose `[0,W]` record covers only its consolidated portion) was said to lack the explicit "disclosed, never silent" floor its recall-exclusion sibling carries — **rejected:** the un-consolidated tail is recall-excluded exactly as *every* un-consolidated ambient delta already is (the standing "capture fuel, not recall content" property), it is transient (closes at the next boot's sweep), content-safe (raw resident and recoverable), and it rides the **standing recall-completeness content floor** ([D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md) — verbatim kept and recoverable at the point of consumption); the law already names the partial window honestly ("stands in only for the portion it covers"), so no **new** per-recall operator floor is owed at the memory-law altitude. **(b)** there is no operator-weighable correlate that a deferred tail was *reflected* — **rejected as not owed:** incremental consolidation is a **convenience over the standing recoverable-content guarantee, not a new guarantee** (D-307 Rationale), and content-safety already carries its correlate (the operator can always request the verbatim); minting a new "caught-up earlier sessions" attestation would be [R6](../reference/risks.md) over-build for a content-safe convenience. §12 leak-guard confirmed clean in the landed text (watermark/`seq`/sweep confined to the maintainer layer; the operator-facing disclosure stays plain and the exact wording is a boot/audits build-spec leaf — a build-owe reminder, below).
