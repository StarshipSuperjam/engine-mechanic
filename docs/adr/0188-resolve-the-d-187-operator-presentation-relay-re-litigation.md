# Resolve the D-187 operator-presentation relay re-litigation: landed-text cold audit, five docs re-locked

*Decided 2026-06-08 in the design workspace.*

## The decision

The [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with four independent no-shared-context lenses (adversarial · architect · non-engineer-operator · technical-feasibility) on the as-written edits to [boot](../spec/systems/lifecycle/boot.md), [modes](../spec/systems/lifecycle/modes.md), [close](../spec/systems/lifecycle/close.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [modules/core](../spec/modules/core.md) plus the non-locked carriers ([constraints](../reference/constraints.md), [glossary](../reference/glossary.md), [risks](../reference/risks.md) [R19](../reference/risks.md)). **Outcome: no surviving blocking/serious *design* findings; three precision folds applied before re-lock; two adversarial "blocking" calls rejected as over-reads / out-of-scope.** Re-lock set: **5**.

  **The audit + dispositions.**
  - **Architect — PASS (no blocking/serious).** Propagation complete per the matrix; the convention is defined **once** (glossary) + the quirk **once** (constraints), **referenced** (never restated) by the five producers; all relative link paths (`../../../glossary.md` from `systems/lifecycle/*`, `../../glossary.md` from `modules/core`) and intra-glossary anchors resolve; the **verified-no-edit** set confirmed sound against the as-written text — [hooks](../spec/systems/infrastructure/hooks.md) ("a guardrail only an AI reads is advisory theatre" already routes operator-visibility via the PR Validation section + boot relay), [control-plane](../spec/systems/infrastructure/control-plane.md) ("the operator sees each session whether the gate is on" is *realized* by the relay, not falsified), [telemetry](../spec/systems/guardrails/telemetry.md) (same), [engine-architecture](../architecture.md) (push framed "in front of the model" — truthful index), attention, scenarios; the model-auto status verb satisfies the locked skills "few, sharply-described" rule (one model-auto verb, schema-described, listed in `/engine-help`).
  - **Non-engineer-operator — one serious, folded.** The present-marker floor copy was an absence-leaning check → rewritten **presence-first with a concrete example** (`Project status: all clear` / `⚠ Protected branch is off`) so a non-engineer recognizes the block rather than inferring its lack; the honest-tier merge-wall framing and status-verb discoverability passed clean.
  - **Adversarial — two serious folded, two "blocking" rejected.** Folded: (1) the glossary present-marker definition fore-grounded the block's *content* over its *presence* → reordered to lead with **presence as the binary check**; (2) the glossary status-verb said "model-auto … when the operator asks," narrowing it toward operator-typed semantics → broadened to true model-auto (the model may load it on a relevance match, not only an explicit ask), matching the [modules/core](../spec/modules/core.md) wording. **Rejected:** the constraints "into the model's context" phrasing (clear as written — the lens's own analysis conceded "correct in intent") and the compaction-"not-airtight" vs boot-"always grounds" tension (pre-existing, not introduced here, and not a contradiction — "always grounds at the floor" is the design intent, "substantially reliable, not airtight" its honest caveat, consistent with the posture tier).
  - **Technical-feasibility — PASS.** No new unverified platform claim: every channel fact is already in [constraints](../reference/constraints.md) (live-verified + #17356/#50542); "model-auto = operator-typeable AND model-invocable" is stated correctly; "the AI renders a named block first every session" is a sound behavioral spec carried by the always-loaded floor, correctly framed as posture, not a platform guarantee. Build-spec re-verify leaves recorded ([R19](../reference/risks.md)): `additionalContext` reaches the model on the current version; `systemMessage`/`permissionDecisionReason`/stderr remain non-delivering.

  **Folds applied before re-lock** (one in boot, two in glossary): the boot present-marker copy (presence-first + example); the glossary present-marker definition (presence-as-the-check); the glossary status-verb invocation (true model-auto).

  **Re-lock set (5):** [boot](../spec/systems/lifecycle/boot.md), [modes](../spec/systems/lifecycle/modes.md), [close](../spec/systems/lifecycle/close.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [modules/core](../spec/modules/core.md). **Re-lock:** `python3 lock.py --relock` run on all five under this decision; `python3 validate.py` green. **Non-locked carriers edited:** [constraints](../reference/constraints.md) (the version-contingent quirk), [glossary](../reference/glossary.md) (operator-presentation relay + imperative relay marker + status verb), [risks](../reference/risks.md) ([R19](../reference/risks.md)). **No [open-questions.md](../reference/open-questions.md) opened/resolved** ([Q18](../reference/open-questions.md) unchanged — the relay *reduces* per-session push volume rather than worsening habituation); **no [deviations](../reference/prototype-deviations.md) entry.** The engine-template **#83** build realization (reframe the boot pack AI-facing; the imperative markers; the model-auto status verb; the present-marker relay; the per-surface relays; the venv-race fix) is a downstream follow-up filed against the build, not authored here.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran (four lenses), the architect + technical lenses passed, and the three precision folds (non-engineer copy, two glossary tightenings) were applied in the as-written text before re-lock. The re-lock set held at the [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)-scoped **5** — the audit confirmed the verified-no-edit set genuinely holds (no producer re-defines the convention; the "operator sees" claims are realized by the relay), so no further doc was drawn in. The design is faithful to [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md): the quirk version-contingent in constraints, the convention once in glossary, AI-facing reframe + imperative markers + push/pull + the named-first present-marker, posture honestly tiered with the merge wall the backstop.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Treat the adversarial "blocking" calls as blocking** (rejected — ground-truthed as an over-read on clear text and a pre-existing non-contradiction out of this litigation's scope; logged, not silently dropped). **Fix the absence-leaning present-marker by tightening only the law** (rejected — the law was already a presence check; the *copy* a non-engineer reads needed the presence-first example, so the illustrative build-spec-leaf copy was improved in place). **Draw control-plane/telemetry into the re-lock for their "operator sees" wording** (rejected — the relay *realizes* those claims; editing them would duplicate the convention and expand the lock set with no truth gain).
