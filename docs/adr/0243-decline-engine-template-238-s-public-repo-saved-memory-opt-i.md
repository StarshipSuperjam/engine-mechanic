# Decline engine-template #238's public-repo saved-memory opt-in: the thin public review is a build under-delivery, not a design gap — enrich the existing aggregate staleness review + offer the operator's own levers (no locked re-litigation)

*Decided 2026-06-23 in the design workspace.*

## The decision

engine-template #238 asked to relax the [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) audit-digest privacy bound — the structural withhold of saved-memory belief *specifics* from the committed digest on a **public** project repo — into a **default-off, per-public-project, informed-consent opt-in** that would let the operator turn on naming the specifics. **Declined.** A **plan-stage three-lens cold review** (adversarial · non-engineer-operator · architect, no shared context) of the proposed relaxation, **weighed by the operator from their own seat**, converged against it, and the operator chose instead to **enrich the existing safe review and offer their own levers** — keeping the structural gate. The real gap #238 reacted to is a **build under-delivery, not a design gap**: [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) already fixes the public path as "reviewing saved-memory staleness **only in the aggregate** it can safely commit," and the [audits](../spec/systems/guardrails/audits.md) digest contract already requires the digest name "what is recommended, **in terms the operator can act on**" ([§7](../principles.md): no dead-end reporting) — but the build (engine-template PR #236) shipped a **dead-end** (it reports only that memory exists and its count, withholds, and stops; no staleness analysis, no follow-up). The fix is therefore a **build-owe that realizes the existing locked design faithfully**, with **no locked-doc edit**: on a public repo the scheduled review **(a)** reports a **substantive aggregate staleness finding** — the *count* of saved decisions that look stale, not merely that memory exists — names withheld; and **(b)** is **actionable, never a dead-end** — it points the operator to the **exposure-free in-session named review** (the engine reviews the operator's own local gitignored ledger in an ordinary interactive session — ephemeral, no vault read, nothing committed) and to the **private-repo / per-project-vault** escape ([audit-library](../spec/modules/audit-library.md) already names the per-project repo as the escape). The structural belief-specifics withhold from the **committed** public digest stands unchanged. **Build approach (a build-spec leaf):** the persona judges staleness with the beliefs in-run (ephemeral) but, on a public repo, emits only the aggregate count + the lever-offer, with the existing repo-visibility structural gate (`_project_repo_is_private()`, the audit-digest generator) the backstop that strips any specifics that slip. Filed as the engine-template #238 build-owe (against the #224/#236 lineage) citing this decision. **`python3 validate.py` green — no locked-doc fingerprint moves (the only design artifact is this append-only entry).**

## Why

The cold review did exactly its job — it caught that #238 as framed was the wrong shape *and* that its premise was false, before any locked re-litigation. **(non-engineer-operator, blocking)** a non-engineer cannot give *weighable* consent to **irreversible public exposure** — "permanent in git history / forks / caches, un-unpublishable" has **no behavioral correlate** the operator can run and feel ([§17](../principles.md)'s bound), so a one-time consent screen is a nominal waiver against an **unbounded future stream** of digests; and the engine already refuses this shape for even *reversible-feeling* memory **erasure**, which it gates on a **per-instance merged single-purpose PR**, never a standing setting ([memory](../spec/systems/cognitive/memory.md)). **(adversarial, blocking)** the standing flag has **no legal config home** — it is an **action/privacy flag**, which [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)'s policy-override lane excludes ("tunable values only, never enforcement/action config") and which [D-239](0239-reject-an-engine-owned-git-hygiene-reconciler-accumulated-lo.md) already rejected as a class; a flag committed to a *public* repo is itself a **leak beacon** and is **flippable by any write-capable actor** (the structural gate, template-owned machinery, is not); and the faithful realization of the security-floor **disclose-and-offer** pattern is to **offer the operator the lever they already control** (keep the project private; use a per-project private vault), not to build a new engine-owned lever that weakens the bound in place. **(architect)** confirmed the policy-override exclusion and that the standing flag would balloon the blast radius across [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)/[D-239](0239-reject-an-engine-owned-git-hygiene-reconciler-accumulated-lo.md)/topology/[R31](../reference/risks.md). The operator lens also corrected #238's premise: the safe path is **not** a dead check — it is *designed* to review staleness in the aggregate; the dissatisfaction traced to the **build** doing less than the design requires. Option A serves the genuine need — a useful public-repo staleness check **and** a path to the named specifics — with **zero irreversible exposure**, faithful to the engine's safe-default + disclose-and-offer posture and to the north star (the named review happens where it is exposure-free, neither behind a paternalistic block nor behind an un-weighable waiver).

## What we ruled out

Build #238's **standing default-off opt-in flag** (rejected — the cold-review grounds: irreversible exposure is not weighable by a one-time toggle; no legal config home; public beacon / write-actor-forgeable; against the per-instance erasure-PR precedent). The **per-instance publish opt-in** (Option B — let the operator approve each public digest that would name specifics, the erasure-PR shape): **deferred, not built** — it is the only *weighable* form if naming specifics in the committed public artifact is ever truly wanted, but it still incurs irreversible exposure and the exposure-free in-session named review serves the realistic need, so it is held as a separately-scoped item to revisit only on a demonstrated gap. A **private-repo opt-out** (suppress specifics on a private repo too): out of scope — the operator scoped this to the public case, and it would re-open the [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)/[D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) private-default reasoning. **Re-litigate [audits](../spec/systems/guardrails/audits.md)/[audit-library](../spec/modules/audit-library.md) to make the substantive-aggregate and lever-offer floors explicit** (rejected — the existing locked design already requires both: the aggregate-staleness phrasing and the digest "act on" contract + [§7](../principles.md); making implicit-but-present requirements explicit is not a change the *current work requires*, and a second same-session re-lock of just-locked docs is the unjustified churn lock discipline guards against — the build-owe spec and the audit's own "act on" self-check are the enforcement; available as a justified pass later if the implicit floor proves insufficient in practice). Do nothing / leave #238 open as filed (rejected — it would leave a standing relaxation request implying the engine might still build the flag; the operator made the call).
