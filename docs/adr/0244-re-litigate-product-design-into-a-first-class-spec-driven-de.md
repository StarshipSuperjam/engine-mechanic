# Re-litigate `product-design` into a first-class spec-driven-design system; re-scope the engine/product wall on the mechanical-FORM-validation vs semantic-audit seam (authorization + design; re-locks land under the per-carrier resolve entries)

*Decided 2026-06-23 in the design workspace.*

## The decision

engine-template #237 paused the [product-design](../spec/modules/product-design.md) build (Slice 1) and routed a re-litigation here: the operator — the non-engineer sole maintainer — holds the **locked** product-design design ([D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md); resting on [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md)/[D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)/[D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)) a *watered-down bolt-on* against the spec-driven-design (SDD) system this very workspace uses to design the Engine. **This entry is the litigation alarm + operator authorization** (given across a full design session) **and the design of record**; the **re-locks land under per-carrier resolve entries** (D-245…D-250) after each carrier's mandatory **landed-text cold audit** — the [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)→[D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md) / [D-241](0241-authorize-completing-the-audit-s-off-repo-memory-read-enable.md)→[D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) authorize/resolve pattern. **The shape was cold-audited this session** (five independent lenses — adversarial · technical-feasibility · non-engineer-operator · architect · engine/product-wall, no shared context); its blocking/serious findings are resolved into the design below.

  **The design.** Promote the product **spec + acceptance criteria** from free-prose engine-labeled GitHub **Issues** to a **committed, template-shaped, validated `docs/spec/` tree** in the product tree — joining the arc42 / C4 / ADR / Diátaxis docs the module already authors — with a **`stub → draft → locked`** lifecycle; demote Issues to **derived work-pointers**. Concretely: **(1) Spec corpus** — a `docs/spec/` tree (master/index "coherence ledger" + one conforming doc per capability), authored from a **product-authoring scaffold** (not a catalogued engine-surface template); acceptance criteria as a **criterion → how-verified table** whose verification cells are **typed by who can discharge them** (operator-runnable — a screen, a behavioral demo the operator runs — vs engine/CI-internal), the operator readout never collapsing the two into one "all green" ([§17](../principles.md): structure must not manufacture confidence the verification does not deliver to the operator). **(2) Validation** — **engine-cornered `check` rules** inspecting the product-owned corpus **read-only** (`presence`/`shape` per doc; `coverage`/`coherence` across the tree), the [migration-discipline](../spec/modules/migration-discipline.md) precedent ([D-129](0129-reconcile-dependency-discipline-to-depends-core-l2-the-targe.md)/[D-142](0142-lock-migration-discipline-product-migration-governance-the-s.md): a check targeting product artifacts, read-only, `depends: core`, the removal test *strengthened*); the operator readout states its own bound (form checked, not correctness). **(3) Lock with real gravity, operator-governed** — a `locked` spec is settled don't-churn ground; the gate is the **operator's recorded acceptance**, earned on **validation green + (optional, when [design-review](../spec/modules/design-review.md) is installed) the four lenses *advising* on the spec**; the engine never *vetoes* what the product may become ("only locked specs build" = only **operator-accepted** specs build). Weight is reproduced through native surfaces — the boot-grounding don't-churn norm, a **CI re-acceptance check keyed to the operator's acceptance marker** (self-removing from the required-roster on engine removal), ADR-recorded alarmed re-litigation — **retiring only** the bespoke `lock.py`/`locks.yaml` hand-tooling. **Rigor uniform, ceremony proportionate**: a small single-doc spec locks light; a real product earns the fuller review. **(4) Stub skeleton** — at first engagement the engine **proposes** the full stub map (every obviously-required system as a named slot) for the operator to confirm **at the shape level** before drafting any one, so each piece is drafted with the others' seams in mind (the "21 stubs to lock before coherent" coherence the workspace itself runs on) without making the operator adjudicate 21 systems. **(5) Build legibility** — the locked spec feeds a committed, **living** build-plan that **build-orchestration consumes** to group/sequence into its existing **"the Milestone is the plan"** model ([build-orchestration](../spec/systems/lifecycle/build-orchestration.md):30); the engine emits **native GitHub Milestones** (`gh api`) so a large build reads as ordered phases with progress, not an issue dump; [github-projects-sync](../spec/modules/github-projects-sync.md) enriches when present, native Milestones the floor. **(6) Issues are spec-POINTERS, not substitutes** — each work Issue references its spec doc + the criteria rows it realizes, framed non-authoritative; the build grounds in the **locked spec**. Un-skippability has honest teeth: a **mechanical coverage check** (every locked criterion traced to committed work — CI-gateable, self-removing) **+ `spec-conformance` judged vs the locked spec as posture** surfaced at the operator's merge with gaps dispositioned — **never a required CI gate on an agentic verdict** ([validation](../spec/systems/guardrails/validation.md): "a persona judges, a check gates — never duplicate"). **(7) Anti-churn parity** — anti-choices captured **and presence-validated** in the product ADR stream; re-litigating a locked spec **propagates** (build-plan / milestones / open Issues / dependent specs reconcile — coverage catches orphans mechanically, staleness stays the `spec-conformance` judgment, [§7](../principles.md)-honest); a per-milestone **build-readiness** gate before a phase starts.

  **Surgical supersessions** (only the named clause moves; the rest of each decision STANDS): **[D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md)** — "design product-intake **native**, not bundled" STANDS; **spec-home = GitHub Issues superseded** (→ committed `docs/spec/` corpus; native `gh` Issues remain for the *derived work* Issues). **[D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)** — the **referent-producer** role + the falsifiable producer↔roster separation STAND; **"spec-in-Issues" + "the Issue is the hand-off seam" superseded** (Issue = derived pointer; the committed locked spec is the referent). **[D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)** — the **4+4 roster + falsifiable separation test** STAND; **ADDED** design-review's **optional advisory** spec-lock invocation (referent = the spec) when installed (no hard product-design→design-review edge, so the separation holds); `spec-conformance`'s referent becomes the committed locked spec. **[D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)** — **free-prose acceptance criteria superseded** (→ structured criterion→how-verified table); the **operator-surface / no-framework-vocabulary** rules ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)) STAND, **re-discharged** across every new operator surface (spec docs, validation readout, status field, milestone names, how-verified cells, ADR if shown). **[D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md) / [R9](../reference/risks.md)** — the engine/product **wall STANDS**; scope **clarified**: the engine MECHANICALLY validates spec **FORM** (the read-only, removal-safe, migration-discipline-shaped checks) — distinct from the **SEMANTIC** cold-context quality audit, which **stays off product artifacts**. **[R9](../reference/risks.md) edited** to this clarified state.

  **Phase-0 adjudications (no edit owed — recorded here, architect-confirmed):** **no new surface / no new ontology** — the design composes existing surfaces (spec docs + build-plan = [docs](../spec/systems/surfaces/docs.md); spec checks = [check](../spec/systems/surfaces/check.md); advisory lenses = [agents](../spec/systems/surfaces/agents.md)); the `stub→draft→locked` ladder is the **product spec's own** maturity (product-layer, like the product's own ADR numbering), not an engine [ontology](../spec/systems/grammar/ontology.md) lifecycle vocabulary — confirmed exactly as [D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)/[D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) did. Spec checks ride the migration-discipline model → **`depends: core`** (product-targeting checks depend `core`, not [validators-core](../spec/modules/validators-core.md) — no WBS re-sort). So **[templates](../spec/systems/guardrails/templates.md), [validation](../spec/systems/guardrails/validation.md), [ontology](../spec/systems/grammar/ontology.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md) (the wall), [migration-discipline](../spec/modules/migration-discipline.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [github-projects-sync](../spec/modules/github-projects-sync.md) take no re-lock** (the spec template is product-authoring scaffold, not a catalogued engine-surface template; the checks are an additive module-provided `check` rule).

  **Carriers + sequence** (each locked re-lock under its own resolve entry, after its landed-text cold audit, in dependency order — upstream systems first, the module last): [state](../spec/systems/cognitive/state.md) (D-245), [control-plane](../spec/systems/infrastructure/control-plane.md) (D-246), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (D-247), [qa-review](../spec/modules/qa-review.md) (D-248), [design-review](../spec/modules/design-review.md) (D-249), [product-design](../spec/modules/product-design.md) (D-250); then non-locked propagation ([glossary](../reference/glossary.md), [modules/README](../reference/module-catalog.md), [engine-architecture](../architecture.md), [scenarios/product-design-intake](../architecture.md#product-design-intake), wbs). **In this entry's pass only [R9](../reference/risks.md) is edited** (non-locked); no locked fingerprint moves. The build resumes in engine-template #237 against the re-locked design.

## Why

The operator's objection is correct and goes to the north star: the burden of proof is on the engine, and a non-engineer cannot weigh free prose — so free-prose acceptance criteria ([D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)) put the burden on the operator backwards. A **conforming, validated** spec is the confidence surface ([D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md)'s premise that free prose is "lowest-ceremony, trust-safe for the non-engineer" is refuted by the non-engineer it is about), and the Engine already owns the grammar to author and check it ([templates](../spec/systems/guardrails/templates.md) + [validation](../spec/systems/guardrails/validation.md) + [check](../spec/systems/surfaces/check.md) + the [migration-discipline](../spec/modules/migration-discipline.md) product-targeting precedent), so a structured spec corpus is **reuse of locked substrate, not a bolt-on**. The five-lens shape audit affirmed the thesis and corrected three load-bearing moves now reflected in the design: a required mechanical conformance gate is infeasible *and* breaches the wall (it makes merging product changes depend on engine machinery and revives the [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) close-friction spiral [D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)'s anti-choice rejected) → **coverage-teeth + conformance-as-posture**; gating the lock on the engine's lenses is the [R9](../reference/risks.md) semantic-audit-on-product breach → **lenses advise, the operator accepts**; the milestone scheme collided with locked [state](../spec/systems/cognitive/state.md)/[build-orchestration](../spec/systems/lifecycle/build-orchestration.md) → **build-orchestration produces, the build-plan feeds it**. The wall re-scope is justified because mechanical FORM-validation of a product-owned, read-only-inspected corpus is the already-locked [migration-discipline](../spec/modules/migration-discipline.md) shape ([D-142](0142-lock-migration-discipline-product-migration-governance-the-s.md): removal test *strengthened*), genuinely distinct from the SEMANTIC audit [R9](../reference/risks.md) keeps off product artifacts — the clarification *narrows* [R9](../reference/risks.md)'s "no validation" to "no semantic audit," it does not breach the wall. Authorize-now / resolve-per-carrier keeps each irreversible re-lock behind its own landed-text audit, the [D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md)/[D-241](0241-authorize-completing-the-audit-s-off-repo-memory-read-enable.md) precedent.

## What we ruled out

**Keep the spec in free-prose Issues** (the [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md)/[D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)/[D-141](0141-lock-product-design-the-design-front-door-the-fifth-module-l.md) status quo) — rejected (issue #237: no committed/structured/validated home, no confidence surface for a non-engineer, Issues misused as the spec rather than as derived work). **Make `spec-conformance` a required pre-merge gate** — rejected (three lenses: an agentic verdict is not a mechanical CI status, it breaches the wall by coupling product merges to engine machinery, and it revives the [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) spiral; the realizable un-skippability is coverage-teeth + posture + the informed merge). **Gate the lock on the engine's lens verdict** — rejected ([R9](../reference/risks.md) semantic-audit-on-product breach, and it would couple the lens suite to product-design's lifecycle against [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)'s separation; the lenses advise, the operator governs). **Clone the full lock apparatus** (`lock.py`/`locks.yaml`/manual fingerprints/the hand-walked matrix) onto the product — rejected (heavy hand-tooling; the *gravity* is reproduced natively, only the bookkeeping dropped) — but **dropping the gravity entirely** also rejected (the operator's load-bearing point: a toothless flip is ignored by future sessions). **Uniform ceremony** — rejected (uniform *rigor* is right; uniform *friction* strands small-but-real work — ceremony scales, weight does not). **Have the build-plan author milestones directly** — rejected (collides with locked [state](../spec/systems/cognitive/state.md) "build-orchestration owns none of it" + [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) "the Milestone is the plan"; the build-plan is a consumed input). **Re-lock [templates](../spec/systems/guardrails/templates.md)/[validation](../spec/systems/guardrails/validation.md)/[ontology](../spec/systems/grammar/ontology.md) for the spec corpus** — rejected (the [migration-discipline](../spec/modules/migration-discipline.md) precedent + the no-new-surface adjudication mean the checks and scaffold need no engine-surface re-scope). **Batch all re-locks under one entry/audit** (the [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) shape) — rejected for this scope (six substantial, dependency-ordered carriers across systems and modules warrant per-carrier landed-text audits and resolve entries; the [D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md) batch fit a tighter coupled set).
