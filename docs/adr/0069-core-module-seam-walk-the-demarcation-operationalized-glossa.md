# Core/module seam-walk: the demarcation operationalized (glossary), the v1 sort confirmed

*Decided 2026-05-26 in the design workspace.*

## The decision

Complete the core/module boundary seam-walk. **(1) The v1 sort is confirmed clean** — a cold-context pass across all nine system seams found the core/module line already correctly drawn: the only seams that expose a *slot* for optional *fillings* are [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (the gates take review-lens fillings) and [memory](../spec/systems/cognitive/memory.md)/[interfaces](../spec/systems/surfaces/interfaces.md) (the `search`/retrieval interface takes a semantic-recall filling); audits, telemetry, modes, close, knowledge, and provisioning are pure core with no fillings. The other v1 modules ([product-design](../spec/modules/product-design.md), [dependency-discipline](../spec/modules/dependency-discipline.md), [migration-discipline](../spec/modules/migration-discipline.md), [github-projects-sync](../spec/modules/github-projects-sync.md)) are **standalone** optional capabilities that fill no core slot. No system doc requires editing. **(2) The demarcation is operationalized, not re-legislated** — what is core vs a module is already governed by [§12](../principles.md) (contagious-by-nature; a candidate is core unless it can be an extension) + [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) (core is always-on and off the install menu); the operational *test* is "**remove every module — what survives is core, what disappears is a module**." **No new principle:** minting one (the proposed §16) would restate §12 with a defining clause ("no-op when unfilled") true only for the two *fillable* seams — a false genus (cold-audit BLOCKING). **(3) Two clarifications land as glossary terms** — **Slot** (the *fillable* subset of core that accepts a filling and runs as a disclosed no-op when unfilled) and **Filling** (a module that fills a slot, discovered by presence per [§14](../principles.md); a *subset* of modules — standalone modules fill no slot) — framed as *consuming* §14's discovery axis and *operationalizing* §12's floor, never amending either (the [D-064](0064-lock-the-interfaces-surface-final-wave-2-lock-single-active.md) refine-don't-amend precedent). The **self-host-MVP caveat** (a filling the operator always installs stays a filling; operator selection never redefines core) lands in the Filling term. **(4) The audit asymmetry is intentional** — a core slot may ship its v1 filling as core/always-on (self-checkups, `audit-library`, [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)) or accept operator-selected fillings (review lenses); "always-on vs operator-chosen" is decided per slot by §12 + [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md) (cross-cutting + no-overlap), not by the slot/filling vocabulary. **(5) Operator disclosure:** Slot/Filling are maintainer-layer vocabulary — the [§12](../principles.md) leak guard applies; operator-facing disclosure of always-on core states, in plain language, *what it does and why it cannot be disabled*, never "slot"/"filling" (a forward requirement for the [Q4](../reference/open-questions.md) disclosure wording).

## Why

The seam-walk had two jobs — sort the behaviors (drain latent expectations that, un-stated, ripple from a module conversation into core, the SDD failure) and codify a durable, testable demarcation. A cold pass found the sort already clean (the recent [D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)/[D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)/[D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md) decisions plus the locked cognitive docs drew every line), so the residual was the rule. A four-lens cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) against the plan caught that the proposed peer principle §16 was a false genus restating §12 and re-narrating §14's discovery-by-presence; the disciplined fix is to operationalize the existing law (a glossary test + two terms) rather than mint a contradictory peer principle — the [D-064](0064-lock-the-interfaces-surface-final-wave-2-lock-single-active.md) precedent (refine doc-locally, consume the cited principle, never amend the closed-law layer). Remaining audit findings folded: the §14 "consumes-not-amends" framing is in the terms; Filling⊂Module is stated so "core" keeps one definition; the leak guard and the always-on-core "why" disclosure are required at the operator surface.

## What we ruled out

Mint a peer principle §16 (rejected by the cold audit — its "no-op when unfilled" clause fits only 2 of 8 seams, a false genus, and it restates §12 while re-narrating §14; minting it invites a second, partially-contradictory core/module law). Refine [§12](../principles.md) in place (rejected for this pass — the genuinely-new content is two glossary clarifications plus a test, not a change to §12's containment law; an additive glossary capture is lower blast radius — the operator's call). Re-sort the seams / edit system docs (rejected — a cold pass found the sort already drawn; no doc needs reconciliation, and the locked exemplars must not be touched for cosmetics, which would trip the litigation alarm). Read the slot/filling vocabulary onto operator surfaces (rejected — maintainer-layer; the [§12](../principles.md) leak guard forbids it). Imply all modules are fillings (rejected — only lenses + semantic-recall fill a slot; the standalone modules fill none, so Filling is a strict subset of Module).
