# Lock the `tools` surface (Wave 1)

*Decided 2026-05-25 in the design workspace.*

## The decision

Ratify and lock [tools](../spec/systems/surfaces/tools.md) to its designed end-state: the **code surface** — the engine's executable machinery (the [validation](../spec/systems/guardrails/validation.md) thin dispatcher + its check-kind callables, hook scripts, MCP server code, the [module-system](../spec/systems/grammar/module-system.md) wiring library, and the implementations behind [interfaces](../spec/systems/surfaces/interfaces.md)), all under `.engine/tools/`. Class `code`, so the meta-contract's `governing_schema` and `template` fields are the **sanctioned empty case** (code is governed by tests and [checks](../spec/systems/surfaces/check.md), including the post-install coherence kind, not by a schema or a prose-shape rule). A Wave-1 advance. The lone `designed`-neighbor seam — how an interface implementation binds and how a default/fallback is chosen — stays a **pure deferral** to the `designed` [interfaces](../spec/systems/surfaces/interfaces.md) surface per [D-053](0053-procedural-surfaces-reconciled-to-the-merged-claude-code-ski.md), so a future interfaces lock cannot force a tools change; `tool` fixes only that those implementations are engine code under `.engine/tools/`. The `core`-package `provides`-owner mapping for the surface definition stays the [D-054](0054-lock-the-operations-and-docs-surfaces-wave-1-partial.md) deferred-forward obligation (modules/core is a stub; not asserted present-tense). Two pre-lock nits applied: the MCP reference aligned to the locked `${CLAUDE_PROJECT_DIR:-.}` form ([D-028](0028-module-system-locked-end-state-as-laws-not-leaves.md)), and the governance sentence softened so it does not over-imply a non-engineer can judge code correctness (the change stays *visible in PR review*; the operator-communication law). Catalog membership is additive — **no ontology re-lock** ([D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)).

## Why

Wave 1 is the unblocked head of the [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) lock-order runway (the Q10 gate blocks only *cognitive* locks), and `tools` anchors entirely on **locked** grammar (ontology class `code`, [topology](../spec/systems/infrastructure/repository-topology.md) `.engine/tools/` code-home, validation/check governance, module-system wiring-library home), so it is safe to lock now and is independent of `agents` (the two surfaces never reference each other). The cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran four lenses — adversarial / technical-feasibility / non-engineer-operator / architect, no shared context — and returned **no blocking or serious findings**: the interface-binding pure-deferral ([D-053](0053-procedural-surfaces-reconciled-to-the-merged-claude-code-ski.md)) and the code-class no-schema/no-template empty case (locked ontology) were both verified, platform facts (hooks/MCP `${CLAUDE_PROJECT_DIR}`, diffable-not-compiled source, the directly-callable post-install coherence kind) confirmed against the locked neighbors. Nits were resolved or declined with rationale: the MCP fallback-form and the review-readability wording were applied; an on-page degradability clause was **declined** as boot/degradation scope rather than code-surface grammar; [R5](../reference/risks.md) (the wiring library) was checked and **stands**; the `glossary.md` `Tool` entry already matched and needed no edit.

## What we ruled out

Batch the tools lock with agents (rejected — the operator chose sequential locks; independent surfaces sharing no seam each get their own audit, decision, and validate pass, the [D-054](0054-lock-the-operations-and-docs-surfaces-wave-1-partial.md) "two independent locks" honesty applied across a reground rather than one pass). Freeze the interface-binding mechanism in the tools doc (rejected — [D-053](0053-procedural-surfaces-reconciled-to-the-merged-claude-code-ski.md) neutralized it to a deferral precisely so the interfaces lock cannot force a tools change). Add a governing schema or template to satisfy the meta-contract (rejected — class `code` is the sanctioned empty case; code is governed by tests and checks). Add an on-page "a down MCP server never strands boot" degradability clause (rejected — it reaches into boot/degradation, another system's scope; the [principle §5](../principles.md) links suffice and the code surface should not over-reach).
