# Authorize the standing-situation-pointer-advance re-litigation: build-orchestration advances the cursor on a merged tracked build (engine-template #100)

*Decided 2026-06-14 in the design workspace.*

## The decision

Authorize a re-litigation editing **two** locked docs ([state](../spec/systems/cognitive/state.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md)) + framing carriers to close the **standing-situation-pointer advance** gap behind engine-template **#100**: the committed status cursor (`.engine/state/state.json`, the `standing_situation` field surfaced as the status card's Milestone/Phase line) goes stale on its own — it is hand-seeded at first-run and hand-edited thereafter, so it still reads `phase: "…(issue #83)"` though builds #74/#79/#80 merged since.

  **The gap (verified, not inferred).** [state](../spec/systems/cognitive/state.md) states the law — *"The standing-situation pointer advances on committed acts. It moves when Build work merges"* — but its "Seams are deferrals" list names every writer/reader (telemetry refreshes the debt count, attention orders, boot reads/surfaces, modes decides stance) **except** who advances the standing-situation pointer: the law has **no owner**. [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) — the producer of the merge — never picks it up: its durable-state set is *"the PR, the build Issue, and memory,"* `state.json` absent, no step writing the cursor. As-built confirms it (the only writer, `telemetry.refresh_state`, touches `integration_debt` and preserves `standing_situation`, with a passing test). #100's premise that the design "hands the job to build-orchestration" is an inference — the actual state is that **neither** doc names the owner. The clean precedent: telemetry writing *its* slice of `state.json` IS named in state's seam list; the standing-situation pointer is the one part of the file with no named writer.

  **The settled design (operator-chosen forks, refined by a four-lens cold plan-audit).**
  - **(1) Derivation — the heart.** The marker is **derived, never hand-typed**: `milestone` ← the build's GitHub **Milestone** (the stable broad context); `phase` ← the build's **build Issue** (the granular track). Honors [§3](../principles.md). The derivation is **well-defined** (exactly one Milestone per build; fail-loud if absent/ambiguous — a build-spec leaf), and the advance commit carries a **plain-language derivation line** so the change is legible in the PR.
  - **(2) Mechanism — a deterministic `tools`-surface helper** that reads `state.json`, modifies **only** `standing_situation`, preserves `integration_debt`, writes back — the exact read-modify-write pattern `telemetry.refresh_state` uses and tests. The orchestrator calls it while authoring the integrated commits (Integrate). The concrete tool is a build-spec leaf.
  - **(3) When — per tracked build.** The pointer advances when a **tracked Build merges** (one carrying a build Issue / Milestone — build-orchestration's **non-fast-path**). An Explore-only stretch (no commits) and a **trivial fast-path build** (the "no Issue checklist" path) both leave it intact. This **edits state's locked law** from "advances on committed acts" to "advances on a merged **tracked** Build" — an authorized refinement grounded in build-orchestration's existing fast-path boundary (not a vague "trivial"): the cursor is a *standing-situation* pointer, not a commit log, so a one-line typo's subject is noise as "where we stand."
  - **(4) The constraint — rides the PR.** The helper writes `state.json` into the **PR branch** at Integrate; the committed cursor on the **protected branch advances when the PR merges** (no separate post-merge step exists). The committed diff is the review surface.
  - **Honest tier.** The advance step is **posture** (the gate-skeleton tier), but the value is **deterministically derived** and **merge-visible**. A stale/wrong cursor is **not mechanically governance-critical** (cannot breach the protected branch) but **is a trust concern** for a non-engineer — named, not dismissed; and **deriving the value reduces** the "factually-wrong cursor" risk vs. hand-editing (state's existing known-unbounded bound), the residual backstopped by the merge-visible diff + the derivation line.
  - **Operator-facing semantics (a naming, not a redesign).** The committed cursor is the **standing position as of the last merged tracked build** (`milestone` = the stable phase; `phase` = the most-recent track) — the offline **degradation floor**, *not* the live "now / next," which [boot](../spec/systems/lifecycle/boot.md) already assembles from native GitHub sources (state's existing "now and next is surfaced, not stored" law). The card rendering must label this honestly in plain language (no jargon; now/next shown separately) — a **boot build-spec obligation** the existing present-marker law already covers, so **no boot edit/re-lock**.

  **The cold plan-audit (four no-shared-context lenses) and dispositions.** **Technical-feasibility — PASS:** every load-bearing claim verified against the real `telemetry.py`/tests (PR-committed cursor lands at merge with no post-merge step; milestone/phase API-derivable at integrate; read-modify-write preserves disjoint fields; schema gates validity). **Architect — §16 CORRECT, R6-clean, [modules/core](../spec/modules/core.md) NO edit** (core enumerates tools by role, not file). **Folded:** the honest law-coverage edit, the "authored-at-Integrate / lands-at-merge" wording, the concurrent-PR conflict (resolved by **re-derivation** — the cursor is a regenerable derivative, [§2](../principles.md) — never a non-engineer hand-merge), the external-contribution bound (the product cross-fork PR is engine-clean by origin, so the advance does not ride it there), the determinism boundary, and the trust-tier sharpening. **Rejected with rationale:** the adversarial **"§16 reversal" (BLOCKING)** — an over-read that misread the telemetry precedent (state *hosts the file*; the writer *owns the value+mechanism*, exactly parallel), independently contradicted by the architect lens; and the architect's **"edit + re-lock telemetry"** — over-propagation, since §16's payoff is that a disjoint co-writer attaches **additively** without forcing the integrator's doc to change (the co-write safety is named in `state`, the file owner, not by coupling telemetry to build-orchestration). The operator-lens "where-are-we confusion (BLOCKING)" was **downgraded**: the semantics are sound (milestone = stable context; boot assembles live now/next), the fix is the plain-language card-label obligation + the derivation line + the honest trust-tier.

  **Scope.** **Re-lock (locked) — 2:** [state](../spec/systems/cognitive/state.md) (name build-orchestration as the standing-situation-pointer advancer in "Seams are deferrals" + the disjoint-field co-write safety + the "tracked Build" law refinement + affirm the regenerable standing-position floor distinct from boot's now/next), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (the Integrate marker-advance step + the matching design commitment + the build-spec leaves: the tool, the determinism rule, the derivation line). **Edit (non-locked):** [scenarios/build-session](../architecture.md#build-session-lifecycle), [scenarios/routine-session](../architecture.md#routine-session) (Finalize advances once per track), [glossary](../reference/glossary.md) (*standing-situation pointer*, plain language), [risks](../reference/risks.md) (the posture/derived-value residual; the concurrent-conflict residual mitigated by re-derivation; a boot re-derive cross-check noted but **not built**, R6). **Verify-no-edit (logged):** [boot](../spec/systems/lifecycle/boot.md), [close](../spec/systems/lifecycle/close.md), **[telemetry](../spec/systems/guardrails/telemetry.md)** (disjoint co-writer attaches additively), [tools](../spec/systems/surfaces/tools.md)/[schemas](../spec/systems/surfaces/schemas.md), [modules/core](../spec/modules/core.md), [external-contribution](../spec/systems/lifecycle/external-contribution.md) (engine-clean product PR — named bound), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning), [modules/README](../reference/module-catalog.md). The re-locks land under the **resolve** entry ([D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md)) after the mandatory landed-text cold audit (the [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)→[D-190](0190-resolve-the-d-189-operator-checkout-boundary-re-litigation-l.md) pattern). The engine-template **#100** build realization (the advance tool, the runbook step, the plain-language card rendering, and proving it by moving the stale `#83` marker) is a downstream follow-up filed against the build, not authored here.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval ("Issue 100 needs to be relitigated here," naming the locked systems and the gap). The gap is real and verified — a committed cursor the design *says* advances on merge but that no system owns, so it silently rots, eroding the cold-start/trust quality the cursor exists to serve. The fix is **minimal capability** (R6): it adds no new state field (the field exists), no new gate (a step inside Integrate), and one deterministic tool that reuses telemetry's proven read-modify-write shape; the two re-locks are propagation breadth (naming a seam on both sides, symmetric with the existing telemetry seam), not capability breadth. The honest tiers (posture step; derived value reduces but does not eliminate the wrong-cursor risk; the cursor is the offline floor not the live now/next) are named, never over-promised.

## What we ruled out

**Advance on every merged Build PR** (rejected — the operator chose per-track; a trivial fast-path build's subject is noise as a standing-situation pointer, and the cursor is not a commit log). **Edit build-orchestration only, leave state's seam list silent on the writer** (rejected — §16 symmetry and the telemetry precedent require the seam named on the owning side; a half-named seam is the §16 incompleteness). **Edit + re-lock [telemetry](../spec/systems/guardrails/telemetry.md) for the new co-writer** (rejected — §16's additive-attachment payoff: a disjoint co-writer does not force the integrator's doc to change; the co-write safety is named in `state`, the file owner). **A post-merge GitHub Actions step to advance the cursor** (rejected — the constraint is that the update rides inside the work's own PR; a post-merge commit to the protected branch is a separate step that does not exist and would itself be a protected-branch write). **Keep the status quo (hand-set marker)** (rejected — the very rot #100 exists to remove). **Promote the cursor to a richer "what's next" store** (rejected — state forbids a committed work inventory; the live now/next stays boot-assembled from native sources). **Build a boot re-derive cross-check now** (rejected for v1 — real build complexity for a low-probability path the derivation already de-risks; noted as a candidate residual, R6).
