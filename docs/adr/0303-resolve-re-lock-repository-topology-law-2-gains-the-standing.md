topology holds the ownership law the standing touch depends on, so it re-locks first (the propagation-matrix ordering). ## Further record

### The reviewed-PR rework (the audit's headline change)

[D-302](0302-litigate-engine-template-471-design-the-standing-foreign-lic.md) authored the on-consent fix as a boot-time clear "exactly as first run does." The **landed-text feasibility lens found this a BLOCKING infeasibility**: first run's clear is a genesis-time, pre-protection deletion riding the initial commit, but the standing detector runs in a fully-provisioned, **branch-protected** repo where the *committed* `LICENSE` is the harm — and no boot-time write is both durable and protection-compatible (a working-tree delete is non-durable and dirties the checkout, tripping the strand detector's losslessness gate; a direct default-branch commit is rejected by protection or diverges the checkout into a strand). **Resolution folded across all four docs:** on consent the removal lands as a **reviewed pull request the operator merges** — the operator's consent realized as the sanctioned **plan-acceptance Build entry** ([modes](../spec/systems/lifecycle/modes.md)), handing the one-file removal to [build-orchestration](../spec/systems/lifecycle/build-orchestration.md)'s **trivial fast path**; the detector reads the committed `HEAD:LICENSE`, dedupes against an already-open removal PR, and names a bounded local-`HEAD` staleness residual. This diverges from the strand fix (which realigns to already-committed history, needing no new commit) and is why [modules/core](../spec/modules/core.md)'s never-strand generalization was **reverted** (the re-clear is a reviewed-PR commit — *out of the floor's scope*, not a new exception to it).
