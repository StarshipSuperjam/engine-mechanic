  **Faithfulness — CLEAN:** all four [D-275](0275-litigate-engine-template-342-a-checkout-parked-on-a-non-defa.md) laws landed faithfully, authored-complete (no changelog cruft), internally consistent (provisioning keeps "two binary *broken* states"; boot keeps "Five"; glossary preserves "ordinary behind is never alarmed" and mints no new term), links resolve, propagation complete. **Architect/seam — CLEAN:** both structural invariants HOLD (the off-main signal is a new gentle standing detection, **not** a third binary broken state / sixth boot bullet — the widening is a widening); **no hidden re-lock** — [modules/core](../spec/modules/core.md)'s never-strand carve-out is genuinely **class-scoped** ("the operator-consented un-stranding correction … scoped to the working-location/strand class"), so a consented return-to-default branch-switch falls inside it with no text change (the adversarial-S3 "branch-switch is forbidden" concern resolved against the landed text); single-ownership clean (mechanism + cherry read in provisioning, boot relays read-only); scope R6-minimal. **Non-engineer-operator — CLEAN:** every operator-quoted string is git-vocabulary-free, merged/unmerged collapses to one decision with the "nothing deleted" reassurance, the disclosure-gap "earlier sessions couldn't spot this; that's fixed now" framing is bound to the first full relay, consent is felt, ranking is below governance-critical and collapses when unchanged.

  **The SERIOUS finding, folded before re-lock (the [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md) fold-before-relock practice):** **(adversarial+feasibility)** the landed sentence "`git cherry` … **correctly recognizes a squash-merge**" was an **overclaim** — empirically (git 2.50.1) `git cherry <default> <branch>` recognizes a squash only when the branch collapses to a **single equivalent commit**; for the common **multi-commit** PR squashed into one commit, no individual commit's patch-id matches the combined squash, so cherry reports `+`/unmerged exactly like the ancestry checks. The headline contradicted the doc's own "no certain offline merged check" hedge. **Re-framed: `git cherry` catches *more* merges than the ancestry checks (the single-equivalent-commit squash they miss) but cannot certainly recognize a multi-commit squash — there is no certain offline merged check — so the read stays advisory-only.** Critically the lens **confirmed the safety invariant survives the cherry weakness**: cherry's uncertainty is **asymmetric in the safe direction** (it over-reports *unmerged*, never false-*merged*), so a multi-commit squash gets the gentle "I'll keep your unfinished work safe" framing — slightly conservative copy, never a breezy catch-up over real work. This is a **wording fold within the existing advisory-only / errs-gentle law**, no design change and no blast-radius widening; the [D-275](0275-litigate-engine-template-342-a-checkout-parked-on-a-non-defa.md) law (3) phrasing ("only `git cherry` recognizes a squash-merge") is **refined here** to the asymmetric-and-best-effort framing (the append-only [D-275](0275-litigate-engine-template-342-a-checkout-parked-on-a-non-defa.md) text stands; this newer entry is the refinement of record). The other three lenses' **NITs** folded too: boot's "missing work finished since recently" → "the last few weeks of finished work" (a concrete illustrative anchor); provisioning's quoted offer "showing an older version" → "showing an older version of your project"; "squash-aware" → "best-effort and advisory" in the provisioning Design-commitments summary and the glossary term.

  **The adversarial+feasibility lens also re-verified empirically (git 2.50.1):** named-branch return is structurally lossless (the branch ref retains its commits; switching away never orphans them); the clean-tree + in-progress-op (`MERGE_HEAD`/`rebase-merge`/… — confirmed a paused `rebase -i` leaves `status --porcelain` empty, so the in-progress probe is load-bearing) + empty-`stash` predicate is sufficient with **no residual destructive case**; detached/no-remote silence is consistent (off-main stays computable offline with no remote, the behind escalation genuinely uncomputable); `refs/stash` is repo-global while `MERGE_HEAD` is per-worktree (the landed "fails safe" asymmetry is correct).

  **A focused re-check** of the folded cherry sentence (adversarial+feasibility) confirmed the narrowed wording is accurate, reconciles with the build-spec-leaf law and the [D-275](0275-litigate-engine-template-342-a-checkout-parked-on-a-non-defa.md) anti-choice's "no certain offline merged check," and preserves the safe-direction asymmetry. `python3 lock.py --relock systems/infrastructure/provisioning/README.md systems/lifecycle/boot/README.md --decision D-276`; the non-locked propagation ([glossary](../reference/glossary.md) *Stranded checkout*, [risks](../reference/risks.md) R20 mitigation touch) landed under [D-275](0275-litigate-engine-template-342-a-checkout-parked-on-a-non-defa.md); `python3 validate.py` green.
