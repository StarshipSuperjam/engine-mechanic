# Reconcile every designed-module status section to current truth (post-`core`-lock, post-WBS, the dry-run-sweep verdicts)

*Decided 2026-05-29 in the design workspace.*

## The decision

Reconcile the "Status: designed, not locked" sections of all eight designed modules that carried one — [validators-core](../spec/modules/validators-core.md), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md), [routine-mode](../spec/modules/routine-mode.md), [audit-library](../spec/modules/audit-library.md), [external-contribution](../spec/modules/external-contribution.md), [github-projects-sync](../spec/modules/github-projects-sync.md), [migration-discipline](../spec/modules/migration-discipline.md), [dependency-discipline](../spec/modules/dependency-discipline.md) — to current truth. These sections predated three landings and had gone stale: **(a)** `core` is **locked** ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)), so "its dependency `core` is itself only `designed` / locking atop a churning neighbor" (github-projects-sync, migration-discipline) was false; **(b)** the WBS module sort is **authored** ([D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md)), so "the WBS must be authored / locks behind the WBS" (validators-core, memory-substrate, routine-mode, github-projects-sync, migration-discipline) was false; **(c)** the module-by-module build-readiness dry-run ([D-123](0123-run-the-l2-dry-run-validators-core-memory-substrate-both-bui.md)/[D-124](0124-dry-run-the-routine-mode-module-build-step-build-ready-surfa.md)/[D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md)/[D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md)) has **run**, so each section now states its verdict rather than naming a dry-run as a future gate. The uniform current model: `core` locked + WBS authored ⇒ the build-readiness dry-run is the precondition (met or not), and the remaining gate is the fresh cold-session design audit. Applied per module: **build-ready** (validators-core [D-123], memory-substrate [D-123], routine-mode [D-124] with its [D-128](0128-reconcile-routine-mode-s-stance-marker-framing-to-d-088-the.md) remediation noted complete, external-contribution [D-127], migration-discipline [D-127], dependency-discipline [D-127] artifact-axis + [D-129](0129-reconcile-dependency-discipline-to-depends-core-l2-the-targe.md) reconciled) — remaining gate is the cold-session audit; **not build-ready** ([audit-library](../spec/modules/audit-library.md) — the [Q29](../reference/open-questions.md) untypeable audit persona; [github-projects-sync](../spec/modules/github-projects-sync.md) — the [Q28](../reference/open-questions.md) engine-label scheme) — stated honestly as litigation-alarm-gated, the most material fixes since both previously implied readiness (audit-library: "substrate **settled** … ready to lock"; external-contribution: "the one remaining gate is a clean dry-run"). Additionally, [validators-core](../spec/modules/validators-core.md)'s claim that it "waits" until its **dependents** are designed is corrected to the **upstream-first** framing its sibling [memory-substrate](../spec/modules/memory-substrate-sqlite-fts5.md) already states (it locks **before** its dependents settle; they adapt to the floor) — the "atop churning neighbors" rule governs a doc's *dependencies*, not its dependents.

## Why

These are living, current-state documents (the four authoring rules); a status section that still names an authored artifact as a pending gate, or calls a Q29-blocked module "ready to lock," is exactly the staleness the deletion mandate and finding-disposition forbid. The pass was triggered by the [D-128](0128-reconcile-routine-mode-s-stance-marker-framing-to-d-088-the.md)/[D-129](0129-reconcile-dependency-discipline-to-depends-core-l2-the-targe.md) discovery that [D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)'s `core` lock and [D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md)'s WBS authoring were never propagated into the module status sections, and it absorbs the [D-123](0123-run-the-l2-dry-run-validators-core-memory-substrate-both-bui.md) carry-forward nit (status sections should name the build-readiness precondition) for validators-core + memory-substrate. Scope was held to **status sections** — the standing design content of each module is untouched, and no locked doc is edited (the Q28/Q29 remedies remain separate litigation alarms, named here only as the honest blockers). A two-lens cold-context audit (propagation-completeness + faithfulness, no shared session context) verified the reconciliation: every stale claim located and fixed, each per-module verdict checked against its dry-run entry, no new false claim minted, no locked doc touched, and the sections read authored-complete-today. Propagation per the matrix: the eight module docs above; this entry. Verified no-change with rationale: [engine-architecture.md](../architecture.md) (indexes systems not module lock-state), [modules/README.md](../reference/module-catalog.md) (design-maturity / build-readiness is not catalog-tracked), [glossary.md](../reference/glossary.md) (no new term), wbs/README.md (references the instrument's role, unchanged). `python3 validate.py` green; lock-fingerprint integrity confirms no locked doc changed. **Flagged, not done:** [design-review](../spec/modules/design-review.md), [qa-review](../spec/modules/qa-review.md), and [product-design](../spec/modules/product-design.md) carry **no** status section (the first two are build-ready per [D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md); product-design is [Q28](../reference/open-questions.md)-blocked per [D-125](0125-dry-run-the-product-design-module-not-build-ready-a-cross-cu.md)) — a consistency gap, not a stale claim, left for an operator-gated decision on whether to add them.

## What we ruled out

Fix only the literal "WBS must be authored" / "core is only `designed`" claims and leave audit-library's "ready to lock" and external-contribution's "remaining gate is a dry-run" (rejected — those are status staleness too; a partial sweep knowingly leaves false claims, the worse outcome). Reflect the dry-run verdicts in a separate richer pass (rejected — the verdicts *are* the current truth of these sections; reconciling to truth requires them, and external-contribution/audit-library cannot be made true without them). Leave validators-core's "waits for its dependents" framing (rejected — it contradicts the sibling memory-substrate's correct upstream-first statement and is partially stale now that [audit-library](../spec/modules/audit-library.md) is `designed`; reconciled to the established correct framing). Treat the audit-library / github-projects-sync corrections as **litigation alarms** (rejected — they edit the `designed` module docs only; the Q28/Q29 re-litigations of the locked control-plane/agents docs remain separate, un-touched, operator-gated). **Add status sections to the three modules that lack them** (rejected this pass — a missing section is not a stale claim; adding content is scope beyond a staleness sweep, so it is flagged for an operator decision rather than done silently).
