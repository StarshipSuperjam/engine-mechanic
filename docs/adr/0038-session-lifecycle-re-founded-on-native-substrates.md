# Session lifecycle re-founded on native substrates

*Decided 2026-05-24 in the design workspace.*

## The decision

Re-found the engine's session lifecycle on the substrates the platforms already provide — git, GitHub, and Claude Code — keeping bespoke machinery only where nothing native serves. The shape: **(1) Three enforced stances** ([modes](../spec/systems/lifecycle/modes.md)) on two mechanically-real axes (permission posture × attendance): **Explore** (default, interactive, writes gated off), **Build** (interactive, the orchestration), **Routine** (unattended, scope-locked) — no per-session slot, no transition state machine. **(2) Explore is enforced**, not posture: a `PreToolUse` write-gate registered into the [hooks](../spec/systems/infrastructure/hooks.md) block budget (owned by modes per [D-034](0034-re-litigation-hooks-block-budget-example-retargeted-off-the.md)) denies the actions that begin building and allows reads/subagents/`gh issue`; it emits `permissionDecision: deny`; honoring fail-open it is a **strong local default, not an absolute wall** (the merge gate stays the wall). Leaving Explore is a deliberate human act; the session never self-flips; stance, denials, and the entry to Build are operator-legible in plain language. **(3) Boot always grounds** ([boot](../spec/systems/lifecycle/boot.md)): `SessionStart` runs unconditionally so every session — Explore included — starts from a known floor (degradable-up; degradation is loud and consented, never silent). `/start-engine` is dropped (its only job, grounding, is automatic). **(4) Build is a multi-agent orchestration** ([build-orchestration](../spec/systems/lifecycle/build-orchestration.md)): a draft PR is the claim; the work is a planned commit graph; fixed gates run module-supplied cold-context [agent](../spec/systems/surfaces/agents.md) lenses at a depth set in Plan and approved at a mandatory, cost-legible **risk-assessment template** gate; **close = the PR submitted for human review** (no `Stop`-hook close ritual; the per-turn `Stop` keeps only ambient memory capture and the finding-disposition gate). **(5) Core ships the orchestration workflow; agent suites are modules**; the agent **persona template** is the core grammar and rosters are derived from self-declared frontmatter (file-drop, no wiring). **(6) Routine = time-distributed execution of a build's implement phase** on **Local Desktop** routines (Fork 1): commits accumulate on one open PR, an interactive session reviews and closes, routine never merges the protected branch. **Dissolutions:** the `eager-claim` artifact + session-slot numbering → branch + draft PR; the `sessions` active/archive records + leases + wedge detection → git branches + open/merged PRs (plus a Claude-session-id memory boot-sweep for abandoned-delta consolidation); the heavy close ritual → close = PR submitted; `HANDOFF.md`/`next-session.yaml` → GitHub Issues (deferrals) / Milestones (plan) / Projects (board); the `changelog` surface → the structured pull-request body (the locked [control-plane](../spec/systems/infrastructure/control-plane.md) PR contract), which the pull request carries as the durable record. The deletions and the full reference sweep land across the same redesign pass; [D-034](0034-re-litigation-hooks-block-budget-example-retargeted-off-the.md)/[D-035](0035-re-litigation-policies-retargets-the-contract-threshold-narr.md)/[D-036](0036-re-litigation-contracts-retargets-the-default-session-narrat.md) already reconciled the three locked docs ahead of them.

## Why

The prototype's lifecycle was a parallel coordination system layered on git — eager-claim's own record admits git already serializes — and it produced a non-converging **close-friction spiral** (Paideia ADR 0099/0100: eight gate interactions to ship a one-line change; *"the apparatus we built to prevent close-friction is itself a source of close-friction"*). Re-founding on native substrates removes the bespoke commit-shape policing that caused it, while git branches/PRs and GitHub Issues/Milestones/Projects already provide claim, accountability, cross-session continuity, and shared visibility — and in tools a non-engineer can actually use. The migration was already underway in the prototype (HANDOFF→Issues; native Routines over Paperclip); this finishes it. The plan passed a five-lens cold-context audit (direction validated by 3/5); its findings were resolved before landing — the routine-substrate platform fault line settled to Local Desktop, the explore-gate reframed honestly against the fail-open law, a trivial-write fast path added, the worker partial-failure story written, and operator-legibility (visible stance, deny-surfacing, cost estimate, stalled-PR narration) folded in.

## What we ruled out

Keep the prototype's slot / active-record / wedge / lifecycle-push machinery (rejected — it is the close-friction spiral's cause; git already serializes). Collapse to two stances with Explore as a mere phase (rejected — Explore needs an *enforced* default or the AI runs to work; the operator cannot babysit the trigger). Use plan mode as the Explore vehicle (rejected — plan mode pushes toward producing-a-plan and forbids the light bookkeeping, e.g. logging an Issue, that ideation needs). A separate routine lifecycle (rejected — the prototype's five-difference split; the uniform workflow makes routine a constraint-profile, not a second pipeline). Cloud/Remote routines or GitHub Actions as the v1 default (rejected — Remote races the batch branch and forces operator identity; Actions is API-billed; Local Desktop fits the solo subscription, with Actions a documented fork/upgrade). Assert the changelog dissolves into a squash-merged `git log` (rejected — control-plane locks the PR contract, not a merge strategy; the PR body is the durable record). Keep a heavy `Stop` close ritual for completeness guarantees (rejected — it is the friction; ambient capture plus the disposition gate give the guarantees without the ritual).
