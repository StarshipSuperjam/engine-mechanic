# Cut `expression-contracts`; disposition prose (organization covered, internal AI-voice dropped) and re-home the code angle to a future optional `clean-code` module; resolve Q19

*Decided 2026-05-27 in the design workspace.*

## The decision

**Cut** the `expression-contracts` module and **resolve [Q19](../reference/open-questions.md)** in the dedicated design session [D-094](0094-defer-the-expression-contracts-design-to-a-dedicated-session.md) opened. Probing the concept against the canon and the three-tier enforcement landscape (decode-time grammar-constrained decoding / prompt-time injection / lint-in-loop) collapses it. The Engine consumes Claude Code as a black box and never touches the decode loop, so **there is no Tier-1**: any "expression contract" can only be Tier-2 posture or a Tier-3 check, and naming it a "contract" would dress posture as enforced ([§7](../principles.md)). Its three intended output-classes disposition unequally. **(prose — organization)** AI-prose *placement* ("proper home, no junk-drawer") is already governed by the [topology](../spec/systems/infrastructure/repository-topology.md) placement law + [templates](../spec/systems/guardrails/templates.md) structure + [ontology](../spec/systems/grammar/ontology.md) amend-first, and operator-facing prose *voice* by the operator-communication law — no new structure. **(prose — internal AI-to-AI voice)** the tenor of agent finding `message` text and PR-body prose is governed by none of those, but is **dropped for v1** as low-ROI unverifiable posture: its high-value carriers already carry structure/completeness governance (the [agents](../spec/systems/surfaces/agents.md) `output-contract` schema and the [control-plane](../spec/systems/infrastructure/control-plane.md) PR-body contract), so voice/tenor does not earn a surface — revisitable on drift evidence. **(code)** standards-conformance + linting is the only class with checkable payoff and is **re-homed to a future, optional `clean-code` module family** — a parent module injecting per-language standards into the coding/worker [agents](../spec/systems/surfaces/agents.md) plus a commit-boundary linter [check](../spec/systems/surfaces/check.md), extended by per-language packs (e.g. PEP 8/ruff for Python) — **out of v1 build scope**. The `clean-code` slot is catalogued as a `stub` in a new operator-facing **Future optional (post-v1)** subsection of [modules/README.md](../reference/module-catalog.md), destined for the **Verification & Validation** menu on promotion (it governs the operator's own product code — unlike the hidden engine-infra [engine-knowledge-graph](../spec/modules/engine-knowledge-graph.md)). Deferring it is safe by the north-star test: **every realization path it could take is additive within the locked grammar without a refactor** — the reuse path binds check-kinds and agents *by presence* (not a wiring seam) and rides the `pre-commit`/`CI` suites (the commit-boundary linter a local nudge, CI the only unbypassable gate), and the new-surface path is a tier-3 catalog entry the locked ontology lets attach *without a re-lock*. The precise realization (reuse vs. a new tier-3 surface) and the standards-injection seam into worker subagents stay **open design-session threads**, both preserved — not pre-decided. **Operator disclosure obligation:** v1 ships with **no automated code-style/lint floor**; because the operator is a non-engineer and does not review code, the project README's plain-language package disclosure ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)) must state this absence and name `clean-code` as the planned remedy — the design decision to disclose is recorded now, the wording discharged when that surface is built.

## Why

The operator scoped this session to *probe* expression-contracts — find an existing standard to follow before deriving novel structure, and build only where payoff beats overhead. The probe established the no-Tier-1 constraint and that the prose half is either already covered (organization) or unverifiable low-ROI posture (internal voice), leaving code as the only worthwhile class; the operator then directed the pivot to **code only, as a future add-on, not a v1 target**, shaped as a "Clean Code" module + per-language packs. This cut supersedes [D-094](0094-defer-the-expression-contracts-design-to-a-dedicated-session.md)'s "deferred, stays `required`" holding: with the design now done, the prose surface is dropped and the code function is `optional`/post-v1, so the `required` slot is not retained. At the operator's instruction a **two-pass cold multi-lens audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran on the plan before approval; its serious findings were folded — the AI-prose "already covered" overclaim corrected to the dropped-with-rationale framing above, the "needs no new grammar" overclaim replaced by the additive-path argument, the silent-lint-floor gap turned into the disclosure obligation, and `clean-code` committed to the operator-facing menu rather than hidden. Propagation per the matrix: [modules/README.md](../reference/module-catalog.md) (row + edge removed, Future-optional subsection + `clean-code` row added), [modules/core/README.md](../spec/modules/core.md) (carve-out bullet removed; the kernel-partition list and spine stay coherent — they never named it), the `modules/expression-contracts/` stub deleted and [modules/clean-code/README.md](../reference/module-catalog.md) created as its replacement stub, [open-questions.md](../reference/open-questions.md) Q19 deleted, wbs/README.md fully-classified roster sentence reconciled (required roster now five). Verified no-change: [engine-architecture.md](../architecture.md) (no `expression-contracts` reference; indexes via the catalog) and [glossary.md](../reference/glossary.md) (no term was coined; none coined for the deferred `clean-code` stub, matching `engine-knowledge-graph`). No locked doc is edited (`core`/`modules` are `designed`) and no lock is performed, so the cold-audit lock gate correctly does not fire and the change is fully reversible.

## What we ruled out

Build the prose surface anyway (rejected — unverifiable posture; organization is already covered and internal AI-voice is low-ROI, so a surface is R6 cost without payoff). Keep `expression-contracts` as a `required` slot (rejected — its required-ness was asserted over undesigned content per [D-094](0094-defer-the-expression-contracts-design-to-a-dedicated-session.md); the real function is optional and post-v1). Build `clean-code` in v1 (rejected — the operator scoped it future and its ROI does not gate the v1 build topology). Leave only a log note without cataloguing the future slot (rejected — the north star names every module in the end-state catalog; `engine-knowledge-graph` is the precedent for the **stub shape only**, while `clean-code`'s catalog *home* is the operator-facing Future-optional subsection, not the hidden Experimental swap-seam subsection). Log "AI-prose already covered" as the rationale (rejected as the [§7](../principles.md) honesty failure — internal AI-to-AI voice is a real gap, dropped-with-rationale, not covered). Assert "Clean Code needs no new grammar" as settled (rejected — it pre-decides Q19's open realization question; the honest claim is that *every* path is additive within the locked grammar, leaving the choice to the design session).
