# Authorize correcting the falsified Agent-SDK-credit auth claim in locked `audit-library` (engine-template #175): the scheduled-run setup has no monthly credit allowance and no account opt-in

*Decided 2026-06-21 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) editing **one locked doc** — [audit-library](../spec/modules/audit-library.md) ([D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)) — to correct a **false platform detail** baked into its locked auth prose. The change **supersedes only the auth-credit sub-claim** of [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)/[D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md); everything else those decisions settled (GitHub-Actions-default substrate, the Cloud-Routine option, the non-interactive / non-`--bare` / top-level `--agent` / `--model`-pinned grammar, the memory-backup read, the staleness baseline) stands unchanged.

  **The litigation alarm (operator-flagged + empirically falsified).** engine-template **#175** (forward-carry from the deployed-page fix **#179**): the locked module asserts that "*From 2026-06-15 a non-interactive `claude -p` run … draws a **separate, finite, monthly Agent-SDK credit allowance** … gated by a **one-time account opt-in**,*" and builds a two-step operator setup on it (step (a) "*claim the one-time Agent-SDK credit opt-in*"; failure mode "*a skipped opt-in fails the run silently*"; recurring-cost note "*a too-frequent cadence can exhaust the monthly allowance*"). **All of this is false.** The credit-split cutover this prose anticipated never materialized — it was a forward-looking claim the [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) lock-audit "verified" against the docs as they read on **2026-05-30**, 16 days before a cutover that did not happen.

  **Ground-truth (verified this session).** The live [authentication](https://code.claude.com/docs/en/authentication.md) doc: the `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token` is a **one-year** token that **"requires a Pro, Max, Team, or Enterprise plan"** and "authenticates with your Claude subscription" — and it documents **no** Agent-SDK credit allowance, **no** separate/monthly credit pool, and **no** account opt-in/toggle anywhere. Empirically (#175), the real scheduled run on **2026-06-21** authenticated and ran the model on a **Max** token with no toggle ever touched. The deployed setup page was already corrected by **#179** (the trust model values truth over fidelity to a false claim); this re-litigation carries the same correction into canon so the design doc matches reality.

  **The corrected model (lands under [D-230](0230-resolve-the-d-229-audit-auth-correction-landed-text-cold-aud.md) after the mandatory landed-text cold audit).** The auth section keeps its true core — a subscription-funded `CLAUDE_CODE_OAUTH_TOKEN` repository secret, generated once with `claude setup-token` (a browser sign-in), a **one-year** token, **not** a metered `ANTHROPIC_API_KEY`, never `--bare` — and is corrected so that: the token simply **requires a paid plan (Pro/Max/Team/Enterprise)** and draws on that subscription; the **monthly-allowance / one-time-opt-in** sentence is **deleted**; the setup **collapses to one step plus the secret** (`claude setup-token` → add the result as a repository secret named *exactly* `CLAUDE_CODE_OAUTH_TOKEN`), keeping only the **name-typo** silent-fail and dropping the opt-in failure mode; the recurring-cost note is reframed off the false allowance (runs draw on the subscription's normal usage like any other Claude Code work) while the **one-year-expiry → run stops → staleness notice → re-run `setup-token`** recovery path is preserved. No new field, capability, or surface ([R6](../reference/risks.md)) — the change is subtractive (removes a false precondition + a false cost model) plus a one-clause paid-plan truth.

  **Scope. Edit + re-lock (1 locked):** [audit-library](../spec/modules/audit-library.md) (the auth subsection of "The scheduled run — substrate, invocation, and auth"). **Verify-no-edit (to confirm at resolve, re-grepped):** the credit/opt-in terms and `CLAUDE_CODE_OAUTH_TOKEN`/`setup-token` appear in **no** other design doc — not [risks](../reference/risks.md) ([R14](../reference/risks.md)/[R17](../reference/risks.md) name un-exercised-at-v1 and the Cloud-Routine research-preview, not the auth credit), [glossary](../reference/glossary.md), the scenarios/ walkthroughs, [audits](../spec/systems/guardrails/audits.md), [agents](../spec/systems/surfaces/agents.md), or [modules/core](../spec/modules/core.md) — so propagation is contained to this one doc plus the append-only log. **Supersedes** only the [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)/[D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md) auth-credit sub-claim. The deployed correction (#179) and this canon correction discharge **#175**, closed at [D-230](0230-resolve-the-d-229-audit-auth-correction-landed-text-cold-aud.md).

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval (given: the approved plan named this doc + the correction). The locked claim is **empirically false and contradicted by the current docs** — a forward-looking bet that did not land, exactly the failure mode the cold-audit's technical-feasibility lens exists to catch but here certified because the claimed cutover post-dated the lock by 16 days. The correction is minimal and subtractive (no new field/capability/surface, [R6](../reference/risks.md)), removes operator friction (a phantom opt-in step the run never needed), and aligns the canonical design with how the platform actually authenticates a subscription-funded scheduled run. Carrying #179's deployed fix into canon closes the design-vs-reality divergence the forward-carry flagged.

## What we ruled out

**Edit the locked doc silently to match reality** (rejected — the litigation alarm + a logged re-litigation is the only sanctioned path; a silent edit trips the lock fingerprint, by design). **Leave the design doc false and rely on the deployed-page fix alone** (rejected — `engine-planning` is canonical; a generated repo's setup page is overlaid from this spec, so a false canon re-emits the false claim on the next build/upgrade). **Keep the opt-in step "just in case"** (rejected — a phantom precondition the live docs and the empirical run both disprove; a setup step for a toggle that does not exist is friction that fails the operator, not safety). **Reframe the whole substrate** (rejected — only the auth-credit sub-claim is false; the substrate, invocation grammar, Cloud-Routine option, and memory-backup read are all confirmed-true and out of scope, [R6](../reference/risks.md)).
