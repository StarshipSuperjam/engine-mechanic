# Resolve: re-lock `boot` (relay [state](../spec/systems/cognitive/state.md)'s `milestone` selection bound without restating it; the card's rendering law gains the several-open case and loses the "keeps none" mis-render) — a carrier of [D-314](0314-litigate-engine-template-394-attention-s-work-record-commiss.md)/[D-315](0315-amend-d-314-correct-its-operator-authorship-premise-the-buil.md)

*Decided 2026-07-16 in the design workspace.*

## The decision

Re-lock [boot](../spec/systems/lifecycle/boot.md), a carrier of [D-315](0315-amend-d-314-correct-its-operator-authorship-premise-the-buil.md)(3) — the operator-directed expansion of `#394`'s scope to the `active GitHub Milestone` platform defect. **Boot's [D-312](0312-resolve-re-lock-boot-the-recognition-slice-read-with-no-dedu.md) text is otherwise untouched; three sites landed, all on the standing-situation card.** **(1) `:307-310`, the derive** — *"`milestone` from the project's **active** GitHub Milestone"* named a concept GitHub does not have. It now reads *"the open Milestone set that [state](../spec/systems/cognitive/state.md)'s selection bound carries"*, **naming the owner and restating none of the rule** ([§16](../principles.md)) — one, several, or `none set`. **(2) `:464-466`, the design-commitment twin** — the identical claim, in boot's own commitments list. Found by the semantic sweep **after** the lenses had named `:307`; a fix that stopped at the prose would have re-locked boot with its own commitment contradicting it. **(3) `:314-318`, the rendering law** — boot owns the card, so the operator-facing behavior is pinned **here**, not in state: a `none set` `milestone` renders as an honest normal state meaning **no Milestone is open** — *not* the old *"a project that keeps no Milestone"*, a **different predicate** that would tell an operator with three closed Milestones something false — and a **several-open `milestone` renders as the several it is**, named, never silently promoted to a "current" the engine did not elect. `python3 lock.py --relock systems/lifecycle/boot/README.md --decision D-319`.

## Why

(3) is the finding that mattered most and the one the [§16](../principles.md) discipline exists to catch. [D-315](0315-amend-d-314-correct-its-operator-authorship-premise-the-buil.md)'s prescribed text had **state** legislating a render — an inversion — while boot's rendering law is a **closed list**, so a builder implementing the card from boot's own laws would have shipped neither the several-open case nor any disclosure: the rule would have been true in state and absent from the screen. Homing it here makes the operator-facing behavior an obligation of the doc that owns the surface. (2) is the twin-miss class ([D-151](0151-whole-corpus-design-audit-re-litigate-state-af-1-to-fix-the.md)→[D-154](0154-build-ready-capstone-re-run-re-litigate-attention-s4-to-fix.md)) caught for the second time in this pass by a sweep rather than a lens, which is the argument for running both. (1) is a pure relay: boot binds to state's bound by name and holds no copy of it to drift, so if the bound ever changes there is one site to change.

## What we ruled out

**Leave the Milestone defect as pre-existing and out of `#394`'s scope** (rejected by the operator — [state](../spec/systems/cognitive/state.md) re-locks in this pass either way, and shipping a re-lock around a verified-false platform claim is the [R35](../reference/risks.md) defect performed knowingly; boot carries the twin, so fixing state alone would have left the corpus contradicting itself). **Restate the bound in boot** (rejected — two docs asserting one rule is two sites to drift; boot relays, state owns, per [§16](../principles.md). Boot does still assert the *platform fact* alongside state — a knowing, minimal duplication so the relay explains itself). **Keep *"a project that keeps no Milestone"*** (rejected — it is a different predicate from *"none are open"* and renders false for a project whose Milestones are all closed; the drift appeared **inside the same pass that created the bound**, which is why the render law is now stated in the predicate state actually uses). **Defer the several-open render to the build-spec leaf** (rejected — the *wording* is a leaf, but *that the several-open case is rendered as several* is a law: it is the whole operator-facing content of the ruling, and a leaf cannot be relied on to invent it).
