# Product-design front door: design the Q14 intake module as a native, product-layer referent producer

*Decided 2026-05-26 in the design workspace.*

## The decision

Resolve [Q14](../reference/open-questions.md) (the operator has no front door to say *what* to build) by designing a native, optional, product-layer module — [product-design](../spec/modules/product-design.md) — that turns operator intent into a product **specification with acceptance criteria** and native engine-labeled GitHub Issues, and authors the product's own design documentation (product-principles, an arc42 architecture doc, stable-`flowchart` C4 diagrams, an ADR stream under the **product's own** numbering, and a Diátaxis doc tree). It is the producer of the **referent** the review lenses ([D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)) consume. **(1) Native, not bundled** — the methodology is mined from github/spec-kit but the module composes the already-complete surface set (one `operator-typed` [skill](../spec/systems/surfaces/skills.md), the `product-intake` [operation](../spec/systems/surfaces/operations.md), one operator [doc](../spec/systems/surfaces/docs.md)); **no new surface or ontology** ([D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)/[D-055](0055-collapse-command-into-the-skill-surface-invocation-is-a-gove.md)), confirming [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md). **(2) Issue emission is native `gh`**; this **supersedes Q14's "reusing github-collab-bundle / github-projects-sync" phrasing** — those stubs are optional enrichment *when present*, never a hard dependency, so the module **depends only on `core`** and adds no edge to an optional/feature module. **(3) The wall holds** ([§13](../principles.md)/[D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md)): every artifact is product-owned output authored by the Engine as a contributor and lives in the product's own tree; the authoring machinery stays engine-cornered, and CODEOWNERS (file-precise) never claims product docs. **(4) One plain-language front door** — a single `engine-design` verb; the operator describes intent and the engine attaches the framework as an internal label; the five framework names never appear as a menu or as a prompt's working vocabulary ([operator-communication law](../reference/glossary.md)). **(5) Proportionate** — an operator-controlled depth choice that names its consequence, defaulting low; the per-framework authoring procedures are branches within `product-intake`, promoted to standalone operations only on the ≥2-referencer bar ([D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)); a model-invocable slot is not authored on spec. **(6) Degradable** — every step lands as committed files or native Issues; a `gh` pre-check gives one concrete next action on failure and the typed intent is persisted so nothing is lost. The module lands `designed` (not locked). Propagated per the matrix to the [catalog](../reference/module-catalog.md), [engine-architecture.md](../architecture.md), [glossary](../reference/glossary.md), [scenarios](../architecture.md#product-design-intake), [risks](../reference/risks.md) ([R9](../reference/risks.md)), [deviations](../reference/prototype-deviations.md), and [provisioning](../spec/systems/infrastructure/provisioning.md)'s Q14 pointer.

## Why

The north star requires a non-engineer to express *what* to build, and no surface captured it; [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md) already settled "design it native, do not bundle spec-kit," leaving only the *shape*, which this entry fixes. Separating the **referent producer** (this module) from the **review-lens roster** ([D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)) is the load-bearing call: the lenses review *all* build work, not only spec-backed work, so bundling them behind intake would gate general review on a product-layer module — the separation keeps each composable and is provable by the falsifiable test in [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md). A four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md): adversarial / technical-feasibility / non-engineer-operator / architect, no shared context) ran twice against the plan; its blocking/serious findings were resolved before this entry: the self-defeating "no edge to a stub" gate was corrected to "no new hard edge to an *optional/feature* stub" (the universal `→ core` root is the standard deferred-forward edge); the stale "reusing the bundle" phrasing is superseded here; the framework-vocabulary leak into the operator's path was closed (one intent-shaped front door, label-not-menu); the "spec lives in Issues" trust cliff was closed (the flow states where the spec lives and how to reopen it); and the criteria-quality verdict was moved early to intake. Technical-feasibility verified the native-`gh` Issue path, the default-branch `closes #N` caveat, the skills invocation cost, and that `C4Context` is experimental so stable `flowchart` C4 is the durable default.

## What we ruled out

Make product-spec intake an in-orchestration gate (rejected — a spec is authored before any build unit exists; the draft PR is the claim and has nothing to attach to, and a spec gate would duplicate Plan and revive the close-friction spiral [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) dissolved; the Issue is the hand-off seam). Add a spec-reference field or new semantic obligation to the locked control-plane PR contract (rejected — trips the litigation alarm and imposes standing ceremony on every PR; the referent rides the derived lens `output-contract` instead). Hard-depend on the stub github-collab-bundle (rejected — designing a stub's contract from a dependent's pass; `gh` does it natively, the bundle is optional enrichment). Ship two `engine-design*` verbs or a framework menu (rejected — operator-vocabulary leak; one intent-shaped door, labels attached internally). Mint four framework-authoring operations on spec (rejected — R6 anti-sprawl; they are branches within `product-intake` until one earns standalone status). Bundle github/spec-kit (rejected — already [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md): a Python/uv runtime and in-flux command surface that strands a non-engineer). Treat product-intake as out of scope for v1 (rejected — the north star implies the front door).
