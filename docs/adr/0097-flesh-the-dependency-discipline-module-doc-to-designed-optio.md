# Flesh the `dependency-discipline` module doc to `designed`: optional dependency governance as a CI-suite check rule riding the existing required check; review gate hard, pinning soft

*Decided 2026-05-28 in the design workspace.*

## The decision

Take the [`dependency-discipline`](../spec/modules/dependency-discipline.md) module doc from `stub` → `designed` (packaging-view depth, matching the `designed` peers; **not** locked). It is the **optional** Software Configuration Management module ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md)) shipping **domain dependency governance** — version pinning, a dependency-change review gate, and update-cadence posture — *beyond* the control-plane Dependabot floor; `depends: validators-core` because it ships **its own domain check rules on top of** the mechanical self-validation floor that module consolidates (a presence assertion, validators-core transitively bringing `core`); standalone, fills no [Slot](../reference/glossary.md) ([D-069](0069-core-module-seam-walk-the-demarcation-operationalized-glossa.md)). **Two operator decisions settled this session: (1) enforcement** — the security **review gate is `hard` at CI**, **pinning is `soft`-warn** (never blocks; local `pre-commit`/`pre-close` runs nudge, CI is the only gate, [§6](../principles.md)), cadence is **posture**; **(2) gate mechanism (Design A)** — the review gate is a **CI-suite `check` rule that relays GitHub's native dependency-review data, riding the existing ruleset-bound PR-validation check** (no new ruleset binding, no operator-privileged step, no third-party Action), **not** a standalone `.github/workflows/` Dependency Review Action file. Settled points: `provides` = a **posture** dependency-discipline [policy](../spec/systems/surfaces/policies.md) + the **hard** review-gate [check](../spec/systems/surfaces/check.md) rule + the **soft** ecosystem-detected pinning check (disclosed no-op when no manifest) + the read-only detection logic those checks invoke; **`wires: none`**; the **no-overlap axis** (control-plane = mechanical floor / this module = mechanical discipline / the [design-review](../spec/modules/design-review.md)·[qa-review](../spec/modules/qa-review.md) lenses = judgment); **cadence is posture by construction** (no closed-vocabulary seam can edit `dependabot.yml`, the control-plane floor file, [§16](../principles.md)); **operator-trust binding requirements** (a firing hard gate surfaces a plain-language next step + the AI-remediation offer; a per-finding operator-informed **recorded accepted-exception path** so a legitimately-unfixable finding never strands the operator; **setup-time disclosure** that the package can block merges; plain-language messages) — each **relayed** to an existing seam, not re-owned; it **ships read-only domain detection** (unlike validators-core's data-only corpus), never rewriting a lockfile; the [§13](../principles.md) wall holds (optional = consent, read-only inspection, removal test passes).

## Why

A module doc is the packaging view; the depth lives in the locked [check](../spec/systems/surfaces/check.md)/[validation](../spec/systems/guardrails/validation.md)/[policies](../spec/systems/surfaces/policies.md)/[control-plane](../spec/systems/infrastructure/control-plane.md) systems, so the doc maps that machinery → the bundle without restating laws (depth comparable to [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md) — a substantive module owning real enforcement + trust seams). A **four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context, plan inlined) ran **on the plan at the operator's request** — not the lock-gate audit (this pass produces `designed`), but lock-grade rigor. Blocking/serious dispositions: **(convergent BLOCKING, three lenses)** the prior plan's standalone Dependency Review Action *workflow* could not be "hard at CI with no new ruleset binding" — a separate workflow is its own check needing an operator-privileged ruleset bind ([add-a-module](../architecture.md#adding-a-module-to-a-live-repo) names exactly this exception), presence licenses *reporting* not *gating*, and the Action **hard-errors on free private repos** with no git-native floor beneath it; **resolved by Design A** (the operator's choice): a CI-suite check rule relaying the native dependency-review data rides the existing required check, so `wires: none`, file-drop install, no bind, no third-party Action all hold, and the false "three-tier floor that travels" framing is dropped for the honest *full-teeth-where-available / disclosed-no-op-where-not* model. **(operator BLOCKING×2)** a hard gate can strand a non-engineer — resolved by binding the actionable-next-step + AI-remediation + recorded operator-informed accepted-exception path ([Degradability](../reference/goals-and-quality.md)), distinct from a silent pass ([§6](../principles.md)/[§15](../principles.md)), plus setup-time consent disclosure and plain-language messaging. **(serious)** a single policy cannot honestly carry three enforcement tiers → the policy is **posture** and the teeth live in the checks; the security-lens **overlap** with the review roster → the no-overlap axis is stated explicitly; **R12** (a third-party-Action supply-chain surface) → **withdrawn**, dissolved by Design A (native data, no third-party Action shipped to any repo's CI); `add-a-module` propagation → verified (Design A is the *ordinary-add* path, its own-required-workflow exception **not** triggered — the scenario independently confirms the gate rides the existing check); the `depends`/disclosed-no-op-kind realization → stated honestly (the disclosed-no-op biases toward `custom/script` or a kind that can emit a not-applicable finding). Technical-feasibility verified against current GitHub documentation: the dependency-review data is cross-ecosystem and gates the PR diff but requires the dependency graph (+ GitHub Code Security on private repos), with no floor beneath it; the `custom/script` **read-only check-kind** exists and is distinct from the rejected *wiring* escape-hatch; a check joins the required CI gate by self-declaring into the `CI` suite with **no** new ruleset binding. Propagation per the matrix: [modules/dependency-discipline/README.md](../spec/modules/dependency-discipline.md) authored to `designed`; this entry. Verified no-change with rationale: [modules/README.md](../reference/module-catalog.md) (the `dependency-discipline | optional | validators-core` row, the `validators-core → dependency-discipline` edge, the SCM category, and the line-114 scope note — which already names "pinning, cadence, review gates" — all present and correct; design-maturity is not catalog-tracked), [scenarios/add-a-module.md](../architecture.md#adding-a-module-to-a-live-repo) (Design A ships no own required workflow → ordinary-add path; no edit), wbs/README.md (the module sort is unauthored; this pass feeds it and gates the eventual lock, not the `designed` state), [engine-architecture.md](../architecture.md) (indexes via the [D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md) roster sentence; the module's role is unchanged), [glossary.md](../reference/glossary.md) (`Slot`/`Filling` already place it as a standalone module; "review gate"/"cadence"/"pinning" stay descriptive prose, not coined terms — no edit), [deviations/README.md](../reference/prototype-deviations.md) (D24 already `DECIDED` at [D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md)), [risks.md](../reference/risks.md) (no R12 — withdrawn). No locked system doc edited — the design **consumes** the locked check/validation/policies/control-plane/module-system/topology laws and honors control-plane's existing "belongs to its module" deferral, so the litigation alarm and the lock-audit gate correctly do not fire and the change is fully reversible.

## What we ruled out

Ship the review gate as the module's **own required `.github/workflows/` Dependency Review Action workflow** (rejected — per [add-a-module](../architecture.md#adding-a-module-to-a-live-repo) it forces an operator-privileged ruleset bind, adding [R1](../reference/risks.md)-class friction for a non-engineer and a third-party-Action supply-chain surface to every repo's CI; the CI-suite check rule rides the existing required check with no extra step). Frame the gate's degradation as a **"three-tier floor that travels"** mirroring the secret-scan floor (rejected — checkably false: dependency review has **no** git-native fallback; the honest model is full teeth where the data is available and a disclosed no-op where it is not). Carry the three concerns under **one policy enforcement tier** (rejected — [§7](../principles.md) dishonesty; the policy is posture, the teeth are per-check). Make **pinning `hard`** (rejected — the operator chose soft; pinning is hygiene, and a hard pinning gate blocking a non-engineer's own product PR is friction without proportional trust, [§6](../principles.md)). Make the **whole module soft/advisory** (rejected — the operator chose a hard review gate; a security gate on dependency changes is governance-critical). **Edit `dependabot.yml`** for cadence (rejected — no seam reaches it; it is the control-plane floor file). **Register R12** for the supply-chain surface (rejected — Design A ships no third-party Action, so the surface does not exist; registering it would be a phantom risk). Ship **ecosystem-specific pinning gates per language** (rejected — one ecosystem-detected check with a disclosed no-op is cross-project-correct; five brittle gates silently pass on the wrong project type). **Lock** `dependency-discipline` this pass (rejected — the WBS + a fresh cold audit gate the lock, in dependency order after `validators-core`, which is itself only `designed`).
