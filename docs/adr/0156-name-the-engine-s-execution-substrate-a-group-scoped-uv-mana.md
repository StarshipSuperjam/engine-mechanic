# Name the engine's execution substrate: a group-scoped uv-managed Python tool-runtime (reopens build-ready; authorizes an 8-doc re-litigation)

*Decided 2026-05-31 in the design workspace.*

## The decision

The corpus **never named the execution substrate** — what language the engine's executable tools are written in, nor how their runtime dependencies are isolated (`uv`/`pyproject`/`.venv`/PEP 668 appeared zero times) — yet the engine runs **Python on the operator's machine** (the [validation](../spec/systems/guardrails/validation.md) dispatcher, the [boot](../spec/systems/lifecycle/boot.md)/[memory](../spec/systems/cognitive/memory.md) hooks, the [provisioning](../spec/systems/infrastructure/provisioning.md) instantiator + module manager, the MCP substrate servers). Name it explicitly and lock it: the engine's `tool` code ([surfaces/tools](../spec/systems/surfaces/tools.md)) is **Python**, run inside an **engine-namespaced, uv-managed tool-runtime** — committed `.engine/pyproject.toml` + `.engine/uv.lock` (foundation infrastructure artifacts) and a gitignored `.engine/.venv/` materialized by `uv sync`. **uv manages a pinned standalone interpreter itself** (verified against current Astral docs), so the engine neither depends on nor mutates the operator's system Python — the failure mode (global pollution / PEP 668 `externally-managed-environment`) that would strand a non-engineer ([principles §5](../principles.md), QA-7). **uv is auto-bootstrapped on first run behind an operator consent gate** — a **heavier trust class** than the control-plane OAuth grant (a binary install + a PyPI fetch, not a scoped permission), so it installs PATH-independently (`UV_NO_MODIFY_PATH` to a known engine location, invoked by absolute path), its source + version pinned, and it **never degrades to the operator's system Python**. Two crux choices contain the blast radius: **(a)** the lockfiles are **foundation infrastructure artifacts** (the [topology](../spec/systems/infrastructure/repository-topology.md) engine/product-wall set ∪ the [module-system](../spec/systems/grammar/module-system.md) coherence carve-out set — alongside the engine manifest, root `CLAUDE.md`, CODEOWNERS), replaced wholesale on upgrade — **not** a new `dependency` directive in the locked closed-seam vocabulary; **(b)** **group-scoped sync** preserves "installed means present" — `pyproject.toml` declares one dependency-group per dep-carrying module, `uv.lock` resolves the full set for reproducibility, and the module manager runs `uv sync` with the groups **derived** from the installed module set (the check-roster derived-not-wired precedent), so `.engine/.venv/` materializes only selected capabilities' deps and a deselected module ships no live dependency surface. **Scope: the deployed Engine only** — not this planning workspace's own `validate.py`/`lock.py`. **This honors, not reverses, [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md)/[D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md)** (which rejected an *un-managed external Python/uv prerequisite* as a non-engineer stranding risk): the runtime is engine-managed, auto-bootstrapped, and **degrades loud to the git-native [boot](../spec/systems/lifecycle/boot.md) floor** (interpreter-independent) with a non-engineer-recoverable retry path — accepting the named bound that an engine whose runtime never materializes is **inoperable** (§5 honored by floor-orientation + loud disclosure, never a silent or dishonest fallback). **It supersedes the "all-41-locked / corpus-clean" evidentiary leg of [D-155](0155-declare-engine-template-v1-s-design-build-ready-for-the-firs.md):** build-ready is now **provisional**, re-affirmed only after the genesis dry-run re-run. **Authorized propagation — the litigation gate, operator-approved re-litigation of 8 locked foundations**, each edited to final state and re-locked (`lock.py --relock <doc> --decision D-156`) only after its own ≥4-lens cold-session design audit, in seam order: **[tools-surface](../spec/systems/surfaces/tools.md)** (the Python design commitment; the `class: code` meta-contract record fields stay unchanged) → **[repository-topology](../spec/systems/infrastructure/repository-topology.md)** (the `.engine/` tree leaves + foundation-artifact-set membership + a Law-5 corollary; the `.venv/` ignore is a foundation `.gitignore` block applied by the wiring-library **helper** — the CODEOWNERS precedent — **not** the module-owned `gitignore` seam) → **[module-system](../spec/systems/grammar/module-system.md)** (two coherence carve-outs: the foundation `.gitignore` block outside the wiring leg; the lockfiles added to the named foundation-artifact set in the file-ownership leg) → **[provisioning](../spec/systems/infrastructure/provisioning.md)** (group-scoped `uv sync` in apply, before substrate init; the heavier-trust tool-runtime-bootstrap subsection; the §5 floor-degradation + retry recovery; upgrade re-sync ordered between overlay and migrations, with `uv sync` never mutating a data store; build-spec-leaf copy laws) → **[control-plane](../spec/systems/infrastructure/control-plane.md)** (engine CI jobs materialize the runtime before invoking engine Python; the frozen required-check-name binding is unaffected) → **[hooks](../spec/systems/infrastructure/hooks.md)** (invocation form: absolute venv interpreter on hot paths, `uv run` for entry points, platform-agnostic; a missing runtime is the interpreter-absent variant of fail-open-and-flag) → **[validation](../spec/systems/guardrails/validation.md)** (the dispatcher runs identically locally and in CI; CI materializes via `astral-sh/setup-uv` pinned to a commit SHA + `uv sync`) → **[boot](../spec/systems/lifecycle/boot.md)** (a §16 deferred-surfacing of a missing/unhealthy runtime, read-only, below governance-critical alarms). Non-locked propagation: [glossary.md](../reference/glossary.md) (tool-runtime, uv, uv sync, dependency-group), [risks.md](../reference/risks.md) (**R18** — uv-unavailability / network-at-first-run / installer + lockfile supply-chain; partitioned vs [R7](../reference/risks.md) upgrade-time re-materialization, cross-ref [R15](../reference/risks.md)), [constraints.md](../reference/constraints.md) (uv is engine-managed, not an operator chore — honoring "operator cannot debug Python"), wbs/stage-0-harness.md (home the committed seed `pyproject.toml`+`uv.lock` as maintainer-hand-seeded per the §6 engine-manifest precedent; the seed CI workflow's setup-uv + sync + run-validator steps; the runtime added to the §2 seed attestation as a fail-then-pass proof; `.venv/` gitignored from the seed commit; rides R15), wbs/module-order.md (the runtime is a genesis precondition, not a ratchet row; the CI/local→deployed-auto-bootstrap handoff), [scenarios/first-run.md](../architecture.md#first-run-provisioning) (consent gate + sync before substrate init) and [scenarios/upgrade-the-engine.md](../architecture.md#upgrading-the-engine) (the re-sync step), and [engine-architecture.md](../architecture.md) §3 (a one-clause master-index touch at the gitignored-data-doesn't-travel bullet). **No edit owed** to [ontology](../spec/systems/grammar/ontology.md) (infrastructure-artifacts-are-not-surfaces already absorbs it), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (the runtime is invisible at "suite green" altitude; a missing-runtime readout flows through boot), or the module manifest grammar (the module→group mapping is derived, not a field). Re-locks proceed per the approved plan one doc at a time; build-ready is re-affirmed only after the genesis dry-run re-run (wbs/dry-run.md §7) and a clean `python3 validate.py`.

## Why

The execution substrate is foundational grammar — a feature without pre-existing grammar becomes a system refactor ([D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md)) — so it must be named in the design, before the first build PR, not discovered during construction. Python is already the de facto tool language (dispatcher, hooks, memory, provisioning), so naming it is honest where silence left a build-time landmine: the genesis dry-run that fed [D-155](0155-declare-engine-template-v1-s-design-build-ready-for-the-firs.md) silently assumed an ambient interpreter, and a uv-isolated runtime is exactly what keeps a non-engineer off the PEP-668 / global-pollution rocks §5 and QA-7 forbid. uv over stdlib `venv` because uv manages the interpreter version itself, so the engine is self-contained and never depends on or mutates the operator's Python. The change is genuinely cross-cutting (topology, provisioning, the CI harness, hooks, validation, boot), but the foundation-artifact + group-scoped-sync crux contains it to additive, lock-discipline-respecting edits rather than a seam-grammar change. A five-lens cold plan-audit (adversarial, technical-feasibility, non-engineer-operator, architect, genesis/build-readiness) verified the uv facts TRUE against Astral docs, expanded the locked set from 6 to 8, and surfaced the corrections folded in above (gitignore-ownership, group-scoped sync, the §5 reconciliation, the consent-gate trust class, the module-system + control-plane additions, the upgrade re-sync ordering). Reopening build-ready one day after declaring it is the honest cost of a real gap the gates missed; the per-lock audits and the genesis dry-run re-run are what re-earn the verdict.

## What we ruled out

**stdlib `venv` + pip** (rejected — still couples to a correct system Python and cannot manage the interpreter; the operator's machine version becomes a dependency). **Degrade to system Python when uv is absent** (rejected — a [§7](../principles.md) honesty violation reintroducing the exact coupling; the engine instead degrades loud to the boot floor and accepts the named inoperable bound). **A naive single superset `uv sync`** (rejected — installs deselected modules' deps into `.venv/`, a live supply-chain surface violating the locked "installed means present / absent capability carries no defect" law; group-scoped sync fixes it). **Per-module install-time dependency resolution** (rejected — a `uv lock` at every add puts network/resolution failure on the add path; a fully-resolved shipped lock + group-scoped install is reproducible and offline-after-first-sync). **A `dependency` directive in the closed-seam vocabulary** (rejected — re-litigates the locked [module-system](../spec/systems/grammar/module-system.md) seam grammar for no gain; the lockfiles are foundation artifacts). **Docker / conda** (rejected — too heavy for a non-engineer; uv is a single self-contained binary). **An abstract "isolated runtime" that does not name Python/uv** (rejected — dishonest, since the tooling is already Python; the lock benefit needs a named home). **A manual uv prerequisite the operator installs** (rejected — the non-engineer premise [constraints](../reference/constraints.md) forbids a setup chore). **Treat the uv consent as a mirror of the control-plane OAuth gate** (rejected — a binary install + PyPI fetch is a heavier trust class needing more plain-language scaffolding, the isolation guarantee and verifiable source, not the same gate). **A new operator-facing "respect a capable non-coder" copy law** (rejected — redundant with the locked operator-communication law [glossary.md](../reference/glossary.md) and unsafe as worded, pointing toward less explanation and colliding with §5; the condescending phrase is fixed as a copy-leaf defect, no new law). **Defer the substrate to the build phase** (rejected — [D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md): foundational grammar discovered during build is a system refactor). **Let build-ready stand despite this** (rejected — the gap means the genesis dry-run never exercised running the seed validator; build-ready is provisional until the dry-run re-runs).
