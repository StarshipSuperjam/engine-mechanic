# Author the WBS module build-order; the builder crossover; resolve Q20 (defined point = M1; in-repo for v1, separate mechanic post-v1)

*Decided 2026-05-28 in the design workspace.*

## The decision

Author the topological module build-order as wbs/module-order.md — the companion to the stage-0 harness, indexed by the slim wbs/README.md. It records the **build-order root** ([repository-topology](../spec/systems/infrastructure/repository-topology.md), pre-graph), the stage-0 preamble (referenced), the **topological capability layers** (L0 topology; L1 `core`; L2 the nine `core`-dependents; L3 `audit-library` + `dependency-discipline` on `validators-core`) tagged required/optional, and a **milestone overlay** that turns the raw sort into a plan. `core` is one atomic block ([D-089](0089-flesh-the-core-module-doc-to-designed-the-kernel-partition-t.md)); the WBS does not re-decompose it. The conceptual spine is the **builder crossover**: genesis is *necessarily* the hand-governed planning-session builder (Builder A) because the nascent engine (Builder B) cannot exist until `core` is committed (the bootstrap paradox); the stage-0 **supersession ratchet** flips the advantage to B as `core` (coherence), `validators-core` (correctness), and `memory-substrate-sqlite-fts5` (recall) land — that bundle **is M1**. **[Q20](../reference/open-questions.md) resolved.** Its genuine residual is *the defined point* — *when* construction hands off — and that point is **M1** ([D-101](0101-pin-the-stage-0-self-construction-threshold-to-a-concrete-mo.md)). The build-*locus* leg **confirms** the already-settled engine-mechanic home ([D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)/[D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md)), it does not re-decide it: the nascent engine carries all post-M1 v1 work **in-repo** (additive module installs, low self-modification hazard, reversible), its v1 safety the **maintainer merge gate** (stage-0 §7) — *not* version-separation; the **separate engine-mechanic repo** is the **post-v1 maintenance terminus**, where version-separation safety (run a released, ratified version N to build N+1) earns its complexity once self-modification turns foundational. Per [D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md)'s honesty constraint the mechanic's guard is named as the **engine-template maintainer's human ratification gate** (version N is ratified before N+1 is built), not unenforced separateness as a self-acting mechanism. `external-contribution` is built **in v1** (a shippable capability) though the mechanic that uses it stands up post-v1. The experimental/stub tail ([engine-knowledge-graph](../spec/modules/engine-knowledge-graph.md), [clean-code](../spec/modules/clean-code.md), [product-knowledge-graph](../spec/modules/product-knowledge-graph.md)) is named but **deliberately unsorted** — out of the v1 build-order graph.

## Why

wbs/README.md recorded the module sort as "not yet authored," gated on the deviation verdicts; [D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md) cleared the last `OPEN` verdict and the module graph is fully classified, so the sort is now mechanically determined and authorable. The real design content is not the sort (the acyclic graph fixes it) but *who builds the engine and from when* — settled with the operator this session: minimize the un-substrated genesis builder's footprint to the irreducible bootstrap, and cross over to the nascent engine at the earliest point it strictly dominates (M1). Splitting [Q20](../reference/open-questions.md) into **build-quality crossover** (M1) and **build locus** (in-repo → separate mechanic) dissolves the long-parked "defined point" ambiguity: the defined point Q20 asked for is M1; the locus is a separate, later transition that only *confirms* [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)/[D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md). Keeping the in-repo nascent engine as the v1 builder is justified because post-M1 v1 work is additive and reversible under the same human merge gate, so version-separation buys nothing yet; the separate mechanic's distinct value (it never builds atop its own un-reviewed output) is worth its cross-repo complexity only on **foundational** revision, which is post-v1. It touches **no locked doc**: the `wbs/` group is outside the validator's frontmatter/coverage gates and freely revisable; `core` and `external-contribution` stay as cataloged; the M1 subset is [D-101](0101-pin-the-stage-0-self-construction-threshold-to-a-concrete-mo.md)'s, unchanged. Propagation: wbs/module-order.md authored; wbs/README.md status + index; wbs/stage-0-harness.md §8 reconciled (the in-repo engine carries post-M1 v1; the separate mechanic is the post-v1 locus; "remains Q20" → resolved here); [open-questions.md](../reference/open-questions.md) Q20 deleted; [engine-architecture.md](../architecture.md) §9 marks the WBS authored (constrained wording, no maintainer-only builder vocabulary); [glossary.md](../reference/glossary.md) adds **Self-construction threshold (M1)** (with the [§12](../principles.md) leak-guard fence) and updates the **Engine-mechanic** entry's Q20-residual clause to cite this decision; [risks.md](../reference/risks.md) adds the un-exercised-at-v1 external-contribution/mechanic risk (split maintainer-dogfooding vs operator-maturity-disclosure, related to [R13](../reference/risks.md)) and re-points [R6](../reference/risks.md)'s WBS-layering mitigation at the now-authored sort; this entry. No `README.md`/`CLAUDE.md` document-map edit is needed — `module-order.md` is a new doc inside the existing `wbs/` group, not a new top-level doc or systems group. `validate.py` green.

## What we ruled out

Author the sort without the builder-crossover model (rejected — the topological sort is mechanical; the operator's actual question was who builds and from when, and the crossover is the substance that makes it a build *plan*). Keep Builder A (the un-substrated genesis builder) building the full required spine or all of v1 before any crossover (rejected — once `core`+`validators-core`+`memory` are online the nascent engine strictly dominates on coherence/correctness/recall; prolonging genesis past M1 wastes the ratchet and raises drift risk). Hand off to the **separate engine-mechanic** repo as soon as `external-contribution` is built (rejected — version-separation safety is worth its cross-repo complexity only on foundational self-modification, post-v1; in-repo additive v1 work is adequately governed by the maintainer merge gate). Defer the engine-mechanic entirely / treat it as undefined (rejected — its home is settled [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)/[D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md); Q20's residual was only the *timing*, now pinned). Re-decompose `core` into a sub-sequence in the WBS (rejected — its partition is settled [D-089](0089-flesh-the-core-module-doc-to-designed-the-kernel-partition-t.md) and the WBS operates at module granularity; the supersession ratchet governs `core`'s internal construction). Present the mechanic's separateness as a self-enforcing guard (rejected — [D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md): the honest guard is the human ratification gate on engine-template, not unenforced non-reflexivity). Leave Q20 open pending the mechanic stand-up (rejected — conflates the defined *point*, now M1, with the *locus transition*, deferred but decided).
