# Resolve: re-lock `control-plane` (the spec leaves the engine-label scheme) — second carrier of D-244

*Decided 2026-06-23 in the design workspace.*

## The decision

Re-lock [control-plane](../spec/systems/infrastructure/control-plane.md), the second carrier of [D-244](0244-re-litigate-product-design-into-a-first-class-spec-driven-de.md). The "Engine Issues and the label scheme" section sheds the product spec entirely: **(1)** the **spec-Issue marker is removed** — the product spec is no longer an engine-labeled Issue but [product-design](../spec/modules/product-design.md)'s committed `docs/spec/` corpus, so the scheme carries no spec marker; **(2)** product-design is **dropped from the engine-label producer list** (it applies the engine label to nothing); **(3)** product-design's **decomposed work Issues are ordinary product backlog** — un-labeled, outside the engine-labeled channel / issue-authoring helper / body contract / reroute gate (closing issue #237 concern #3: the engine label is engine-internal); **(4)** the **spec-detection contract moves to [build-orchestration](../spec/systems/lifecycle/build-orchestration.md)** as a path resolution of the committed corpus, no longer a label this scheme defines; **(5)** the spec-Issue body-contract **exception is removed** (no spec Issue). No milestone scheme is added — control-plane never gated milestones; build-orchestration owns their production. **The full four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context — the proportionate gate for a substantial carrier, operator-confirmed) returned **no blocking finding**: concern #3 delivered (the operator lens confirmed the work Issues are genuinely un-labeled ordinary backlog and the engine label means only the engine's own health); the technical lens ground-truthed against current GitHub/`gh` docs that the reroute gate + `on:issues` backstop scope to the engine label (no false interception of product-work Issues), that `gh issue create --milestone <name>` is feasible, and that Milestones must pre-exist via `gh api` (no native `gh milestone` verb); the adversarial lens confirmed **no self-monitoring gap** (the debt/telemetry/state/attention/audits loop runs over engine-labeled Issues by design — [D-039](0039-reports-self-improvement-scope-engine-only-self-monitoring-o.md)/[R6](../reference/risks.md) — so un-labeled product work is correctly invisible to it, never orphaned) and no dangling spec-marker reference. **Four serious findings, dispositioned:** **(a, fixed in-line)** the work-Issue sentence led with engine machinery before the reassurance — reworded so "ordinary product backlog … human-legible pointers grouped under the build's Milestones" leads and the machinery trails as a parenthetical; **(b, fixed in-line)** control-plane pinned build-orchestration's `locked`-spec no-op predicate (the wrong home) — genericized to "a build with no spec to resolve is build-orchestration's disclosed no-op," attributing "the precise condition" to build-orchestration; **(c, carry-forward to [D-247](0247-resolve-re-lock-build-orchestration-committed-spec-referent.md))** Milestone names are an operator-facing surface bound by the plain-language law — but milestone naming is build-orchestration's home, so the binding lands at D-247 (where [D-244](0244-re-litigate-product-design-into-a-first-class-spec-driven-de.md) already re-discharges the no-framework-vocabulary rule across milestone names); **(d, carry-forward to [D-247](0247-resolve-re-lock-build-orchestration-committed-spec-referent.md))** the landed control-plane text now directly contradicts the still-locked [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (":34-37 the build Issue *is* the originating spec Issue … engine-labeled"; ":151-157 detection resolves Issue → spec) — the authorized per-carrier-sequence cost ([D-244](0244-re-litigate-product-design-into-a-first-class-spec-driven-de.md)), closed by D-247 **in this same pass** (the pass does not end with control-plane re-locked and build-orchestration open). The two in-line fixes are **bounded, audit-prescribed prose** (a reorder and a genericization implementing the lenses' own recommendations), folded before re-lock without a separate re-check — the [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) fold-before-relock practice. `python3 lock.py --relock systems/infrastructure/control-plane/README.md --decision D-246`; `python3 validate.py` green.

## Why

control-plane owns the engine-label scheme (the spec-detection contract rode it because detection was label-based); once the spec becomes a committed corpus, detection is a path read build-orchestration owns, so control-plane cleanly sheds the spec — the right ownership boundary. The full audit was the proportionate gate for a substantial change to a locked trust contract and earned its keep: it caught the lead-with-machinery legibility cost, the cross-doc no-op-predicate overreach, and the milestone-name binding gap, all resolved or carried. The build-orchestration contradiction is the known cost of dependency-ordered per-carrier re-locks ([D-244](0244-re-litigate-product-design-into-a-first-class-spec-driven-de.md)/[D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md) precedent) — acceptable only because D-247 lands it in the same pass; the carry-forward to D-247 now has **six items** (two from [D-245](0245-resolve-re-lock-state-the-milestone-honest-bound-first-carri.md), four from here), recorded so the seam closes symmetrically.

## What we ruled out

**Add a milestone scheme to control-plane** (rejected — control-plane never gated milestones and build-orchestration owns their production; a milestone section here mints a law in the wrong home, architect-confirmed). **Keep the `locked`-spec no-op predicate in control-plane** (rejected — it fixes a build-orchestration detail in the wrong doc and risks a wording mismatch with D-247; genericize here, let build-orchestration own the precise trigger). **Bind Milestone names to the plain-language law in control-plane** (rejected — milestone naming is build-orchestration's home; the binding lands at D-247). **Leave the work-Issue sentence machinery-first** (rejected — the operator lens's legibility point is cheap to honor and the reassurance should lead). **Re-run a full audit on the two in-line fixes** (rejected — bounded, audit-prescribed prose implementing the lenses' own prescriptions; the [D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md) fold-before-relock practice is proportionate). **Edit build-orchestration now to close the contradiction immediately** (rejected — build-orchestration is its own substantial carrier needing its own full audit; D-247 is next in this same pass, the correct close).
