# Correct the non-existent GitHub scope `admin:repo_ruleset` in control-plane / provisioning / module-system (litigation alarm + authorization)

*Decided 2026-06-06 in the design workspace.*

## The decision

The locked [control-plane](../spec/systems/infrastructure/control-plane.md) ([D-017](0017-control-plane-locked-end-state-as-contracts-not-leaves.md); re-locked [D-122](0122-enumerate-the-branch-ruleset-protection-floor-in-control-pla.md)/[D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md)), [provisioning](../spec/systems/infrastructure/provisioning.md) ([D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md); re-locked through [D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md)), and [module-system](../spec/systems/grammar/module-system.md) ([D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md)) docs are **re-litigated** to correct a **falsified platform fact**: the permission to apply a branch ruleset is named **`admin:repo_ruleset`**, **a scope that does not exist**. This entry is the **litigation alarm + authorization** (the operator authorized the audited change via plan-mode approval); the **re-locks land under the resolve entry** [D-182](0182-resolve-the-d-181-scope-name-correction-landed-text-cold-aud.md) after the mandatory landed-text cold audit — the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)→[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) / [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)→[D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) pattern. Raised from build-repo **engine-template issue #65**: core slice 25a built the control-plane bootstrap against the *correct* mechanism (`.engine/tools/bootstrap.py`), leaving the locked **contract** sound and only the canonical *prose* wrong.

  **The falsified fact (ground-truthed this session — the [§17](../principles.md) gold standard, not inference).** Verified directly, each independently:
  - `admin:repo_ruleset` is **not** a documented OAuth scope (GitHub's scopes-for-OAuth-apps list enumerates every scope; it is absent — `repo` is the one that "grants full access to public and private repositories").
  - Creating/updating a repository ruleset requires **repository-administration capability**: the classic **`repo`** scope, or a fine-grained token with **Administration: write** (GitHub permissions-required-for-fine-grained-PATs — Create/Update a repository ruleset → Administration, write).
  - The operator's own `gh` **already carries `repo`** by default (`gh auth status` → `gist, read:org, repo, workflow` on this machine). The premise *"a plain operator login does not carry the needed scope"* is **false**.
  - The `gh auth refresh -s repo` consent screen shows the operator the label **"Full control of private repositories"**, not the literal `repo`.
  - Unchanged/correct (retained): the default Actions `GITHUB_TOKEN` cannot create a ruleset; the per-branch evaluated-rules endpoint reads with the default token.

  **The three-count [D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md) error (decision-log entry, append-only — stands; superseded here).** [D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md)'s rationale called this "the `admin:repo_ruleset`-vs-fine-grained-Administration nit … a non-issue (the design uses `gh auth refresh` OAuth scopes, where the name is correct, and it is enshrined in locked constraints)" — wrong on **(a)** the conclusion (the name is *not* correct), **(b)** the corroboration (it cited the claim's own restatement in constraints as authority — circular), and **(c)** the premise that `constraints.md` is "locked" (it is **not** in locks.yaml). This is the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) pattern: a "verified" platform fact overturned by direct verification.

  **The correction (authorized; final text + landed-text audit land under [D-182](0182-resolve-the-d-181-scope-name-correction-landed-text-cold-aud.md)).**
  - **Axis 1 — the false name:** `admin:repo_ruleset` → **`repo` / fine-grained Administration:write**, everywhere.
  - **Axis 2 — the false premise + an honest read of what it unlocks.** Because the operator usually **already holds `repo`**, the `gh auth refresh` consent screen becomes a **fallback for the rare missing-scope case**, not the default — the common first-run needs **one fewer approval screen** when the operator is present and running the bootstrap. **Over-claim guards (the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)/[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) capability-discovery steer — analyze the unlock, but no reach):** do **NOT** claim it "firms R1" (R1 is the operator *skipping* the bootstrap; scope-possession does not change that — R1 stays open until first-run UX); do **NOT** imply autonomous protection (holding `repo` lets the *operator's local `gh`* apply the ruleset in an interactive moment, never the engine as a background/Actions step — "Actions token cannot / operator-privileged actor / operator present" stays explicit). The locked **contract is fully preserved**: operator-privileged actor, consent-gated, verify-after-refresh, degrade-never-fake; "defer is the common path" still holds for its other reasons.
  - **§15 residual — honest re-frame (not "unchanged").** The false narrow-scope language *under-described* the solo residual; reality (always true, since solo uses the operator's `gh`) is that the engine inherits the operator's standing **`repo`** — full repository control, of which ruleset-admin is one part. Disclose that true breadth. §15's *guarantee* and its *enumerated* weakening-guard ([D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md): `.claude/settings.json`, `.github/workflows/`, check defs, `CODEOWNERS`, the ruleset) are unchanged in substance; only the inherited-capability *description* moves fiction-narrow → true-broad, which **strengthens** [§7](../principles.md)/§15 honesty. No §15 redesign (out of scope for #65); whether the broader powers warrant added disclosure is for the [D-182](0182-resolve-the-d-181-scope-name-correction-landed-text-cold-aud.md) audit to adjudicate.
  - **Operator-facing, per the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) discipline.** The locked doc currently bakes the literal scope string ("the screen will say `admin:repo_ruleset`"); replace with the **durable principle** (*pre-translate the actual on-screen label and pre-empt its apparent breadth*), with the **dated string** ("Full control of private repositories") in the Build-spec leaf + this log — a naïve swap to `repo` would show a *scarier* real label than the fake one it replaces. And the no-consent common path must stay **visible**: a plain-language **"your review gate is now ON"** confirmation, symmetric to the existing standing "gate is off" banner, so the operator can distinguish *protection succeeded* from *protection skipped*.

## Why

A locked trust document that names as required a GitHub permission that does not exist — and rests a first-run premise on it — is a direct hit on **auditability** and **trustworthiness**; and because the planning workspace is the source for the eADR-canon transplant, the falsehood would propagate into every deployed Engine and cold session. Justified re-litigation, not drift (the lock stops drift, not warranted edits — CLAUDE.md litigation alarm). The build already proved the correct mechanism (slice 25a), so this aligns the canon to the built truth — the locked *contract* is unchanged. A three-lens cold **plan**-audit (architect · adversarial · non-engineer-operator, no shared context; the **technical-feasibility** lens discharged by direct live verification — the lens [D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md) got wrong by inference) ran against the plan before this authorization and reshaped it: it caught the missed wbs/stage-0-harness.md §5 carrier, the under-cited [risks.md](../reference/risks.md) R1 block, the [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md) reasoning-claim carrier, the "firms R1" / autonomous-protection over-claims, the §15-residual-is-wider finding, and the "screen says `repo`" pre-translation trap — all folded above. Keeping the dated platform strings in the log + leaf and only durable principles in the locked docs applies the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) lesson.
