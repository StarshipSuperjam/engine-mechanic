# Reject an audit that researches external upstream-issue currency; track `upstream`-blocked issues via a GitHub-native watch + the audit's existing in-repo backlog surfacing (no locked re-litigation)

*Decided 2026-06-22 in the design workspace.*

## The decision

To tell the operator when an `upstream`-blocked engine Issue (e.g. engine-template #221, the stale-worktree temporary measure) can be **closed**, and to **remind** that its temporary measure needs running/retiring, the Engine uses two layer-respecting mechanisms and **adds no new engine capability**: **(a)** the operator **watches the upstream Issue on GitHub** ([anthropics/claude-code#26725](https://github.com/anthropics/claude-code/issues/26725) for #221) — the platform notifies on close and the operator reads whether the fix actually *shipped*, the reliable detection that lives in the operator's own account; **(b)** the [audit](../spec/systems/guardrails/audits.md)'s **existing "stale debt / triage-pressure backlog health" concern** already keeps open engine-labeled Issues in front of the operator (surfaced via [telemetry](../spec/systems/guardrails/telemetry.md)'s register and [boot](../spec/systems/lifecycle/boot.md)), optionally sharpened by an **additive concern-row** flagging open `upstream`-labeled Issues that carry a temporary measure — surfacing the **in-repo fact + the existing upstream link to check, never polling external state**. The concern-row rides the audit's **sanctioned Build-PR concern-list growth path** in the deployed repo (adjudicated at merge against the entry bar), so **no design doc is edited and no locked system is re-litigated**; it is filed as an engine-template build-owe citing this decision. The [D-239](0239-reject-an-engine-owned-git-hygiene-reconciler-accumulated-lo.md) local-layer boundary stands.

## Why

A cold adversarial audit — **verified against source** — refuted the alternative the operator first chose: have the audit research each `upstream` Issue's external status every run, backed by a new structured upstream-reference in the **locked** [control-plane](../spec/systems/infrastructure/control-plane.md) Issue body contract. Four grounds. **(1)** The audit's **function-probe law** (audits §"Function-probe, not stats") requires a fitness claim to rest on a content probe run during the audit and **"never on a cached count, status field, or existence check,"** and explicitly disclaims **liveness** ("is X resolved right now") as [boot](../spec/systems/lifecycle/boot.md)/[hooks](../spec/systems/infrastructure/hooks.md) territory, *not* audits' — reading a remote Issue's open/closed status is exactly the forbidden status-field/liveness check. **(2)** It contradicts [D-239](0239-reject-an-engine-owned-git-hygiene-reconciler-accumulated-lo.md) (same session), which placed this problem at the **local/Claude layer, not an Engine surface**, and forbade autonomous monitoring ([§8](../principles.md) no-daemon). **(3)** The signal is too weak to act on — a *closed* `anthropics/claude-code` Issue **≠ released in the operator's installed version** — so an "appears resolved → close" recommendation would train **premature closure**, eroding the audit's no-rubber-stamp / declining-is-a-real-choice trust posture. **(4)** The structured reference would force changes to the **locked** reroute gate + `on:issues` backstop (control-plane/[hooks](../spec/systems/infrastructure/hooks.md)/[modes](../spec/systems/lifecycle/modes.md)) — an undercounted blast radius — and is scope creep at a build-ready ([D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)) line. The chosen path serves the operator's goal fully: detection via the platform's own notification (better judgment than the audit guessing), reminder via the audit's existing in-repo backlog surfacing — with **zero locked-doc movement**.

## What we ruled out

Have the audit poll external upstream-Issue currency each run (rejected — function-probe-law violation, liveness not owned by audits, [§8](../principles.md) daemon, weak closed≠released signal). Add a structured machine-readable upstream-reference to the locked [control-plane](../spec/systems/infrastructure/control-plane.md) Issue body contract (rejected — useful only to feed the rejected poller; forces locked reroute-gate + backstop changes; the existing human-readable upstream link in the Issue body's references already lets the audit surface it for the operator to check). A scheduled engine-template workflow that comments on the Issue when the upstream closes (rejected for now — still polls external state on a cron, needs its own design, and carries the same closed≠released caveat; the GitHub-native watch is lighter and puts the read in the operator's hands). Do nothing / rely only on the cross-link (rejected — the operator asked for an active reminder, which the audit's existing backlog surfacing + the watch provide without new machinery).
