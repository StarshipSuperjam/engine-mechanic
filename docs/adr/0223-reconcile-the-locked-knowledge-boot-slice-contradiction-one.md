# Reconcile the locked knowledge boot-slice contradiction: one-word committed→gitignored correctness fix, proportionate cold audit, knowledge re-locked (engine-template #37 litigation flag)

*Decided 2026-06-19 in the design workspace.*

## The decision

On the litigation alarm and explicit operator approval, correct a self-contradiction in the locked [knowledge](../spec/systems/cognitive/knowledge.md) doc and **re-lock** it. Line 52's degrade cascade read "*read the **committed** boot slice → rebuild it from committed entities → …*", calling the boot slice *committed* — but the same doc states three times that it is **gitignored** ([:19](../spec/systems/cognitive/knowledge.md) "a prioritized boot slice (both gitignored, regenerated on demand)", [:21](../spec/systems/cognitive/knowledge.md) "gitignored index + boot slice", [:45](../spec/systems/cognitive/knowledge.md) "the index and boot slice are caches that rebuild") and [:46](../spec/systems/cognitive/knowledge.md) explicitly **excludes** the slice from the [§19](../principles.md) derived-committed class ("the gitignored index and boot slice are tier-4 derived outputs, outside the class"), as does the ratifying [D-060](0060-lock-the-knowledge-system-wave-2-the-purely-derived-structur.md) ("a gitignored derived index + boot slice regenerated on demand"). The fix changes exactly one word — "committed" → "gitignored" on the *boot slice* noun; the second "committed" (modifying *entities*, the rung-2 rebuild source) is correct and unchanged. It is a **pure corrective alignment with zero new design semantics**.

  **The litigation flag.** Surfaced by engine-template **#37** (the gitignored knowledge boot-slice producer): the build conformed to the gitignored reading and **flagged the locked-doc imprecision rather than papering over it or silently editing the locked doc** — the correct litigation-alarm posture. The slice had a near-total mechanical correlate (five statements + D-060 unanimously *gitignored*; one outlier *committed*), so the contradiction is the semantic kind the lock fingerprint cannot catch — exactly what the alarm exists for.

  **Proportionate cold audit.** Two independent no-shared-context lenses — **adversarial/correctness** and **architect/propagation** — ran against the landed text, **reduced from the four-lens floor** by the operator's delegated audit-depth call because the change is provably non-semantic with a near-total non-AI correlate. **Outcome: no blocking, serious, or nit findings.** Correctness confirmed the cascade now reads coherently — rung 1 reads the gitignored cache, rung 2 rebuilds it from committed entities; under "committed" rungs 1–2 collapsed into the same artifact, so the fix restores the distinction the cascade depends on. Propagation confirmed **verify-no-edit everywhere**: [modules/core:31](../spec/modules/core.md) ("reads the *committed* entities and the *gitignored* derived index"; `gitignore` covers "the knowledge derived index + boot slice"), [glossary:31](../reference/glossary.md) (names "the gitignored knowledge index/boot-slice" tier-4, correctly outside the §19 class), and [engine-architecture](../architecture.md) / `scenarios/` / [risks](../reference/risks.md) (no boot-slice statement to reconcile) are all already correct.

  **Scope. Re-lock set — 1:** [knowledge](../spec/systems/cognitive/knowledge.md) (`python3 lock.py --relock` under this decision; `python3 validate.py` green). **No carriers; no propagation owed** (verify-no-edit confirmed above). **No [open-questions](../reference/open-questions.md) opened/resolved; no [deviations](../reference/prototype-deviations.md) entry.** Still **42 docs locked** (1 re-locked, none added). **Build-owe (engine-template, downstream):** none new — the build already conforms to the gitignored reading; this re-lock **closes #37's litigation flag** by bringing the locked doc into agreement with the as-built behavior. (#37's *producer build* remains gated on its own prerequisite — an orientation-time focused knowledge read, i.e. the git/GitHub work-record reader slice — and its placement is the knowledge cache per [core:31](../spec/modules/core.md), neither of which is a design decision; see the #37/#92 dispositions.)

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval, and the gap was a real self-contradiction inside a locked doc — the semantic class the lock fingerprint cannot detect, which is why the build correctly raised the alarm instead of editing silently. A four-lens panel for a one-word, provably-non-semantic alignment would be friction without proportional trust ([§6](../principles.md)); confidence here is bounded by the non-AI correlate ([§17](../principles.md)) and that correlate is near-total (five concordant statements + D-060), so two independent adversarial lenses honor the HARD gate's *intent* — independent eyes that can refute — without ceremony disproportionate to the change. The reduction is **logged, not skipped**: the audit ran and returned clean.

## What we ruled out

**Edit the locked doc silently** (rejected — the fingerprint backstop would hard-fail validate.py and, more to the point, the posture forbids it; the alarm is the path). **Skip the cold audit entirely** (rejected — that ranks with a silent edit; the gate is HARD, so it ran, only proportionately scoped). **Run the full four-lens panel** (rejected as disproportionate for a one-word non-semantic fix with a near-total mechanical correlate; the operator delegated depth and the reduction is recorded with rationale). **Drop the adjective ("read the boot slice")** (rejected — "gitignored" actively corrects the error and matches [:46](../spec/systems/cognitive/knowledge.md)'s phrasing). **Rewrite the cascade** (rejected — only one word was wrong; the minimal corrective edit is the discipline). **Split into an authorize/resolve pair** (rejected — CLAUDE.md requires "a re-litigation entry," singular; the pair convention serves substantive multi-step re-litigations, not a typo-class correction).
