# Authorize git-native retention for the pre-migration memory snapshot (resolve engine-template #287): a distinct retained backup *tag* the routine backup never overwrites; re-litigate locked [memory](../spec/systems/cognitive/memory.md) + its packaging bundle [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md); coupled re-lock lands under D-265

*Decided 2026-06-27 in the design workspace.*

## The decision

Build's [`snapshot_for_migration` seam (#233)](https://github.com/StarshipSuperjam/engine-template/issues/233) — back-up-memory-before-a-data-migration-reshapes-it — shipped against the locked backup design and exposed a durability gap the operator asked this workspace to litigate ([engine-template #287](https://github.com/StarshipSuperjam/engine-template/issues/287)): memory's vault keeps **one rolling slot per namespace** (the namespace folder at the vault's default-branch HEAD), overwritten by the routine ~daily backup, and the pre-migration snapshot reuses that same slot (the locked "one mechanism, two consumers", [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)/[D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)). A routine backup firing between an engine update and the operator's undo overwrites the pre-update copy at HEAD; the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) *code-older-than-data* boot alarm still fires with "the exact restore command," but that command now restores the **reshaped** copy. **The litigation:** the gap is real but is a **mis-pointed restore, not data loss** — the vault is a git repo, so the pre-update content survives in history; what is missing is a restore path that can *address* it, and the non-engineer operator has only the engine's offered command. **The fix (operator-chosen): git-native retention** — the pre-migration snapshot lands as a **distinct, manifest-named git tag the routine backup never overwrites**, and the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) restore command targets that tag. This **completes a promise the locked design already makes** ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)'s loud warning + exact command) rather than adding a new store. **This entry is the litigation alarm + operator authorization** (given in-session over a four-lens plan-stage cold audit) **and the design of record**; the **coupled re-lock lands under [D-265](0265-resolve-coupled-re-lock-of-memory-memory-substrate-sqlite-ft.md)** after the mandatory **landed-text cold audit** — the [D-262](0262-authorize-the-disposition-issue-resolution-check-a-17-7-mech.md)/[D-263](0263-resolve-re-lock-validators-core-the-disposition-issue-resolu.md) authorize-then-resolve pattern, the carriers **edited-but-not-relocked** until D-265 (the sanctioned transient — `validate.py` flags their lock fingerprints until the relock).

  **The mechanism — laws the carriers settle (a four-lens cold audit reshaped these; none is a deferred leaf):** **(1)** the snapshot is a **distinct, retained, manifest-named git *tag* the routine backup never overwrites — not an "immutable" ref.** Platform-enforced tag immutability (rulesets / tag protection / Immutable Releases) requires GitHub Pro/Team/Enterprise and is **unavailable on the default free private vault**; the actual guarantee — no daily-backup clobber — is **structural and tier-independent** (a different ref, not a different store), and is never promised as enforced immutability. Platform immutability is **optional paid-tier hardening**, build-verified, degrade-and-disclosed when absent (memory's existing detect-don't-prevent posture). **(2)** A **tag** (`refs/tags/…`), not a custom `refs/snapshots/*` ref — custom refs do not travel on default clone/fetch (breaking the bare-machine recovery floor) and cannot carry the optional hardening. **(3)** **Collision-free per-snapshot naming** — one engine upgrade runs **multiple** migrations in dependency order (locked [provisioning](../spec/systems/infrastructure/provisioning.md)), all at the same `engine-version` and possibly the same `ledger-generation`, so a `<version>-<generation>` name would collide and re-create the overwrite bug on the retained tag; the name carries a per-snapshot discriminator (the migration id and/or the manifest timestamp), **collision-free by construction** (the rigor memory already applies to the namespace id), **refuse-and-surface on collision, never silent overwrite**. **(4)** **Snapshot-restore ↔ the locked generation-guard (the deepest seam):** a pre-migration snapshot is **older-generation**, so restoring it is exactly the "land an older generation over a newer one" operation the locked **Compaction↔provisioning ordering law** surfaces as a resurrection finding. The snapshot carries its **pre-migration generation**; the revert restores to *that* generation; the resurrection guard fires **only** if an erasure-compaction ran in the revert window (small but **not zero** — a routine forgetting pass between the failed update and the undo can still enact a merge-gated erasure); the new tag **participates in the generation-stamp resurrection check**, closing any backdoor that would silently resurrect an operator-adjudicated erasure ([§17](../principles.md)). **(5)** **Safe-delete is a law; only the numeric cap is a leaf** — a snapshot is retained **at least as long as a [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) mismatch could still cite it** (e.g., until the next successful migration of the same store supersedes the reversibility guarantee); the tension with (1) resolves as **non-overwritable by the routine backup (structural) yet deletable by the engine's pruning path** (never promised undeletable); and boot **degrades-and-discloses if the cited tag is absent**, extending memory's "missing namespace → distinct plain-language finding, never a silent no-restore" floor to a missing snapshot tag. **(6)** **The disk-growth residual is owned, not hidden** — because a migration *reshapes* the ledger, successive snapshots largely do not dedup, so the shared default vault grows ~linearly in (migrations × ledger size); named honestly under [R2](../reference/risks.md) (the shared-vault honesty posture), the pruning *policy* the lever. **(7)** **Restore mechanics:** snapshot-restore reads from the **vault clone**, writing only the gitignored local ledger — never a checkout into the [operator checkout](../reference/glossary.md) ([D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md) leak guard); the large-ledger path is named (the `gh api …/contents?ref=` route caps at 100 MB / needs `.raw` above 1 MB, so the robust floor is `git fetch <tag>` + `git show <tag>:<ns>/…` or a partial/sparse clone — a build-spec constraint, since a pre-migration ledger may be at its largest). **(8)** **Governance:** the tag is governed by the same [topology law 5](../spec/systems/infrastructure/repository-topology.md) off-repo carve-out and **privacy posture** as the rolling export, and the periodic privacy re-check covers historical snapshot tags too.

  **Operator-facing floors (conditions of approval, the non-engineer lens):** **(a)** **one action, never a menu** — in the code-older-than-data case boot names **exactly one** restore command pointing at the pre-update snapshot, with one plain sentence of why; the snapshot-vs-latest choice is the engine's, never surfaced as a fork; **(b)** the committed **vault README** (backup floor (2)) is extended so "ask the Engine; don't hand-edit" covers the snapshot tags, and a hand-deleted snapshot degrades to a named plain-language finding, never a silent no-restore; **(c)** a plain-language **disclosure at the update moment** — "before this update I saved a copy of your memory so it can be undone" — so the later restore command is reassurance, not a mystery.

  **Carriers (coupled, one semantic event — the [D-049](0049-re-lock-topology-and-module-system-file-precise-codeowners-o.md) coupled-relock precedent):** [memory](../spec/systems/cognitive/memory.md) (the restore contract + the "one mechanism, two consumers" restatement to a *retained sibling*) and its packaging bundle [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md) (whose `provides` carries "the backup/restore mechanism + restore contract"); both re-lock under [D-265](0265-resolve-coupled-re-lock-of-memory-memory-substrate-sqlite-ft.md) after the landed-text cold audit. **Recorded verify-no-edit dispositions (no re-lock — confirmed against disk):** [provisioning](../spec/systems/infrastructure/provisioning.md) (its migration-reversal section describes restore *behavior* and owns the command *wording* leaf, naming no target ref — re-litigating it would be an unjustified locked-doc edit); [boot](../spec/systems/lifecycle/boot.md) (a generic open-findings renderer — the snapshot-vs-HEAD target is finding *content* it renders verbatim; the new missing-tag disclosure rides its existing path); [migration-discipline](../spec/modules/migration-discipline.md) (governs *product-schema* migrations, a different class than the engine's own memory-store migration); [engine-architecture](../architecture.md) (carries no backup-durability prose — verified). **Non-locked propagation:** [scenarios/upgrade-the-engine.md](../architecture.md#upgrading-the-engine) (the now-stale backup-first note), [glossary.md](../reference/glossary.md) (a *migration snapshot* / retained-tag vs. rolling-backup term), [risks.md](../reference/risks.md) ([R2](../reference/risks.md)/[R7](../reference/risks.md) touch + the disk-growth residual). Closes the data-durability gap #287 names; pairs with the built #233 seam.

## Why

the snapshot-before-migration step exists to make a migration **reversible**; a reversibility guarantee that silently evaporates on a ~1-day timer is not reversibility, and the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) alarm fires precisely when a routine backup has most likely already clobbered the snapshot — the alarm and the loss co-occur. Git already retains the pre-update content; the honest, minimal fix is to make it *addressable* by a distinct tag the rolling backup cannot reach, which **completes the existing [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) promise** rather than inventing backup design ([R6](../reference/risks.md)-clean). The capability is memory's by [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) (sole owner of the mechanism + restore contract), so the contract widening lands in memory and its bundle; provisioning, boot, and migration-discipline consume it and widen nothing. The authorize→resolve-after-landed-text-audit split keeps the irreversible coupled re-lock behind its own clean gate ([D-262](0262-authorize-the-disposition-issue-resolution-check-a-17-7-mech.md)/[D-263](0263-resolve-re-lock-validators-core-the-disposition-issue-resolu.md)).

## What we ruled out

**Accept-as-is** (the issue's Option A — "snapshot-before-migration + warn loudly + restore promptly") — **rejected as a trust failure**: it puts a race on a clock the operator cannot see (an invisible ~daily timer on a safety guarantee), and the [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) alarm most often fires *after* the snapshot is already overwritten, so the guarantee is weakest exactly when it is needed. **The heavyweight retention subsystem** (the issue's Option B as framed — new vault layout + a bespoke retention store) — **rejected**: on a git substrate point-in-time retention collapses to a distinct tag + a generation-aware restore target, so the heavyweight form is unwarranted scope. **A custom `refs/snapshots/*` ref** — rejected (does not travel on default clone/fetch; breaks bare-machine recovery; cannot carry the optional hardening — a tag wins on both axes). **Promising platform-enforced "immutability"** — rejected (false on the default free private vault; the real guarantee is the distinct-ref structure, tier-independent, with hardening disclosed as optional). **A single `<version>-<generation>` snapshot name** — rejected (collides across the multiple migrations one upgrade runs, re-creating the overwrite bug on the retained tag). **Exempting the snapshot-restore from the generation-resurrection guard** — rejected (would silently resurrect a merge-gated erasure, the [§17](../principles.md) breach the guard exists to prevent). **Surfacing latest-vs-snapshot as an operator choice** — rejected (a two-option fork a non-engineer cannot adjudicate; the engine names the one correct action). **Re-litigating provisioning / boot** — rejected (each consumes memory's contract and names no restore target; an unjustified locked-doc edit).
