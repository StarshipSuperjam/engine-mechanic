# Cross-repo external contribution as a first-class v1 operating mode (fork-native); the engine-mechanic as its non-reflexive special case

*Decided 2026-05-28 in the design workspace.*

## The decision

Make **cross-repo external contribution a first-class v1 operating mode** — the Engine contributing to a product repo the operator does **not** own (an open-source project, or the engine-mechanic building engine-template) — realized **fork-native** and authored as a new `designed` lifecycle system [external-contribution](../spec/systems/lifecycle/external-contribution.md) plus an **optional module** of the same name (`depends: core`, Software Configuration Management). The model: the operator forks the upstream (and so owns the fork); the Engine is brownfield-installed into that fork (an ordinary same-repo deployment — product at root, engine in `.engine/`, full committed substrate); product changes reach the un-owned upstream as a **product-only cross-fork pull request**. The genuinely new pieces are (1) a **[§6](../principles.md) local "upstream-clean" nudge** (predicate = the [topology](../spec/systems/infrastructure/repository-topology.md) file-precise CODEOWNERS engine-owned set; `soft`, self-declares its suite [§14](../principles.md), emits a [telemetry](../spec/systems/guardrails/telemetry.md) finding) plus clean-branch discipline that keeps the engine out of the upstream PR, and (2) a **two-gate trust model**: the fork's own pre-submission checks (contributor-side, configurable) and the **upstream's own review/CI as the acceptance wall** (a [§6](../principles.md) human gate whose human is not the operator — for a governed upstream its required checks run upstream-side via `pull_request_target` regardless of fork settings; for an ungoverned upstream the honest [§7](../principles.md) line is that the fork-side checks are the only real gate). The **cognitive substrate is unchanged** (the fork is a same-repo deployment; [memory](../spec/systems/cognitive/memory.md)/[attention](../spec/systems/cognitive/attention.md) location-agnostic, [state](../spec/systems/cognitive/state.md)/[knowledge](../spec/systems/cognitive/knowledge.md) committed in the fork's `.engine/`). The **engine-mechanic** is the **separate-workspace special case** — a deployed instance whose product is a *checkout* of engine-template it PRs to, **non-reflexive** (engine ≠ product), with the building instance **never self-upgrading to its own output** — which **resolves [Q20](../reference/open-questions.md)(a) trusting-trust** (the human gate lives on the product repo) **and (b) reflexive upgrade** (no engine == product case), narrowing Q20 to its **defined-point** residual. Packaging: **optional, not core** ([§12](../principles.md) — an own-product deployment never contributes externally), `depends: core` not [validators-core](../spec/modules/validators-core.md) (the nudge inspects the *outgoing diff*, presupposing no self-validation corpus); the cross-fork PR satisfies the locked [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) close, so the only locked-doc touches are **minimal additive cross-reference seams** (provisioning's "detached/upstream" disambiguation, build-orchestration's cross-fork close + worker-base note, control-plane's upstream-acceptance note, topology's CODEOWNERS-predicate note, and the hooks/telemetry seams) carried as a **gated Phase-C** pass, each a justified re-litigation. Lands **`designed`, not locked**.

## Why

The operator scoped this session to make cross-repo contribution first-class because the North Star is "any project" and [§13](../principles.md) (contributor-not-component) is its purest expression — the Engine "merely happens to live within the same repo," and the substrate is the contributor's, so filing it in the operator's own fork is the cleaner §13 reading. Two design agents (minimal-churn structure; the hard mechanisms) and a **four-lens cold audit of the plan** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran **before approval**; the audit's blocking/serious findings are folded: the upstream-clean check, mis-framed as a [§15](../principles.md) guardrail, is corrected to a **[§6](../principles.md) hygiene nudge** (a leaked engine file is not a weakening of the fork's own enforcement), which keeps [modes](../spec/systems/lifecycle/modes.md) "complete by construction" intact (no new hard write-gate); the trust model was corrected against **live GitHub** (a governed upstream's required checks run upstream-side via `pull_request_target` regardless of fork Actions — the real wall is the upstream's, not the fork's); "engine-clean by construction" was falsified ([knowledge](../spec/systems/cognitive/knowledge.md)'s commit-boundary regen + a three-dot back-merge reintroduce engine paths) so the **nudge is the guarantor**, not branch topology; the threshold's "orchestrator persona" error was caught and fixed in [D-101](0101-pin-the-stage-0-self-construction-threshold-to-a-concrete-mo.md) (the orchestrator is the session, not a persona); "escalate-upstream" was a miscitation (an [audits](../spec/systems/guardrails/audits.md)-only template-machinery disposition) and the cross-fork PR is **build-orchestration's close re-homed**; the **operator-facing narration** (submitted ≠ accepted; the ungoverned-upstream honesty line; conflicts/rebase/DCO-CLA degrade to a plain "I need a decision," never raw git) is a **concrete deliverable**; and the mechanic's reflexivity is genuinely dissolved only because **the building instance never self-upgrades to its own output**. Platform facts grounded against live GitHub (cross-fork PR via `gh pr create --repo <upstream> --head <fork>:<branch>`; a fork's CODEOWNERS has no cross-repo teeth; the default `GITHUB_TOKEN` cannot create a ruleset but can read evaluated rules); the facts that **still require live validation before any Phase-C lock** (fork Actions enablement; the three-dot-diff no-back-merge caveat; per-upstream DCO/CLA acceptance) are recorded as verification gates. **Lock discipline:** the mode lands `designed`; locked neighbors are touched only in the gated Phase-C, after the `designed` anchor settles and a fresh cold audit — never atop a churning neighbor. **Propagation this pass:** [external-contribution](../spec/systems/lifecycle/external-contribution.md) system doc + [module](../spec/modules/external-contribution.md) authored; [modules/README.md](../reference/module-catalog.md) catalog row + dependency edge + scope note; [engine-architecture.md](../architecture.md) §6 index + §3 distribution disclosure (with the pending seams named); [open-questions.md](../reference/open-questions.md) Q20 rewritten (a/b resolved, narrowed to the defined point); wbs/stage-0-harness.md §8 mechanic paragraph reconciled; this entry. **Continuing under the approved plan (not yet landed):** the [glossary](../reference/glossary.md) terms (*external contribution*, *fork-native*, *engine-mechanic*, the two senses of *upstream*), a runtime [scenario](../architecture.md#first-run-provisioning) walkthrough, the [risks](../reference/risks.md) entries (engine-path-leak nudge; ungoverned-upstream honesty; per-upstream DCO/CLA), the **mandatory cold-session design audit** of the authored design, and the Phase-C locked-doc seams.

## What we ruled out

Treat cross-repo as a **post-v1 capability** (rejected — the operator chose first-class; deferring it makes it a future system refactor, the exact failure this workspace prevents). **Engine-elsewhere / separate-workspace as the *general* realization** (rejected for the general case — it re-litigates the locked [state](../spec/systems/cognitive/state.md)/[knowledge](../spec/systems/cognitive/knowledge.md) committed homes for more churn; fork-native keeps the substrate committed in the fork unchanged, and the mechanic uses the separate-workspace variant only because fork-native degenerates to double-engine there). Make it a **core capability** (rejected — [§12](../principles.md): an own-product deployment never contributes externally, so the cross-repo machinery is a genuine extension; the contagious core stays minimal). `depends: validators-core` (rejected — the nudge inspects the outgoing diff, presupposing no self-validation corpus; `core`'s engine suffices, the [migration-discipline](../spec/modules/migration-discipline.md) target-axis precedent). The **upstream-clean check as a [§15](../principles.md) hard gate** (rejected by the audit — a hygiene failure, not guardrail-weakening; [§6](../principles.md) rations hard local refusal; the nudge guarantees cleanliness and the upstream's own gate is the wall). "**Engine-clean by construction**" (rejected — falsified by the regen hook + three-dot semantics; the nudge is the guarantor). A **new operating *stance*** in [modes](../spec/systems/lifecycle/modes.md) (rejected — the stance set is complete by construction; external contribution is a deployment arrangement downstream of Build's submit, not a fourth stance). Borrow the **escalate-upstream** disposition for the cross-fork PR (rejected — that is an [audits](../spec/systems/guardrails/audits.md)-only template-machinery disposition; the cross-fork PR is build-orchestration's close re-homed). **Lock** this pass (rejected — `designed` first; the WBS sort, the Phase-C seams, and a fresh cold audit gate the lock, and `core` is itself only `designed`).
