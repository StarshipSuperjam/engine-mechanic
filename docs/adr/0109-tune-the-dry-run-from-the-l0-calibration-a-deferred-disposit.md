# Tune the dry-run from the L0 calibration: a `deferred` disposition, reference-root handling, and the corrected worked instantiation

*Decided 2026-05-28 in the design workspace.*

## The decision

The first dry-run calibration pass — L0 [repository-topology](../spec/systems/infrastructure/repository-topology.md), the two-lens floor (builder + independent spec-completeness reviewer) — surfaced a **tuning defect in the instrument itself**, not the design: wbs/dry-run.md §8's worked instantiation listed "the derived CODEOWNERS set" as an L0 output, conflating the **reference root** (topology fixes laws, not leaves) with the **producing** steps (the stage-0 seed, the [provisioning](../spec/systems/infrastructure/provisioning.md) first-run instantiator, L1 `core`). The builder consequently over-escalated five correctly-deferred artifacts (CODEOWNERS, operator handle, branch ruleset, `.gitignore`, root `CLAUDE.md`) to "blocking"; the reviewer rejected each with locked-doc citations (provisioning renders CODEOWNERS at first-run apply; the handle is runtime-derived; `.gitignore`/`.mcp.json` are module-wired seams; the two `CLAUDE.md` files and their owners are pinned). Tune the instrument three ways: (1) add a non-finding **`deferred`** disposition — an artifact assigned to a *later, named* owner is build-ready, not a gap; a finding is warranted only when no owner is named or the named owner's needs are unpinned; (2) state that **reference-root steps emit no leaf**, so the simulation confirms every implied leaf is *homed* to a named owner rather than producing files; (3) correct the §8 L0 worked instantiation to reference-root scope. Form unchanged (protocol + templates, no script).

## Why

The calibration's purpose was to test whether the simulation is tuned; it was not — the prompt instantiation manufactured the over-escalation, exactly the self-inflicted noise that would erode trust in a build-readiness gate. The `deferred` distinction is the minimal robust fix: it lets the builder separate "the docs defer this to a later step" (build-ready) from "the docs fail to specify this" (the real target) — the crux the reviewer's REJECT verdicts turned on for a reference root. The fix is confined to wbs/dry-run.md, and is **deliberately not** propagated into wbs/module-order.md or wbs/stage-0-harness.md: both are in active rework this session (the genesis-phase PR sequence and `core`'s lock), so editing them would collide. The run's **two genuine design gaps** are escalated to the owner for that genesis work, not remediated here: (a) the **engine == product CODEOWNERS degeneracy** in the construction repo — already flagged at stage-0 §6 as a litigation-alarm candidate, still unpinned as to what that repo's CODEOWNERS actually contains; (b) the **unpinned author of the genesis engine manifest** in the construction repo (the instantiator that would write it never runs there). The reviewer also noted L0 emits no committable artifact at all — worth stating in wbs/module-order.md §2 when that doc is next in scope. Propagation: wbs/dry-run.md §2/§3/§8 tuned; this entry. The simulation was **not** run past L0 (operator scoped it to L0 until `core` settles). `validate.py` green.

## What we ruled out

Report the tuning defect and leave it unfixed (rejected — that buries a finding about the instrument the calibration exists to fix). Drop reference-root steps from the simulation (rejected — a reference root with an *unhomed* leaf is a real, valuable finding; the fix is to test homing, not skip the step). Re-base the dry-run's unit of work on the emerging genesis-PR sequence now (rejected — that model is being authored in another session; re-basing prematurely would conflict, so it waits for `core` to settle). Edit wbs/stage-0-harness.md/wbs/module-order.md to home the CODEOWNERS-degeneracy and manifest gaps now (rejected — active-rework collision; those gaps are the owner's to fold into the genesis sequence). Make the tuning a silent tweak (rejected — substantive instrument changes are logged, [D-108](0108-add-the-dry-run-build-simulation-instrument-the-workspace-s.md) precedent).
