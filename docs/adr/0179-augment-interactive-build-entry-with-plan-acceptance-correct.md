# Augment interactive Build entry with plan-acceptance; correct the falsified "plan-mode transitions are not hook-observable" claim (litigation alarm + authorization)

*Decided 2026-06-06 in the design workspace.*

## The decision

The locked [modes](../spec/systems/lifecycle/modes.md) Build-entry design ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md); re-locked through [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md)) is **re-litigated** to (a) **correct a falsified platform claim** and (b) **augment** the interactive Build entry with **plan-acceptance** alongside the existing operator-typed verb. This entry is the **litigation alarm + authorization** (the operator authorized the audited change via plan-mode approval, choosing "augment"); the **re-locks land under the resolve entry** [D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md) after the mandatory landed-text cold audit — the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)→[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) / [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)→[D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) pattern. [Q38](../reference/open-questions.md) is the question this resolves; [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)'s anti-choice deferred it to "that pass" — this is that pass.

  **The falsified claim (live-tested this session — the [§17](../principles.md) gold standard).** [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) rested the operator-typed verb on a platform claim — *"the platform does not reliably expose plan-mode transitions to the gate"* / *"`ExitPlanMode` plan-approval is not reliably observable to hooks"* (D-070 law 4 + rationale + anti-choice). A logging `PreToolUse`+`PostToolUse` hook was installed in this session's settings and **real plan accept/reject cycles run on current Claude Code**:
  - `PreToolUse` **and** `PostToolUse` both **fire on the `ExitPlanMode` tool call** (captured in the hook log).
  - **Accept** → `PostToolUse(ExitPlanMode)` fires; `permission_mode` leaves `plan`. **Reject** → `ExitPlanMode` is refused at the permission layer with **no `PostToolUse`**; `permission_mode` stays `plan`. So accept and reject are cleanly distinguishable.
  - The model cannot accept its own plan (acceptance is a human action), so an acceptance-keyed entry is **not self-electable**; a crashed hook simply fails to set the signal → stays Explore (**fail-safe**).

  This **falsifies** the claim — the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) pattern (a "verified" platform fact overturned by live testing). **Reconciliation:** there is **no dedicated plan-mode-*transition* hook event** (the standing GitHub feature requests #21282 / #14259), **but the `ExitPlanMode` *tool call* does fire the ordinary tool hooks** — the corpus conflated "no transition event" with "acceptance unobservable." The corrected durable fact: plan-acceptance is observable via the `ExitPlanMode` tool-call completion hook.

  **Carrier set of the falsified claim (ground-truthed against full text; append-only carriers NEVER edited — history exceptions; superseded by this entry):** **{[D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) (law 4 + rationale + anti-choice "Keep `ExitPlanMode` as a mechanical Build-entry trigger"), [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md) (anti-choice's "stands until that pass takes it up"), [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) (:1322 nit — the *hook-firing half only*)}**. **Surgical supersession:** D-178's same nit also states *plan mode forbids the Issue-logging Explore needs* — that half is **separately true and preserved** (it concerns plan mode's read-only nature, not whether hooks fire). **The carriers' decisions all stand unaffected:** D-070's other laws (session-scoped stance; allow-by-default gate; fallible §6 nudge; operator-legible; the verb as *an* entry path), D-177's plan-file carve-out, and D-178's carve-out + marker-not-path key. This claim is **distinct** from the deny-ignored-for-edits claim already corrected by [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)/[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md); that correction is not reopened.

  **The design (augment; final text + landed-text audit land under [D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md)).**
  - **Two interactive entry paths.** Build is entered by **EITHER (a) the operator-typed verb (unchanged — the path for builds that did not go through plan mode) OR (b) plan-acceptance.** (b) is a **modes-owned `PostToolUse` hook matching `ExitPlanMode`** that **sets the Build stance signal and nothing else**, then hands off to [build-orchestration](../spec/systems/lifecycle/build-orchestration.md)'s unchanged workflow (the modes-owns-the-signal / build-orchestration-owns-the-workflow split D-070 drained — not re-crossed).
  - **Discriminator = the `PostToolUse(ExitPlanMode)` event itself**, never a `permission_mode` value: acceptance offers three operator-chosen target modes (`auto`/`acceptEdits`/`default`) and `auto` is a gated preview mode, so only the *event firing* (and, as corroboration, that `permission_mode` *left* `plan` — target-agnostic) is durable. Rejection produces no event → never Build.
  - **Legibility ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) law 5) preserved.** A `PostToolUse` hook cannot inject conversational text, so the acceptance path is **announced by build-orchestration's announced kickoff** (the same "opening a draft PR and planning the work" surface the verb path uses), not by the hook. Entry remains **operator-initiated** — accepting a plan is a deliberate human act, not the silent/by-default self-election the stance model forbids.
  - **Honest tier (no over-claim).** Acceptance is **human-gated and honor-rate-free** — it removes [R11](../reference/risks.md)'s dropped-verb fragility — but is **not** framed as a "stronger" gate: the model originates the plan it presents, so a plan-spam/habituation surface exists, **bounded by per-plan human acceptance and the protected-branch merge wall** (still the only unbypassable wall; stance stays a [§6](../principles.md) posture, not the wall).
  - **Gate unchanged; scope fenced.** The Explore write-gate's denied building set is **untouched** — not shrunk toward a nudge (it still guards non-plan Explore, where the platform enforces nothing); Explore's Issue-logging is unaffected (it happens in Explore before plan mode). **Routine unchanged** — headless has no human approver, so the acceptance trigger cannot fire there; the `/engine-routine` scheduled entry stands.
  - **Plan-gate seam.** Plan-acceptance *enters* Build; build-orchestration's [plan gate](../spec/systems/lifecycle/build-orchestration.md) then runs as the substantive **spend/depth/coverage consent** — distinct from accepting the approach, and proportionate (a trivial change collapses it to a one-line headline). No plan-gate redesign.
  - **[D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) discipline.** The **durable principle** goes in the locked doc (*"Build entry may be triggered by plan-acceptance, observed via the plan-exit completion hook; rejection never triggers it; human-only; fails safe to Explore"*); the **dated mechanism** (`PostToolUse`/`ExitPlanMode`, the mode-leaves-`plan` corroboration, field names) lives in the Build-spec leaf + this log, **re-verified at the slice build** (incl. false-fire conformance: a Shift+Tab leave-without-approving and resume/subagent plan mode must NOT enter Build; the marker write uses the engine tool-runtime interpreter per the [hooks](../spec/systems/infrastructure/hooks.md) `:133` contract).

  **Carriers.** **Edited (locked; re-locked under [D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md)):** **{[modes](../spec/systems/lifecycle/modes.md)** (rewrite "Entering Build"; delete the false sentence; add the acceptance Build-spec leaf), **[hooks](../spec/systems/infrastructure/hooks.md)** (the `PostToolUse` owner-inventory gains modes as a third owner — a side-effecting non-blocking hook, block-budget untouched), **[modules/core](../spec/modules/core.md)** (a new `PostToolUse` wire on its locked manifest — the modes plan-acceptance Build-entry hook), **[build-orchestration](../spec/systems/lifecycle/build-orchestration.md)** (`:250` "the locked operator-typed Build entry" → "the locked Build entry", verb or plan-acceptance)}**. **Non-locked propagation:** [R11](../reference/risks.md) (de-risked — acceptance is the honor-rate-free primary path; update its closure line), [scenarios/build-session.md](../architecture.md#build-session-lifecycle) + [scenarios/product-design-intake.md](../architecture.md#product-design-intake) (both name the verb/cue entry), wbs/core-build-roadmap.md slices 21/26 (acceptance-trigger build-conformance). **Verified law-faithful, no edit (confirmed against text):** [glossary](../reference/glossary.md) "Mode (stance)" and [engine-architecture](../architecture.md) §7 name no specific trigger; [deviations](../reference/prototype-deviations.md) D2/D17/#12 — the four `operator-typed` skill roster is **unchanged** (augment adds a *hook*, not a skill; the verb is retained for non-plan builds). **Resolve [Q38](../reference/open-questions.md)** (delete; resolution captured here).

## Why

A locked trust document that asserts as "verified" a platform fact two live, operator-runnable tests on the current platform disprove is a direct hit on **auditability** and **trustworthiness** — and would have stranded the very capability the operator asked for. It is a justified re-litigation, not silent drift (the lock stops drift, not warranted edits). The augment **removes the friction** that opened this thread (a magic verb after every plan) and **de-risks [R11](../reference/risks.md)** (the fragile verb survives only as the no-plan fallback) **without weakening any guarantee**: the merge wall remains the only unbypassable wall, the deny-set is unchanged, and Routine is untouched. Keeping the dated mechanism in the log and only the durable principle in the locked docs applies the lesson [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)/[D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) were written to teach — a future platform change cannot re-falsify a locked doc. A four-lens cold **plan**-audit (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran against the plan before this authorization and reshaped it: it caught the D-178 carrier (the surgical supersession above), the undercounted re-lock set (hooks + modules/core mandatory, not contingent), the discriminator (the event, not `permission_mode==auto`), the announcement seam, and the "stronger gate" over-claim — all folded above.

## What we ruled out

**Replace the verb with plan-acceptance** (rejected — the operator chose augment; non-plan-mode "build this" flows would lose their trigger and be forced through plan mode, which forbids the Issue-logging Explore needs, the original [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) reason). **Shrink the Explore write-gate toward a pure nudge** ([Q38](../reference/open-questions.md)'s aggressive reading; rejected — the gate still guards non-plan Explore, where the platform enforces nothing). **Key the trigger on `permission_mode == "auto"` (or any specific target mode)** (rejected — `auto` is one of three operator-chosen accept outcomes and a gated preview mode; the durable discriminator is the `PostToolUse(ExitPlanMode)` event, with mode-left-`plan` as target-agnostic corroboration). **Frame acceptance as a "stronger" human gate** (rejected — [§6](../principles.md)/§7 over-claim; the model originates the proposal, so the honest tier is honor-rate-free-and-human-gated, bounded by the merge wall). **Leave the falsified claim because the verb still works** (rejected — a "verified" falsehood in a locked trust doc corrodes auditability; the deletion mandate + §7 require correcting it). **Bake the `PostToolUse`/`permission_mode` field names into the locked docs** (rejected — dated, version-brittle platform facts belong in the log + leaf; the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) discipline). **Edit the locked docs without the landed-text cold audit** (rejected — HARD lock gate; the audit + re-lock land under [D-180](0180-resolve-the-d-179-build-entry-augment-landed-text-cold-audit.md)).
