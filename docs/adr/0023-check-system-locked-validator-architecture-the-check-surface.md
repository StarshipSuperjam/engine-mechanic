# Check system locked: validator architecture, the `check` surface, and the suite/trigger grammar

*Decided 2026-05-22 in the design workspace.*

## The decision

Design and lock the check system as three reconciled pieces. **(1)** The [validation](../spec/systems/guardrails/validation.md) foundation is a **thin dispatching core over a registry of callable check-kinds plus rule data** — a closed *core* kind set (schema, shape, presence, coverage, coherence), extensible by modules registering callables, plus a `custom/script` escape hatch, kept as **diffable source**; **directly callable** (the module manager runs the coherence kind post-install, so module-install is a direct invocation, not a fifth trigger); a dangling/unresolvable kind is a finding everywhere **and fails the required check in CI**. **(2)** The **`check` surface** (already named tier-3 in the locked ontology, so additive with no re-lock) is designed: a `structured` rule with seven fields (`id`, `target`, `kind`, `params`, `tier` ∈ {`hard`,`soft`}, `suites`, `message`), governed by JSON Schema 2020-12, instances slug-named under `.engine/check/`, the `message` held to the **operator-communication standard** (clear and complete, never dumbed down; presence hard-checked, quality an audits-layer posture). **(3)** **Check-suites** are a validation-owned file-type (not a surface): thin declarations (name + trigger + execution context) whose rosters are **derived** from rules that self-declare their `suites`; the trigger *law* is fixed and the trigger *set* is additive data (v1: `pre-commit`, `pre-close`, `CI`, `audit-prep` — spanning hooks and control-plane workflows; `audit-prep`'s runner lands with [audits](../spec/systems/guardrails/audits.md)). Tier is intrinsic; **CI is the only unbypassable gate**, local triggers nudge, `audit-prep` reports. Membership is declared in the `suites` field and governed by module `provides`, so it stays in the module system **downstream of the CI harness exactly as locked [control-plane](../spec/systems/infrastructure/control-plane.md) requires** — **superseding the "check-suites as a wire" clause of [D-012](0012-provisioning-is-two-subsystems-on-one-manifest-grammar-modul.md)**. Resolves deviation D22 (no pre-commit framework — the commit-boundary run is a `PreToolUse` intercept) and folds prototype improvement #5.

## Why

The prototype's validator metastasized because check inventory and logic were fused; splitting rules-as-data from a small kind registry makes a new check *data* and keeps the foundation small as the rule set grows. Self-declaring membership derived from `provides` removes the install surgery Risk [R5](../reference/risks.md) exists to kill while keeping control-plane's locked membership claim true (no re-lock). Because the ontology already names `check`, designing its record is the sanctioned additive path. The cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran on the design and again on the authored docs with four lenses; technical-feasibility verified JSON Schema 2020-12 and the GitHub required-check binding. Blocking/serious findings — the `audit-prep` trigger framing, the three-doc membership-ownership wording, an unresolvable `hard` rule failing closed at CI, best-effort locals versus the sole CI guarantee, and the operator-facing gate statement — were resolved before the lock.

## What we ruled out

A monolithic validator that accretes checks (rejected — the prototype's god-file failure). Arbitrary data-expressed predicates / a mini-DSL (rejected — complexity and an injection surface; a closed kind set plus a script escape hatch is honest). A third `posture` rule tier (rejected — a check is mechanical by definition; posture is prose observed by presence checks). Suites that enumerate their rules with module wiring mutating a central list (rejected — the R5 install surgery). A frozen four-trigger vocabulary in the locked doc (rejected — leaf-as-law; the set is additive). A git-native pre-commit hook (rejected — fails closed on its own bug and spawns a parallel hook system). Compiled kind binaries (rejected — not diffable, platform-specific). A dumbed-down operator `message` (rejected — informed consent requires understanding).
