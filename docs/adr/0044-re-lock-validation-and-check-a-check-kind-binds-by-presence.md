# Re-lock validation and check: a check-kind binds by presence (§14), and is not an interface

*Decided 2026-05-25 in the design workspace.*

## The decision

Under **explicit operator approval**, re-litigate two locked docs — [validation](../spec/systems/guardrails/validation.md) and [check](../spec/systems/surfaces/check.md) — to reconcile how a module adds a check-kind, the follow-on [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md) deferred. Both now state: a module adds a check-kind by **providing a conforming callable, discovered by presence** — the [derived binding by presence principle §14](../principles.md), the same discovery axis as the agent roster and check-suite membership — **not through a wiring seam** (the locked [module-system](../spec/systems/grammar/module-system.md) closed seam vocabulary has no check-kind directive, and already names the validation `custom/script` check-kind as "a different axis entirely" from wiring). Validation's "register an additional kind … **through wiring**" was the lone phrase contradicting that locked neighbour; check's "register an additional kind as its own callable" carried no falsehood but is reconciled to the same provide-and-discover framing for identical wording across all three docs (the operator chose maximum crispness). [Module-system](../spec/systems/grammar/module-system.md) is the anchor and is **unchanged**. **Correction to [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)'s anticipated approach (caught by the cold audit):** D-042 expected this pass to "name check-kind as the canonical interface-implementation instance and add it to the interface set." It is **not** added — a check-kind is **not** an [interface](../spec/systems/surfaces/interfaces.md). The interface surface's defining law is that the contract **names a default/fallback** surfaced to the operator when active (for degradability); a check-kind has **no fallback** — a dangling/unregistered kind is promoted to a **finding**, the opposite posture. A check-kind binds by presence (§14, the broad discovery axis) but is not a degradable interface (§5). The interface v1 set stays `search` + knowledge representation/retrieval; the [glossary](../reference/glossary.md) Check-kind entry is aligned to provide-and-discover. Both docs re-locked under this decision (`lock.py --relock`).

## Why

§14 (discovery by presence) and the `interface` surface (a swappable implementation behind a contract with a named fallback) are distinct: §14 is the broad discovery axis (rosters, suite membership, check-kinds, interface implementations, workflow activation), while an interface adds the narrower degradability contract. Conflating them — D-042's anticipated "check-kind is an interface" — would force a contrived fallback onto a kind that has none, or except it from the interface's own defining law; the cold audit's architect lens caught this before it locked. Reconciling the wiring phrasing is the genuine fix: it aligns validation and check with the locked module-system, which already excludes a check-kind seam, so the three docs now agree and the latent contradiction the [interfaces](../spec/systems/surfaces/interfaces.md) design exposed is closed. The cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran across the four lenses on this reconciliation (jointly with [D-045](0045-re-lock-contracts-a-specification-is-a-doc-nature-not-a-cata.md)); its findings were resolved before this entry: the check-kind-is-not-an-interface correction (adopted), the third-locked-doc scope question for `check` (the operator chose to reconcile it for crispness; it was not false, so leaving it was also sound), and confirmation that no further locked doc carries the "through wiring" framing for check-kinds (grep: the phrase was unique to validation). Technical-feasibility verified presence-discovery is a sound validator-plugin pattern (entry points / scanned directory / naming convention) and the per-doc `--relock` mechanics.

## What we ruled out

Add check-kind to the interface set per D-042's literal plan (rejected — overloads the interface concept; a check-kind has no fallback and fails to a finding, the opposite of the interface degradability law). Leave validation's "through wiring" as loose wording with no edit (rejected — it directly contradicts the locked module-system closed seam vocabulary; the interfaces design made the contradiction live). Reconcile validation but leave check's "register … as its own callable" (rejected by the operator in favour of identical framing across all three docs; either choice was defensible since check stated no falsehood). Edit module-system instead (rejected — it is already correct and is the anchor the other two align to). Bundle with the contracts reconciliation under one decision (rejected — they are independent reconciliations touching disjoint locked docs; separate decisions, the [D-035](0035-re-litigation-policies-retargets-the-contract-threshold-narr.md)/[D-036](0036-re-litigation-contracts-retargets-the-default-session-narrat.md) precedent).
