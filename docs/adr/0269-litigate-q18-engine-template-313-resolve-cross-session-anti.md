# Litigate Q18 (engine-template #313): resolve cross-session anti-habituation by **collapse-when-unchanged**; [boot](../spec/systems/lifecycle/boot.md) owns a **local, gitignored standing-alarm presentation ledger** (refining "read-only" to **read-only of *canonical* state**); re-lock boot

*Decided 2026-06-28 in the design workspace.*

## The decision

Under the litigation-alarm protocol (operator-approved this session) and after a **dedicated four-lens cold audit** (adversarial · architect/propagation · non-engineer-operator · technical-feasibility, no shared context), **resolve Q18** — the owner-open anti-habituation residual [D-084](0084-re-litigate-boot-constraints-correct-the-post-compaction-pla.md) parked — and **re-litigate locked [boot](../spec/systems/lifecycle/boot.md)** to land it. The trigger is engine-template **#313** (engine-opened): the boot **"Project status" card repeats verbatim on every resume-after-pause**, which the operator asked to stop; the build session correctly refused to build the suppression (it would break the **present-marker** grounding detector and the underlying need is the open design question Q18), and routed it here to decide. **Resolution — collapse, not suppression.** A standing governance alarm renders on **every** session it is live (present-marker presence unchanged; **all-clear never collapses** — the grounding detector survives intact), but a standing alarm whose **structured condition is unchanged since last relayed in full** collapses to a **terse one-line reminder that keeps the consequence sentence and the offer-to-fix**, while a **new / changed / worsened** condition gets the full plain-language relay; new-versus-old is carried in **words** ("*Still …*" vs "*New:* / this got worse"), never by length alone, so a first-time operator can decode it. **Owner — boot.** The cross-session memory is the **standing-alarm presentation ledger**: a single **local, gitignored, non-canonical** marker (a fingerprint of each alarm's **structured condition** — the per-branch evaluated-rules signal; a [§15](../principles.md) weakening's identity — plus a *shown-in-full* marker), **read and written by boot's own `SessionStart` hook**, deterministic, **fail-toward-full** (missing / unreadable / write-failed / ambiguous ⇒ full relay — repetition is the tolerable failure, suppression is not), **isolated** from memory's `SessionStart` consolidation sweep, rooted at a stable per-instance path (never an ephemeral worktree). This **refines boot's read-only law** from "all orientation is read-only; none regenerates derived state" to **"read-only of *canonical* state — never regenerates derived or committed state; its one local write is the gitignored, non-canonical presentation ledger,"** boot's sole write. **Operator-facing promise** (verifiable without reading code, folded into boot's relay copy): a problem still here shows as a short reminder that still names the risk and still offers the fix; a new/worsened one always shows in full; **a problem vanishing from the block means the engine verified it fixed, never that it stopped checking.** **Q18 closure scope:** resolved via the collapse mechanism; **escalate-phrasing and snooze-with-re-raise are consciously declined** (anti-choices); the non-actionable-alarm residual Q18 named is handled by collapse **retaining the consequence**, not left open. **Re-lock:** `python3 lock.py --relock systems/lifecycle/boot/README.md --decision D-269`; `python3 validate.py` green. **The build owes one-way conformance** (engine-template #313 lineage, to be filed citing this entry via [`issue_author.py`](https://github.com/StarshipSuperjam/engine-template) + the `engine` label): realize the ledger + collapse in boot's `SessionStart` hook to the laws above (hook-owned read/decision/write; structured-condition fingerprint; fail-toward-full; sweep-isolation; stable per-instance path), with the terse wording, the ledger's on-disk form, the ledger's `.gitignore` registration (it rides [core](../spec/modules/core.md)'s existing session-scoped-ephemera class), and the concurrent-session write discipline (which must preserve fail-toward-full under a race) as build-spec leaves.

## Why

Q18 asked the design to "decide the owner and the mechanism"; #313 made it a live operator ask, not a speculative nicety, so leaving it deferred merely preserves the friction. The **four-lens cold audit reshaped the fix** and earned its keep. **(technical-feasibility, decisive)** the audit ground-truthed the platform fact #313 lives in: a **resume is a fresh `SessionStart` with `source:"resume"` whose `additionalContext` injection is *reliable*** — distinct from the field-unreliable `compact` source — so the full boot pack *does* re-render on every resume (hence the verbatim repetition), and the mechanism correctly targets that moment; it also proved the **simpler in-context option** (the AI noticing within its own live context that it already showed the card) **insufficient** — it does not survive the resume/compaction boundary — confirming the on-disk ledger is the right tool, and that the read/decision/write must sit in the **deterministic hook**, never model discretion, with the fingerprint over the **structured condition, not the rendered prose** (prose is a build-spec leaf, model-reworded; hashing it would never collapse). **(non-engineer-operator, blocking, folded)** the word "**unchanged**" reads to a non-engineer as "*resolved / fine now*," inverting the alarm — replaced by a terse line that **keeps the consequence and the fix offer** and labels old-vs-new lexically; and the boot doc now states the **plain-language promise** including "absence means verified-fixed, never stopped-checking." **(adversarial / architect, serious, folded)** the collapse is biased **fail-toward-full** on any loss, collision, or fingerprint ambiguity — the safe direction for the highest-severity signals; the residual (a worsening that does not move the structured-condition fingerprint) is **named in [R19](../reference/risks.md)**, bounded by fingerprinting the structured condition and by the offer-to-fix that clears actionable conditions. The **present-marker contract is provably preserved**: its presence check stays binary and content-blind, the all-clear never collapses, and only the *alarm payload behind* the marker varies — reconciled in the [glossary](../reference/glossary.md) *Operator-presentation relay* definition. Boot is the right owner because the ledger is **presentation history — intrinsically the renderer's concern**, not detection state; this is the proportionate home (one locked doc moves) and the refinement keeps boot's invariant honest ("read-only of *canonical* state") rather than breaking it. **Propagation per the matrix:** [boot](../spec/systems/lifecycle/boot.md) (re-locked end-state — law refinement, the anti-habituation section, the resume-source row + clarifier, the design commitments, the build-spec leaves); ## What we ruled out

**Name [telemetry](../spec/systems/guardrails/telemetry.md) the owner** (rejected, overriding both [D-084](0084-re-litigate-boot-constraints-correct-the-post-compaction-pla.md)'s logged anti-choice and the two cold lenses that tagged boot-as-owner blocking — with rationale: the ledger is **operator-presentation history, the renderer's concern**, not *detection* state §16 keeps with the owner; detection stays with control-plane (protected-branch) and §15 (weakening). Telemetry owns **neither** alarm's detection, and its markers are *signal-observation* epochs (first/last-seen) — a different axis from operator-presentation; routing these alarms through telemetry + adding a presentation-write class would re-litigate its **locked "exactly-one-write, issues-only, mechanical, report-never-heal"** core — a larger, worse change than refining boot. The §16 anti-pattern is binding to an **undeclared detection seam**; boot writing its **own** presentation marker is not that.) **Name [memory](../spec/systems/cognitive/memory.md) the owner** (rejected — its locked engine/product split holds *project narrative recall* and **never** engine self-monitoring; a governance-alarm-shown record is engine state, excluded by lock). **Name [attention](../spec/systems/cognitive/attention.md) the owner** (rejected — its locked determinism forbids mutable/learned state; a per-alarm "shown" counter is exactly the scored store [§3](../principles.md) bars). **Commit the marker** (rejected — it needs no protected-branch persistence; it is single-operator, single-machine, fail-safe-on-loss, so the [D-205](0205-authorize-pinning-the-offline-cache-committer-the-audit-dige.md) audit-digest freight committer and the "no legal committer" problem do not apply; committing it would re-open the artifact-warrant question for no benefit). **Acknowledge-and-snooze-with-re-raise** (rejected — adds an operator command (friction, [§17](../principles.md)) and a real suppression window in which a worsening could hide behind a snooze; collapse needs no operator action and never fully suppresses). **Escalate-phrasing** (rejected — keeps the alarm loud but never quieter, the opposite of #313's ask; a worsening already re-escalates to full relay under collapse, for free). **The simpler in-context-only memory** (rejected — does not survive the resume/compaction boundary, the exact boundary #313 crosses; it would silently fail to collapse precisely when the operator complains). **Keep the word "unchanged" in operator copy** (rejected — a non-engineer reads it as "resolved"; the terse line must keep the consequence + offer and label old-vs-new lexically). **Leave Q18 deferred / close #313 won't-fix** (rejected — a live operator ask with a small, bounded, fail-safe resolution; deferring only persists the friction the build cannot work around). **Open a new risk / principle / `designed`-tier substrate doc** (rejected — the residual folds into existing [R19](../reference/risks.md); the resolution applies existing principles; the ledger is a boot-owned leaf, not a new system, so no new `systems/` doc — [R6](../reference/risks.md) anti-sprawl).
