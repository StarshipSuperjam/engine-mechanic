# Own the engine-label scheme in control-plane (re-litigation + re-lock); resolve Q28

*Decided 2026-05-29 in the design workspace.*

## The decision

**Re-litigate the locked** [control-plane](../spec/systems/infrastructure/control-plane.md) ([D-122](0122-enumerate-the-branch-ruleset-protection-floor-in-control-pla.md)) to **own the engine-label scheme** — the GitHub Issue marking the product-design dry-run ([D-125](0125-dry-run-the-product-design-module-not-build-ready-a-cross-cu.md)) surfaced as **consumed by ~8 living docs but pinned by none** ([Q28](../reference/open-questions.md), hereby resolved). The scheme lands as a **contract** in a new §"Engine Issues and the label scheme": a single **engine-domain label** the engine applies to every Issue it creates (its presence = engine-owned, its absence = ordinary product backlog — the subject-of-claim split decided at [D-039](0039-reports-self-improvement-scope-engine-only-self-monitoring-o.md), now given a living owner), plus a **distinct spec-Issue marker label** identifying a [product-design](../spec/modules/product-design.md) spec Issue, which [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) detects at Plan to resolve Issue → spec → acceptance criteria as the review referent. **Both markers are GitHub Issue labels** (the mechanism-class is pinned); consumers **read the label by its presence and never mutate it** (control-plane owns the channel's *definition*; each consumer owns only its own acting-mechanism over the channel, [§16](../principles.md)). The **concrete label strings**, the **apply mechanism** (issue-template default vs explicit label at programmatic creation), and the **provisioning step that ensures the labels exist** (automatic at bootstrap — the operator never hand-creates a label) stay **deferred build-spec leaves**; because the strings and any template copy are operator-facing they are bound by the plain-language law. A consistency clause in §"Boundary" places the scheme as control-plane-governed infrastructure, not a catalogued surface. The doc is **re-locked under this decision**.

## Why

Justified re-litigation, not drift ([D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md) posture) — completing a contract the locked grammar already presupposed: [ontology](../spec/systems/grammar/ontology.md):121 routes GitHub issue infrastructure to control-plane/topology, control-plane already owns the issue templates + the "issue scaffold" [telemetry](../spec/systems/guardrails/telemetry.md) routes debt to, and [D-039](0039-reports-self-improvement-scope-engine-only-self-monitoring-o.md) fixed the engine/product split as *a label* — yet no living doc named the owner. The owner **must be a foundation, not the optional [product-design](../spec/modules/product-design.md) module**, because required-core systems ([telemetry](../spec/systems/guardrails/telemetry.md), [state](../spec/systems/cognitive/state.md), [attention](../spec/systems/cognitive/attention.md), [audits](../spec/systems/guardrails/audits.md), [memory](../spec/systems/cognitive/memory.md)) read the domain label whether or not product-design is installed; the spec-marker *definition* lives here too so build-orchestration recognises its presence/absence even when the optional producer is absent. The **HARD cold-session design audit** ran four independent cold-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect); **all four endorsed control-plane as the only defensible owner**. Findings folded: pin the mechanism-class (both markers are labels, closing a "label vs field vs title-prefix" ambiguity), the single presence-based domain label (no engine/product mutual-exclusion to police), the crisp §16 ownership split, the operator plain-language law on label/template strings, automatic label provisioning, and a single authoritative [glossary.md](../reference/glossary.md) entry cross-linked from the existing *Debt register* / *Product spec* terms. `python3 lock.py --relock systems/infrastructure/control-plane/README.md --decision D-132`; `python3 validate.py` green. **Propagation:** control-plane re-locked + locks.yaml (ratified_by D-132); [glossary.md](../reference/glossary.md) gains the *Engine-label scheme* term (+ two cross-links); [product-design](../spec/modules/product-design.md) reconciled as the spec-marker emitter; [github-projects-sync](../spec/modules/github-projects-sync.md) Status trued to build-ready (Q28-resolved); [open-questions.md](../reference/open-questions.md) drops Q28 and gains **Q30** (the acceptance-criteria content shape, routed to product-design's own pass); the dry-run ledger annotated (product-design + github-projects-sync unblocked; scorecard + remediation-thread-1 trued up); this entry. **No edit owed** to the locked consumers ([build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [telemetry](../spec/systems/guardrails/telemetry.md), [audits](../spec/systems/guardrails/audits.md), [state](../spec/systems/cognitive/state.md), [attention](../spec/systems/cognitive/attention.md), [memory](../spec/systems/cognitive/memory.md), [policies](../spec/systems/surfaces/policies.md)) — each binds the "engine-labeled Issues" channel (§16) and now resolves to the owned definition; verify-only and current for [scenarios/product-design-intake.md](../architecture.md#product-design-intake) + [remediation-loop.md](../architecture.md#the-detect-to-remediate-loop) (pure relays), [risks.md](../reference/risks.md), [engine-architecture.md](../architecture.md). Deferred build-spec-leaf concerns the audit surfaced (label-enumeration pagination / eventual-consistency; label rename/delete integrity) are build-time, not contract-level; degradation is already owned by [state](../spec/systems/cognitive/state.md) (committed count/pointer) and build-orchestration (offline routine = fail-safe no-op).

## What we ruled out

Home the scheme in **[product-design](../spec/modules/product-design.md)** (rejected — it is optional, and required-core systems consume the domain label regardless; an optional module cannot own a foundation contract). Home it in the **[ontology](../spec/systems/grammar/ontology.md) surface catalog** (rejected — ontology:121 explicitly disclaims platform files; a GitHub label is issue infrastructure, not an engine surface). **Fold the acceptance-criteria content shape** (free prose vs structured) into this control-plane litigation (rejected — that is product-design's spec-format concern, optional-module-local and blocking nothing; routed to product-design's own dry-run/lock pass as [Q30](../reference/open-questions.md), per operator scope direction). **Re-litigate [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) too** for the spec-detection (rejected — its detection is its own consumption *over* the channel, locked behavior; §16-compliant, so no edit and the litigation stays one locked doc; the audit's contrary blocking finding was checked and refuted). **Mandate an auto-label GitHub Actions workflow** (rejected — rests on the audit's mistaken claim that issue templates cannot default-label; GitHub markdown templates and issue forms *do* support default `labels:`, and the apply mechanism is a deferred build-spec leaf regardless). **Skip the cold-session audit** or edit the locked doc without re-litigation (rejected — the CLAUDE.md HARD gate; `lock.py` owns the fingerprint).
