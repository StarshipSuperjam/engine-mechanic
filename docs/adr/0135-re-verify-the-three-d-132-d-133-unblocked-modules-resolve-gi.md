# Re-verify the three D-132/D-133-unblocked modules; resolve github-projects-sync's board-config coherence-home by reframing it as gitignored data + a committed schema; reject the module-system coherence-category re-litigation (cold audit)

*Decided 2026-05-30 in the design workspace.*

## The decision

Re-ran the dry-run build simulation over the three modules the [D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md) sweep left NOT build-ready and that [D-132](0132-own-the-engine-label-scheme-in-control-plane-re-litigation-r.md)/[D-133](0133-type-the-cron-fired-audit-persona-re-litigate-agents-role-tr.md) unblocked — [product-design](../spec/modules/product-design.md), [audit-library](../spec/modules/audit-library.md), [github-projects-sync](../spec/modules/github-projects-sync.md) — mandatory because the instrument is non-deterministic and must re-run after a substantive design change (dry-run.md §7), and a clean run is each module's packaging-lock build-readiness precondition. **Verdicts:** product-design **BUILD-READY** (the D-132 engine-label scheme is exercised clean — spec-Issue emission is a [§16](../principles.md) relay; [Q30](../reference/open-questions.md) correctly stays product-design-owned and non-blocking); audit-library **BUILD-READY** (the D-133 `audit` role types the persona in full; the builder's [serious] "audit `output-contract` severity-profile *form* is unpinned" was **REJECTED on ground-truth** — the form IS pinned by [agents](../spec/systems/surfaces/agents.md):64-73 + [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)'s per-consumer-enum-over-`finding.v1` + the `.v1` fixture-tested profile owner; only the members are a build-time leaf, so the Q27 pattern does **not** recur). github-projects-sync surfaced one **confirmed [serious]** the D-127 sweep glossed: its **board-coordinate config** had no coherence-clean home — [module-system](../spec/systems/grammar/module-system.md):134-138's file-ownership leg admits only surface-grouped `provides` entries or the closed named-foundation-infra set, and an opaque board config is neither, so the module's ":65 real `provides` home / not a coherence orphan" claim — the framing [D-099](0099-flesh-the-github-projects-sync-module-doc-to-designed-native.md) introduced when it fleshed the module to `designed` — was unsubstantiated (this entry supersedes that board-config-home framing; D-099's other dispositions, including its rejection of a CI workflow as an orphan, stand). **Resolution (designed-doc fix; no locked doc touched):** the board-coordinate config is **per-instance runtime state populated by setup**, so it is **gitignored** — outside the coherence file-ownership set entirely, like `mcp` data and the memory ledger ([§4](../principles.md)/[§5](../principles.md)/[topology](../spec/systems/infrastructure/repository-topology.md) law-5 / [module-system](../spec/systems/grammar/module-system.md):151) — and **dropped from `provides`**; the module instead ships a committed **board-coordinate config schema** (a `schema`-surface instance; precedent: [audit-library](../spec/modules/audit-library.md)'s concern-entry schema) as the substrate, and adds a keyed/reversible **`gitignore`** wire for the config-data path (so `wires: hook + gitignore`). github-projects-sync is thereby **build-ready**, with no `provides` entry that is a non-surface committed file.

## Why

The github finding first suggested re-litigating the locked [module-system](../spec/systems/grammar/module-system.md) to mint a third coherence "owner-claimed non-surface declarative-data" category — to settle the board config together with the audit concern-list/digest and the [state](../spec/systems/cognitive/state.md) cursor, all non-surface committed files. The operator approved exploring it, and per the CLAUDE.md HARD gate a **four-lens cold-session design audit** (adversarial · technical-feasibility · non-engineer-operator · architect, cold-context, the proposal inlined) ran against the proposal **before** any edit. It returned two **BLOCKING** findings (adversarial, architect) + three serious, each ground-truthed by the orchestrator against source: **(1)** [D-049](0049-re-lock-topology-and-module-system-file-precise-codeowners-o.md)'s anti-choice **already rejected** folding non-surface files into `provides` ("strains the locked '`provides` … grouped by surface' definition, since infra artifacts are not surfaces"), choosing the closed named-infra carve-out — the proposed open category re-opens settled ground; **(2)** the [ontology](../spec/systems/grammar/ontology.md) **already owns the concept** — tier-4 **system-owned outputs** ([glossary.md](../reference/glossary.md):10, ontology:81) cover the audit digest, and [audits](../spec/systems/guardrails/audits.md):186-187's direct-schema-kind-invocation covers the concern-list, both already clean; **(3)** the **state cursor** is a topology-law-5 committed config/pointer already in `core`'s `provides`, already clean; **(4)** the board config is **runtime data** best gitignored — the `tool`-subtree escape is invalid (`tools` is class `code`, schema-less, [tools](../spec/systems/surfaces/tools.md):29); **(5)** minting the category, done correctly, would tri-fan across **three** locked docs (module-system + ontology + audits) to name a concept two already own — failing the **adapt-to-locked-systems default** (CLAUDE.md) and [R6](../reference/risks.md). The audit therefore drove a **reversal** to the zero-re-lock path: adapt github-projects-sync (gitignore the data + ship its schema), leaving every locked doc untouched — the litigation-alarm protocol working as designed (the burden is on the current work to fit the locked systems, and it does). **Propagation per the matrix:** [github-projects-sync](../spec/modules/github-projects-sync.md) reframed (`provides` → config *schema*, not config data; `wires: hook + gitignore`; the Manifest / Wiring / contributor-wall / design-commitment prose reconciled; the §4 framing corrected — ship the schema, gitignore the data); wbs/dry-run-ledger.md — the 2026-05-30 re-run recorded (the two build-ready verdicts + the github [serious]) and **annotated** "Resolved by D-135" (the frozen verdict not rewritten); this entry. **Verified no-change with rationale (logged, not silent):** [module-system](../spec/systems/grammar/module-system.md) · [repository-topology](../spec/systems/infrastructure/repository-topology.md) · [ontology](../spec/systems/grammar/ontology.md) · [audits](../spec/systems/guardrails/audits.md) · [core](../spec/modules/core.md) — **no edit** (the whole point; the cursor/concern-list/digest are already clean under the existing locked grammar, the audit confirmed); [audit-library](../spec/modules/audit-library.md) · [product-design](../spec/modules/product-design.md) (re-verified build-ready, no doc change owed); [modules/README.md](../reference/module-catalog.md) (github stays `optional`/`depends: core`; the catalog tracks neither `wires` nor schema instances); [glossary.md](../reference/glossary.md) (no new term — the resolution uses existing terms); [engine-architecture.md](../architecture.md) · [risks.md](../reference/risks.md) (no risk opened/closed). `python3 validate.py` green; **lock fingerprints unchanged** (no locked doc edited). The three modules' **packaging locks remain separate later passes**, each owing its own fresh cold-session design audit + operator go.

## What we ruled out

**Mint a third `module-system` coherence category** ("owner-claimed non-surface declarative data"), re-litigating the locked doc (rejected on the cold audit — re-opens [D-049](0049-re-lock-topology-and-module-system-file-precise-codeowners-o.md)'s logged anti-choice, duplicates the ontology's tier-4 system-owned-output concept, and tri-fans across three locked docs to name what two already own; fails the adapt-to-locked default + [R6](../reference/risks.md)). **A one-clause `module-system` clarification** completing D-049's carve-out (rejected — the board config is better gitignored regardless and the cursor/concern-list/digest are already homed; hardening the locked text against cold readers is not worth a re-lock against R6, though the cold re-run builders' stumble on the text is noted as the residual). **Keep the board config a committed empty `provides` file** (rejected — it is per-instance runtime state, not template-shipped content; committing it strains the surface-grouped `provides` reading and is the unsubstantiated "real `provides` home" claim the re-run flagged; gitignoring it is the honest §4 application). **Home the board config under the `tool` surface subtree** (rejected — `tools` is class `code`, carries no schema, [tools](../spec/systems/surfaces/tools.md):29; a schema-governed config is not code). **Log the re-run without re-verifying, or take the D-132/D-133 build-ready assertions on trust** (rejected — dry-run.md §7 mandates re-run after a substantive change; the re-run earned its keep by surfacing the github finding the assertion had glossed). **Skip the cold-session audit on the re-litigation proposal** (rejected — the CLAUDE.md HARD gate; the audit is exactly what caught the over-scope and saved a needless re-lock).
