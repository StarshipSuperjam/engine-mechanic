# Authorize completing the audit's off-repo memory-read enablement: re-open locked [audit-library](../spec/modules/audit-library.md) (D-148), [provisioning](../spec/systems/infrastructure/provisioning.md) (D-222), [audits](../spec/systems/guardrails/audits.md) (D-234) (+ [memory](../spec/systems/cognitive/memory.md) D-238 in-radius) to specify the cross-repo read credential, correct the dead-end disclosure, and gate digest belief-content on repo visibility (engine-template #224)

*Decided 2026-06-23 in the design workspace.*

## The decision

Authorize re-opening the named locked docs to **complete a deferral the locked text already gestures at**: the self-audit's headline "stale saved-memory beliefs" check needs the off-repo backup, but its read **cannot fire on the scheduled substrate** and the disclosure that should turn it on is a dead end (engine-template #224). [D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md) bridged the gitignored-memory limit with a **pure-consumer read of memory's [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) backup + an in-digest disclosure** when "no backup is configured"; [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)'s cold audit then **named the cross-repo-access precondition** (a *separate private repo* needs access the own-repo workflow token lacks) and **homed its remedy to "an operator step owned by [provisioning](../spec/systems/infrastructure/provisioning.md)"** — but provisioning's locked first-run leaf ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)/[D-222](0222-resolve-the-d-221-first-run-license-clear-re-litigation-land.md)/`:766`) lists the backup destination/scope-grant/cadence UX and is **silent on the audit runner's read access**. So the locked corpus describes a precondition with no enablement: on the default GitHub-Actions substrate the own-repo `GITHUB_TOKEN` is repo-scoped and **provably cannot reach the separate private vault**, the read never runs, and the "actionable" no-backup disclosure points at a backup-setup step that **does not complete the job** (verified against the live build + GitHub docs by the plan-stage four-lens cold review). The fix lands in **three components reasoned separately** (the architect-lens vehicle-split, the [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md) multi-finding-one-entry discipline): **(A) disclosure correction — additive.** Name the **real two-part precondition** (the backup exists *and* the scheduled run is granted vault read-access) as **one gated outcome** with concrete turn-on steps, replacing the dead-end "set up a backup"; overturns no anti-choice ([D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)/[D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) *deferred* enablement, never forbade it). **(B) the read credential — a pure-consumer read enabled by a provisioning-owned first-run grant.** The dependable enablement is a **least-privilege read-only credential** (a fine-grained PAT, `contents:read`, scoped to the single vault repo), **provisioned at first-run setup and stored as the scheduled audit's repo secret** — explicitly distinct from the own-repo `GITHUB_TOKEN` (cannot reach the vault) and from `CLAUDE_CODE_OAUTH_TOKEN` (authenticates the Claude run, not the vault read). **Seam adjudication:** this is the same §16 **pure-consumer** read [D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)/[D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) already ruled needs **no memory change**, enabled by a **provisioning-owned credential grant** ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) already homes first-run grants to provisioning), so **memory's export/restore mechanism is not widened** — memory stays its sole owner. The one reservation engaged is [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)'s "a stored credential adds friction + surface," which was scoped to the **interactive bootstrap** (where the operator's own `gh` web-flow scope-grant was the better path and the Actions token lacked `admin:repo_ruleset`); the scheduled audit read is **non-interactive and cross-repo** — no interactive alternative exists at cron time and the own-repo token provably cannot reach the vault — so a least-privilege read-only single-repo PAT is the **minimum-surface mechanism the platform allows**, accepted with eyes open (a new risk entry names the standing-credential surface) and framed as a **heavy-consent trust gate** (the uv-install precedent): platform vocabulary translated at the surface, the **shared-vault blast radius disclosed at paste-time** (one secret reads *every* co-located namespace, [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)) with the **per-project escape actionable there**, steered to a **no-expiry** token, re-armed via the existing staleness backstop with **PAT-specific recovery copy**. The **committed-pointer-for-CI** need (a CI checkout sees only committed files, so the configured pointer must be committed+pushed for the run to find the vault) is **reclassified as a build-owe, not new grammar**: memory already fixes the committed destination pointer (topology law 5 carve-out, [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)) and provisioning already owns writing it at first-run — the build simply has not implemented commit+push — so at most a clarifying disposition that "committed pointer" means committed to the project repo so CI sees it. **(C) digest belief-content gated on repo visibility — the one genuinely new bound.** The committed audit digest may surface **this project's namespace-scoped** saved-belief content **only when the project repo is private**; on a **public** repo the engine **structurally omits belief specifics and discloses the limit** (degrade-and-disclose). Grounded against [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md) (which governs the experiential **store** — never committed; a derived audit **finding** referencing a belief is a distinct surface) and engaging [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)'s anti-choice head-on: [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md) fixed "no engine-applied bound on the **flip** exposure" for the **vault** surface; this bound governs a **different** surface (the committed digest), so it does not contradict D-238's vault-flip reasoning, and [§7](../principles.md) names what it cannot do — the gate stops *future* digests but cannot unpublish a *past* one after a later public flip. Cross-project leakage is already structurally prevented (the read projects only this namespace). **Blast radius (honest):** likely-edited locked docs are **audit-library** (A/B/C delivery), **provisioning** (A/B first-run grant + UX), **audits** (C digest-contract bound); **memory** is named in-radius but the **lean is verify-no-edit** ([D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)/[D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) pure-consumer precedent; [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md) governs the store, not the digest), confirmed by the landed-text audit, not pre-committed to an edit. Non-locked carriers: **[constraints.md](../reference/constraints.md)** (pin the cross-repo-read platform fact — own-repo `GITHUB_TOKEN` cannot reach a separate private repo, the least-privilege fine-grained PAT is the cross-repo read vehicle; extends the [D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)-logged audit-substrate line), **[risks.md](../reference/risks.md)** (a new entry for the standing CI-resident vault-read credential whose shared-vault grant spans every co-located namespace + access-grant maturity, or an [R2](../reference/risks.md) amendment), **[engine-architecture.md](../architecture.md)** (check + disposition — the master index is silent on the cross-repo read), **[scenarios/first-run.md](../architecture.md#first-run-provisioning)** (carrier: the first-run credential-provisioning step). Verify-no-edit + logged: repository-topology law 5 (re-confirm config-not-data holds for the committed pointer), [glossary.md](../reference/glossary.md) (no new term, [D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md) precedent), [modules/README.md](../reference/module-catalog.md) (catalog/graph unchanged). **Protocol:** the **plan-stage four-lens cold review** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) already ran against the proposed shape and the operator weighed its findings (it corrected a fabricated "public-template pointer leak," an under-counted blast radius, and a D-007/git-history hole in the bare privacy posture — all folded above); the operator's two governing decisions are recorded here — **Path A** (GitHub Actions + least-privilege vault token) over the Cloud-Routine/both/disclosure-only alternatives, and the **structural-gate, private-only** digest-privacy posture. The **landed-text four-lens cold audit** re-runs against the on-disk edits and re-adjudicates the (B) seam and the (C) anti-choice before the re-lock; **[D-242](0242-resolve-the-d-241-audit-memory-read-enablement-the-landed-fo.md)** resolves with the re-locks in dependency order (memory if touched → audits → provisioning → audit-library) via `lock.py --relock`. The complete spec is filed as the engine-template #224 build-owe citing D-242.

## Why

This clears the justified-re-litigation bar: not a design weakened to fit current work, but the **completion of a deferral the locked docs already point to**, directly engaging — not papering over — the recorded grounds. The lock guards against *silent drift*, not *justified completion*; here three locked docs jointly describe a precondition with no enablement, and the "actionable" disclosure ([D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)) is provably a dead end. The **seam holds on precedent**: [D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md) and [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) both ruled the backup read a [§16](../principles.md) pure consumer of memory's [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) export that widens nothing, and [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md) already homes first-run credential grants to provisioning — so the credential is consumer/provisioning-side, and memory remains the sole owner of the mechanism it always owned. The credential's only friction with a recorded decision is [D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)'s stored-credential reservation, which was an **interactive-bootstrap** call with a better interactive alternative; the **non-interactive cross-repo** scheduled read has none, the own-repo token cannot reach the vault, and the least-privilege read-only single-repo PAT is the minimum the platform permits — the reservation is **accepted with a named new risk, not dismissed**. Component C is the genuinely new design, and it is honest about its surface: [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md) governs the store, the digest is a derived finding, the structural private-only gate is the **operator's weighed burden-on-the-engine choice**, and [§7](../principles.md) names the residual it cannot remediate. The plan-stage cold review earned its keep (the corrections above), and the operator approved the refined three-component shape.

## What we ruled out

Leave the read disclosure-only / local-run-only and never wire the scheduled cross-repo read (rejected — the operator weighed the token-management + privacy cost against the lost capability and chose to wire it; the headline stale-memory check would otherwise stay dark on every scheduled run, the gap #224 was filed to close). Carry the read on an Anthropic Cloud Routine as the v1 reader (rejected — the routine runs the persona but executes no GitHub-Actions step, so it performs no read without re-architecting the read to be persona-owned, and it rides a research preview the engine never depends on; it stays the documented-optional secondary, [R17](../reference/risks.md)). Use a classic broad-scope `repo` PAT (rejected — a single least-privilege fine-grained `contents:read` token scoped to the one vault repo is the minimum surface; the shared-vault grant already spans every co-located namespace, so breadth beyond read-only-one-repo only enlarges the blast radius). Treat the flip as a pure provisioning UX leaf ridable without re-litigation (rejected — it edits locked audit-library/provisioning/audits text and adds a new digest-privacy bound; per [D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)/[D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md) a locked-body edit is a re-litigation the lock fingerprint forbids changing silently). Bundle the seam-sensitive credential and the new privacy bound under one "just fill the silence" rationale (rejected — the architect-lens vehicle-split: the disclosure correction is additive, but the credential and the digest-privacy bound each carry their own seam/anti-choice scrutiny, reasoned separately above). Pre-commit to editing memory to define the credential or the digest carve-out (rejected as the lean — [D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)/[D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md) already ruled the read a pure consumer needing no memory change and [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md) governs the store, not the digest; memory is named in-radius and the landed-text audit confirms its disposition, not pre-decided). Fold the authorize and resolve into one entry (rejected — the authorize/resolve split is the litigation-protocol convention, [D-233](0233-authorize-the-audit-over-audit-re-litigation-feed-the-period.md)/[D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md), [D-235](0235-authorize-the-engine-issue-conformance-reroute-gate-promote.md)/[D-236](0236-resolve-the-d-235-engine-issue-conformance-reroute-gate-land.md), [D-237](0237-authorize-flipping-the-memory-backup-default-to-a-shared-vau.md)/[D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)).
