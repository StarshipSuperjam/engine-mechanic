# Lock the `knowledge` system (Wave-2): the purely-derived structural store; Q16 sharpened

*Decided 2026-05-25 in the design workspace.*

## The decision

Ratify and lock [knowledge](../spec/systems/cognitive/knowledge.md) — the cognitive substrate's "how does this world work?" store — to its end-state: a **purely structural, purely derived** knowledge graph whose **canonical entities are committed per-surface JSON** (governed by the locked [schema](../spec/systems/surfaces/schemas.md) layer; not JSON-LD), with a **gitignored derived index + boot slice** regenerated on demand, reached through a graph-query MCP server. **Regeneration is a mutation triggered at the `PreToolUse` git-commit boundary** (batched, best-effort, fail-open); because the hook fires *before* the commit, the regenerated JSON lands in the working tree and is **not guaranteed to ride that same commit** — it is captured by a following commit, and the **fingerprint coverage check at CI is the unbypassable backstop** that fails when a surface changed without a matching regen. **Boot only reads.** Knowledge is **derived not hand-authored** and fingerprint-gated ([D-011](0011-knowledge-graph-state-is-derived-not-hand-authored.md)/[principle §3](../principles.md)); **carries no debt** ([D-031](0031-integration-debt-is-a-telemetry-owned-register-not-a-knowled.md) — telemetry references entity-ids); **upgrade-safe** (overlay replaces entities, next regen self-corrects, [D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)); and keeps a **swappable representation/retrieval leaf** bound via the [interface](../spec/systems/surfaces/interfaces.md) surface ([D-033](0033-ground-the-cognitive-substrate-in-established-standards-line.md)), behind which **[R8](../reference/risks.md) hub-explosion stays open** and bounded. The **concrete entity/edge schema, generator, and per-surface coverage are build-spec leaves** ([D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md), laws-not-leaves). **[Q16](#) is resolved by sharpening (this session owns it):** knowledge's *Heritage* line and the [glossary](../reference/glossary.md) CoALA entry now state that knowledge takes CoALA-semantic's *structure* only — CoALA-semantic is belief-bearing, but distilled project beliefs live in [memory](../spec/systems/cognitive/memory.md)'s `decision`/`lesson` roles, never in the derived graph ([D-008](0008-memory-and-knowledge-are-distinct-substrates.md) wall); the verbatim [engine-architecture.md](../architecture.md) §4 novelty statement is **untouched** (it claims taxonomy-lineage, which the structural-vs-belief clause does not contradict). **No locked doc is edited** (the Q16 edits touch only the unlocked knowledge doc + glossary); **Q16 is deleted** from [open-questions](../reference/open-questions.md). This is the first Wave-2 store lock; seams to its `designed` neighbours (the symmetric memory read-time join; telemetry referencing entity-ids; boot reading the slice; the interface leaf) are pure deferrals.

## Why

Knowledge is intra-wave parallel with memory but had **no open design decision** — its two open questions were always build-spec leaves — so it locks first, banking a clean Wave-2 advance and validating the regrounding cadence before the harder memory lock. Locking it now is sound under the lock discipline: it anchors only on locked docs (schemas, check, validation, hooks, topology law 5, ontology, module-system) plus pure deferrals, so no neighbour's later lock can force a knowledge change (the read-time join is stated symmetrically in both docs; the swappable-leaf and entity-id-reference seams are stated abstractly). The four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md): adversarial / technical-feasibility / non-engineer-operator / architect, no shared context) ran against the joint knowledge+memory design; it returned **no blocking findings** and confirmed knowledge clean, the no-re-lock claim true (grep of all 17 locked docs), and the lock order correct. Its knowledge-relevant findings were folded before this entry: the **technical-feasibility** finding that a `PreToolUse` hook fires before the commit and so cannot guarantee its regen output rides that commit → the doc now states the regen lands in the working tree, is captured by a following commit, and the CI fingerprint gate is the backstop (the design always relied on that gate; this only makes it explicit); the **architect** note to record R8-stays-open and to verify §4 verbatim-novelty consistency → both done. The Q16 sharpening is the honest fix for a documentation imprecision ([D-050](0050-hermes-interprets-coala-mining-a-lineage-precision-question.md)): the flat "semantic = knowledge" shorthand could misfile belief content into the derived graph, so naming the structural-vs-belief split closes that without importing any CoALA machinery (the [D-033](0033-ground-the-cognitive-substrate-in-established-standards-line.md) leak guard and cite-don't-implement rule hold).

## What we ruled out

Lock memory first or both together (rejected — memory carries the open Q3 backup decision; knowledge is clean, so knowledge-first banks a clean advance and the mutual read-time join means knowledge's lock cannot constrain memory's later backup choice). Keep an "Open questions" section in the locked doc (rejected — the two items are build-spec leaves, restated as design commitments; a locked doc implying unresolved design is the drift the lock forbids). Claim regen rides the intercepted commit atomically (rejected — false to the `PreToolUse` ordering; the CI fingerprint gate is the real backstop). Edit the verbatim §4 novelty statement for Q16 (rejected — it claims taxonomy-lineage, which the structural-vs-belief clause does not contradict; sharpening the Heritage line + glossary CoALA entry suffices). Leave Q16 open or treat it as a substrate design gap (rejected — the belief-home is already settled in memory's roles; only the wording was open, and this session owns it per [D-050](0050-hermes-interprets-coala-mining-a-lineage-precision-question.md)). Adopt a frontier graph engine now or commit to a dense-graph representation (rejected — [Q11](#) stays open; v1 ships the derived plain-JSON floor behind the swappable leaf, which keeps R8 conditional and the swap re-litigation-free).
