# Resolve Q32: keep the locked persona-file agent realization (no locked-doc edit); clear the design-review / qa-review / audit-library persona gate

*Decided 2026-05-30 in the design workspace.*

## The decision

Resolve [Q32](../reference/open-questions.md) → **keep the locked [agents](../spec/systems/surfaces/agents.md) persona-file design**: reviewer/audit personas remain `.claude/agents/` **files** discriminated by engine-governed `role`/`lens` frontmatter, with the roster **derived by the engine reading its own agent files** ([§14](../principles.md)). **No locked-doc edit, no litigation alarm** — the resolution *consumes* the locked grammar and changes nothing in it. The platform realities are accommodated **inside the existing locked grammar** as build-spec leaves the locked docs already anticipate: (a) the agent `model:` frontmatter being ignored for spawned subagents (claude-code#44385) is handled by **passing `model` at the spawn**, which locked [build-orchestration](../spec/systems/lifecycle/build-orchestration.md):399 already provides for (`model` carries a per-spawn override; `effort` is pinned in-file); (b) the platform tolerating unknown `role`/`lens` frontmatter keys is **already hedged** at locked [agents](../spec/systems/surfaces/agents.md):86-87 ("convention, not a documented platform guarantee") — the sole authority, and the §14 read-its-own-files roster derivation is robust regardless of the historically-flaky agent auto-discovery path; (c) the build session verifies the frontmatter-roster derivation works, the verification [Q32](../reference/open-questions.md) itself names. This **clears the persona-mechanism gate** for [design-review](../spec/modules/design-review.md), [qa-review](../spec/modules/qa-review.md), and [audit-library](../spec/modules/audit-library.md): design-review and qa-review need **no doc edit** (both already describe persona-files + a derived roster correctly) and become lock-eligible; audit-library's persona axis is cleared, its remaining work being the [Q33](../reference/open-questions.md) audit-substrate rework ([D-146](0146-resolve-q33-github-actions-stays-the-default-audit-substrate.md)). **Propagation:** [Q32](../reference/open-questions.md) deleted from [open-questions.md](../reference/open-questions.md) (resolution captured here); this entry. **No edit owed** to locked [agents](../spec/systems/surfaces/agents.md)/[build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (the design anticipated these realizations), [modules/README.md](../reference/module-catalog.md) (no catalog change), [glossary.md](../reference/glossary.md), [risks.md](../reference/risks.md), or [engine-architecture.md](../architecture.md).

## Why

Grounding in current product facts — the local prototypes are **not** a functional model, the v1 spec supersedes them — removed the only motivation for the lens-in-brief alternative, which existed solely because the prototypes drove personas via `subagent_type: general-purpose` + lens-in-brief. Without that, switching would **re-litigate the locked [agents](../spec/systems/surfaces/agents.md) grammar + [module-system](../spec/systems/grammar/module-system.md) + [validation](../spec/systems/guardrails/validation.md)'s coherence kind + all three modules** for no benefit, and the bugs it claimed to dodge (#44385, auto-discovery) bite a `general-purpose` spawn equally (it too inherits the parent model unless `model` is passed at the call). A four-lens cold audit of the resolution plan confirmed Q32-keep is **sound and edit-free** — the persona substrate is documented, the frontmatter hedge matches the locked text, and the roster derivation is the §14 read-its-own-files pattern. Per the [lock discipline](#), the burden sits on the current work to fit the locked grammar, which it does.

## What we ruled out

**Adopt the lens-in-brief pattern** (drive reviewers as `general-purpose` agents with the lens in the per-invocation brief, shipping no persona files) — rejected: it re-litigates the locked agents grammar + module-system + validation coherence + the three modules, a large blast radius for no gain once the prototype is not the model, and it does **not** avoid #44385 (a `general-purpose` spawn also needs `model` passed at the call). **Edit the locked [agents](../spec/systems/surfaces/agents.md) doc to name the #44385 workaround or the persona-invocation realization** — rejected: locked [build-orchestration](../spec/systems/lifecycle/build-orchestration.md):399 already provides the per-spawn `model` override and the realization is a build-spec leaf, so no locked-doc edit is owed (editing one would be an unjustified re-litigation). **Leave Q32 open** — rejected: the decision is made and the modules it gates are ready to lock; an unresolved question whose decision is settled belongs deleted with its resolution captured in the log.
