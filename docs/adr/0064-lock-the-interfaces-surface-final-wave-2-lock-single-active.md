# Lock the `interfaces` surface (final Wave-2 lock): single-active polymorphism with a named, never-silent fallback

*Decided 2026-05-25 in the design workspace.*

## The decision

Ratify and lock [interfaces](../spec/systems/surfaces/interfaces.md) — the protocol-contract surface, a stable callable boundary a swappable implementation satisfies, naming its own default/fallback so degradability ([principle §5](../principles.md)) is stated at the contract — **completing Wave 2** of the [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) runway. Interfaces **anchors entirely on locked docs** ([tools](../spec/systems/surfaces/tools.md), [memory](../spec/systems/cognitive/memory.md), [knowledge](../spec/systems/cognitive/knowledge.md), [module-system](../spec/systems/grammar/module-system.md), [check](../spec/systems/surfaces/check.md), [validation](../spec/systems/guardrails/validation.md), [ontology](../spec/systems/grammar/ontology.md), [boot](../spec/systems/lifecycle/boot.md), [schemas](../spec/systems/surfaces/schemas.md)) with **zero designed-neighbor seams** — none of the six still-`designed` docs reference it — so the lock is unconditionally clean and it **owns the binding model [tools](../spec/systems/surfaces/tools.md) ([D-053](0053-procedural-surfaces-reconciled-to-the-merged-claude-code-ski.md)/[D-056](0056-lock-the-tools-surface-wave-1.md)) deferred to it**. Eight reconciliations land on the (designed) interfaces doc; **one locked doc is *not* touched and one unlocked doc is**: **(1)** the **single-active resolution law** (the "subtle named-fallback law" [D-044](0044-re-lock-validation-and-check-a-check-kind-binds-by-presence.md) anticipated) — an interface resolves to *exactly one* active implementation: a present conforming non-default overrides the named fallback, with none present the fallback answers, and **more than one conforming non-default present is a [coherence](../spec/systems/surfaces/check.md) finding** (surfaced, never a silent arbitrary pick — the trust breach [§5](../principles.md) forbids). This is the interface's *resolution* semantics, distinct from the **set-valued** discovery cases ([agent](../spec/systems/surfaces/agents.md) roster, check-suite membership, where every present member joins); it **refines** the [§14](../principles.md) discovery axis and **does not amend it** (see the adjudication below). **(2)** Conformance: the declaration is `schema`-governed (JSON Schema 2020-12) and a present implementation's conformance + the single-active invariant are confirmed by the locked **`coherence`** check-kind post-install — **no new check-kind**, locked validation/check untouched; behavioral equivalence of arbitrary code is a test concern, not a check. **(3)** The active-fallback disclosure splits two conditions so "loud" never becomes a nag: a richer implementation *installed but its substrate is down* is surfaced loudly (the locked [module-system](../spec/systems/grammar/module-system.md) inactive-substrate disclosure law, rendered by [boot](../spec/systems/lifecycle/boot.md)), whereas *no richer implementation installed* is a **valid steady state** (the `search` FTS5 floor is offline/zero-dependency by design) offered at most once/acknowledgeably and **never a standing nag**. **(4)** The upgrade step is **engine-driven** (the engine installs the module on operator approval, the [D-063](0063-lock-the-boot-orientation-system-wave-2-terminal-the-integra.md) boot posture), never a typed command. **(5)** Operator rendering is plain capability-language, never the interface slug. **(6)** Discovery is by a known engine-namespaced handle (the engine-prefixed MCP server name for the v1 MCP-backed interfaces); the concrete handle is a build-spec leaf. **(7)** The "always a working answer" guarantee rests on the named fallback being a shipped foundation [`tool`](../spec/systems/surfaces/tools.md) ([§4](../principles.md)). **(8)** A **"Build-spec leaves"** section restates the residue (the concrete `search`/knowledge-retrieval declarations, the conformance-check specifics, the selection precedence, the acknowledgment mechanism, the discovery handle) so the locked doc implies no unresolved *design*. The [glossary](../reference/glossary.md) `Interface` entry is updated with the single-active clause. **No-re-lock** (grep-verified across all 21 locked docs: every "interface" reference is consumer-side or a pure deferral *to* this surface). **[R5](../reference/risks.md)/[R8](../reference/risks.md) stay open** (interfaces is the discovery-side half of R5 containment — closes when the wiring library is built; the swappable leaf is R8's mitigation, not its resolution — both firm, neither closes). This is the **22nd lock**; Wave 2 is complete, leaving Wave 3 (modes, close, build-orchestration), Wave 4 (telemetry, audits), Wave 5 (provisioning).

## Why

Interfaces is the correct final Wave-2 lock: its v1 members (`search`, knowledge representation/retrieval) bind it to the now-locked cognitive retrieval leaf ([memory](../spec/systems/cognitive/memory.md) [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md), [knowledge](../spec/systems/cognitive/knowledge.md) [D-060](0060-lock-the-knowledge-system-wave-2-the-purely-derived-structur.md)), and it has no churning upstream at all, so locking it forces no later change and is the cleanest possible lock. The four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md): adversarial / technical-feasibility / non-engineer-operator / architect, no shared context) ran against the design; technical-feasibility returned **no findings** (verified the `structured`/tier-3/schema-governed meta-contract against the locked schemas+check precedent, the file-drop presence-discovery via the engine-prefixed MCP server name, multiple-present detection by the locked post-install `coherence` kind, and the two swappable MCP-backed seams over gitignored data). The senior lenses **split** on the single-active law's relationship to [§14](../principles.md): the architect wanted §14 (and the glossary) edited to record a single-vs-set distinction; the adversarial warned that editing a closed-law-layer principle is high-blast-radius and the rule should stay doc-local since §14 makes no cardinality claim. **Adjudication: §14 is deliberately NOT edited** — it governs *discovery by presence*, not *resolution cardinality*, so the single-active rule refines it without contradiction; editing §14 would be high blast radius (change-propagation matrix) for no necessity. The architect's precision concern is met by stating the law in the interfaces doc (framed as a §14 refinement) and a one-clause [glossary](../reference/glossary.md) `Interface` edit — neither touches a locked doc. The remaining serious findings were resolved before this entry: **(adversarial)** conformance must not imply a new check-kind → pinned to the locked `coherence` kind with an affirmative "no new check-kind"; **(non-engineer-operator)** a fallback the operator runs *by choice* must not be nagged like a down substrate, and the upgrade must be engine-driven not a typed command → both folded into the two-condition disclosure split and the engine-driven step. Propagation per the matrix is otherwise empty: [engine-architecture.md](../architecture.md) §6 indexes interfaces truthfully, the glossary `Check-kind` entry already states "not an interface… no fallback" ([D-044](0044-re-lock-validation-and-check-a-check-kind-binds-by-presence.md)), no scenario or module doc references interface selection, and [R5](../reference/risks.md)/[R8](../reference/risks.md) need no edit (firmed, not closed).

## What we ruled out

Edit [§14](../principles.md) to encode the single-vs-set distinction (rejected — high-blast-radius edit to a closed-law-layer principle for no contradiction; §14 governs discovery not resolution cardinality, so the doc-local refinement + glossary clause is the proportionate fix, the adversarial path over the architect's). Invent an interface-conformance check-kind (rejected — re-locks [validation](../spec/systems/guardrails/validation.md)/[check](../spec/systems/surfaces/check.md), the exact drift [D-044](0044-re-lock-validation-and-check-a-check-kind-binds-by-presence.md) forbids; the locked `coherence`/`schema`/`presence` kinds express it). Resolve multiple-present implementations by a silent arbitrary pick (rejected — a silent choice among implementations is the non-engineer trust breach [§5](../principles.md) forbids; surface it as a coherence finding). Surface a fallback the operator runs by choice as a standing nag (rejected — a permanent alarm against a deliberate offline floor erodes trust as much as silence, against [boot](../spec/systems/lifecycle/boot.md)'s "loud must not become noise"; only an unexpectedly-down richer substrate is surfaced loudly). Hand the operator a typed command to install the richer implementation (rejected — strands the non-engineer, the [constraints](../reference/constraints.md) operator limit; the step is engine-driven on approval, the [D-063](0063-lock-the-boot-orientation-system-wave-2-terminal-the-integra.md) posture). Leave the doc with no "Build-spec leaves" restatement (rejected — a locked doc implying unresolved design is the drift the lock forbids, the [D-060](0060-lock-the-knowledge-system-wave-2-the-purely-derived-structur.md)/[D-063](0063-lock-the-boot-orientation-system-wave-2-terminal-the-integra.md) precedent). Close [R5](../reference/risks.md)/[R8](../reference/risks.md) at this lock (rejected — R5 closes when the wiring library is built and R8 stays conditional behind the swappable leaf; the lock firms both). Defer interfaces past Wave 2 (rejected — its members bind the now-locked retrieval leaf and it has zero designed seams, so it is ready now and completes the wave).
