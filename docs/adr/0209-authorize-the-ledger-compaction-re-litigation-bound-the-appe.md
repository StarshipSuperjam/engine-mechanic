# Authorize the ledger-compaction re-litigation: bound the append-only ledger's growth and realize hard-delete via audit-gated erasure (memory growth gap)

*Decided 2026-06-17 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) on explicit operator approval to add a **ledger-compaction** mechanism to the locked [memory](../spec/systems/cognitive/memory.md) system, with reconciling edits to [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md), [boot](../spec/systems/lifecycle/boot.md), and [audits](../spec/systems/guardrails/audits.md). **The litigation alarm:** the operator observed that "forgetting" on an append-only ledger is under-specified — the locked design ([D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)/[D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md)) promises "**hard-deletes only on evidence**" (superseded/contradicted/duplicate/operator-directed) and a demotion tier ending in "**archived**" + "archives the raw," but names **no mechanism** by which a true hard-delete, or any bound on growth, reconciles with the append-only canonical store. Two real gaps: (1) the ledger grows monotonically forever (every `Stop` appends, nothing leaves); (2) "hard-delete on evidence" has no realization and "archived" names a home that **does not exist**. The append-only ledger itself is **not** the defect — it is load-bearing for crash-safety, cheap-generous capture, [§2](../principles.md) canonical/derived, and reversible operator-undo; the gap is the missing compaction mechanism.

  **The decision — compaction = a self-directed whole-ledger rebuild-and-swap, split along the locked judgment ladder.** Append-only governs *live writes* (never seek-and-edit in place); **compaction produces a new canonical ledger by folding to current state and atomically swapping it in** — memory invoking its **own already-blessed** "replace the ledger and rebuild the derived index" restore primitive, gated on retirement evidence, so **no contract is widened** and there is **no second store** ("the one source of truth" stays literally one ledger). Two layers:
  - **Layer 1 — reversible, mechanical, memory-autonomous.** Compaction folds redundant transition/marker records (access/reinforcement, tier transitions, supersession links) into current-state fields, carrying the current **frecency snapshot + tier value** forward (frecency stays durable because its function is a **recurrence on the carried snapshot**, not a window-scan over the folded-away history — consistent with [D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md)/[D-062](0062-lock-the-attention-system-wave-2-the-policy-plus-function-pr.md) where frecency is an input scalar to attention); prunes the hot FTS5 index; and applies **logical retirement** — a retired record is excluded from recall but **stays resident in the one ledger, fully recoverable**. **"archived" = an index-exclusion *state*, not a separate store.** Compaction **never autonomously erases recall content** (validation enforces the bright Layer-1/Layer-2 boundary). No boot horizon, no autonomous purge.
  - **Layer 2 — irreversible, judgment, human-gated.** Permanent erasure is **not** memory-autonomous. The [audits](../spec/systems/guardrails/audits.md) stale-memory-beliefs concern runs a function-probe over *already-retired* records (it does not re-detect retirement — that stays memory's mechanical call) and recommends physical erasure of those that earn it, as an **engine-labeled Issue** stating the concrete cost with a low-friction keep-it path. **Erasure is enacted only by the merge of a single-purpose erasure PR** (recorded by its merge SHA), the [§17](../principles.md)/[§6](../principles.md) informed-consent gate.

  **The hardened erasure-enactment seam.** (a) **Trigger = a merge event only** — Issue-*closed* is explicitly **not** a trigger ([telemetry](../spec/systems/guardrails/telemetry.md) auto-resolve, dedup-close, and the operator's keep-it decline all close the Issue; none may erase). (b) **A new, honestly-named evidence class — `operator-adjudicated erasure`** — added to memory's hard-delete set as its own pathway, **not** a stretch of "operator-directed" (which means the operator pointed at a record and said delete it). (c) **Targets referenced by a stable, content-free record id** minted at capture (survives the rewrite; an offset would not), so the committed Issue/PR names the record without leaking gitignored content ([D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)) and without showing the operator an offset/record-id (the operator sees the plain-language cost; the machine binding is the opaque id). (d) **Enactment is a new cross-session observer** (acknowledged as new machinery, not a reuse of the [close](../spec/systems/lifecycle/close.md)-gate, which is never read across sessions): a later local session reads merged erasure-PRs via `gh`, appends an erasure marker keyed by the merge SHA / stable id, and the next compaction removes the target **idempotently** (double-enactment is a no-op).

  **Two feasibility laws (stated as law; concrete values leaf).** **Crash-safe swap:** temp written in the ledger's **own directory** (cross-filesystem rename is non-atomic, EXDEV) → `fsync(temp)` → atomic rename over the original → **`fsync(directory)`** (rename atomicity is ordering, not crash-durability; without the dir-fsync an enacted erasure can silently resurrect) → **full index rebuild gated on a monotonic ledger-generation stamp, never an incremental patch** (else an erased record resurfaces from a stale index). A crash at any point leaves exactly one intact ledger; a stale index is always fully rebuilt. **Compaction↔provisioning ordering:** the shared exclusive write lock prevents *tearing* but not *ordering* among three independent lock-takers (append, compaction, [provisioning](../spec/systems/infrastructure/provisioning.md) snapshot/migration), so compaction **does not run within a migration window**, and the **ledger-generation stamp is carried into the snapshot manifest** so a restore/revert that would resurrect an enacted erasure is surfaced via [boot](../spec/systems/lifecycle/boot.md)'s open-findings path ([D-048](0048-provisioning-delivery-designed-end-state-brownfield-capable.md)'s code-older-than-data channel), never silent. Memory extends its **own** manifest; provisioning consumes the same restore-contract *shape* — unwidened. The "schema-identical ⇒ safe" syllogism is dropped: compaction changes the record-set within one engine-version, which the version-stamp cannot see, so the generation stamp makes it detectable.

  **Reshaped by two four-lens cold plan-audits.** The **first** killed the original candidate — an **autonomous purge gated on a boot-surfaced undo horizon** — because [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)/[D-188](0188-resolve-the-d-187-operator-presentation-relay-re-litigation.md) established that no Claude Code channel reliably reaches the operator (boot "disclosure" is posture, not a guarantee), so a present-but-passive operator burns the horizon on a skimmed readout and the irreversible deletion fires on a channel proven unreliable — the exact "silent deletion of their brainstorming" the locked doc names as the trust-eroding event (adversarial + operator lenses, convergent BLOCKING). It also killed a **separate cold-archive store** ([§2](../principles.md) second-canonical-store, [D-058](0058-discharge-the-wave-0-gate-q10-substrate-content-world-taggin.md) per-substrate re-split, restore-contract widening). **The operator redirected** permanent erasure to the audit loop — the reliable, deliberate, merge-gated channel the locked corpus already built (the [audits](../spec/systems/guardrails/audits.md) stale-memory concern + "the merge is the adjudication" + the operator-communication law). The **second** plan-audit (on the audit-gated design) **cleared the operator lens** (trust earned where the rejected design failed: do-nothing → nothing-lost) and converged on: the **merge-only** trigger (a "merged/closed" wording would have re-admitted telemetry auto-resolve as a silent-purge path); the **honestly-named evidence class** (not an operator-directed overload); **boot and audits are both certain edits** (boot's locked readout promises an undo handle on "deleted" recall the new model cannot keep; audits' report-never-heal posture does not currently authorize an irreversible-consequence recommendation); the **re-lock set is exactly 4**; and the **crash-safe-swap + ordering + stable-record-id** laws were under-specified. The **telemetry backlog stream was dropped** (not needed to close the gap; the audit's own generic sweep finds the backlog — [R6](../reference/risks.md)).

  **Scope. Re-lock set — 4** (all currently locked → re-locked, none added): [memory](../spec/systems/cognitive/memory.md) (PRIMARY — the compaction subsection + four reconciling clauses), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md) (`provides` names compaction + the audit-adjudicated erasure hook + the cross-session observer; `gitignore` wires **unchanged** — single ledger), [boot](../spec/systems/lifecycle/boot.md) (the reversible-forgetting readout drops "deleted"; erasure rides the audit-digest surface; returning-operator surfacing names pending audit adjudications), [audits](../spec/systems/guardrails/audits.md) (the load-bearing clause authorizing the stale-memory concern to recommend physical erasure of already-retired records under the merge-gate). **Carriers (non-locked):** [glossary](../reference/glossary.md) (*Ledger compaction*, *operator-adjudicated erasure*, *archived* = index-exclusion state; reconcile *Memory ledger* / *Frecency*), [risks](../reference/risks.md) (open **R24** — compaction closes the growth gap and opens the compaction-crash-corrupts-the-one-canonical-store risk the crash-safe-swap law mitigates; the cron-strands-erasure-only nuance), wbs/memory-build-plan.md (step 4 absorbs compaction + the audit-gated erasure path). **Verify-no-edit (to confirm at the landed-text audit):** [telemetry](../spec/systems/guardrails/telemetry.md) (untouched — the stream is dropped), [provisioning](../spec/systems/infrastructure/provisioning.md) (restore contract unwidened — load-bearing; the generation stamp is memory's own manifest field), [modules/README](../reference/module-catalog.md), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning) + [scenarios/upgrade-the-engine](../architecture.md#upgrading-the-engine) (no stale "deleted-with-undo" / "archived-store" prose), [open-questions](../reference/open-questions.md). The re-locks land under the **Resolve** entry ([D-210](0210-resolve-the-d-209-ledger-compaction-re-litigation-landed-tex.md)) after the mandatory landed-text cold audit.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval. The gap is real — an append-only canonical store with no compaction grows forever and cannot realize the hard-delete it promises — and the only honest fix names the mechanism. Compaction-as-self-directed-restore-primitive reconciles append-only with bounded growth **without a second store or a widened contract**; the reversible/irreversible split puts the only irreversible act behind the [§17](../principles.md) merge gate — the one channel proven to reach a non-engineer — and reuses the audit loop the corpus already built for deliberate, cost-stated, consent-gated retirement, rather than the boot channel [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)/[D-188](0188-resolve-the-d-187-operator-presentation-relay-re-litigation.md) proved unreliable. The crash-safe-swap and ordering laws are necessary to keep the one canonical store intact and an enacted erasure durable; the stable content-free record id is necessary to reference a gitignored record from a committed Issue without leaking it. Honest naming of the new evidence class is preferred over overloading "operator-directed."

## What we ruled out

**Autonomous purge gated on a boot-surfaced undo horizon** (rejected — boot is not a reliable operator channel, [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)/[D-188](0188-resolve-the-d-187-operator-presentation-relay-re-litigation.md); a present-but-passive operator suffers a silent purge, the trust-eroding event). **A separate cold-archive store** (rejected — a second canonical store violates [§2](../principles.md), re-splits homogeneous project-recall [D-058](0058-discharge-the-wave-0-gate-q10-substrate-content-world-taggin.md), and widens the restore contract memory owns and provisioning may not, [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)). **Trigger erasure on Issue-closed** (rejected — telemetry auto-resolve, dedup-close, and the keep-it decline all close the Issue; keying on "closed" re-admits the autonomous silent-purge and collapses *decline* onto the same signal as *consent*; the trigger is the **merge** of a single-purpose erasure PR only). **Overload the locked "operator-directed" evidence class** (rejected — "operator merged a referencing PR" is not "the operator pointed at this record"; name the new pathway honestly as `operator-adjudicated erasure`). **Bundle erasure into a multi-purpose PR** (rejected — launders an irreversible deletion through consent given to other work, defeating the anti-rubber-stamp posture; the erasure PR is single-purpose with the cost on the consented artifact). **Reference targets by ledger offset, or by quoting content into the Issue** (rejected — an offset does not survive the rewrite and a record-id is not operator-legible; quoting content leaks the gitignored ledger into the committed tree, [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md); use a stable opaque id for the machine binding + plain-language cost for the operator). **Mark boot / audits verify-no-edit** (rejected — boot's readout promises an undo handle on "deleted" recall the new model cannot keep; audits' report-never-heal posture does not authorize an irreversible-consequence recommendation without the load-bearing clause). **An incremental index patch after the swap** (rejected — an erased record resurfaces from a stale index; the generation-stamp forces a full rebuild). **Rely on the shared lock alone for provisioning safety** (rejected — the lock prevents tearing, not ordering; a migration-revert could resurrect an enacted erasure without the generation-stamp-in-manifest surfacing). **Add a telemetry backlog stream this pass** (rejected — not needed to close the gap; scope creep against [R6](../reference/risks.md); the audit's generic sweep finds the backlog). **Treat the append-only ledger itself as the defect** (rejected — it is load-bearing for crash-safety, capture, [§2](../principles.md), and reversible undo; the gap is the missing compaction mechanism, not append-only).
