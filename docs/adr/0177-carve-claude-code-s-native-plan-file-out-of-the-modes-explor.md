# Carve Claude Code's native plan file out of the modes Explore write-gate (litigation alarm + authorization)

*Decided 2026-06-06 in the design workspace.*

## The decision

The locked [modes](../spec/systems/lifecycle/modes.md) Explore write-gate ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md), law 2; re-locked [D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md)) is **re-litigated** to stop it blocking Claude Code's **native plan-mode artifact** — the plan file the platform writes to disk when a plan is accepted (observed at `~/.claude/plans/<name>.md`, under the operator's *home* `.claude/`, **outside any repo**). **This entry is the litigation alarm + authorization** (the operator authorized the audited change via plan-mode approval); the **re-lock lands under the resolve entry** [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) after the mandatory landed-text cold audit — the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)→[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) pattern.

  **The defect.** The gate's *law* denies only *"edits to engine or product files"* and *"allows everything else"*; its *realization* (the build-spec leaf "the tool names treated as file-mutating"; [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md) law 2 "file-mutating tools by tool name") is **broader than the law** — it denies every `Write`/`Edit` by tool name, so it catches the plan-file write even though that file is neither an engine/product file nor in the repo. The block is **real, not fail-open theatre**: [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)/[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) live-verified that a correctly-formatted `PreToolUse` deny *is* honored for `Write`. So in a generated engine, an Explore session's plan-file write dies — at the worst moment, right after a plan is accepted, on every planned build. (Confirmed by contrast: this planning workspace, which runs no engine gate, writes its own plan file without issue — the block is the Engine's gate, not the platform.)

  **Why it is a first-class failure.** The Engine exists to make a non-engineer *more* capable on top of Claude Code, never less; here a guardrail meant to guard engine/product source instead **regresses a Claude Code basic** the non-engineer relies on — leaving them worse off at a native capability than plain Claude Code ([goals](../reference/goals-and-quality.md) trust; [§5](../principles.md)).

  **The fix (authorized; final text + audit land under [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md)).** Make the realization honor the law:
  - **Law (modes' gate paragraph):** name the platform's plan-mode artifact explicitly among what the gate **allows** — it is planning, not building; the gate guards *in-repo engine/product source*, never the platform's own working files.
  - **Leaf (modes' Build-spec-leaves denied-action match list):** a file-mutating call is denied as a build-beginning edit only when it targets in-repo engine/product source; Claude Code's plan-mode artifact (the `.claude/plans/` plan file) is **never** denied. The exact match expression (path identity vs. out-of-repo scoping, robust to a configurable or version-changed location) is a build-spec leaf the [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md) technical-feasibility lens verifies against current Claude Code.

  **Scope discipline.** A **targeted carve-out for the plan-file artifact**, not a generalized "deny in-repo only / allow all out-of-repo writes" rewrite (see anti-choice).

  **Carriers.** **Edited (locked):** [modes](../spec/systems/lifecycle/modes.md) (the only locked doc; re-locked under [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md)). **Verified law-faithful, no edit:** [glossary](../reference/glossary.md) "Mode (stance)" and [engine-architecture](../architecture.md) §7 already state *"engine/product writes gated off"* — the law-intent framing that already excludes the plan file; [hooks](../spec/systems/infrastructure/hooks.md) defers the deny-list to modes and enumerates nothing. **Non-locked propagation:** wbs/core-build-roadmap.md slice 21 (which builds the match list) gains the carve-out as a build-conformance demo so the live build implements + tests it. **Queued, not taken up:** [Q38](../reference/open-questions.md) — whether the *interactive* Build entry should key on plan-acceptance instead of the operator-typed verb (the deeper question the operator surfaced; a separate foundational re-litigation).

## Why

A locked guardrail silently breaking a platform basic for the exact non-engineer the Engine serves is a direct hit on **trust** and on [§5](../principles.md) (never strand the operator). The gate's realization had drifted broader than its own law; this is a **correction back to intent**, not a weakening — the merge wall remains the only unbypassable wall, the denied building set is unchanged for in-repo engine/product source, and the carve-out is scoped to one harness-owned artifact. Justified re-litigation: the lock stops silent drift, not warranted edits (CLAUDE.md litigation alarm).

## What we ruled out

**Leave it / treat plan files as acceptable collateral** (rejected — the operator named it a first-class failure; regressing a Claude Code basic violates the trust north star). **Fix it only in a future build-spec leaf without touching the locked doc** (rejected — the leaf as written, "tool names treated as file-mutating," *is* what causes the bug; the law must make the carve-out explicit so a build-spec author cannot reintroduce it). **Generalize to "deny in-repo engine/product only, allow all out-of-repo writes"** (rejected — generalizes a narrow operator steer into a new gate law and over-broadens: arbitrary `~/.claude/` writes can alter the Engine's own guardrail config; the carve-out names the plan artifact specifically). **Make plan-acceptance the Build trigger now** (rejected for *this* pass — it is the queued [Q38](../reference/open-questions.md), a foundational re-litigation with wide blast radius; [D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md)'s "`ExitPlanMode` is not reliably hook-observable" anti-choice stands until that pass takes it up). **Edit the locked doc without the cold audit** (rejected — HARD lock gate; the audit + re-lock land under [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md)).
