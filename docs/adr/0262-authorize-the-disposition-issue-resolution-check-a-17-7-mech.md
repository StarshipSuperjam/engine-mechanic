# Authorize the `disposition-issue-resolution` check: a §17/§7 mechanical correlate that the disposition Issue numbers a PR cites actually resolve to real engine-labeled issues; re-litigate locked [validators-core](../spec/modules/validators-core.md) (rule-data instance; re-lock lands under D-263)

*Decided 2026-06-27 in the design workspace.*

## The decision

The operator (the non-engineer sole maintainer) observed that the cold-review gates are reported in the PR's **Review** record but **GitHub cannot verify the report** — for a repo whose premise is *do not trust the AI's story*, the highest-value residual weakness — and proposed converting review evidence into committed artifacts with CI-checkable presence. **Grounding found most of the proposal already served or pre-empted by the [check-honesty family](#)** ([D-252](0252-authorize-binding-the-17-operator-runnable-behavioral-correl.md) the §17 operator-runnable behavioral correlate on the Review record; [D-256](0256-authorize-the-every-hard-check-is-proven-to-bite-re-litigati.md)…[D-260](0260-resolve-re-lock-core-the-dispatcher-run-one-rule-entry-point.md) the negative-fixture meta-check; [D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) the artifact-warrant discipline) — and that the committed-manifest form does **not** close the gap it targets (the same untrusted process authors the manifest; a green check on it manufactures trust, the [§17](../principles.md)/[§7](../principles.md) trap, and rebuilds the dissolved session archive, [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md)). A full design session (observation → fork analysis → four-lens cold audit of the draft → re-grounding against the just-landed family) **shrank the change to one still-unfilled mechanical gap**: nothing verifies that the disposition **Issue numbers a PR's Review cites** (the [finding-disposition](../spec/systems/surfaces/policies.md) "real-but-out-of-scope → tracked issue" routing) actually **resolve** to real engine-labeled issues — "logged as a follow-up, #412" can today be a fabrication. **This entry is the litigation alarm + operator authorization** (given across that session) **and the design of record**; the **re-lock lands under [D-263](0263-resolve-re-lock-validators-core-the-disposition-issue-resolu.md)** (validators-core) after its mandatory **landed-text cold audit** — the [D-252](0252-authorize-binding-the-17-operator-runnable-behavioral-correl.md)/[D-256](0256-authorize-the-every-hard-check-is-proven-to-bite-re-litigati.md) authorize-then-resolve pattern. The validators-core edit + the non-locked propagation **land under this entry as the landed text the audit reviews**; validators-core sits **edited-but-not-relocked** until D-263 (the sanctioned authorize-then-resolve transient — `validate.py` flags its lock fingerprint until the relock).

  **The design.** A new **`disposition-issue-resolution`** check — a **`custom/script`** rule [validators-core](../spec/modules/validators-core.md) owns outright, the sibling of `reference-closure` and the negative-fixture meta-check — **riding existing machinery, so only validators-core re-litigates**: the grammar is [check](../spec/systems/surfaces/check.md)'s ([D-258](0258-resolve-re-lock-check-the-by-presence-negative-fixture-gramm.md)), the law + execution-model + the `custom/script` **fail-closed** contract are [validation](../spec/systems/guardrails/validation.md)'s ([D-257](0257-resolve-re-lock-validation-the-negative-fixture-meta-check-l.md)), and the standing negative-fixture meta-check **auto-covers the new instance by presence** ([D-259](0259-resolve-re-lock-validators-core-the-negative-fixture-meta-ch.md)). **Logic** (the PR-body-citation direction): parse the `#N` Issue tokens the engine cites in the Review section's disposition lines and confirm each resolves via `gh` to a **real, engine-labeled issue** (open **or** closed — a disposition issue may be auto-resolved later, [D-040](0040-telemetry-designed-end-state-native-signal-of-record-tracked.md)); a cited `#N` that resolves to nothing, or to a non-engine issue, is the [`finding.v1`](../spec/systems/surfaces/schemas.md). **Tier `hard`** (merge-blocking) — the [D-252](0252-authorize-binding-the-17-operator-runnable-behavioral-correl.md) "a gate needs a non-AI correlate" bar is **met**: unlike the Review *judgment*, this rests on the **Issue object** (a real GitHub artifact the engine cannot fabricate without creating it — and creating it *is* the disposition), so a false citation is an unambiguous, operator-legible failure, not a posture self-judgment. **Fails closed** ([D-257](0257-resolve-re-lock-validation-the-negative-fixture-meta-check-l.md)): on inability to evaluate (`gh`/API unreachable) it fails closed, never a false green — conformant with [§15](../principles.md) ("a guardrail that can't run is not trusted"); the operational cost (a merge can block during a GitHub API outage; any retry/grace is the build's call) is named, not hidden. **Least-privilege token:** the workflow declares `permissions: issues: read` — never write (a check that could mutate issues is itself a trust hole). **Negative fixture** ([D-256](0256-authorize-the-every-hard-check-is-proven-to-bite-re-litigati.md)/[D-258](0258-resolve-re-lock-check-the-by-presence-negative-fixture-gramm.md), bound by presence, co-located with the rule per the existing validators-core rule): a committed seeded PR-body input citing a **sentinel-nonexistent** issue, so the meta-check witnesses the unit **bites**; the check has a statically-decidable failure path, so it needs no disclosed-not-applicable carve-out. **Artifact warrant** ([D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md), posture tier, the plain-language line the operator meets): green **shows** "every Issue number this PR cites as a follow-up resolves to a real tracked engine item"; **does not show** "that the engine logged *everything* it should have (an **uncited** disposition is not checked), nor that a disposition was the right call"; **review still covers** "whether anything out-of-scope went unlogged" — an authoring-time judgment named honestly, no invented step.

## Why

The operator's push is correct and grounding made it precise: the design already says prose is a consent layer over a non-AI correlate ([§7](../principles.md)/[§17](../principles.md)), so the honest move is **not** a committed "review-evidence" artifact (it relocates self-report into a file the same process authors and manufactures a green-check halo — the [§17](../principles.md) trap, and the [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) archive the lifecycle dissolved), but to add the **one mechanical correlate the family still lacks** at the place consent happens: that the disposition Issues a PR cites are **real**. It is the cheapest possible conforming addition — a rule-data instance riding [D-257](0257-resolve-re-lock-validation-the-negative-fixture-meta-check-l.md)/[D-258](0258-resolve-re-lock-check-the-by-presence-negative-fixture-gramm.md)/[D-259](0259-resolve-re-lock-validators-core-the-negative-fixture-meta-ch.md), so it widens no grammar and re-litigates one doc — and it strengthens, never fights, the locked [D-040](0040-telemetry-designed-end-state-native-signal-of-record-tracked.md)/[D-168](0168-resolve-the-d-167-operator-policy-override-re-litigation-lan.md) Issue-as-disposition substrate. Authorize-now / resolve-per-carrier keeps the irreversible re-lock behind its own landed-text audit ([D-252](0252-authorize-binding-the-17-operator-runnable-behavioral-correl.md)/[D-256](0256-authorize-the-every-hard-check-is-proven-to-bite-re-litigati.md)); landing the edit under this entry gives that audit concrete text and is the [§7](../principles.md) honest tier (the transient un-relock is disclosed, not silent).

## What we ruled out

**Committed review-evidence artifacts + a CI presence check** (`.engine/reviews/…`, `review-manifest.json`, `finding-disposition.json`) — rejected (the same untrusted process authors them, so a presence check verifies the self-report is *well-formed*, not *true*; a green check dresses it as proof — [§17](../principles.md)/[build-orchestration](../spec/systems/lifecycle/build-orchestration.md) "never dress a filled Review section as proof," [D-254](0254-resolve-re-lock-build-orchestration-the-filler-renders-the-o.md) — and rebuilds the dissolved session archive, [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md)). **Advisory CI-computed post-review divergence** (the reviewed-SHA→merge-head git delta) — rejected (its honest-limit framing is now [D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) canon and its content is thin marginal gain over the existing post-audit-fix prose; it would re-litigate the days-old [D-254](0254-resolve-re-lock-build-orchestration-the-filler-renders-the-o.md) lock **and** add a new commit-before-lenses discipline — disproportionate). **A `soft` tier** — considered, but a false Issue citation has a real non-AI correlate and is operator-legible, so a `hard` gate is the honest tier ([D-252](0252-authorize-binding-the-17-operator-runnable-behavioral-correl.md)); the final tier is the [D-263](0263-resolve-re-lock-validators-core-the-disposition-issue-resolu.md) audit's to confirm. **control-plane mandating a machine-parseable disposition citation** — declined (reopens the fresh [D-253](0253-resolve-re-lock-control-plane-the-review-record-carries-the.md) lock; the residual is carried in the warrant). **Reading the GitHub timeline `CrossReferencedEvent`** — rejected (it populates only when a linkage was actually created — fragile, false-negatives; the PR-body-citation direction is robust and self-consistent). **A new check-kind** — rejected (`custom/script` is the designed instance grammar; widening the closed-kind set would re-litigate [check](../spec/systems/surfaces/check.md)/[validation](../spec/systems/guardrails/validation.md) for nothing). **Write the [D-263](0263-resolve-re-lock-validators-core-the-disposition-issue-resolu.md) resolve entry now** — rejected (it records a cold audit that runs later; writing it pre-audit would dress un-audited as audited, the [§7](../principles.md) violation this family exists to prevent).
