# Resolve the D-237 memory-backup shared-vault flip: the four-lens audit widened the blast radius to three locked docs; landed-text re-check clean; [memory](../spec/systems/cognitive/memory.md) + [memory-substrate](../spec/modules/memory-substrate-sqlite-fts5.md) + [audit-library](../spec/modules/audit-library.md) re-locked

*Decided 2026-06-22 in the design workspace.*

## The decision

The [D-237](0237-authorize-flipping-the-memory-backup-default-to-a-shared-vau.md) flip landed: [memory](../spec/systems/cognitive/memory.md)'s backup law now **defaults to a single shared cross-project memory vault**, a per-project repo the alternative **offered at every new project's setup**, with the namespace-identity law, the §7-honest privacy framing, the restore-coherent concurrency model, and the generalized floors (1)/(2)/(3). The **plan-stage four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran against the **landed** memory text and **corrected [D-237](0237-authorize-flipping-the-memory-backup-default-to-a-shared-vau.md)'s "only doc in the blast radius" claim**: two further **locked** docs restated the overturned per-repo default and were now self-contradictory — reconciled under operator-approved widened scope and re-locked here. **What landed and where.** **(memory)** flip + the **namespace-identity-minting law** (minted once by memory at destination-binding, **collision-free by construction needing no read of the vault**, written into the committed pointer **before first export**, never re-minted, a reused vault mints its **own fresh id**) + **restore-coherent concurrency** (disjoint-path retry-on-reject, or per-namespace branches the Engine integrates, restore reading the namespace's folder from the integrated default branch) + **§7 privacy honesty** (the re-check *detects*, does not *prevent*; **no engine-applied bound** on the flip exposure under shared-default — only the operator's **opt-in** per-project choice; cross-project *mis-routing* separately bounded by the namespace-id) + **floor (2)** honest that the Engine cannot prevent a hand-deletion and surfaces a now-missing namespace + **floor (3)** covering the **first** project (creates and names the vault) and the stated bare-machine bound. **(memory-substrate module, locked)** default wording corrected to shared-vault-default / per-repo-alternative, the **namespace-identity binding** added to the owned mechanism, and the **namespace-identity representation** given a home in the build-spec-leaf list. **(audit-library module, locked)** the "Coverage of local memory" access model corrected — under the shared-vault default the audit run's grant **spans every co-located project's namespace** (disclosed), with the per-project repo the way to keep a project out of that shared grant. **(risks R2, not locked)** the v1-default phrase reconciled to shared-vault / per-repo. **Adopter-distribution axis (the audit raised it):** the vault is **per-operator-account, created per-deployment at first-run, and never committed into the template**, so no co-location model ships to downstream adopters — [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)'s adopter-leakage axis is untouched by the flip (only the off-repo *backup* co-locates, by the operator's own-account choice). Re-locks land in dependency order: `python3 lock.py --relock systems/cognitive/memory/README.md --decision D-238`; `… modules/memory-substrate-sqlite-fts5/README.md …`; `… modules/audit-library/README.md …`; `python3 validate.py` green.

## Why

A **focused two-lens cold landed-text re-check** (faithfulness + adversarial/technical, no shared context) ran against the on-disk edits — the proportionate close after the plan-stage four-lens audit ([D-148](0148-lock-audit-library-the-engine-self-audit-delivery-the-tenth.md)/[D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md)/[D-236](0236-resolve-the-d-235-engine-issue-conformance-reroute-gate-land.md) precedent). **Adversarial/technical returned no blocking and no serious:** it confirmed the namespace-id minting law airtight (owner / moment / before-export / reuse-mints-own / no-vault-read), the §7 privacy fix **genuine, not merely reworded**, restore-coherence established via the integrated default branch with retry safety resting on path-disjointness, the floors honest, and the audit-library access-scope correct against the GitHub-Actions-token reality and consistent with memory's "one credential reads every namespace." **Faithfulness returned one blocking, resolved:** the first export bullet still asserted "the v1 default is a private GitHub repo" (the overturned per-repo default) two bullets above the new shared-vault default — fixed by scoping that bullet to the *transport* (a private GitHub repo via `gh`, true of both topologies) and pointing to the shared-vault default below. The bare-flip review's "the re-check mitigates the blast radius" reasoning was the central error and is folded into the law as detect-not-prevent with the per-project escape named as opt-in, never a structural bound. The widened blast radius is the audit doing its job: [D-237](0237-authorize-flipping-the-memory-backup-default-to-a-shared-vau.md)'s grep was scoped to the literal default phrase and missed audit-library's *consequential* dependence on repo cardinality; the operator approved reconciling all three locked docs for a self-consistent spec. The litigation-alarm protocol held throughout — [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md) untouched (append-only), each locked edit re-locked under this decision.

## What we ruled out

Re-lock memory alone (rejected — audit-library's access model and the substrate module's default wording would be left now-false; a relock atop a self-contradictory spec is the drift the lock guards). Hedge "collision-free by construction" to "collision-resistant" (rejected — the re-check rated it sound; the mechanism — a sufficiently wide opaque id with no vault read — is stated, and the by-construction claim is honest engineering, not an unbacked platform guarantee). Rewrite the pre-existing "`repo` scope" wording for fine-grained-token neutrality (rejected — outside this change's scope, not false, and the scope-grant interaction already defers to provisioning's build-spec leaf). Fold the per-project-at-scale concurrency preference into the law (rejected — a build-spec-leaf preference, carried as guidance: the branch-per-namespace arm is the safer default for a many-project operator; the law keeps both arms and defers the cadence). Add a glossary "memory vault" term now (rejected — additive, not corrective; a separate pass if wanted).
