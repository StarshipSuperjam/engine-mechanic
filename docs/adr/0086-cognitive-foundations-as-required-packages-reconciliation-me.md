# Cognitive foundations-as-required-packages reconciliation: memory floor its own `required` package, knowledge rides `core`, the semantic layer the lone optional/experimental package

*Decided 2026-05-27 in the design workspace.*

## The decision

Resolve the **foundations-as-required-packages reconciliation** that [D-077](0077-lock-the-provisioning-system-terminal-foundation-lock-the-bo.md) named as the last standing block before WBS authoring. The catalog ([modules/README.md](../reference/module-catalog.md)) is re-cut to match the locked cognitive systems: **`memory-substrate-sqlite-fts5` → `required`** (its own required package, moved out of the resolved "Pending reconciliation" rows into the Required-spine table; id unchanged); the **[knowledge](../spec/systems/cognitive/knowledge.md) foundation has no separate package** — its committed entities + derived index ride **`core`'s `provides`**; **`engine-knowledge-graph` stays `experimental`** as the one genuinely optional semantic-recall / graph-representation layer atop the ledger, behind the swappable `search` interface, off the [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) operator menu (engine choice deferred to [Q11](../reference/open-questions.md)). The dependency graph needed no re-cut (the `core --> memory-substrate-sqlite-fts5` and three `engine-knowledge-graph` in-edges already routed correctly). Resolved after a **four-lens cold-context audit** (adversarial / technical-feasibility / non-engineer-operator / architect) of the plan; its serious findings are discharged in this entry.

## Why

Every floor system is `required` and always ships, so optionality cannot decide where it lives; the package boundary is decided by *purpose*. A boundary is justified by two non-speculative facts about **memory**: it **owns the `search` interface seam** the swappable semantic layer binds to (a clean named dependency target), and its canonical store is the only floor store that is gitignored, accumulated, and **non-regenerable** (the NDJSON ledger — [R2](../reference/risks.md), [D-061](0061-lock-the-memory-system-wave-2-the-episodic-ledger-store-q3-b.md)/[D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md)), so the engine's most irreplaceable data gets an owned, legible migration unit instead of burying ledger migrations in a monolithic `core` migration (schema evolution is a *consequence* of that, not the driver). This follows the existing pattern of breaking out substantial required subsystems others bind to. **Knowledge** is committed entities + a derived/regenerable index ([principle §3](../principles.md)), so it has no per-instance store to migrate and no v1 consumer binding a knowledge-specific boundary; it rides `core`, matching the precedent for light foundations (state/attention/telemetry/hooks live in `core`, not separate packages) and satisfying the module-system one-owner rule (knowledge's files map to `core`'s `provides`). **On the package name:** the audit's adversarial lens flagged `-sqlite-fts5` as over-committing a required foundation to a swappable index; the id is **kept** because the locked [memory](../spec/systems/cognitive/memory.md) doc makes FTS5/BM25 the *actual v1 foundation floor index* (only the semantic layer is the swappable part; FTS5's fallback-to-NDJSON-scan is internal robustness, not a misnomer), so the name truthfully describes the v1 substrate — and a rename would break this append-only log, which already cements the path at [D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md). Propagation per the matrix: [modules/README.md](../reference/module-catalog.md) (rows reclassified, "Pending reconciliation" subsection retitled to the experimental swap-seam note, cognitive scope-note rewritten to current truth, graph verified), [glossary.md](../reference/glossary.md) (a reconciling clause: a foundation is its own `required` package only when it owns non-regenerable per-instance data or a bound seam; otherwise its files ride `core`), wbs/README.md (the cognitive-reconciliation blocker removed; the pre-existing deviation-verdicts gate left intact), this entry. Verified consistent, no edit: the locked [memory](../spec/systems/cognitive/memory.md) and [knowledge](../spec/systems/cognitive/knowledge.md) docs (the reconciliation adapts the catalog *to* them — no lock touched), [engine-architecture.md](../architecture.md) §3/§4/§9 (states the law generically; does not enumerate per-foundation packaging class), [risks.md](../reference/risks.md) (R8 stays behind the swap seam), [open-questions.md](../reference/open-questions.md) (Q11 is engine-choice, packaging-agnostic).

## What we ruled out

**Both memory and knowledge as their own required packages** (rejected — knowledge has no non-regenerable per-instance store and no v1 consumer binding a knowledge-specific boundary, so a `knowledge` package is ceremony without payoff, against low-ceremony). **Fold both floors into `core`** (rejected — buries memory's irreplaceable-ledger migrations inside a monolithic core migration and forces `engine-knowledge-graph` to bind to `core` for a sub-capability instead of memory's named `search` seam). **Rename the package to `memory-substrate`** (rejected — FTS5 is the actual v1 floor index so the id is accurate, and a rename would break the append-only [D-081](0081-re-litigate-memory-ledger-write-integrity-law-reframe-usage.md) link, forcing either a hand-edit of immutable history or a GRAVEYARD entry stretched from its deleted-doc purpose to a rename). **Promote `engine-knowledge-graph` to the v1 operator menu** (rejected — engine choice deferred at [Q11](../reference/open-questions.md); it fits none of the three [D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md) SDLC discipline categories).
