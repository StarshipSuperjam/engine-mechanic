# Flesh the `migration-discipline` module doc to `designed`: optional product-migration governance — discipline bar + posture-grade escalation routing for destructive migrations + a soft presence check; `depends: core`

*Decided 2026-05-28 in the design workspace.*

## The decision

Take the [`migration-discipline`](../spec/modules/migration-discipline.md) module doc from `stub` → `designed` (packaging-view depth, matching the `designed` peers; **not** locked). It is the second kept optional Software Configuration Management module ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md)), sibling of [`dependency-discipline`](../spec/modules/dependency-discipline.md) ([D-097](0097-flesh-the-dependency-discipline-module-doc-to-designed-optio.md)), governing the **product's** own data/schema migrations (Rails/ActiveRecord, Django/Alembic, Prisma, Flyway, Liquibase, golang-migrate, raw SQL) — **distinct from the engine's own migration machinery** (the manifest `migrations` field applied to engine state on upgrade: provisioning's engine-upgrade migrations + backup-first reversal, the [memory](../spec/systems/cognitive/memory.md) ledger unit, the engine's **own surface-schema** version-pinning). Standalone, fills no [Slot](../reference/glossary.md) ([D-069](0069-core-module-seam-walk-the-demarcation-operationalized-glossa.md)). **Operator decision (settled this session): Option A** — a posture **policy** + destructive-migration **escalation routing** + **one `soft` ecosystem-detected presence check**; **`depends: core`** (no catalog edit). Settled points: `provides` = the **policy** (its own tier **posture**; **names a destructive/irreversible product-schema migration a recognized instance** of the locked, always-present Escalation policy — recognition guidance + the recommendation/safe-path shaping, a [§16](../principles.md) relay) + a **`soft` presence check** (a schema-changing PR carries a migration artifact; a migration carries a rollback **where the framework has the concept** — a **three-way** resolution: present / missing-soft-warn / **no-concept-disclosed-not-applicable**; ecosystem-detected by manifest **or** migration-tooling config/convention; disclosed no-op when no framework) + read-only detection logic; **`wires: none`**; `depends: core`; `migrations: none (v1)`. The product/engine migration boundary is **terminological, not mechanical** (the two "migration" concepts share no code path/file/seam); the module **never runs a product migration** — read-only inspection of artifacts in pull requests + escalation.

## Why

A module doc is the packaging view; the depth lives in the locked [policies](../spec/systems/surfaces/policies.md)/[check](../spec/systems/surfaces/check.md)/[validation](../spec/systems/guardrails/validation.md) systems, and the closest peer [`dependency-discipline`](../spec/modules/dependency-discipline.md) ([D-097](0097-flesh-the-dependency-discipline-module-doc-to-designed-optio.md)) sets the skeleton. The honest core: **migration *safety* is not mechanically decidable across ecosystems** — there is no "migration-safety database" to relay (unlike dependency-discipline's vulnerability gate), so the destructive-migration response is **human escalation, not a hard gate**. A **four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context, plan inlined) ran **on the plan before approval** (the audit-before-approval discipline now covers substantive `designed` passes, not only locks). Dispositions: **(operator BLOCKING)** the escalation must hand a non-engineer a **recommendation + a concrete reversible/safer path**, not bare "options" — **bound** (the discipline bar made actionable: expand-contract / backup-first / additive-then-cutover where the framework supports it). **(§7 honesty, adversarial+architect)** "escalation is primary teeth" overstated — there is **no mechanical destructiveness detector** (the presence check is presence-only), so the destructive-migration response is **judgment-triggered, posture-grade** escalation backstopped by the locked policy's three backstops (lock fingerprint, protected-branch merge gate, **close-ritual disposition gate**, [§6](../principles.md)) — reframed as the primary **mechanism, not teeth**. **(adversarial)** the **core Escalation policy already escalates** irreversibility with or without this module, so the module's policy is **domain recognition guidance** over an already-firing trigger, not a new pathway — stated, which **strengthens the [§13](../principles.md) removal test** (removing the module leaves irreversibility still escalating). **(technical, externally verified)** the rollback nudge is a **three-way** resolution (Prisma has no native down; Flyway undo is paid Enterprise; Liquibase rollback is tier-gated) — detect framework first, then present / missing-soft-warn / no-concept-disclosed-not-applicable; detection is manifest **or** tooling config/convention. **(technical+architect+adversarial)** **`depends: core` justified on the target axis** — the check inspects **product** artifacts and presupposes **no** engine-self-validation corpus, so it needs only `core`'s kind dispatcher + the read-only `custom/script` (or a presence-discovered conforming) kind, never `validators-core`'s corpus; the divergence from dependency-discipline's `validators-core` edge is **deliberate**, flagged for the lock pass; **no catalog edit**. **(operator)** **setup-time disclosure** bound (the package pauses an in-progress build and halts an unattended routine before destructive schema changes — a provisioning selection-UX requirement); the **routine halt** emits a **legible** plain-language finding (stopped *because* a destructive migration needs a human + what it would do + the recommended safe path, surfaced at next boot, no less than the interactive path); **plain-language** for the high-frequency no-op/nudge cases (not-applicable-vs-could-not-run; explain "rollback" + the risk). **(adversarial)** **precise no-overlap attribution** — [design-review](../spec/modules/design-review.md) `feasibility` names "migration" explicitly; [qa-review](../spec/modules/qa-review.md) judges migration *outcomes* via `spec-conformance`/`technical-integrity` **without** a migration-named lens; the axis is standing-discipline (this module) vs gate-judgment (the lenses). **(NITs)** boundary terminological-not-mechanical; `migrations: none` glossed; the engine's **own surface-schema** version-pinning labelled; the Escalation policy stated always-present; escalation "before authored/applied" means **described-enough-to-judge**; the operator **can approve** (stop-and-ask, never a veto); no glossary term coined. The technical lens **confirmed** the central premise (cross-ecosystem destructive-migration detection is genuinely infeasible) against current framework documentation. Propagation per the matrix: [modules/migration-discipline/README.md](../spec/modules/migration-discipline.md) authored to `designed`; this entry. Verified no-change with rationale: [modules/README.md](../reference/module-catalog.md) (the `migration-discipline | optional | core` row, the `core → migration-discipline` edge, the SCM category, and the scope note all present and correct; **the `core` edge stays — no catalog edit**; design-maturity is not catalog-tracked), [engine-architecture.md](../architecture.md) (indexes via the [D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md) roster sentence; role unchanged), wbs/README.md (the module sort is unauthored; this pass feeds it and gates the eventual lock, not the `designed` state), [glossary.md](../reference/glossary.md) (no term coined — `Slot`/`Filling` already place it as a standalone module; "migration"/"rollback"/"expand-contract" stay descriptive prose), [deviations/README.md](../reference/prototype-deviations.md) (D24 already `DECIDED` at [D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md)), [risks.md](../reference/risks.md) (no new risk — read-only, no third-party Action, no product-source mutation), [open-questions.md](../reference/open-questions.md) (no migration-owned Q). No locked system doc edited — the design **consumes** the locked policies/check/validation/module-system/provisioning/memory/schemas laws and **relays** into the locked Escalation policy without editing it ([§16](../principles.md)), so the litigation alarm and the lock-audit gate correctly do not fire and the change is fully reversible.

## What we ruled out

A **`hard` destructive-migration gate** (rejected — "destructive" is not reliably detectable across ecosystems; a false block strands a non-engineer on their own PR, [§6](../principles.md); the locked Escalation policy is the right seam). **Move the edge to `validators-core`** to parallel dependency-discipline (rejected — this module's check presupposes no self-validation corpus, so `core`'s engine suffices; a catalog edit would re-open a decided graph edge for no gain). **Policy-only, no check** (rejected — the operator chose Option A; the presence nudge is honest hygiene with a disclosed no-op). A **migration review agent/lens** (rejected — [D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md) no-overlap with the `feasibility` lens; the review lenses are separate modules). A **standalone operation** (rejected — the [operations](../spec/systems/surfaces/operations.md) ≥2-invoker anti-sprawl bar; the escalation is the locked policy's own runbook). Carry the bar/escalation/check under **one policy enforcement tier** (rejected — [§7](../principles.md); they are three tiers). Call the escalation **"mechanical teeth"** (rejected — [§7](../principles.md) honesty; it is judgment-triggered posture backed by the human gate, with no mechanical destructiveness detector). **Lock** `migration-discipline` this pass (rejected — the WBS + a fresh cold audit gate the lock, in dependency order; `core` itself is only `designed`).
