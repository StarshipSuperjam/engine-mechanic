# Authorize the status-verb cold-start re-litigation: `model-auto` skills are not cold-start-typeable, so `/engine-status` is unreachable at session start; flip it to `operator-typed` (engine-template #102)

*Decided 2026-06-15 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) editing **two locked docs** — [skills](../spec/systems/surfaces/skills.md) ([D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md)) and [modules/core](../spec/modules/core.md) ([D-193](0193-resolve-the-d-192-conduct-surface-re-litigation-landed-text.md)) — plus non-locked carriers ([glossary](../reference/glossary.md), [risks](../reference/risks.md)), to correct a **false platform premise** baked into the locked invocation-axis design: that a `model-auto` skill is operator-typeable.

  **The litigation alarm (operator-verified, not doc-inferred).** engine-template **#102**: `/engine-status` — the operator's only unfiltered, verbatim status view (the *pull* half of the [operator-presentation relay](../reference/glossary.md)) — cannot be typed at a **cold session start**, the one moment it is wanted. Verified against the operator's live Claude Desktop and the five deployed engine skills: a skill is in the operator's `/` menu **only** with `disable-model-invocation: true` (`operator-typed`); a model-invocable (`model-auto`/default) skill's description loads into the model's context and so surfaces in the menu **only from the second message on** — absent at the first. The four `operator-typed` core verbs show immediately; the lone `model-auto` verb (status) does not. The official Claude Code docs assert the opposite (default skills are menu-listed); the live platform falsifies the docs, so the locked claim that `model-auto` = "the operator may also type it" is false at cold start.

  **`model-auto` bought nothing and cost the menu entry.** It was chosen ([D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)/[D-188](0188-resolve-the-d-187-operator-presentation-relay-re-litigation.md)) so the AI may offer/run status on a relevance match — but the AI renders status by running the underlying `engine_status.py` tool directly (the skill is a thin `uv run` wrapper), independent of the skill's invocation mode. So `model-auto` earned no AI capability while removing the operator's cold-start access. On the platform, menu-visibility and model-invocability are **mutually exclusive for one skill** (menu ⇒ `disable-model-invocation: true` ⇒ not model-invocable) — and a "both" skill is unnecessary, since the AI's path is the tool.

  **Resolution (lands under [D-201](0201-resolve-the-d-200-status-verb-cold-start-re-litigation-lande.md) after the mandatory landed-text cold audit).** The status verb becomes **`operator-typed`** (declare `invocation: operator-typed` **and** carry `disable-model-invocation: true`): it shows in the `/` menu at cold start, is listed by `/engine-help`, and passes the `validators-core` skill-coherence check. The AI keeps relaying the dashboard by running `engine_status.py` directly; the "offer status on demand" guidance relocates from the now-non-resident skill description into the AI's standing context (boot pack / deployed `CLAUDE.md` / the relay convention). After the flip, **v1 ships zero `model-auto` skills**; the value survives in the taxonomy for a future module, exactly as `model-only` does ([D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md)). The `invocation:` field **stays** — it is load-bearing (`engine_help` lists by it; `validators-core` `skill_coherence_findings` enforces invocation↔platform-flag agreement, e.g. the operator-typed-without-the-flag self-election leak); this re-litigation is not its removal.

  **Scope. Edit + re-lock (2 locked):** [skills](../spec/systems/surfaces/skills.md) (invocation-axis `model-auto` row gains the cold-start truth — model-invocable skills are absent from the cold-start `/` menu, so a verb the operator must reach cold must be `operator-typed`; add "v1 ships no `model-auto` skill"), [modules/core](../spec/modules/core.md) (the status verb's `model-auto`/operator-typeable claims at the `provides` line and the `/engine-help`-index paragraph → `operator-typed`, AI relays via the tool). **Edit (non-locked):** [glossary](../reference/glossary.md) (*Skill* `model-auto` definition + *Status verb*), [risks](../reference/risks.md) ([R19](../reference/risks.md) — the operator-typed status verb is the operator's cold-start-reachable unfiltered view, mitigating the sole-pipe residual). **Verify-no-edit (logged):** [boot](../spec/systems/lifecycle/boot.md), [modes](../spec/systems/lifecycle/modes.md), [close](../spec/systems/lifecycle/close.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [conduct](../spec/systems/surfaces/conduct.md), [operations](../spec/systems/surfaces/operations.md), [engine-architecture](../architecture.md), the `scenarios/` walkthroughs, [modules/product-design](../spec/modules/product-design.md) — each references the status verb or the `model-auto` category, both of which survive. **Supersedes** only the `model-auto`-for-the-status-verb choice in [D-187](0187-authorize-the-operator-presentation-relay-re-litigation-the.md)/[D-188](0188-resolve-the-d-187-operator-presentation-relay-re-litigation.md); the operator-presentation relay otherwise stands. The engine-template **#102** build realization (flip the SKILL.md frontmatter to `operator-typed` + `disable-model-invocation: true`; confirm `/engine-help` + coherence; relocate the AI's status-relay prompt; re-verify cold-start visibility in Desktop) is a downstream build-owes, not authored here.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval (given: the approved plan named these docs + "continue"). The premise is **operator-verified false** against the live platform — the docs contradict the live behavior, so doc-inference was wrong (it misled this session twice). The correction is minimal and subtractive — no new field, capability, or surface ([R6](../reference/risks.md)) — aligning the locked taxonomy with how Claude Code actually reads `disable-model-invocation`/`user-invocable`. It restores the operator's cold-start unfiltered view at **zero cost to the AI relay** (the tool path is unchanged) and keeps the enforced `invocation:` annotation.

## What we ruled out

**Dismiss #102 as a docs-confirmed non-issue** (rejected — done twice this session by trusting the docs' invocation table; the operator's live Desktop + the five deployed skills falsified it). **Keep the status verb `model-auto`** (rejected — unreachable at the cold start that is the only time it is wanted, for no offsetting AI gain). **Remove the `invocation:` field** (rejected — consumed by `engine_help` and enforced by `validators-core` skill-coherence; the fix declares `operator-typed` + adds the flag). **Make one skill both menu-visible and model-invocable** (rejected — mutually exclusive on the platform, and unnecessary since the AI runs the tool). **Re-lock [boot](../spec/systems/lifecycle/boot.md)/[modes](../spec/systems/lifecycle/modes.md) as the plan first scoped** (rejected — they reference the status verb generically, which survives; verify-no-edit, narrower per [R6](../reference/risks.md)). **Author the fix in the build first** (rejected — locked design lands the re-litigation first; the build conforms one-way).
