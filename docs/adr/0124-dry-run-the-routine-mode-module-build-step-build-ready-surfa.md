## Why

This is the module-vs-system lock-gate discipline in motion — a clean dry-run over a module's build step is the **build-readiness precondition** for that module-packaging lock, distinct from and prior to the cold-session design audit every lock still passes ([D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)→[D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md) precedent; [D-123](0123-run-the-l2-dry-run-validators-core-memory-substrate-both-bui.md) for the L2 pair). `routine-mode` is the natural first of the remaining nine: the L2 required-spine entry into the Routine stance, a thin delivery module that wires nothing and rests entirely on the locked modes / build-orchestration / skills / operations laws. The reviewer's all-REJECT, verbatim-cited adjudication is the well-calibrated profile, so no re-adjudication was needed; the orchestrator still ground-truthed the two escalated `serious` findings per dry-run.md §4 and confirmed both REJECT. The contradiction is **surfaced rather than silently dropped** (finding-disposition) and routed honestly: a real but non-build-blocking designed-doc accuracy defect, fixed in a separate human-gated pass before the lock, never inside this read-only run.

Record the contradiction as a **blocking/serious build gap** (rejected — it does not block construction; the builder produced correct artifacts, so it is build-ready with a designed-doc remediation owed before lock, not a build blocker). Treat it as a **litigation alarm** (rejected — the remedy edits the `designed` routine-mode doc, not a locked one; modes and D-088 are already correct, so no locked doc changes). **Edit `routine-mode`:42 now** as part of this run (rejected — the dry-run is read-only/advisory; remediation is the separate human-gated pass the operator gates). **Confirm the builder's F1/F2 as gaps** (rejected — ground-truthed: the manifest field set and the skill invocation field are enumerated, the concrete schemas are named build-spec leaves, the genesis version value is owner-pinned; the builder over-escalated named-but-deferred leaves, the §2 failure the reviewer correctly rejected). **Lock `routine-mode` now** on build-readiness alone (rejected — build-readiness is the precondition, not the certification; the packaging lock still owes a fresh cold-session audit + explicit operator go, and the `routine-mode`:42 contradiction must be remediated first).
