# Authorize correcting #100: "where we are" is assembled read-only from GitHub, not advanced by build-orchestration (supersedes D-196/D-197)

*Decided 2026-06-15 in the design workspace.*

## The decision

Authorize a re-litigation that **supersedes [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md)/[D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md)** and edits **three** locked docs ([state](../spec/systems/cognitive/state.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [boot](../spec/systems/lifecycle/boot.md)) + carriers. The litigation alarm: the operator showed that [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md)/[D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md)'s design — build-orchestration *advancing* the [state](../spec/systems/cognitive/state.md) standing-situation pointer — is a **category error**. "Where we are" is already defined by GitHub structured state, so having build-orchestration *produce a cursor derived from artifacts it already emits* is **pure relay dressed as ownership** ("build-orchestration is about orchestrating build work, not telling boot status … it does nothing but relay what GitHub has already defined"). The advance was also a **posture step that can silently no-op** — #100's exact failure relocated, not removed.

  **The resolution honors build-orchestration's merit by removing a job that was never its merit.** Its merit is the gate skeleton, the plan-gate consent, single-writer integrate, the cold-review spine, delegation, and Routine — **none of which is a status cursor**. It sheds the cursor responsibility and loses nothing.

  **The corrected model (audit-sharpened — composite, not a clean debt-count sibling).** "Where we are" is **assembled read-only by [boot](../spec/systems/lifecycle/boot.md)** from native sources, the way boot already assembles "what just happened" from merged PRs and the live debt register:
  - **`phase`** (the current track) — **engine-derivable** from the engine's own build Issues + git (the most-recently-merged tracked build Issue); strong, like the debt count (engine-controlled).
  - **`milestone`** (the broad plan phase) — the **operator's plan**, read from the active GitHub **Milestone** when the project uses them, and honestly **`none set`** when it does not (the build repo currently has *zero* Milestones — `gh api` confirmed — and today's `milestone` string is a hand-seed; build-orchestration does not author it either, the operator's plan does).

  **build-orchestration writes nothing** to the cursor. The committed `state.json` value is demoted to a **best-effort offline cache**, refreshed online by the same GitHub-derived-cache pass that refreshes the debt count (a shared, designed-but-build-unwired mechanism — the build owes wiring *both* fields) and rendered with the debt count's `as-of`/"may be stale, re-ground" provenance offline. #100's symptom — the **online** card stale — dissolves because online there is **no stored marker trusted**: boot derives it live. Offline degrades to the labelled cache, the same accepted degradation the debt count already carries. **Honest bound, stated not hidden:** this is *not* a perfect debt-count sibling — `phase` is engine-derivable (strong); `milestone` is operator-Milestone-derivable (best-effort, `none set` fallback). This also corrects [state](../spec/systems/cognitive/state.md)'s original [D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md)-lineage law ("the standing-situation pointer advances on committed acts") — the stored-and-advanced framing is the root error.

  **The four-lens cold plan-audit + dispositions.** **Architect — PASS** (revert complete + scar-free; the reframe is [§2](../principles.md)/[§3](../principles.md)/[§16](../principles.md)-clean; the D-198→D-199 append-only supersession protocol is correct; scope minimal/subtractive); its one serious — **[R23](../reference/risks.md) reframed, not left ambiguous** — folded. **Technical-feasibility — two folds:** (1) **zero GitHub Milestones exist** (ground-truthed via `gh api`) ⇒ the `milestone` derivation degrades honestly to `none set` and the "debt-count sibling" claim is qualified into the composite model above; (2) **the as-built `boot.py` only *reads* the committed cache, never derives** ⇒ the design must **explicitly** require boot to derive live online or #100 recurs online (folded: boot gets the explicit touch + joins the re-lock); confirmed `phase` is GitHub-derivable, the debt-count derive-and-cache pattern is real, and boot deriving-for-display is read-only-clean. **Non-engineer-operator — folds:** the #100 correcting comment must read as a rigorous correction (name the superseded decision + the category error + the more-robust result), **never thrash**; the card rendering must distinguish live-online from cached-offline in plain language (a named boot build-spec leaf); `none set` is honest, not an error. **Rejected over-reads (logged):** "deriving violates boot's read-only law" (deriving-for-display is the read-only assembly boot already performs for the live debt register and "what just happened"; it writes no committed state — architect concurred); "a live-derived view is wrong, the cursor must be a frozen snapshot" (live-derived is the *intended, better* semantics; the snapshot is exactly what froze at `#83`; the offline cache is the snapshot fallback); "a one-hour-old lock cannot be superseded" (the plan follows the litigation-alarm + append-only protocol — architect confirmed).

  **Scope.** **Revert + reframe + re-lock — 3:** [state](../spec/systems/cognitive/state.md) (delete the [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md) advance commitment + the "build-orchestration owns and advances / two writers" seam clause + the [D-059](0059-lock-the-state-system-wave-2-head-the-committed-cursor-recon.md)-lineage advance law; reframe the standing-situation as a read-only assembly from native sources, committed only as a best-effort offline cache with the debt count's staleness provenance), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) (revert all 6 [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md) additions — the skeleton step-4 cursor clause, the "Advance the standing-situation pointer" section, the Routine Finalize clause, the design-commitment bullet, the build-spec leaf — scar-free), [boot](../spec/systems/lifecycle/boot.md) (add that boot assembles the standing-situation read-only at orientation from native sources, like "what just happened"; the committed value is the offline floor; the card distinguishes live-online from cached-offline — build-spec leaf; read-only law preserved). **Edit (non-locked):** [glossary](../reference/glossary.md) (reframe *Standing-situation pointer*, re-attribute D-196 → D-198), [risks](../reference/risks.md) ([R23](../reference/risks.md) reframed to the offline-cache-staleness residual shared with the debt count; the advance-step failure modes are gone), [scenarios/build-session](../architecture.md#build-session-lifecycle) + [scenarios/routine-session](../architecture.md#routine-session) (revert the cursor-advance steps). **Verify-no-edit (logged):** [telemetry](../spec/systems/guardrails/telemetry.md), [attention](../spec/systems/cognitive/attention.md), [knowledge](../spec/systems/cognitive/knowledge.md), [modules/core](../spec/modules/core.md), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning). The re-locks land under the **resolve** entry ([D-199](0199-resolve-the-d-198-standing-situation-correction-landed-text.md)) after the mandatory landed-text cold audit (the [D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)→[D-190](0190-resolve-the-d-189-operator-checkout-boundary-re-litigation-l.md) pattern). The engine-template **#100** build realization is re-aimed (a boot derive-at-orientation step + the offline-cache refresh riding the debt-count pass; **stop the advance tool** a build worktree has already begun) — a downstream follow-up, communicated via a corrected #100 comment, not authored here.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval. [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md)/[D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md) were *wrong at the root* — they misattributed to build-orchestration a status cursor that is a projection of GitHub state, and made its correctness depend on a posture step that can silently no-op (#100's own failure). The correction is **minimal and subtractive**: it adds no state field and no capability, removes a misattributed responsibility, and relocates the standing-situation to the read-only orientation layer that already assembles such views — so the cursor can no longer silently lie online (it is derived), and build-orchestration is freed of a job that was never its merit. The honest bounds (the composite `phase`/`milestone`; `milestone` best-effort with a `none set` fallback; the offline cache labelled stale) are named, never over-promised. Superseding a one-hour-old lock is the lock protocol working as designed — it stops *silent* drift, not a *justified* correction the operator's scrutiny surfaced.

## What we ruled out

**Keep [D-196](0196-authorize-the-standing-situation-pointer-advance-re-litigati.md)/[D-197](0197-resolve-the-d-196-standing-situation-pointer-re-litigation-l.md)'s build-orchestration advance** (rejected — the category error + the silently-no-opping posture step). **Move the derivation to boot but leave build-orchestration a cursor role** (rejected — the operator's point is that build-orchestration must own *nothing* about the cursor; a residual role is the same relay-dressed-as-ownership). **Frame the standing-situation as a clean debt-count sibling** (rejected — ground-truthed: `milestone` depends on the operator using GitHub Milestones (currently none), unlike the always-derivable debt count; the honest model is composite). **Let boot keep reading the committed cache only** (rejected — the as-built proves boot never derives, so a stored cache that nothing refreshes reproduces #100 online; boot must derive live, the committed value being the offline floor). **Treat deriving-for-display as a boot read-only violation** (rejected — it is the read-only assembly boot already does; it writes no committed state). **A frozen-snapshot cursor** (rejected — that is what froze at `#83`; live-derived online + cached-snapshot offline is the correct shape).
