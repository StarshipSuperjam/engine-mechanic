# Provisioning & delivery designed end-state: brownfield-capable grammar, greenfield-first build order

*Decided 2026-05-25 in the design workspace.*

## The decision

Author [provisioning](../spec/systems/infrastructure/provisioning.md) to a firmed `designed` end-state (not locked — it leans on `designed`/open neighbours, below). The driving resolution: **a live product can adopt the Engine** — brownfield adoption is *mandated* by [principle §13](../principles.md) (a contributor joins and learns an existing product), so the grammar is brownfield-capable now ([D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md) forbids deferring it to a refactor) while build order may lead with greenfield. Two axes are separated: **delivery** ("Use this template" is greenfield-only by GitHub mechanics; brownfield reuses the updater's fetch-tagged-release-and-overlay machinery to place engine files onto a populated repo, then runs the same instantiator) and **coexistence** (the wiring library's keyed, insert-iff-absent discipline, extended to every platform-shared path). Six settled laws: **(1) CODEOWNERS keying** — a comment-fenced, engine-keyed block applied by the control-plane bootstrap via a wiring-library *helper* (not a sixth seam directive; no `wires` entry; deterministic placement), required even for greenfield→upgrade so an overlay never clobbers operator-added product rules; the **ruleset is augmented, never weakened** via read-modify-write, de-bootstrap drops only engine-namespaced check names, and an engine-created ruleset is disclosed-not-auto-deleted on clean removal. **(2) Bootstrap mechanism ([Q4](../reference/open-questions.md) mechanism resolved)** — the operator's own local `gh`, engine-orchestrated, applies/augments the ruleset *after the operator approves the scope grant* (the engine cannot self-grant `admin:repo_ruleset`; web flow preferred, scope verified post-refresh); bootstrap is *attempted* in the instantiator but its logic is **permanent in `.engine/tools/`** (defer is the common path; the fail-loud CI guard + boot nag are the backstop; degrade-and-disclose where the scope is ungettable). **(3) Identity** — derive-first (only the tier is prompted); the operator handle is preserved config and the CODEOWNERS block is *derived* from it; tier defaults solo, team is a reconfigurable opt-in *recommended on brownfield team-detection*. **(4) Instantiator** — presence = unprovisioned; a non-destructive **gather** → **confirm** (writes the engine manifest, the resumability checkpoint) → idempotent **apply**; a thin orchestrator composing permanent primitives; the explore write-gate is the existing `hook` seam the apply phase installs, so provisioning runs *ungated until retirement* (no fourth mode). **(5) Module manager** — verbs are add/remove (per-module, current release) + upgrade (engine-wide); **no per-module update**; ordinary add/remove does **not** touch the ruleset (module checks flow through the derived suite roster inside a stable CI check whose status name is a **frozen, migration-immutable contract**); `remove` is reverse-dependency-aware; migrations exist because the overlay preserves config+data, and reversal is **backup-first + an active boot mismatch detector** (reusing memory's [Q3](../reference/open-questions.md) backup path). **(6) Product boundary** — not a new surface; the topology wall (enforcement) + product-side engine-read-only knowledge (captured by the product-intake module on greenfield, *read from the existing product* on brownfield, §13 asymmetry). A four-lens cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran on the plan and again on the authored docs; its findings were resolved before this entry (operator-framing protections, the `gh` device-flow scope-persistence caveat, the frozen-check-name invariant, the ruleset read-modify-write race, the CODEOWNERS future-append residual), and its blocking cross-lock finding is resolved by [D-049](0049-re-lock-topology-and-module-system-file-precise-codeowners-o.md). Stays **`designed`** because it depends on `designed`/open neighbours — memory's Q3 backup, [modes](../spec/systems/lifecycle/modes.md)' write-gate, [boot](../spec/systems/lifecycle/boot.md)'s migration-mismatch detector and onboarding read.

## Why

Provisioning is the bootstrap-paradox foundation that stands the engine up and is the home control-plane ([D-017](0017-control-plane-locked-end-state-as-contracts-not-leaves.md)) deferred Q4's mechanism to. The contributor principle makes brownfield non-optional at the *grammar* level, and the smallest sufficient design is a recombination of the instantiator and the already-designed updater overlay, not a new system. The gather/confirm/apply split makes first-run resumable using the existing engine manifest as the only checkpoint; the write-gate-is-installed-by-provisioning insight removes the need for a setup-phase mode; the frozen-check-name and read-modify-write laws are the platform realities a non-engineer cannot be left to manage. Kept `designed` not `locked` per the lock discipline (never lock atop churning `designed` neighbours).

## What we ruled out

Greenfield-only (rejected — silently contradicts the locked §13 contributor principle; an engine that can only found repos is not a contributor). Defer brownfield to v2 at the design layer (rejected — [D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md) refactor trap). Add a `codeowners` seam directive (rejected — re-litigates the locked closed seam vocabulary needlessly; CODEOWNERS is one foundational block, not a per-module wire). Bootstrap via stored PAT/GitHub App or the Actions token (rejected — [D-017](0017-control-plane-locked-end-state-as-contracts-not-leaves.md) already rejected these; the token provably lacks the scope, a stored credential adds friction + surface). A standalone-command *vs.* instantiator-step either/or for Q4 (rejected — false choice; it is attempted in the instantiator *and* permanent in `.engine/tools/`). Per-module versioning/update (rejected — single-release pinning; a newer module arrives via engine upgrade). PR-body disclosure as the sole migration-revert gate (rejected — a non-engineer will not act on it; an active boot detector is required). A new catalogued product-boundary surface (rejected — the surface set is locked complete, [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md)/[D-043](0043-surface-set-completion-re-lock-ontology-and-hooks-to-clear-t.md); product intake composes existing surfaces, [D-047](0047-product-spec-intake-design-it-native-not-bundled-the-build-t.md)).
