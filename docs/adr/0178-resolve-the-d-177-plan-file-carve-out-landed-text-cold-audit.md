# Resolve the D-177 plan-file carve-out: landed-text cold audit clean (no blocking), two serious findings resolved, match keyed on the platform's plan-file marker, modes re-locked

*Decided 2026-06-06 in the design workspace.*

## The decision

The [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with four independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written [modes](../spec/systems/lifecycle/modes.md) gate paragraph + Build-spec leaf, the [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md) entry, [Q38](../reference/open-questions.md), and wbs/core-build-roadmap.md slice 21. **No blocking findings.** The operator and architect lenses cleared the change (friction genuinely removed; no [§12](../principles.md) jargon leak on any operator-facing surface; propagation complete — [glossary](../reference/glossary.md) "Mode (stance)", [engine-architecture](../architecture.md) §7, and [hooks](../spec/systems/infrastructure/hooks.md) all verified no-edit against their actual text; slice 21 the sole and correct WBS touch; the law-vs-leaf split and the Q38 deferral both correct). **Two serious findings resolved before re-lock:**
  - **(serious — adversarial)** The authored *law* paragraph said the gate guards *"never the platform's own working files"* — **broader than the narrowly-scoped leaf and broader than [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)'s own anti-choice**, re-introducing (inverted) the law-vs-realization gap this re-litigation exists to close: a cold build-spec author could read it as license to wave through any `~/.claude/` write, including the `settings.json`/hooks guardrail surface — which, being a *home-dir* file outside the repo, has **no protected-branch merge to backstop it** (the merge wall covers in-repo diffs only; [§15](../principles.md)'s weakening-guard enumerates *in-repo* `.claude/`). **Resolved:** the law paragraph is tightened to name the carve-out as **the plan artifact specifically**, with an explicit clause that other `~/.claude/` writes (settings, hooks) stay denied in Explore precisely because they have no merge backstop. The scope discipline now lives in the law, not only the rejected anti-choice in this log.
  - **(serious — technical-feasibility, verified live against current Claude Code docs)** The leaf keyed the exemption on a literal `.claude/plans/` **path**. Live verification established: the plan file **is** real, defaults to `~/.claude/plans/<name>.md` (home, outside the repo), and **is written via the `Write`/`Edit` tool through the `PreToolUse` pipeline** — so the engine gate genuinely *is* the blocker ([D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)'s diagnosis confirmed, not phantom). But the path is **operator-configurable via `plansDirectory`** and can be set **project-local — resolving *inside* the repo**, exactly where a path match would wrongly re-trip the gate. The platform exposes its **own plan-file marker** (currently the `PreToolUse` `is_plan_file` flag / plan-`permission_mode`, the signal Claude Code's built-in plan-mode permission itself uses to write the file). **Resolved:** the leaf now keys the exemption on **the platform's own plan-file marker, not a path** — robust to a relocated/project-local `plansDirectory`, and *tighter* on the anti-choice's security concern (a `~/.claude/settings.json` write carries no such marker, so it stays denied; the marker exempts only what the platform itself marks as the plan artifact). Per the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md)/[D-172](0172-resolve-the-d-171-deny-claim-correction-landed-text-cold-aud.md) discipline, the **durable principle** (match the platform's marker, not a path) lives in the locked doc; the **dated field name** (`is_plan_file`/`permission_mode`) lives here and is re-verified at the slice-21 build-spec.
  - **(nits dispositioned)** [Q38](../reference/open-questions.md)'s "deadlocks unattended on `ExitPlanMode`" tightened to the precise platform behavior (a headless run has no way to approve a plan and **aborts**, not infinite-hangs) — the load-bearing conclusion (plan mode cannot back the Routine entry) is unchanged; slice 21's Demo + Leaves updated to the marker-not-path framing and the project-local-`plansDirectory` conformance case. **Two Q38 platform facts re-verified true:** plan mode auto-approves reads only, so it **forbids the Issue-logging Explore needs** ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md)'s original reason for not adopting plan mode as the Explore vehicle stands), and `PreToolUse`/`PostToolUse` **do not fire for `ExitPlanMode`/`EnterPlanMode` transitions** ([D-070](0070-lock-the-modes-system-wave-3-head-three-stances-on-two-axes.md)'s "not reliably hook-observable" anti-choice, which Q38 must preserve, stands).
  **Re-lock set (1):** [modes](../spec/systems/lifecycle/modes.md). **Re-lock:** `python3 lock.py --relock systems/lifecycle/modes/README.md --decision D-178`; `python3 validate.py` green.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran, returned no blocking, and the two serious findings both *strengthened* the change rather than reversing it — the law now states the scope discipline it relied on the log to carry, and the match key is both more robust (survives a configurable path) and more secure (the marker exempts only the platform-marked artifact, leaving guardrail-config writes denied). The platform premises were ground-truthed live (the plan file is hookable and the gate really blocked it; the path is configurable; the marker is the platform's own signal), turning [D-177](0177-carve-claude-code-s-native-plan-file-out-of-the-modes-explor.md)'s authorized fix into a verified one. Keeping the dated field name in the log and only the durable principle in the locked doc applies the very lesson [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) was written to teach.

## What we ruled out

**Re-lock on the as-authored text** (rejected — the law paragraph's "never the platform's own working files" was an over-broad blanket the audit caught; re-locking it would bake the inverted gap). **Key the exemption on the `.claude/plans/` path** (rejected — operator-configurable and can land in-repo; a path match is fragile and can re-trip the gate, and is looser on guardrail-config writes than the marker). **Bake the `is_plan_file` field name into the locked doc** (rejected — a dated, version-brittle platform fact belongs in the log, not a locked trust doc; the [D-171](0171-correct-the-falsified-platform-ignores-a-pretooluse-deny-cla.md) discipline — durable principle locked, dated fact logged). **Take up [Q38](../reference/open-questions.md) now because the audit surfaced it again** (rejected — it remains a separate foundational re-litigation; this pass stays the targeted carve-out).
