# Lock `core` (the root module): the closure wave's terminal ratification; retire the closure procedure

*Decided 2026-05-29 in the design workspace.*

## The decision

Ratify and **lock** [core](../spec/modules/core.md) (`status: designed → locked`) — the universal `required` root every package depends on and the **first module lock** — the terminal step of the core-lock closure wave ([D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md)). `core`'s substrate (the foundations it bundles) is locked and the wave closed every `core`-lock blocker (Q24–Q27 via [D-114](0114-q25-re-litigation-a-fourth-v1-core-policy-the-triage-thresho.md)→[D-119](0119-resolve-q26-pin-the-engine-help-verb-index-kind-discovery-me.md)), so the partition and pinned contracts are settled. **Reconciliation** (citation-only, per `core`'s "names which machinery ships, does not restate the systems' laws" commitment and the [D-119](0119-resolve-q26-pin-the-engine-help-verb-index-kind-discovery-me.md)/CLAUDE.md-rule-3 no-second-source bar): the `provides` manifest gains bare cross-references to the wave's now-pinned contracts — the attention ranking tool *realizing the ordered-partition ranking-function form* ([D-117](0117-q24-q27-2-re-litigation-the-attention-ranking-function-form.md)), the validation dispatcher's kind-callable results *carrying findings on the canonical `finding.v1` base* ([D-115](0115-q27-1-re-litigation-the-validation-kind-callable-result-cont.md)), the telemetry machinery *realizing the finding-record + ambient-capture shapes* ([D-118](0118-q27-4-5-re-litigation-the-telemetry-finding-record-ambient-c.md)); the stale `## Status: designed, not locked` section is **deleted** (it carried the lone factual slip — "all of `systems/` is locked", false while `external-contribution` is `designed`, which `core` does not bundle — plus a now-met WBS gate, [D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md)); and the operator-surfaces bullet is tightened so **maintainer-internal vocabulary never surfaces even as a parenthetical label** (closing the prior "(this is called…)" leak channel, aligning to the [skills](../spec/systems/surfaces/skills.md) "a command — a verb you type" convention). **The HARD cold-session design audit** (the CLAUDE.md gate) ran four independent cold-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) against the finalized doc: **no blocking or serious finding** — the lenses confirmed `core` freezes no [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) close-model/merge-wall claim (so the pending [D-104](0104-phase-c-cross-reference-the-external-contribution-mode-into.md) external-contribution close re-litigation cannot force a `core` re-lock — `core` ships the *operation*, not the close model), the cross-refs are citations not restatements, no `designed`-sibling claim is frozen, and every platform claim verified against the live Paideia engine + current Claude Code docs; one precision NIT was folded (the `finding.v1` phrasing → results "carry findings on" the base). `python3 lock.py modules/core/README.md --decision D-120`. **Terminal cleanup:** the closure procedure has served its purpose, so per [D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md)'s transient mandate wbs/core-lock-closure.md is **deleted**, its path added to `validate.py`'s `GRAVEYARD` (so the append-only log's references do not dangle), and the wbs/README.md pointer to it removed; its out-of-scope seed gaps remain recorded in wbs/dry-run-ledger.md. **Propagation:** `core` locked + the `locks.yaml` entry (ratified_by D-120); this entry; the procedure retired (+ `GRAVEYARD` + `wbs/README.md`). **No edit owed** to [modules/README.md](../reference/module-catalog.md) (design-maturity not catalog-tracked, [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md)), [engine-architecture.md](../architecture.md) (role unchanged; ## Why

`core` is the natural first lock — everything roots on it, and it is upstream-anchored (depends on nothing), so locking it sits atop no churning dependency (its `designed` siblings are its *dependents*, which adapt to it). Both lock gates are met: the WBS is authored (module-order.md, [D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md)) and the HARD cold-session audit passed. A four-lens **plan** audit ran first and caught a blocking mechanical gap — the `GRAVEYARD` requirement plus the `ratified_by`-must-precede-`validate` ordering — folded along with the build-orchestration robustness check, the "all systems locked" slip, and the leak-channel NIT; the **doc** audit then ran against the finalized text per the CLAUDE.md HARD gate and cleared it. The reconciliation stays citation-only because `core` is a packaging view: the wave already pinned the laws in the locked system docs, and re-pinning them in `core` would breach rule 3 ([D-119](0119-resolve-q26-pin-the-engine-help-verb-index-kind-discovery-me.md) precedent). Retiring the closure procedure now honours the deletion mandate (a transient maintainer artifact whose purpose — sequencing the Q24–Q27 wave — is fully spent once `core` locks).

Keep the stale `## Status` section as a "now locked" note (rejected — authoring rule 1 forbids draft/transition cruft; locked docs carry status in frontmatter only). Keep wbs/core-lock-closure.md as a record (rejected — [D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md) made it transient; the deletion mandate forbids a spent procedure lingering; the decision-log preserves its history). Treat the pending `build-orchestration` re-litigation as a `core`-lock blocker (rejected — `core` freezes no close-model claim, so a future build-orchestration re-lock does not touch `core`).
