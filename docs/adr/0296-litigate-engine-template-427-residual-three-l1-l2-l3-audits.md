# Litigate engine-template #427 residual three (L1/L2/L3): [audits](../spec/systems/guardrails/audits.md) gains a standing, conditional **product-spec-conformance sweep** — the traveling [conformance-enforcement floor](../reference/glossary.md)'s **standing cadence** (L1); the [spec-obligation matrix](../reference/glossary.md) stays **judgment-only**, no structural deferred-state (L2); operator-run how-verified rows **suffice**, no engine-run harness (L3) — re-lock of audits lands under D-297

*Decided 2026-07-11 in the design workspace.*

## The decision

The #427 conformance thread's third round — the "residual three" dossier (L1/L2/L3, superseding the per-slice asks; grounded in D-287→D-295) — is ruled here. This entry is the **litigation alarm + operator authorization** (direction and scope confirmed in-session over `AskUserQuestion` before editing, then the mandatory cold audit after) **and the design of record**. Only [audits](../spec/systems/guardrails/audits.md) is edited; its re-lock lands under **[D-297](0297-resolve-re-lock-audits-installs-the-standing-conditional-pro.md)** after the landed-text cold audit (already run, below); it is **edited-but-not-relocked** until then (the [D-285](0285-litigate-engine-template-363-the-layer-2-erasure-grammar-was.md)/[D-287](0287-litigate-engine-template-427-make-the-sdd-spec-drive-the-bui.md) authorize→resolve pattern; `validate.py` flags its fingerprint until the re-lock).

  **L1 — audits gains a standing product-spec-conformance sweep (the core re-litigation).** The deployed [audits](../spec/systems/guardrails/audits.md) checked only the Engine's own accumulated local state — of no value against the operator's actual deliverable, the product. Its locked "Engine-only self-monitoring / not the product's quality" foreclosure ([D-009](0009-telemetry-is-a-remediation-loop-not-self-healing.md)) was **too narrow** and predates [D-287](0287-litigate-engine-template-427-make-the-sdd-spec-drive-the-bui.md), which travelled the [conformance-enforcement floor](../reference/glossary.md) into deployed repos pointed at the product's `locked` `docs/spec/`. The per-merge floor is **introduction-time only** — it cannot catch conformance that **drifts after merge** (a re-litigated spec row whose digest moves, small divergences that each passed but accumulate, code written before its criterion was locked); the 247-non-conformance audit that opened #427 is the proof a **standing reverse-sweep** is load-bearing. So audits now carries the **standing cadence of the same floor**: read product-design's [spec-obligation matrix](../reference/glossary.md) + the `locked` `docs/spec/` **by presence** ([§16](../principles.md)/[§14](../principles.md) — no `depends`, audits stays required core), and run the audit persona's **own forward divergence-hunt** over the locked rows, **report-only**, findings to the reconcile lane (an engine-labeled audit observation → an un-labeled product Build). The bounded line keeps the [§13](../principles.md) wall: audits checks **conformance to the operator's own frozen spec, never product *quality*** (the operator's domain). It is **conditional and per-locked-row** — silent absent a locked spec (an MVP is a first-class choice, [§20](../principles.md), never nagged toward a spec), degrading-and-disclosing only the distinct spec-locked-but-matrix-missing gap.

  **Ownership extends [D-287](0287-litigate-engine-template-427-make-the-sdd-spec-drive-the-bui.md)'s [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) split — stated, not inherited.** D-287 assigned the floor's deployed runtime to **build-orchestration, at the merge**. This entry adds **audits as a second, standing runner** of the floor's legs over the one matrix denominator: two cadences (per-merge gate + standing report-only cron), one matrix. Clean [§16](../principles.md) — product-design owns/produces the matrix; build-orchestration and audits are two integrators relaying over the one channel, forcing no change on the owner or the sibling (confirmed no re-lock of product-design / build-orchestration / qa-review, below).

  **The standing cadence runs two of the floor's three legs, honestly.** The floor is a trio (matrix + adversarial divergence read + operator-run demonstration harness). The cron re-runs the first two; the **demonstration harness — the [§17](../principles.md) non-AI correlate — is *not* re-run** (it stays the operator-runnable behavioral check at the reconcile merge). So a standing finding is **AI judgment** carrying no behavioral correlate at cron cadence and R16's a/b residual; its [artifact warrant](../reference/glossary.md) says so. The adversarial read is the **audit persona's own** (its law-1 posture), **never a qa-review lens invocation** — so no qa-review `depends`, and the standing adversarial leg is present whenever the matrix + locked spec are committed. It runs the **forward arm only** (does each locked criterion's built code still meet it?); the lens's **diff-introduced over-build arm ([D-292](0292-resolve-re-lock-qa-review-the-8-pair-split-across-two-lenses.md)) is inapplicable** absent a PR diff, so the standing whole-repo cadence never revives the "any code tracing to no locked row" storm §20/D-292 foreclosed. It is **prioritized, not exhaustive** — stale-flagged rows + a law-3 sample, partial coverage disclosed — so it fits a real product's run budget rather than degrading to no digest.

  **L2 — the matrix stays judgment-only; no structural `deferred(owner)`/`scoped-out` row-state.** A structural authored row-state breaks [§19](../principles.md) (the matrix is a *derived* index, byte-deterministic from source, not a hand-authored second referent — build-conformance §4), and `scoped-out(D-NNN)` cannot resolve in a deployed repo (the planning log does not travel, #212). An uncovered row already **is** the not-yet-built remainder record; deferral rides the `divergence-hunter`'s judgment + the tracking issue. No matrix data-model change, no locked-doc edit.

  **L3 — operator-run how-verified rows suffice; no engine-run adversarial harness.** Self-hosting construction blindness ([§20](../principles.md)(a), [D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md)) is a named, accepted degeneracy already answered by the locked operator-run how-verified rows — [§17](../principles.md)'s behavioral demonstration the non-engineer runs. An engine-run scratch-repo harness was a *stronger*, never *required*, option; it is new construction apparatus the operator declined, so the line is **closed** (operator-run rows remain the deployed answer). Honest bound: first-run provisioning paths are then demonstrated only in the operator's real deployment — inherent to self-hosting, already accepted.

  **Q31 is narrowed, not resolved.** [Q31](../reference/open-questions.md) is *engine-self*-conformance (an engine self-edit vs the engine's *own* shipped design / eADR canon); L1 adds *product* conformance, a disclosed no-op on the spec-less engine self-build. L1 **removes Q31's stated obstacle** ("audits only probes accumulated local state, not conformance-to-design" — now false) and supplies the mechanism template, but the engine-self residual **stays open**. Resolving Q31 by pointing at the product sweep would be a [§13](../principles.md) category error — foreclosed.

  **Cold audit (four independent lenses, no shared context; the landed-text gate before the irreversible re-lock).** Direction + scope confirmed with the operator before editing. Lenses: adversarial · technical-feasibility · non-engineer-operator · architect. **Two BLOCKING** — (1) a standing whole-repo cadence invoking the divergence-hunter wholesale reopens the diff-scoped over-build storm D-292/§20 foreclosed → resolved (forward arm only; backward over-build arm named inapplicable); (2) the glossary *Audits* term's "acts only on accumulated local state" is now false → reconciled. **Serious** (all resolved): the cron re-run runs only two of three floor legs and omits the §17 behavioral correlate ("the same floor" narrowed + warrant stated); the persona-not-qa-review actor + no-qa-review-`depends` stated; the unbounded sweep bounded (prioritized-not-exhaustive); the finding's engine-label / un-labeled-product-Build home + matrix-row dedup key named; the no-spec-silent vs matrix-missing-actionable split; the glossary *Conformance-enforcement floor* term + `engine-architecture` truthful-index gaps closed; the [§12](../principles.md) leak-guard vocab list extended. **Nits folded** (conformance digest exemplar, scope-difference wording). The feasibility lens **confirmed the seam is clean — no re-lock of product-design / build-orchestration / qa-review is forced** (§14/§16; providers don't track consumers; those docs carry no floor-exclusivity language, independently confirmed by the architect lens). No blocking/serious finding was rejected-with-rationale; all resolved.

  **Scope: audit-library edit reverted; audits-only re-lock.** An earlier reconciling edit to the [audit-library](../spec/modules/audit-library.md) module doc was **reverted** — its manifest (`provides`/`wires`/`depends`) is unchanged (the standing sweep reads committed artifacts, needing no new module machinery or turn-on, unlike the cross-repo memory-backup read), and the module already defers to the audits system doc for the laws — so the propagation matrix's module reconciliation is satisfied with no module edit, keeping this to the single audits re-lock ([R6](../reference/risks.md) surgical scope).

  **Non-locked propagation (landed under this entry):** [glossary](../reference/glossary.md) (*Audits* term reconciled — no longer "only accumulated local state"; *Conformance-enforcement floor* term names the two cadences); [engine-architecture](../architecture.md) (the guardrail rung carries the floor's standing half — index kept truthful); [open-questions](../reference/open-questions.md) Q31 (narrowed, kept open). No term minted ([R6](../reference/risks.md)/[D-255](0255-sharpen-the-post-v1-revisit-triggers-for-product-knowledge-g.md) anti-sprawl — the standing cadence rides the existing *Conformance-enforcement floor* term). [risks](../reference/risks.md) R16 considered — its "the same matrix travels to a deployed product build" is cadence-agnostic and not false, so **no edit owed**.

  **Build-owe:** the standing product-conformance sweep is a **v1** engine-template build (operator chose to build it, not defer) — filed as an `engine-template` issue (via `.engine/tools/issue_author.py` + the `engine` label); the build executes in engine-template, this workspace lands the design of record.

  **Carrier (locked, edited under this entry; re-lock under the named resolve entry after the landed-text audit above):** [audits](../spec/systems/guardrails/audits.md) → **[D-297](0297-resolve-re-lock-audits-installs-the-standing-conditional-pro.md)**. `validate.py` flags exactly this one fingerprint until the re-lock. **Id allocation:** tail was D-295, no forward reservation above it; D-296–D-297 allocated monotonically.

## Why

the deployed audit had no value against the operator's deliverable; the "Engine-only" foreclosure was a pre-D-287 artifact, and product divergences are locally actionable (the reconcile lane), so the standing cadence is the honest completion of the floor D-287 already ships — conditional on the operator's own lock, so §13/§20 hold and an MVP is never pressured. Homing it in audits reuses the existing cron/persona/findings machinery rather than a new rung. L2/L3 close on the merits (judgment-only preserves §19; operator-run rows are §17's own gold standard) without adding apparatus. The four-lens cold audit caught two real blocking flaws (a foreclosed storm, a false canonical term) before an irreversible re-lock.

## What we ruled out

**Route L1's sweep around audits (a report-only surfacing riding boot/telemetry) to avoid editing the locked audits doc** (rejected — contorts the design to dodge a justified re-litigation; the audits foreclosure is the thing that is actually wrong, so re-litigate it properly). **Keep the "Engine-only" foreclosure; leave the deployed audit product-blind** (rejected — the operator's core complaint; a deployed audit with no product value is not worth shipping). **A distinct new standing product-conformance rung beside audits** (rejected — new apparatus the operator declined; audits is the natural home, and a new rung duplicates the persona/cadence/findings machinery). **Have the standing sweep invoke qa-review's `divergence-hunter` lens** (rejected — would add a qa-review `depends` audits must not carry; the audit persona carries the posture itself). **Run the full trio including the demonstration harness on the cron** (rejected — the harness is the operator-run §17 correlate, not an AI-cron leg; re-running it would misrepresent an AI verdict as behavioral evidence). **Exhaustive sweep every cron** (rejected — does not fit a real product's budget, degrading to no digest exactly where needed; prioritized-plus-sampled with disclosed partial coverage is the honest form). **Adopt a structural `deferred`/`scoped-out` matrix row-state (L2)** (rejected — breaks §19's derived-index property and reintroduces a non-traveling `D-NNN` namespace). **Build the engine-run adversarial harness (L3)** (rejected — new construction apparatus the operator declined; operator-run how-verified rows are the accepted answer to self-hosting blindness). **Resolve/delete Q31 citing the product sweep** (rejected — product ≠ engine-self, a §13 category error; Q31 is narrowed and kept open). **Edit + re-lock audit-library** (rejected — its manifest is unchanged and it defers to the system doc; a module re-lock for a reconciling note is [R6](../reference/risks.md) over-reach).
