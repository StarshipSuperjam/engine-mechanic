# Reject engine-template #255's Explore-gate memory carve-out: the engine supersedes harness auto-memory with its own Explore-passing substrate; the multi-reason boundary is recorded, the cross-project residual deferred ([R32](../reference/risks.md)), no locked re-litigation

*Decided 2026-06-23 in the design workspace.*

## The decision

engine-template #255 escalated a litigation: a deployed-engine **Explore**-stance session could not update a "working-memory resume pointer" (a `Write`/`Edit` the Explore write-gate denies), and proposed carving a **memory-substrate exemption** — a `Write`/`Edit` whose target resolves under a memory directory (the harness `~/.claude/.../memory/` **and** `.engine/memory/`) allowed in Explore — alongside the locked plan-file carve-out ([modes](../spec/systems/lifecycle/modes.md)), asking whether **path-based** recognition is acceptable since the memory store carries no platform marker. **Rejected — both halves; no locked doc moves** (the [D-243](0243-decline-engine-template-238-s-public-repo-saved-memory-opt-i.md)/[D-239](0239-reject-an-engine-owned-git-hygiene-reconciler-accumulated-lo.md) reject-and-record shape; the only design artifact is this append-only entry, `python3 validate.py` green, no locked fingerprint moves). A **four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) converged on reject and found it **strictly more coherent** than the carve-out, not merely lower-blast-radius. **The premise is inverted (lead):** "leaving the non-engineer worse than plain Claude Code at a native capability" — the same [§5](../principles.md) floor that earned the plan-file carve-out — does not apply, because the engine **deliberately supersedes** Claude Code's built-in per-project auto-memory with its own `.engine/memory/` substrate ([memory](../spec/systems/cognitive/memory.md) "Built-in auto-memory — the boundary"; [constraints](../reference/constraints.md): auto-memory is "off-repo and bounded… insufficient as the citable system of record"), and that substrate **already works in Explore** (verified against the live build): **raw capture** is the `Stop` hook (`close.py` → `ledger.append` under `flock` — a hook subprocess, never a model tool call, so the PreToolUse gate never sees it; passes in every stance), and **consolidation** is the in-context AI running `consolidate.py read`/`store` via **Bash** (JSON on stdin; the memory MCP server is read-only `search`), which the gate's enumerated build-set (Write/Edit/MultiEdit/NotebookEdit, an MCP-PR tool, Bash matching git-commit/branch/checkout/switch/`gh pr create`) does **not** match → allowed. So the **only** thing the gate blocks is a `Write`/`Edit` to the **harness notebook** — exactly the act the standing memory-authority policy forbids ("the Engine never writes project content into built-in auto-memory and never cites it as fact"). The §5 floor is **met better**, not breached: recall lands in the authoritative, backed-up, Explore-passing substrate rather than the invisible non-citable cache, and the plan-file analogy **breaks** (the plan file had **no** engine replacement, so denying it was a true regression; harness memory **has** one). The "working-memory resume pointer" the session reached for is a plain-Claude-Code habit with **no slot in the engine's grammar**: continuity is owned by the [memory](../spec/systems/cognitive/memory.md) ledger + the session-id consolidation **sweep** and the committed [state](../spec/systems/cognitive/state.md) cursor (advanced only in Build), never a hand-written notebook. **Three independent reject grounds, any one sufficient.** **(1) Memory-authority boundary (operative)** — a carve-out would have the engine *write* the non-citable notebook in Explore, contradicting a *second* locked policy ([memory](../spec/systems/cognitive/memory.md); the contributor metaphor [D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md) + the [D-030](0030-memory-ledger-canonical-observe-don-t-predict-capture-lexica.md) role home), not merely relaxing the gate. **(2) Path-recognition infeasible/unsafe — answers the open question** — verified against current Claude Code: there is **no platform marker** on an auto-memory write (a PreToolUse hook sees only `tool_name`/`tool_input`/`permission_mode` — no `is_memory_file`), and the directory is **operator-relocatable into the repo** via `autoMemoryDirectory` (read from project/local scope), so a carve-out could only be **path-based** — reintroducing the exact in-repo collision the **marker-based** plan-file carve-out was built to avoid, with no marker fallback. **Path-based recognition is therefore rejected.** **(3) Ledger-integrity law** — a raw `Write`/`Edit` to `.engine/memory/`'s NDJSON bypasses memory's single-writer `flock` and can tear a line; that half is harmful *and* moot (the lock-safe Bash store already passes the gate). **The locked gate's `~/.claude` denial has a two-reason structure, recorded here, not re-litigated:** [modes](../spec/systems/lifecycle/modes.md) denies non-plan `~/.claude/` writes with one stated reason — "no protected-branch merge to backstop them" — naming only "(settings, hooks)"; that reason is load-bearing for **settings/hooks** (the [§15](../principles.md) governance-critical enforcement config) but **vacuous for memory content** (which cannot reach the protected branch anyway), so the operative objection to a harness-**memory** write is the **memory-authority boundary** (a stronger, independent reason the gate's memory-silent phrasing happens to cover but does not name). The fuller reasoning lives **in this entry** per [§11](../principles.md) (history lives in the log) so a future cold session cannot regenerate #255 from the blanket phrasing; **the locked `modes` doc is deliberately NOT re-litigated** — its sentence is not false about memory (it names settings/hooks), and a re-lock + cold audit for a clarification the log already carries is the unjustified just-locked-doc churn lock discipline guards against; the entry + the build-owe-(i) legibility copy + ground (2)'s infeasibility together defend against regeneration without a locked edit. **Cross-project residual — deferred, registered, not buried:** the one need the per-project substrate does **not** supersede is **genuinely cross-project contributor memory** ("remember X across all my projects"; the per-project scope is [D-058](0058-discharge-the-wave-0-gate-q10-substrate-content-world-taggin.md)), registered as **[R32](../reference/risks.md)** (the [D-243](0243-decline-engine-template-238-s-public-repo-saved-memory-opt-i.md) "Option B deferred, revisit on demonstrated gap" shape) **and** the anti-choice below, with an interim contract of **honest-on-contact** disclosure (build-owe (ii)), never a silent project-local file. **Build-owes (engine-template #255 lineage, filed citing this entry) — build under-deliveries of existing locked law, not design gaps:** **(i) memory-write denial legibility (load-bearing)** — the current `_DENIAL` is build-set-specific (for a blocked *memory* note it reads as the engine mishearing "remember this" as a code change, "…open a pull request…"), so it needs a **memory-specific** plain-language line that (a) confirms the remembering as a competent "noted" (realizing [modes](../spec/systems/lifecycle/modes.md)'s operator-legibility law + the memory-authority policy), (b) surfaces a **behavioral correlate the operator can see/run** (e.g. "you'll see it in my next orientation"), not a bare assurance ([§17](../principles.md)/north-star burden-of-proof), and (c) does **not** leak the two-store seam ([§12](../principles.md) vocabulary-leak rule); **(ii) the operator-directed "remember this" path in Explore** — a literal operator "remember X" must be **durably captured** (typed as the `preference` role, not swept into decaying ambient delta) and **legibly confirmed**, a cross-project "remember everywhere" gets the [R32](../reference/risks.md) disclosure, and resume continuity rides the existing consolidation sweep (**rely on automatic capture; never hand-write the ledger** — a raw write re-creates ground (3)'s violation); a pure consumer of memory's existing sweep that widens no contract. **Verify-no-edit dispositions (honest-disposition discipline, recorded not skipped):** [glossary](../reference/glossary.md) (the *Memory* term already names the built-in-auto-memory boundary — no edit), [engine-architecture](../architecture.md) (no new surface/wiring — no edit), scenarios (no new path — no edit); **[risks.md](../reference/risks.md)** carries the only non-locked propagation ([R32](../reference/risks.md)).

## Why

The litigation's premise inverts the actual situation, and the four-lens cold audit confirmed reject on every checked point: the engine's own memory upkeep passes the Explore gate (Stop-hook raw capture; Bash `consolidate.py store`; read-only MCP — all verified against the live build), so the [§5](../principles.md) floor is met by a better, citable substrate rather than a gate hole. The reject is **not** lock-avoidance (the justified-re-litigation anti-pattern): the design already covers the need, and a carve-out would *create* incoherence — having the engine write the very notebook the memory-authority policy forbids ([D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md)/[memory](../spec/systems/cognitive/memory.md)), on an unmarked, repo-relocatable path that is the [§15](../principles.md) fragility the marker-based plan-file carve-out was built to avoid. The audit earned its keep: the technical-feasibility lens ground-truthed the no-marker and `autoMemoryDirectory`-relocatable facts against current Claude Code, turning the open question ("is path-based acceptable?") into a decisive **no**; the non-engineer-operator lens caught that the genuine gaps are an operator-experience under-delivery (the build-set denial string mishearing "remember this"; a "remember X" that could silently decay), routed to the two build-owes that realize the **existing** legibility + memory-authority law faithfully ([D-243](0243-decline-engine-template-238-s-public-repo-saved-memory-opt-i.md) "build under-delivery, not design gap" pattern) rather than a design change; the architect lens confirmed reject is the only ruling that keeps the corpus self-consistent (no doc asserts the engine uses or that harness memory works in Explore). Recording the two-reason boundary in the log rather than editing locked `modes` keeps the rejection durable at the proportionate cost — the [§11](../principles.md)/[D-243](0243-decline-engine-template-238-s-public-repo-saved-memory-opt-i.md) shape.

## What we ruled out

**Accept the carve-out (exempt the memory directories in Explore)** — rejected on the three independent grounds (memory-authority boundary; no platform marker + repo-relocatable path = path-brittleness with no fallback; ledger-integrity `flock`), any one sufficient, and it meets no real need since the engine's own upkeep already passes the gate. **Carve out only the harness `~/.claude/.../memory/`, re-litigating locked `modes`** — rejected as *less coherent*, not merely higher-blast-radius: it would have the engine write the non-citable notebook the memory-authority policy forbids, keyed on an operator-relocatable path with no marker, to serve a §5 floor the engine substrate already meets. **Carve out `.engine/memory/` for direct Write/Edit** — rejected: it bypasses the single-writer `flock` (tears the ledger) and is moot (the lock-safe Bash store already passes the gate). **Refine locked `modes` to name the memory-authority boundary as the second `~/.claude` denial reason** — rejected as the disposition: the locked sentence names only "(settings, hooks)" and is not false about memory, so a re-lock + cold audit is the unjustified just-locked-doc churn lock discipline/[§11](../principles.md) avoids; the log entry + build-owe-(i) copy carry the clarification (a justified pass remains available if regeneration recurs). **Park the cross-project residual silently in the anti-choice only** — rejected: a standing gap any cross-project operator will feel belongs in the risk register ([R32](../reference/risks.md)), the matrix-faithful home, not buried. **Treat #255 as a pure build bug and skip the decision-log ruling** — rejected: it litigated a *locked* trust contract, so the adjudication (even a reject) is recorded history per the litigation protocol, and the build-owes alone would lose the *why*.
