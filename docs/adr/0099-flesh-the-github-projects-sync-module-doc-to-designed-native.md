# Flesh the `github-projects-sync` module doc to `designed`: native-first one-way Project-board projection over committed truth; the engine-field layer via a non-blocking hook; module-owned setup

*Decided 2026-05-28 in the design workspace.*

## The decision

Take the [`github-projects-sync`](../spec/modules/github-projects-sync.md) module doc from `stub` → `designed` (packaging-view depth, matching the `designed` peers; **not** locked). It is the **optional**, adopter-facing **Product Management** module ([D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)/[D-068](0068-q1-resolved-the-v1-optional-module-roster-4-cut-2-kept.md)) that **projects** the repo-authoritative work-control signal onto a **GitHub Project board** for a non-engineer's visibility ([D-021](0021-github-projects-ships-as-an-optional-adopter-facing-module-p.md)); the board is a **one-way, replaceable projection over committed truth — never authoritative** ([§2](../principles.md)). `depends: core` (reads the `core`-resident [state](../spec/systems/cognitive/state.md) + [attention](../spec/systems/cognitive/attention.md) floors, [D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md), and the [telemetry](../spec/systems/guardrails/telemetry.md)-owned debt register, each by a **[§16](../principles.md) channel relay, not a module edge** — there is no state/attention/telemetry *package* to depend on; the deliberate `depends: core` matches [migration-discipline](../spec/modules/migration-discipline.md)). Standalone, fills no [Slot](../reference/glossary.md) ([D-069](0069-core-module-seam-walk-the-demarcation-operationalized-glossa.md)). **Operator/design decisions settled this session: native-first two-layer design.** **(1)** Native GitHub Projects built-in automation carries the native work record server-side with **zero engine code** (auto-add Issues/PRs + Status-on-merge/close). **(2)** A thin engine layer projects only the engine-specific **custom fields** native automation cannot see — the set **fixed here as law**: the committed **state cursor**, **attention** prioritization/ordering, and the **debt count** (open engine-labeled issues) — via a sync [tool](../spec/systems/surfaces/tools.md) that reads those sources and writes **only its own board custom fields** through the operator's **local `gh`/GraphQL** (read-repo/write-board; field- and single-select option-IDs resolved at runtime). Settled points: `provides` = the **sync tool** + a **setup [operation](../spec/systems/surfaces/operations.md)** (board create/link + native-automation enable + the `project`-scope-grant walkthrough, with an optional `operator-typed` setup [skill](../spec/systems/surfaces/skills.md)) + a **board-coordinate config** **shipped empty and populated by the setup step** (*ship-the-substrate-not-the-data*, [§4](../principles.md) — so it has a real `provides` home and is **not a coherence orphan**) + an optional orientation [doc](../spec/systems/surfaces/docs.md); **`wires: hook`** (the sync trigger — **non-blocking, best-effort, fail-open, never block-eligible, mode-declared**, keyed distinctly from `core`'s, the [memory](../spec/modules/memory-substrate-sqlite-fts5.md)-own-capture-hooks precedent [D-091](0091-flesh-the-memory-substrate-sqlite-fts5-module-doc-to-designe.md); the module's **own** trigger because `core` cannot depend on an optional module); `migrations: none (v1)`. **No enforcement** — pure projection, gates nothing, no enforcement tier ([§7](../principles.md)). **Field ownership makes "one-way" honest:** the engine writes **only its own custom fields — never Status, column, or card position** — so a human card drag is **never overwritten**; the engine's fields are read-only on the board where the UI permits, and divergence is **surfaced, never silently reverted**. **Module-owned setup of a non-traveling resource:** Projects v2 are **user/org-owned and linked to a repo, not template-borne**, so the module's setup creates/links the board, enables native automation, and walks the one-time scope grant — **reusing [provisioning](../spec/systems/infrastructure/provisioning.md)'s operator-privileged / degrade-and-disclose *pattern* but NOT a new bootstrap leaf on the locked provisioning doc** (no litigation alarm); the org edge case is handled by degrade-and-disclose; **no PAT-as-repo-secret** (local `gh`), so no standing-credential/CI supply-chain surface. **Degradation, operator trust, the §13 wall, the §16 relay:** every failure degrades to the git-native truth, the hook no-ops without blocking, and a **board-face "last synced / STALE — one fix" marker** keeps a board-trusting operator from being misled; the `project`-scope grant carries an **informed-consent frame** (it is broader than this repo, revocable, with the command) and **install-time disclosure** of the costs and that it controls nothing; board labels are plain language honoring the [§12](../principles.md) leak guard; the module is read-only outward and the removal test passes (the dangling external board + granted scope are **inert, non-reversible residuals** stated honestly, the bare-`permission`/MCP-approval "errs toward leaving it" class); it is a **pure §16 integrator/relay**, additive over native automation.

## Why

A module doc is the packaging view; the depth lives in the locked [state](../spec/systems/cognitive/state.md)/[attention](../spec/systems/cognitive/attention.md)/[telemetry](../spec/systems/guardrails/telemetry.md)/[hooks](../spec/systems/infrastructure/hooks.md)/[module-system](../spec/systems/grammar/module-system.md)/[control-plane](../spec/systems/infrastructure/control-plane.md) systems, so the doc maps that machinery → the bundle without restating laws (the closest peers are [product-design](../spec/modules/product-design.md) and [migration-discipline](../spec/modules/migration-discipline.md)). **D-021 explicitly deferred** "its wiring and dependencies … to its own module-spec pass" — this pass — so reconsidering its provisional "syncs via the control-plane CI harness" mechanism needs **no litigation alarm** (no *locked* doc binds it; the control-plane CI law scopes its harness to validation suites). A **four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context, **plan inlined**) ran **on the plan before approval** (the audit-before-approval discipline covers substantive `designed` passes). Dispositions, all resolved with **no locked-doc edit**: **(adversarial BLOCKING — hook deadlock in routine)** the projection hook is **non-blocking and never block-eligible**, so the [hooks](../spec/systems/infrastructure/hooks.md) block-satisfiability law (which binds only *blocking* `Stop` hooks) does not bite; it declares its active modes per the hooks mode-awareness law and is keyed distinctly from `core`'s, the [D-091](0091-flesh-the-memory-substrate-sqlite-fts5-module-doc-to-designe.md) precedent. **(adversarial SERIOUS + architect SERIOUS — un-homed config / coherence orphan)** the board-coordinate config **rides `provides`**, shipped-empty and populated by setup ([§4](../principles.md)), so the locked coherence rule's two-home test (exactly one `provides`, or a named foundation-infra artifact) is satisfied — not the orphan a "provisioning-written, not-in-`provides`" third category would be; the board + scope are **module-owned setup**, not a leaf on the locked provisioning doc; the residual board + scope are inert non-reversible residuals, stated honestly. **(adversarial SERIOUS — stale source list)** D-099 supersedes D-021's "state, attention, **eager-claim, sessions**" list: [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) dissolved "the `sessions` active/archive records + leases + wedge detection → git branches + open/merged PRs" and routed "`HANDOFF.md`/`next-session.yaml` → … Projects (board)", so the projection is **additive over native automation, never a re-homing of session/claim tracking** (that lives in native branches/PRs). **(technical SERIOUS — board not template-borne / org case)** verified against current GitHub docs: Projects v2 are user/org-owned and merely linked, **not copied by "Use this template"**, so module-owned setup creates+links the board and degrade-and-discloses the org edge case (operator may lack org-project permission or org policy may disable user projects). **(technical SERIOUS + operator BLOCKING — overwrite surprise)** the engine writes **only its own custom fields**, never Status/column/position, so a human card drag is never clobbered; the honest statement is narrowed; engine fields read-only where the UI permits, divergence surfaced not silently reverted. **(operator SERIOUS — silent staleness)** a **board-face staleness marker** (the [audit-digest](../reference/glossary.md) run-date discipline) so staleness shows where the operator looks, not only at boot. **(operator SERIOUS — scope consent / install disclosure)** informed-consent frame for the `project` scope (broader than this repo, revocable + command, the [dependency-discipline](../spec/modules/dependency-discipline.md) consent shape) + setup-time disclosure of the costs and that it controls nothing. **(operator NIT — leak guard)** plain-language board labels, [§12](../principles.md) leak guard, no maintainer vocabulary on the board face. **(architect SERIOUS — §3 propagation)** resolved by **logged rationale rather than a hand-wave**: [engine-architecture.md](../architecture.md) §9 indexes modules via the catalog (no edit), and **§3 (Distribution) needs no edit because the board + scope are a module-level instance of §3's existing "only true repo settings … do not travel" model already stated for the ruleset, not a new foundation-level class §3 must enumerate**. Technical-feasibility verified against current GitHub documentation + live `gh`: Projects v2 ships built-in auto-add + Status-on-merge/close with no code (**Free plan = 1 auto-add workflow** — a disclosed multi-repo caveat); `gh project item-edit` writes custom fields with the **`project` scope** (granted via `gh auth refresh -s project`, **no** PAT-as-secret); the default Actions `GITHUB_TOKEN` **cannot** write user/org Projects v2 (no repo-owned-v2 loophole), which grounds rejecting the CI-workflow path; field/option-IDs are opaque and resolved at runtime. **Canon-discipline note:** the design is grounded **solely in engine-planning's locked docs**; the prototype/Paideia/engine-template are idea-generation inputs only and were used here **only** to ground-truth *platform behavior*, never as a design justification. ## What we ruled out

A **dedicated CI sync workflow** (D-021's provisional lean) — rejected on locked canon: an *optional* module's `.github/workflows/` file has **no clean `provides`/coherence home** (not a surface, not a named foundation-infra artifact → orphan; and uninstall, which removes engine-identified files + reverses wiring, would strand it); the [control-plane](../spec/systems/infrastructure/control-plane.md) CI law scopes the harness to **validation suites** and lets only the *required* audits system land a scheduled workflow; and a CI board write would force a **PAT-as-repo-secret** (standing credential + supply-chain surface). The non-blocking `hook` is the closed-seam home with a guaranteed reverser, and native automation already does the server-side item/status work while the engine fields only change in-session, so a server-side workflow would add little. **Make the board two-way / authoritative** (rejected — [§2](../principles.md), D-021's own anti-choice: strands the AI on an outage, does not travel, breaks degradability/portability). **`wires: none` / native-automation-only, no engine code** (rejected — drops the state/attention/debt projection that is the module's distinctive value per [D-021](0021-github-projects-ships-as-an-optional-adopter-facing-module-p.md); native automation cannot see engine signal). **Silently revert a human's manual board edits** (rejected — operator trust; the engine writes only its own fields so human Status/column moves survive, and divergence on engine fields is surfaced not silently reverted; a silent overrule of a non-engineer's deliberate gesture is the "quietly misled" failure). **Bootstrap the board as a new leaf on the locked [provisioning](../spec/systems/infrastructure/provisioning.md) doc** (rejected — provisioning's bootstrap-leaf set is closed and foundation-scoped; a per-optional-module external resource is **module-owned setup** reusing the operator-privileged/degrade-and-disclose pattern, keeping the locked doc untouched and the side-effect honestly homed). **An `mcp` wire / a Projects MCP server** (rejected — `gh`/GraphQL from the hook suffices; no server, no second outage surface). **Carry the module under an enforcement tier / dress the projection as a guardrail** (rejected — [§7](../principles.md); it gates nothing, the board is observational). **Restate the state/attention/control-plane laws in the module doc** (rejected — the laws live in the locked systems; the module applies them). **Coin a glossary term** (rejected — `Slot`/`Filling` already place it, and "projection over committed truth" is [§2](../principles.md) + the Memory-ledger precedent). **Lock** `github-projects-sync` this pass (rejected — the WBS + a fresh cold audit gate the lock, in dependency order after `core`, which is itself only `designed`).
