# Enumerate the branch-ruleset protection floor in control-plane (re-litigation + re-lock)

*Decided 2026-05-29 in the design workspace.*

## The decision

**Re-litigate the locked** [control-plane](../spec/systems/infrastructure/control-plane.md) ([D-104](0104-phase-c-cross-reference-the-external-contribution-mode-into.md)) to author the **protection floor** — the set of protection rules a generated repo's branch ruleset must require — which the doc previously asserted it "locks… what it must require" without ever enumerating (finding #1 of the GitHub control-architecture audit: the constitutional layer of Risk [R1](../reference/risks.md) was asserted-locked with its rules unwritten, an authoring-rule-1 / complete-final-state gap a cold builder could not construct from). The floor lands as a **contract** in §"The branch ruleset" — the concrete ruleset payload and apply mechanics stay [provisioning](../spec/systems/infrastructure/provisioning.md)'s build-spec leaf, and the required *check names* stay derived: **require a pull request** (zero required approvals in solo so the sole owner can still self-merge, one code-owner review in team), **status checks to pass**, **conversation resolution**, **blocked force-pushes**, **restricted deletion**, and an **honestly-named bypass posture** (solo *can* bypass — not airtight, §15's *cannot weaken silently*; team holds no bypass — *cannot weaken at all*). Loosening any floor rule is a [§15](../principles.md) weakening-class change. Two consistency edits in the same doc: the solo merge-gate sentence now reads "requires a pull request and the required checks but no required reviews in solo" (was "required-checks only"), and the guard-endpoint hedge "may read" → "can read". The doc is **re-locked under this decision**.

## Why

Justified re-litigation, not drift ([D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md) posture) — completing a claim the locked doc already makes whose substance was missing; the floor is additive and consistent with every locked constraint ([constraints](../reference/constraints.md) sole-owner-cannot-self-approve, [principles §6/§7/§15](../principles.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) merge-and-walk). The **HARD cold-session design audit** ran four independent cold-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) against the proposed floor. The technical lens verified, against current GitHub rulesets + sources, that all six rules are achievable — require-a-PR with **0 approvals** blocks direct pushes yet still lets the author merge once checks pass; the default `GITHUB_TOKEN` cannot create a ruleset (needs `admin:repo_ruleset`); the per-branch evaluated-rules endpoint reads with Metadata-only. Two **serious** findings resolved: "require branches up to date" was **cut from the solo floor** (under multi-PR / routine builds it produces an operator-unactionable blocked merge, contradicting merge-and-walk), and the bypass wording was **bound to §15 inline** with the team-mode structural action named. The architect's **blocking** D-number collision was **independently verified and corrected** — D-121 was already minted ([external-contribution](../spec/systems/lifecycle/external-contribution.md) lock), so this entry is **D-122**; the architect's "dangling D-121 reference" sub-claim was a stale-read false alarm (D-121 is properly minted), nothing to escalate. `python3 lock.py --relock systems/infrastructure/control-plane/README.md --decision D-122`; `python3 validate.py` green. **Propagation:** control-plane re-locked + the locks.yaml entry (ratified_by D-122); [glossary.md](../reference/glossary.md) gains a "Protection floor" term distinguished from the security floor; this entry. **No edit owed** to locked neighbours [provisioning](../spec/systems/infrastructure/provisioning.md) (its "ensures the protection floor" now resolves to the defined term — a clean reference, no reopen), [repository-topology](../spec/systems/infrastructure/repository-topology.md), [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [validation](../spec/systems/guardrails/validation.md); verify-only and current for [constraints.md](../reference/constraints.md), [risks.md](../reference/risks.md) R1 (**stays open** — enumeration ≠ first-run UX), [scenarios/first-run.md](../architecture.md#first-run-provisioning), wbs/stage-0-harness.md §5, [engine-architecture.md](../architecture.md) §3.

## What we ruled out

Include **require-branches-up-to-date** in the solo floor (rejected — strict mode starves merge-and-walk and hands a non-engineer a rebase they cannot perform; the stale-base risk is already carried behaviorally and is a team-tier opt-in). Require **≥1 approval in solo** (rejected — a sole owner cannot approve their own pull request, [constraints](../reference/constraints.md), so it deadlocks the one operator; solo is zero required approvals). Require **signed commits** (rejected — setup friction a non-engineer cannot be assumed to complete; trust rests on review + checks, not commit-author cryptography). Require **linear history** (rejected — merge method is the product's workflow choice, not an engine law). Include the **"restrict updates"** rule (rejected — it deadlocks merges for an admin acting through bypass; named as an explicit non-member so it is not reintroduced). Home the floor in **provisioning** instead of control-plane (rejected — the rule *set* is a contract/law, control-plane's lane; provisioning owns only the apply *mechanism*, and restating it would be a rule-3 second source). **Skip the cold-session audit** or edit the locked doc without re-litigation (rejected — the CLAUDE.md HARD gate; `lock.py` owns the fingerprint).
