# Type the cron-fired audit persona: re-litigate `agents` (role⇒trigger spine, the `audit` role) and reconcile `audits`; resolve Q29

*Decided 2026-05-29 in the design workspace.*

## The decision

**Re-litigate the locked** [agents](../spec/systems/surfaces/agents.md) surface ([D-057](0057-lock-the-agents-surface-wave-1-four-settled-design-forks.md)/[D-100](0100-decouple-the-locked-agent-grammar-from-the-model-landscape-m.md)) so the cron-fired [audits](../spec/systems/guardrails/audits.md) self-audit persona — a `required`-core artifact found untypeable by the [audit-library dry-run](../spec/modules/audit-library.md) ([D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md), [Q29](../reference/open-questions.md), hereby resolved) — has an admissible type. Root cause: every routing field assumed the build orchestration was the *sole consumer*. Fix — bind `role` to the **trigger it runs for**, reusing the **already-locked `audit-prep` validation trigger** ([check](../spec/systems/surfaces/check.md):70 / [validation](../spec/systems/guardrails/validation.md):70) rather than minting a new "consumer" abstraction (the [§16](../principles.md) spine): **(1)** the closed `role` set grows to four — `plan-review` · `worker` · `pre-submission-review` · **`audit`** — generalizing [D-057](0057-lock-the-agents-surface-wave-1-four-settled-design-forks.md) fork (2)'s role⇒**gate** identity to role⇒**trigger** (the build orchestration for the first three; the `audit-prep` cron for `audit`); the set stays closed and coherence-checkable. **(2)** `lens` is **review-role-scoped** — `worker` and `audit` carry **no lens** (resolving a pre-existing `worker`-lens inconsistency), and a `lens` declared on a non-review role is now a coherence **finding** (the symmetric guard making "no lens" a typed invariant). **(3)** the build orchestrator's **derived roster is partitioned to the build-gate roles**, so a present `audit` persona never leaks into a gate. **(4)** `output-contract` fixes only the **report shape** on the canonical [`finding.v1`](../spec/systems/surfaces/schemas.md) base; **`severity` is a per-consumer axis** ([D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)) (review roles narrow to `blocking|serious|nit`, the `audit` role declares its own) and **disposition is the trigger-owner's** (the orchestrator's finding-disposition policy vs. audits' two lanes) — no review enum or orchestrator triple pinned onto the auditor. **(5)** the second **invocation mode** is named: the `audit` persona runs as the **top-level `--agent` session** fired by the cron, not an orchestrator-spawned subagent. **(6)** `permissions: read-only` covers the auditor and `model-tier: judgment` is admissible unchanged (the whole routing-field set is scoped, closing [D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md)'s mandate); the leak-guard fence is extended to the new nouns. **[audits](../spec/systems/guardrails/audits.md) is reconciled** (re-locked): the persona-frontmatter deferral is discharged — typed `role: audit`, read-only, cron-fired, no lens, `judgment`, findings via the two-lane disposition — keeping the requirement-vs-fields split ([D-076](0076-lock-the-audits-system-re-founded-for-the-deployed-repo-hygi.md)). Both docs re-locked under this decision.

## Why

Justified re-litigation, not drift — the [D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md) dry-run proved a `required`-core artifact unconstructible from the locked grammar (the genesis Q27/§16 meta-pattern recurring in L3: a downstream consumer presupposing a form the upstream never pinned). The **plan-level cold-session design audit** (four cold lenses) reshaped the first-draft "consumer" generalization: the **architect** found a BLOCKING **roster cross-contamination** (the orchestrator's role-unfiltered roster derivation could pull the audit persona into a gate) → fixed by the trigger-partition; **adversarial** + **operator** found a BLOCKING **output-contract** untruth (pinning the review severity enum + `fix/log/escalate` onto the read-only auditor, whose dispositions are audits' two lanes) → fixed by per-consumer severity ([D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)) + trigger-owner disposition; **adversarial** forced dropping a synthetic `lens: self-audit` (vacuous coherence) for a no-lens audit role; **feasibility** named the top-level-`--agent`-session invocation mode. A **second, as-written cold audit** of the edited `agents` doc then ran (the [D-100](0100-decouple-the-locked-agent-grammar-from-the-model-landscape-m.md) precedent): it caught a residual **coherence gap** (a stray `lens` on `worker`/`audit` was silent → added the symmetric finding), tightened the worker "gate"→"Implement phase" wording, and extended the leak-fence to `--agent`. **Platform facts verified firsthand** against current Claude Code docs: `--agent <name>` makes the agent file the top-level session (adopting its prompt/tools/model); a scheduled GitHub Actions run drives it headless and read-only (`--permission-mode dontAsk` / tool-deny); `.claude/agents/` file-drop discovery holds **only non-bare** (under `--bare`, default-bound for `-p`, agents must be passed via `--agents` JSON) — so the `audit-prep` workflow's **non-bare `--agent audit`** invocation is a load-bearing build-spec leaf. **Verified no-touch (logged, not silent):** [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) derives gate lenses "from the installed agent **suites**" (the design-review/qa-review **review-role** suites) and `agents` is authoritative on roster membership, so its text stays truthful — *the architect recommended a four-word clarifying edit for defense-in-depth; overridden to stay within the operator-approved two-doc scope, the determination recorded here rather than asserted by silence*; [schemas](../spec/systems/surfaces/schemas.md) governs the JSON-Schema mechanism generically and the per-consumer audit finding profile is a build-spec-leaf instance (like the existing agent profile), no surface edit; [engine-architecture.md](../architecture.md) never enumerates the closed role set, so it stays a truthful index. `python3 lock.py --relock systems/surfaces/agents/README.md --decision D-133` then `... systems/guardrails/audits/README.md --decision D-133`; `python3 validate.py` green. **Propagation:** agents + audits re-locked + locks.yaml (ratified_by D-133); [glossary.md](../reference/glossary.md) — `Agent (persona)` generalized to the two triggers, `Persona template` scoped (`lens` review-only), the agent-`output-contract` severity made per-consumer, an **Audit persona** term added; [modules/audit-library/README.md](../spec/modules/audit-library.md) Status unblocked (Q29 cleared) + the non-bare `--agent` invocation leaf recorded; wbs/dry-run-ledger.md D-126 entry annotated "Resolved by D-133" (not rewritten); [Q29](../reference/open-questions.md) deleted; this entry.

## What we ruled out

**A coherence-kind carve-out whitelisting the auditor** (rejected — the agent-coherence rule lives *in* `agents`, so a carve-out edits the same doc yet keeps the grammar falsely claiming all agents are gate agents and silences only two of the four mis-fitting fields). **A new `consumer`/`trigger` routing *field*** (rejected — contradicts the locked "one fewer way to misconfigure", [D-057](0057-lock-the-agents-surface-wave-1-four-settled-design-forks.md)/[D-100](0100-decouple-the-locked-agent-grammar-from-the-model-landscape-m.md); role⇒trigger carries it with no field, and distinct from [D-100](0100-decouple-the-locked-agent-grammar-from-the-model-landscape-m.md)'s rejected *sixth field* this adds a *value*). **Keep `lens: self-audit`** (rejected — entrenches the `worker`/`audit` lens inconsistency and makes the dangling-lens guarantee vacuous for the new role). **Pin `blocking|serious|nit` + `fix/log/escalate` on the auditor** (rejected — re-creates [D-126](0126-dry-run-the-audit-library-module-not-build-ready-the-audit-p.md) one field over, contradicting [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md) per-consumer severity and audits' two-lane disposition). **Re-enumerate the field grammar inside `audits`** (rejected — duplicates grammar; `audits` owns the requirement, `agents` the fields, [D-076](0076-lock-the-audits-system-re-founded-for-the-deployed-repo-hygi.md)). **Edit + re-lock build-orchestration this pass** (rejected — `agents` is authoritative on roster membership and build-orchestration references the review *suites*; the four-word clarifier is deferred and the no-touch determination logged; the operator approved the two-doc scope with the architect dissent on record). **Type the auditor as a skill-driven session instead of an agent** (rejected — locked [audits](../spec/systems/guardrails/audits.md)/[audit-library](../spec/modules/audit-library.md) already commit to a `.claude/agents/` persona; `--agent` runs that file headless, so no re-typing is owed).
