# Triage engine-template issue #42 (per-project attention tuning): a post-v1 design gap sharpened in Q17, not a build-conformance deviation

*Decided 2026-06-04 in the design workspace.*

## The decision

Adjudicated the build-repo enhancement **engine-template issue #42** ("attention tuning values should be per-project tunable, not template-enforced"). **It is a post-v1 *design gap*, not a build-conformance deviation.** Ground-truthed against `origin/main` (not the lagging local checkout or the roadmap's stale status line): the `core` slice-12 build (PR #41, merged 2026-06-04) homed attention's tuning values in the `core`-owned policy `.engine/policies/attention.md` — exactly what the locked design mandates ([attention](../spec/systems/cognitive/attention.md): the values live in "a committed, governed policy-surface instance" that "lands on the locked [policies](../spec/systems/surfaces/policies.md) surface"). The build conformed; there is nothing to fix in it. The gap is in the *locked design*: a `core`-owned policy is template-owned machinery, overlaid (replaced wholesale) on every engine update ([audits](../spec/systems/guardrails/audits.md)), and the preserved operator-config lane ([provisioning](../spec/systems/infrastructure/provisioning.md)) holds no per-project policy-value override — so a deployed project cannot keep its own calibrated values across an overlay. This is the "operator-override config model so tuned knobs survive engine overlays" component **[Q17](../reference/open-questions.md)** already owns; Q17 was **rewritten in place** (it stays open) to (i) record the concrete surfacing at the slice-12 build / #42 with the *build conformed* finding, (ii) name the gap as a **standing v1 limitation present in every deployment** and scope the auto-tuning evidence-gate off it, (iii) bound the **broader-than-attention** claim to the verified structural sibling — the [triage-threshold policy](../spec/systems/surfaces/policies.md) (a `core`-owned value-carrying policy with the identical overlay fate) — while caveating that the build-review-depth default is a per-build operator choice with a memory-preserved preference ([build-orchestration](../spec/systems/lifecycle/build-orchestration.md)), *not* an overlaid policy value, and (iv) split the **determinism-safe manual-override-persistence** component (needs no usage evidence; decidable ahead of auto-tuning) from the **telemetry-driven auto-calibration** half that collides with attention's locked determinism. **No locked doc is touched; the fix stays deferred post-v1.** **Propagation:** rewrote Q17 in [open-questions.md](../reference/open-questions.md) to its finished current state; this entry. No `risks.md` reconciliation is owed — [R6](../reference/risks.md) already records the deployed-Engine self-tuning deferral (tied to Q17) and [R7](../reference/risks.md) owns the overlay-preserves-config seam, so the open question is the sufficient carrier and no new risk is opened. `python3 validate.py` green.

## Why

The lock default is "adapt the work to the locked system; never bend the plan to a build mistake" — and here the build made no mistake (verified against `origin/main`), so there is nothing to conform. A real design gap surfaced during construction belongs in the canonical workspace's parking lot (no concern dies outside a durable home — the [finding-disposition](../spec/systems/surfaces/policies.md) discipline), not solely in a downstream repo's tracker; recording it up into the plan is legitimate provenance, distinct from feeding template *drift* into the design ([D-161](0161-relocate-the-core-build-roadmap-from-the-engine-template-bui.md)). Folding into Q17 rather than minting a new question avoids parking-lot duplication, since Q17 already names the override-config component. The disposition was hardened by a four-lens cold-context audit (adversarial · technical-feasibility · non-engineer-operator · architect): the adversarial lens's "slice 12 is unbuilt" was refuted by `origin/main` ground-truth, the build-review-depth over-claim was bounded to the verified triage-threshold sibling, and the operator-lens honesty findings (name the present-deployment limitation; scope the evidence-gate to the auto half) were adopted.

## What we ruled out

**Treat #42 as a build-conformance deviation and change slice 12** (rejected — slice 12 conforms to the locked attention/policies design, verified on `origin/main`; the gap is in the design, not the build). **Re-litigate the locked [policies](../spec/systems/surfaces/policies.md)/[attention](../spec/systems/cognitive/attention.md)/overlay docs now to add an override layer** (rejected — the fix is post-v1 and the operator deferred it in #42; this triage opens no locked doc). **Mint a new Q37 for the override-persistence model** (rejected — Q17 already names the operator-override config model; the determinism-safe sub-component is captured inside Q17 by the (a)/(b) split rather than duplicated across two parking-lot items). **Open a new `risks.md` entry** (rejected — [R6](../reference/risks.md) already records the self-tuning deferral and [R7](../reference/risks.md) owns the overlay/preserve seam; a new entry would duplicate their blast radius for a deferred, out-of-core capability). **Leave the gap only in build-repo #42** (rejected — a design gap tracked solely in a downstream repo violates canonical-workspace ownership and the finding-disposition discipline).
