# Discharge the Wave-0 gate (Q10): substrate-content world-tagging is misattributed to the module grammar

*Decided 2026-05-25 in the design workspace.*

## The decision

Under **explicit operator approval**, **discharge [Q10](../reference/open-questions.md) clean** — the [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) Wave-0 gate — and resolve it, clearing the only precondition on the Wave-2 cognitive locks. The gate asked whether the cognitive substrate (state, memory, knowledge, attention) needs substrate *content* world-tagged (engine vs product) in a way the locked [module-system](../spec/systems/grammar/module-system.md) `provides`/`wires` grammar cannot express, which would reopen that locked grammar. The finding: **the concern is misattributed to the module grammar and is substrate-design-independent**, so the grammar is sufficient *by not being the relevant layer* — verified, not forecast: **(1)** wiring is **master-agnostic** and the engine↔product asymmetry is enforced **mechanically** (no `wires` seam edits product source; clean removal) **independent of any manifest field** — this is the direct consequence of [D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md)'s already-locked anti-choice, which rejected a per-capability `master` manifest field on exactly these grounds; **(2)** the engine/product *content* split is carried **structurally by which substrate holds what**, never by a per-record tag: [memory](../spec/systems/cognitive/memory.md) is the **project's institutional recall** (ships **empty** per [D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md), accumulated at runtime), [knowledge](../spec/systems/cognitive/knowledge.md) is **purely derived** from source surfaces so an entity's world is **path-derived** from [topology](../spec/systems/infrastructure/repository-topology.md) (`.engine/<surface>/` = engine; root = product), and Engine **self-monitoring** lives in a **separate** store — engine-labeled GitHub Issues unwound by a domain **label** ([D-039](0039-reports-self-improvement-scope-engine-only-self-monitoring-o.md)), never the memory ledger — so the ledger is homogeneous project-recall and needs no per-record world tag; **(3)** modules ship committed engine-world data via `provides` (world **path-derived** — e.g. [audit-library](../spec/modules/audit-library.md)'s seed concern-list under `.engine/`) and ship accumulating substrate stores **empty** ([D-007](0007-memory-data-is-local-and-gitignored-substrate-ships-empty.md)/[§4](../principles.md)); there is **no install-time content-load** into a runtime store, so no shipped content needs a manifest world-tag; **(4)** any residual world-tagging the substrate's own schema might want is a **substrate-schema leaf** owned by the cognitive design sessions (per [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) "designed systems' open threads are leaf"), on the locked [schema](../spec/systems/surfaces/schemas.md) surface — a *different* surface from the module grammar. **Invariant recorded** (the gate converted to a standing design commitment, not deleted as moot): the cognitive-implementation sessions must honor that Engine self-monitoring episodes never enter the project memory ledger (memory's institutional-recall scope); if a leak ever occurred, the operator's backstop is memory's existing **operator-visible, reversible forgetting** readout. This invariant is propagated to the (still-`designed`) memory doc's design commitments. **Discharges the [D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) Wave-0 hard gate** — Wave 0 is now clear and the Wave-2 cognitive locks have **no remaining precondition**; the gate is cleared *categorically/early* (not at the first cognitive lock as D-052's framing presumed) precisely because the discharge does not depend on substrate design — it relocates the concern off the grammar. **Locked-doc handling:** re-lock [module-system](../spec/systems/grammar/module-system.md) as a **faithful reconciliation** — remove only its now-resolved "Cognitive forward-dependency" open-question bullet (the [Q1](../reference/open-questions.md) bullet stays), which changes **no law, grammar, or seam** (the bullet was a discharged watch-item pointer, not a rule); then `python3 lock.py --relock`. No other locked doc references Q10's content ([topology](../spec/systems/infrastructure/repository-topology.md), [ontology](../spec/systems/grammar/ontology.md), glossary, architecture all clean); [D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md)/[D-052](0052-foundational-law-layer-closed-the-implementation-lock-order.md) references stay as append-only history. Q10 is deleted from [open-questions.md](../reference/open-questions.md).

## Why

Q10's premise — that the world-tagging dependency might fall on the *module grammar* — is the misattribution; D-026 had already located the answer (wiring is master-agnostic; asymmetry is mechanical) and explicitly flagged that a `master` field "edges into the deferred cognitive-content scoping," which is exactly this gate. The discharge is therefore the consequence of a decision already locked, not a new forecast of the unbuilt substrate, which is what makes closing it now sound rather than lock-atop-sand: the surviving check (the substrate's *own schema* may want world-tagging) is a leaf already owned by the cognitive sessions, not a module-grammar open question, so a narrowed residual would wrongly re-assert the disproved dependency. The four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md): adversarial / technical-feasibility / non-engineer-operator / architect, no shared context) ran against the discharge argument; its blocking and serious findings were resolved before this entry: **(adversarial, blocking)** the draft argument's premise "modules *never* ship content" is **false** — [audit-library](../spec/modules/audit-library.md) ships a seed concern-list via `provides` ([D-041](0041-audits-designed-state-a-purpose-built-adversarial-self-revie.md)) — and a hypothetical module shipping seed *memory* records into the gitignored ledger would need an install-time content-load absent from the closed `wires` seam → **resolved** by withdrawing the false premise and re-grounding on (3): committed shipped data is engine-world by *path* (expressible), accumulating stores ship empty (D-007), and seeding the ledger is forbidden by memory's ships-empty/institutional-recall scope, not a grammar gap; **(non-engineer-operator, serious)** the draft conflated the *file-wall* (mechanically enforced) with the *content-wall* (the real concern) → **resolved** by re-grounding on the structural carriers (memory scope / knowledge derivation / D-039 issue-label) and by **converting the gate into the standing invariant** above rather than deleting it as moot, with the reversible-forgetting readout named as the operator's backstop; **(architect, serious)** the discharge must rest on the D-026 master-agnostic / misattribution argument (not a substrate forecast), carry explicit-approval phrasing for the re-lock, and explicitly reconcile D-052's "Wave 0 is hard / verify at first cognitive lock" language → all **incorporated** above; **(technical-feasibility, nit + adversarial nit)** cite knowledge **path-derivation** and product-source **seam-discipline** as *two separate legs* (the mechanical no-seam-edits guarantee covers product source, not content provenance inside a shared store) → reflected in the two-part structural argument. Technical-feasibility verified every platform fact firsthand (topology placement laws, the derived-from-surfaces generator, the gitignored NDJSON ledger + FTS5 index + MCP server, the fieldless manifest and closed seam, `${CLAUDE_PROJECT_DIR:-.}`) and returned no blocking/serious. Propagation per the matrix: resolution captured here, Q10 deleted, the locked module-system bullet reconciled by re-lock, the invariant propagated to the `designed` memory doc; `engine-architecture.md`, `glossary.md`, `risks.md` (R2 untouched) need no edit.

## What we ruled out

Litigate / reopen the locked module grammar (rejected — no case forces a manifest world field once memory's institutional-recall scope and D-039's separate self-monitoring store are read correctly; the dependency is misattributed, and D-026 already rejected the `master` field). Keep Q10 open as a **narrowed residual** to confirm at the first cognitive lock (rejected — the surviving check is a substrate-schema leaf already owned by the cognitive sessions per D-052; a residual would wrongly re-assert a module-grammar dependency the discharge disproves, and D-052 placed the gate ahead of the first cognitive lock precisely so it would not have to be carried into one). Ground the discharge on "modules never ship content" (rejected/withdrawn — falsified by audit-library's seed concern-list; the correct grounding is master-agnostic wiring + structural scope + path-derivation). Add a `master`/world field to the manifest (rejected — already rejected by [D-026](0026-the-engine-is-an-embedded-team-member-contributor-not-compon.md); it forces a classification and is unnecessary). Leave the locked module-system bullet stale after resolving Q10 (rejected — a discharged watch-item pointer left in a locked doc is the drift the lock mechanism forbids; faithful reconciliation + re-lock is the honest end-state, the [D-049](0049-re-lock-topology-and-module-system-file-precise-codeowners-o.md)/[D-055](0055-collapse-command-into-the-skill-surface-invocation-is-a-gove.md) precedent). Delete the gate as moot without recording the content-wall invariant (rejected — the Wave-0 gate did protective work for the operator; closing it must *promote* its content to a standing design commitment, not drop it).
