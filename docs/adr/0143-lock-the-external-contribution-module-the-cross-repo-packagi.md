# Lock the `external-contribution` module (the cross-repo packaging): the seventh module lock

*Decided 2026-05-30 in the design workspace.*

## The decision

Ratify and **lock** the [external-contribution module](../spec/modules/external-contribution.md) (`status: designed → locked`) — the `optional` packaging that realizes the external-contribution mode (the Engine contributing to a repo the operator does not own): the `soft` upstream-clean nudge, the cross-fork submission operation, and the operator-narration policy/doc. This is the **seventh module lock** and the **packaging-doc** half of external-contribution — its **SYSTEM doc (the laws) was already locked at [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md)**, which deliberately deferred this module-packaging lock to its dry-run build. **Both gates met:** build-readiness at the L2 dry-run (BUILD-READY, all four dry-run lenses; no contradictions across 8 axes), and the **HARD cold-session design audit** — four cold-context lenses **all ratify, no blocking and no serious finding**. The lenses confirmed: the module **consumes the locked laws and restates none** (the close-model — the merge wall moves to the upstream — is carried *in* locked [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) §Close [D-104](0104-phase-c-cross-reference-the-external-contribution-mode-into.md), consumed not re-authored; the nudge predicate is [topology](../spec/systems/infrastructure/repository-topology.md)'s already-derived file-precise CODEOWNERS engine-owned set); the **two-gates honest tiers** ([§6](../principles.md)/[§7](../principles.md)) — the hard gate is the **upstream's** (a governed upstream's required checks run in its context for a fork PR + maintainer review; an ungoverned upstream's merge is vacuous and disclosed, never dressed as review it is not); **`depends: core` on the target axis** ([D-129](0129-reconcile-dependency-discipline-to-depends-core-l2-the-targe.md) — the nudge inspects the OUTGOING diff, presupposes no engine-self-validation corpus, no validators-core edge); **`wires: none`** (the nudge self-declares its `pre-close` suite, the tooling is an operation, and **no hook touches [knowledge](../spec/systems/cognitive/knowledge.md)** — the engine-clean product branch holds no engine surfaces, so the core-owned regen hook produces nothing on it, the [D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md) resolution; the cross-fork `gh` permission is a build-spec leaf); the **[§13](../principles.md) wall** (outward read-and-propose, never seizes the upstream, the upstream carries no Engine dependency, removal test passes); and the **[R14](../reference/risks.md) un-exercised-at-v1 disclosure** at setup-time (the cross-repo path has not been exercised end-to-end at v1 — informed consent before opt-in). The technical lens ground-truthed the cross-fork mechanics against live `gh` 2.92.0 / `git` 2.50.1: `gh pr create --repo <upstream> --head <owner>:<branch>` is the correct current invocation for an operator-owned fork; the keystone trust fact (the upstream's required checks gate the fork-PR merge regardless of the fork's settings; first-time-contributor approval strengthens it) holds; the three-dot `upstream…fork` outgoing-diff predicate is realizable read-only and correctly directed; `wires: none` is true (the operator's local `gh` carries the auth, no repo secret); the three [R13](../reference/risks.md) facts (fork Actions enablement, the back-merge/three-dot caveat, per-upstream DCO/CLA) are honestly gated as post-build verification, not assumed. The [D-137](0137-clear-the-residual-dry-run-designed-doc-precision-nits-and-r.md) `pre-submission`→`pre-close` suite fix is in place (the doc declares only the real `pre-close` suite). **Nit dispositions (none blocking, none touching a locked doc):** the "[clean-code](../reference/module-catalog.md) disclosure precedent" cite points at a `stub` — **left** (the substantive home is [R14](../reference/risks.md) + the locked system doc, which carries the *same* cite verbatim; editing the module alone would desync it from the locked neighbor, the design-review-entanglement pattern; the cite borrows a pattern, freezes nothing); the check `target` selector for an outgoing-diff predicate — a **build-spec leaf** (a `custom/script` kind computes `upstream…fork`; `target` scopes when it runs; not a locked-check gap); the "no hook touches knowledge" phrasing — **adequately qualified** (D-137 left it; an optional tightening toward the laws' "produces nothing on it" is not a gap); the org-owned-fork `gh` limitation — a **build-spec leaf** confirming the design's operator-owned-fork scoping (the [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) nit); "engine-mechanic" unexplained in the module doc — a maintainer-orientation nit (defined in the locked lifecycle doc + glossary, never an operator surface). **Propagation (floor only, architect-confirmed):** the module doc (`status: locked` via `lock.py`) + the locks.yaml entry (ratified_by D-143) + this entry. **No edit owed** — [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) already reconciled [engine-architecture.md](../architecture.md) §3/§6, [modules/README.md](../reference/module-catalog.md), [risks.md](../reference/risks.md) R13, and [glossary.md](../reference/glossary.md) for the system lock; design-maturity is not catalog-tracked ([D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md)); R13/R14 stay open by design (build-time/post-build gates a packaging lock neither opens nor closes); ## Why

This completes the external-contribution system/module split [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) deliberately staged — the laws locked on the cold-session audit, the packaging locking now on its clean dry-run build + its own fresh cold audit (the module-vs-system lock-gate discipline). The module is upstream-anchored on the locked `core`, standalone (fills no Slot), and consumes locked laws by citation, so it sits atop no churn. The riskiest surface — the cross-fork PR mechanics — was the one most worth a fresh live-platform ground-truth (the [D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md) lesson), and it held against live `gh`/`git`. The nits are build-spec leaves or the desync-avoiding clean-code cite; none warrants a pre-lock edit.

## What we ruled out

**Lock the module together with the system doc back at [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md)** (rejected then and confirmed now — the packaging locks on its dry-run build, the build-readiness gate, distinct from the cold-session audit that gated the system-laws lock). **Edit the clean-code-precedent cite to point at R14 instead of the stub** (rejected — the locked system doc carries the identical cite; changing the module alone desyncs it from a locked neighbor for a cosmetic gain, and the cite freezes nothing). **Pin the outgoing-diff `target` selector or the org-fork scoping in the doc now** (rejected — both are build-spec leaves the kind-realization/submission-tooling owns; the form is pinned, the concrete realization deferred [§2](../principles.md)). **Re-litigate the locked external-contribution/build-orchestration laws** (rejected — the module consumes them cleanly; nothing requires a locked-doc edit, so no litigation alarm). **Edit catalog/architecture/glossary/risks to mark the lock** (rejected — [D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) already reconciled them for the system lock and design-maturity is not catalog-tracked; floor only).
