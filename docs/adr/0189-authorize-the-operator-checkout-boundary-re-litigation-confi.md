# Authorize the operator-checkout-boundary re-litigation: confine build to worktrees by recognizing native isolation, and detect a stranded operator checkout (engine-template #74/#79/#80)

*Decided 2026-06-13 in the design workspace.*

## The decision

Authorize a re-litigation editing **five** locked docs + framing docs to close the **operator-checkout boundary** gap behind engine-template **#74/#79/#80** — all three opened from one incident (2026-06-03): an AI session running **in the top-level operator checkout** ran a Bash-mediated `git checkout`+`commit`, stranding it detached / 62-behind / pre-`.claude/settings.json`, so no hooks/boot ran and the operator saw **no `Project status` card for ~5 days**; protected-`main` was the only backstop. The thread is that the top-level checkout is the operator's **surface**, not a build **workspace**, and the engine guarded that boundary at no layer.

  **Keystone (verbatim-grounded, settles #74's coupled finding).** #74's claim that the Explore write-gate "keys on the tool, not the action" is **false at the law layer**: [modes](../spec/systems/lifecycle/modes.md) already denies *"the building actions … edits to engine or product files, branch creation, commits, and the opening of a pull request (whether via `gh` or a GitHub MCP tool)"* (action-axis) and already treats Bash-mediated git as *best-effort* (shell strings not fully parseable). The incident did **not** escape through a tool-vs-action gap — it escaped because the gate is **stance-axis** (it permits commits in Build/Routine *by design*) and the engine had **no notion of *where* a session runs**. So #74's gate concern is a *realization-conformance* item (slice-21 must implement the designed detection), not a litigation — **[modes](../spec/systems/lifecycle/modes.md) is NOT edited.**

  **Decisive live fact (probed in the operator's own environment).** A fresh Claude Desktop session on the operator's project **auto-lands in a linked worktree** (`.claude/worktrees/<name>` on a `claude/<name>` branch); `git worktree list` shows the main checkout **untouched at `[main]`** beside ~14 siblings. **Claude Desktop auto-isolates every session in its own worktree** — so the platform already provides #79's isolation, and the incident's worst symptom is **structurally mitigated** (a session now runs in a worktree carrying its own committed engine files and grounds regardless of main's state; the incident was a pre-auto-worktree / non-Desktop session). The fix therefore **recognizes and relies on the native substrate** rather than building a bespoke guard.

  **The settled design (two cold 4-lens audits; v1's mechanism rejected, v2 reshaped + folded).**
  - **#79 — recognize native isolation + a scoped "never-strand-main" posture floor; NO bespoke guard.** [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) states build/Routine work runs in the platform's per-session worktree and the operator checkout is a protected surface, not a workspace (honest tier: a strong platform **default, not a guarantee**; the merge wall stays the only unbypassable wall for shipped history). [modules/core](../spec/modules/core.md)'s deployed-floor `CLAUDE.md` carries the floor: *never mutate the operator checkout's git state **as build work, autonomously, or unconsented*** — the **one exception** being the operator-consented un-stranding correction (below) — scoped to the **working-location / detach-strand class**, explicitly **not** "any commit reaching the default branch through the reviewed channel" (so [external-contribution](../spec/systems/lifecycle/external-contribution.md)'s legitimate fork-main substrate commits are untouched). The Routine residual (Local Desktop scheduled tasks do **not** auto-isolate by default) is covered by the floor + `/engine-routine` worktree-toggle setup guidance + build-orchestration's existing every-commit scope-lock.
  - **#80 — detect a *stranded* main, offer to fix it, at the open-findings tier.** [provisioning](../spec/systems/infrastructure/provisioning.md) owns a new standing, boot-invoked `.engine/tools/` **detector** (reads the main checkout's state from the worktree session via `git worktree list` / `--git-common-dir`) **and** the **un-stranding fix** (re-materialize missing engine files / re-attach a detached HEAD / fast-forward), a new explicitly-consented operator-checkout-scoped mechanism parallel to the protected-branch-off fix. [boot](../spec/systems/lifecycle/boot.md) adds a **fifth** deferred surfacing at the **open-findings tier** (not governance-critical — a stranded main cannot reach the protected branch), **relaying** the finding and **offering** the fix while staying read-only (provisioning acts on consent). **Scoping laws:** ordinary "N behind origin" is the *normal* state of the main under the worktree-and-PR model and **must not alarm** — the per-boot **offline** check covers only the binary states (**detached HEAD**, **missing engine files**); behind-origin rot is an **opt-in, network-gated, consequence-gated** tail (fires only on a concrete felt consequence, never a bare distance count). **Safety law:** the fix is **offline-decidably lossless or it does not run** — safe iff `git -C <main> rev-list HEAD --not --branches` empty AND `stash list` empty AND `status --porcelain` clean; **never** re-attach off a commit-carrying detached HEAD without first creating a **rescue branch**, **never** silently `--ff-only` a diverged branch. The **unsafe path stays actionable** (rescue-then-update on one consent, never a command, never a loss). **Double-fault honesty:** #80 runs in the boot pack, so it is hook+runtime-dependent and does **not** fire in the pre-`settings.json` / no-runtime case — it covers less-degraded successors, not the literal incident (which #79 prevention + native isolation address).
  - **#74b — fold the binding into core; defer the control-plane note.** The session AI, asked by the operator to open an engine-labeled issue, authors it **through the shared issue-authoring helper** (posture — GitHub cannot gate issue creation) — landing in [modules/core](../spec/modules/core.md)'s deployed-floor `CLAUDE.md`. The [control-plane](../spec/systems/infrastructure/control-plane.md) producer-set enumeration note is **deferred to the #62/#63 follow-up** (re-locking a foundation for a provisional one-liner is the churn lock-discipline forbids).

  **Scope.** **Re-lock (locked) — 5:** [build-orchestration](../spec/systems/lifecycle/build-orchestration.md), [modules/core](../spec/modules/core.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [boot](../spec/systems/lifecycle/boot.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md) (one-line defer-pointer only). **OUT:** [modes](../spec/systems/lifecycle/modes.md) (no gate change), [control-plane](../spec/systems/infrastructure/control-plane.md) (#74b note deferred). **Edit (non-locked):** [constraints](../reference/constraints.md) (home the auto-worktree platform fact, version-contingent, scoped per session-entry-type), [glossary](../reference/glossary.md) (*operator checkout*, *stranded checkout*), [risks](../reference/risks.md) (new bounded-residual risk, relating R19/R18/R1/R6), scenarios (reconcile or log). **Verified-no-edit (logged):** [external-contribution](../spec/systems/lifecycle/external-contribution.md) (holds because the floor is scoped to working-location, not branch — fork-main substrate commits are legitimate reviewed-channel own-repo writes; product commits isolate to short-lived worktree branches), [engine-architecture](../architecture.md) (role-granularity truthful), [state](../spec/systems/cognitive/state.md) (a strand is not the project-status cursor), [attention](../spec/systems/cognitive/attention.md) (§16: a new boot finding attaches additively), [modes](../spec/systems/lifecycle/modes.md). The engine-template build realization (the detector, the fix, the floor, the worktree-toggle guidance, the #74b binding) is a downstream follow-up filed against the build, not authored here.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval, given after the live probe settled the decisive platform fact and the design converged through two cold audits. The gap is real (an engine session stranded the operator's checkout for ~5 days), but the fix is *recognition of a native substrate* (Desktop auto-worktrees) plus a posture floor and a detect-and-offer-to-fix — minimal capability surface (R6 confirmed): #79 adds no mechanism (it names what the platform does and rejects a bespoke guard that would re-open [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md)'s "always-on enforcement is not modes' concern"); #80 adds exactly one detector + a consented fix reusing provisioning's existing re-materialize and the protected-branch offer precedent. The five re-locks are propagation breadth, not capability breadth; the honest tiers (native isolation a default not a wall; #80 hook-dependent; the fix lossless-or-not-run) are stated, never over-promised.

## What we ruled out

**A bespoke mechanical location guard (the v1 mechanism)** (rejected — native Desktop isolation covers the common case; an always-on stance-independent PreToolUse guard re-opens [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md)'s settled drop, and detecting reach-back is best-effort shell-parsing — the fragility the design rejects). **"The orchestrating session runs in a worktree" by self-relocation** (rejected — the orchestrator *is* the operator's session opened at the repo root; it cannot `cd` itself into a sibling worktree (cwd resets; no runtime cwd switch), and the platform already isolates new sessions natively). **Add a *where* axis to the [modes](../spec/systems/lifecycle/modes.md) gate** (rejected — the location guard is stance-independent, so [D-051](0051-guardrail-integrity-the-builder-cannot-silently-weaken-its-o.md)'s home principle bars it from the stance gate; and no guard is built at all). **`@{upstream}..HEAD` to detect unpushed work** (rejected — invalid on a detached HEAD, the incident's own state; replaced by `rev-list HEAD --not --branches`). **Alarm on "N behind origin"** (rejected — the worktree-and-PR model makes the main normally behind; a distance alarm is Q18 fatigue; only the binary strand states + a consequence-gated behind-rot tail alarm). **Auto-fix that could discard local work** (rejected — lossless-or-not-run; rescue-then-update on the unsafe path; never silent loss in an engine a non-engineer trusts). **Re-lock control-plane for the #74b producer note** (rejected — provisional one-liner; deferred to the #62/#63 follow-up where the producer set is worked). **Treat #74's gate-by-action as a litigation** (rejected — the gate law is action-axis already; it is a slice-21 conformance item, not a design change).
