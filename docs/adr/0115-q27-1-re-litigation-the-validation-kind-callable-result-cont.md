# Q27 #1 re-litigation: the validation kind-callable result contract (pass/fail over finding.v1)

*Decided 2026-05-29 in the design workspace.*

## The decision

Resolve [Q27](../reference/open-questions.md) **instance #1** — the unowned validation kind-callable result/return contract — by pinning it across the locked [check](../spec/systems/surfaces/check.md) and [validation](../spec/systems/guardrails/validation.md) docs (the second locked-doc step of the closure wave, [D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md)). A kind callable returns a **result** = a pass/fail verdict plus zero or more findings, each conforming to the canonical [`finding.v1`](../spec/systems/surfaces/schemas.md) base `{severity, message, location ref (file/line)}` ([D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)); a **check finding's `severity` is the rule's `tier`** (`hard`|`soft`) — the per-consumer severity the canonical base leaves open. [validation](../spec/systems/guardrails/validation.md) (the dispatcher / kind-registry owner) *fixes* the contract; [check](../spec/systems/surfaces/check.md) (the rule grammar) *references* it ("every callable conforms"). The per-finding JSON Schema stays a build-spec leaf; the result *shape* is pinned (the laws-not-leaves form/contract convention, [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)). This is the litigation-alarm re-litigation of the locked check + validation docs ([D-044](0044-re-lock-validation-and-check-a-check-kind-binds-by-presence.md)), operator-approved this session; both re-locked. **Q27 instance #1 closes; [Q27](../reference/open-questions.md) itself stays open until all five instances close** (#4 telemetry-record lands at the telemetry step). No other propagation is owed: `core`'s `provides` already ships the dispatcher + five kinds (the contract is what those callables satisfy — no new artifact); the glossary `finding.v1` term already names check as a consumer; engine-architecture / risks / scenarios are unaffected.

## Why

[D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)'s genesis dry-run found the kind callables' return contract unowned while the only uniform finding shape was the agent `output-contract` — the gap [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)'s `finding.v1` cross-cut was decided to fill. Pinning the result as pass/fail-over-`finding.v1` is the minimal form the meta-convention requires; it keeps the dispatcher thin (collect uniform results, report by the rule's tier) and leaves the per-finding schema a build-spec leaf. A **focused cold re-audit** (two independent lenses) ran on both as-edited docs before the re-lock: it confirmed consistency (validation defines, check references; no contradiction), faithfulness to D-113 (base shape; severity-per-consumer = tier; agents untouched; telemetry deferred), no conflict with the locked dangling-kind promotion (a dispatcher-synthesized finding for an *unregistered* kind is distinct from a *registered* callable's returned result), and that the uniform return does not over-constrain the `custom/script` or module kinds. Two dispositions: **(nit, fixed)** validation had rendered the base `{severity, message, location}`; aligned to the canonical `{severity, message, location ref (file/line)}`. **(serious, rejected with rationale)** an architect lens flagged that the [schemas](../spec/systems/surfaces/schemas.md) doc does not itself acknowledge `finding.v1` as a homed shared base — rejected: `finding.v1` is `$ref`'d *by* the catalog-routed governing schemas (the check-result, telemetry-finding-record, and agent output-contract schemas), so it sits within the schemas README's wholesale JSON-Schema-2020-12 model (which "invents no bespoke meta-machinery"); schema *instances* are not enumerated in that grammar README (the locked agent output-contract `.v1` is likewise referenced + linked to schemas without README enumeration); and `finding.v1`'s existence/home/consumers are made legible by the [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md) glossary term — so no schemas grammar amendment or re-lock is owed, confirming D-113's no-schemas-re-lock construction. `python3 lock.py --relock` on both check and validation against D-115; `python3 validate.py` green.

## What we ruled out

Home the result contract in `check` rather than `validation` (rejected — the kind callable lives in validation's registry; validation owns the contract, check references it — the clean ownership seam). Make the check finding severity a fresh enum rather than the rule's `tier` (rejected — D-113 fixed severity as a per-consumer enum and the check consumer's axis is its `tier`; a parallel enum duplicates it). Pin the per-finding JSON Schema now (rejected — that is a build-spec *value*; the convention pins the form/contract and defers the values). Amend/re-lock the [schemas](../spec/systems/surfaces/schemas.md) doc to acknowledge `finding.v1` (rejected — `finding.v1` is `$ref`'d by catalog-routed governing schemas, within the README's wholesale 2020-12 model; instances aren't README-enumerated; D-113 + glossary make it legible). Delete [Q27](../reference/open-questions.md) now (rejected — it is a five-instance umbrella; only #1 closes here).
