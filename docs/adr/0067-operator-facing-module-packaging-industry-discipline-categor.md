# Operator-facing module packaging: industry-discipline categories; core is never an install choice

*Decided 2026-05-26 in the design workspace.*

## The decision

Establish the **operator-facing packaging model** for the module catalog — additive to the locked [module-system](../spec/systems/grammar/module-system.md) ([D-028](0028-module-system-locked-end-state-as-laws-not-leaves.md) fixes *laws not membership*; this touches presentation and grouping, never the manifest grammar) and an advance on [Q4](../reference/open-questions.md)'s selection UX. **(1) The install walkthrough enumerates only what the operator can opt *out* of** — the optional packages. Core/`required` packages — the foundation internals plus **`routine-mode`** (the routine *stance*, a constraint-profile of the core workflow per [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md), not a module) and **`audit-library`** (self-checkups) — are **never presented as install choices**, are **not disablable in v1** (core-feature toggles are out of v1 scope; a possible future), and are disclosed in plain language in the **project README** (and remain queryable via the self-map readout). This **reclassifies `routine-mode` + `audit-library` from default-on module → core** (a catalog correction). **(2)** The optional packages are grouped under **recognized SDLC discipline umbrellas** (IEEE 1012 / SWEBOK) — **Product Management, Software Configuration Management, Verification & Validation** — chosen as durable categories that scale to dozens of future modules; **the grouping is provisioning-side selection-UX presentation data keyed by module `id`**, *not* a manifest field (the locked [D-028](0028-module-system-locked-end-state-as-laws-not-leaves.md) enum has no `category` and rejected a classification field), so it is purely additive. Each module also carries a one-line plain-language gloss (final wording a Q4 leaf) so a recognized label stays legible to a non-engineer. **(3)** "module" and "package" remain the same unit ([D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)); **no new install grain** is introduced. **(4)** Hidden-from-the-installer ≠ undisclosed ([operator-communication law](../reference/glossary.md)). **(5) Dependency-closure invariant:** hiding required internals is safe only while no operator-facing package depends on a hidden one (true for the v1 roster — every kept optional depends only on `required` `core`/`validators-core`); the selection UX must still surface any future operator-facing→operator-facing dependency at confirm.

## Why

The primary stakeholder (the non-engineer operator) flagged a flat ~19-row module list that mixed foundation-internals with real capabilities as illegible — the highest-authority signal for an operator-facing concern (goals attr. 1 trustworthiness, attr. 6 low-ceremony). The fix is presentation, not grammar: [D-028](0028-module-system-locked-end-state-as-laws-not-leaves.md) locked laws-not-membership and deferred operator-facing selection UX to [Q4](../reference/open-questions.md), so grouping/visibility is additive. Recognized discipline labels beat invented ones for a non-engineer who can look them up and form a stable taxonomy for growth; the operator chose three SWEBOK/IEEE umbrellas over invented plain-language names, and "reviews *are* V&V" (IEEE 1012) places the review suites in Verification & Validation. A four-lens cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran against the plan; its findings were folded before this entry: the taxonomy was pinned to provisioning presentation-data keyed by `id` (not a manifest field) to keep it additive; the `routine-mode`/`audit-library` mis-cataloguing (a stale default-on-module assumption [D-038](0038-session-lifecycle-re-founded-on-native-substrates.md) had already dissolved for routine) was corrected to core; the dependency-closure-display invariant was recorded; and hidden≠unexplained was satisfied via the README + self-map disclosure rather than install-time enumeration.

## What we ruled out

Present default-on items (self-checkups, routine stance) as a disablable menu group (rejected — a one-item category plus a v1 core-feature-toggle mechanism we are explicitly not building; core is disclosed in the README, not toggled at install). Merge related modules into coarse packages (rejected — re-couples the deliberately-decoupled [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) lenses and recreates the grab-bag the operator warned against). A formal two-tier package-of-modules grain (rejected — a new install unit colliding with [D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)'s single package=module; the category layer is presentation, not a unit). Invented plain-language category names (rejected — the operator prefers recognized SDLC labels that scale and are googleable). "GitHub integration" as a category (rejected — the engine lives entirely *inside* GitHub, so "integration" is meaningless; `github-projects-sync` is work-tracking → Product Management). Add a `category` manifest field (rejected — trips the locked [D-028](0028-module-system-locked-end-state-as-laws-not-leaves.md) enum / rejected classification field; grouping lives in provisioning presentation data keyed by `id`).
