# Litigate the deployment eADR collision: the operator's per-instance engine-decision stream adopts a per-project namespace `<project-slug>-eADR-####` on the `eADR` root (the identifier wall applied engine-vs-engine); canon keeps `eADR-####` — re-locks of ontology + contracts land under [D-299](0299-resolve-re-lock-ontology-the-instance-identifier-law-gains-t.md) + [D-300](0300-resolve-re-lock-contracts-the-two-eadr-populations-named-can.md)

*Decided 2026-07-12 in the design workspace.*

## The decision

The [contracts](../spec/systems/surfaces/contracts.md) surface's **per-instance stream** — a deployment's own *engine* decisions, authored under `.engine/contracts/instance/` and preserved across an upgrade ([D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md)) — adopts a **per-project identifier namespace on the `eADR` root: `<project-slug>-eADR-####`** (e.g. `acme-eADR-0007`). The **engine canon keeps `eADR-####` unchanged.** This entry is the **litigation alarm + operator authorization** (direction and the token confirmed in-session over `AskUserQuestion` before any edit) **and the design of record**. It re-litigates two locked docs: the [ontology](../spec/systems/grammar/ontology.md) instance-identifier law ([D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md)) and the [contracts](../spec/systems/surfaces/contracts.md) shape/canon spec ([D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md)). Both are **edited under this entry but not re-locked here**; the mandatory landed-text cold audit runs after the edits and its findings + resolutions are recorded in the resolve entries — **[ontology] → [D-299](0299-resolve-re-lock-ontology-the-instance-identifier-law-gains-t.md), [contracts] → [D-300](0300-resolve-re-lock-contracts-the-two-eadr-populations-named-can.md)** — which carry the `lock.py --relock` invocations (the [D-296](0296-litigate-engine-template-427-residual-three-l1-l2-l3-audits.md)→[D-297](0297-resolve-re-lock-audits-installs-the-standing-conditional-pro.md) authorize→resolve pattern; `validate.py` flags both fingerprints until the re-locks).

  **The flaw.** The locked design pinned **both** eADR populations — the engine-owned foundational canon and the deployment-owned per-instance stream — to the identical `eADR-####` token, distinguished **only by path** ([contracts](../spec/systems/surfaces/contracts.md) "distinguished by path, never by a content marker"). The canon is an **advancing frontier** (a new foundational law ships `eADR-0034`, `-0035`, … post-v1), so a deployment that authored its own `instance/eADR-00NN` eventually owns a second record with the **same bare token**. This is exactly the collision the shipped canon **eADR-0017** ([D-020](0020-engine-instance-identifiers-are-engine-namespaced-decision-r.md)) exists to prevent — *"a bare token, which has no path — so the wall has to reach identifiers explicitly or it leaks exactly where it is hardest to see"* — reintroduced **engine-vs-engine** (canon-vs-deployment), one namespace-level inside the wall eADR-0017 built engine-vs-product. **No numeric range is safe** — the frontier can catch up to any boundary a deployment starts from.

  **The true collision bound (stated honestly, [§7](../principles.md)/[§17](../principles.md) — not inflated).** Two legs are already contained: a `Supersedes:` link is **intra-stream** (a deployment record can only supersede another deployment record — the canon is engine-owned and overlaid, so a deployment cannot author a record superseding a canon eADR), and the knowledge-graph entity key is **already path-qualified** (`instance.<stem>` vs `contract:<stem>`) as a legitimate build-leaf ([knowledge](../spec/systems/cognitive/knowledge.md)). The **irreducible residual** is the bare token in **free text that carries no folder context** — a commit message, a prose citation, an ad-hoc AI/operator reference — the precise leg eADR-0017 names. The fix targets that leg.

  **The token, and why the `eADR` root is retained.** `<project-slug>-eADR-####` keeps the `e`-marker, so it **is** an engine-namespaced identifier — the recursive application of eADR-0017's own law, engine-vs-engine. Because the records are **still eADRs**, the standing descriptor **"per-instance eADR stream"** stays *true* in the five locked docs that carry it ([provisioning](../spec/systems/infrastructure/provisioning.md), [module-system](../spec/systems/grammar/module-system.md), [modules/core](../spec/modules/core.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md)) — they are **verify-no-edit**, not re-locks, holding the [R6](../reference/risks.md) surgical scope to the two docs whose text actually names the scheme. The engine authors the id; the **operator never types it**, and (the operator's acceptance check) a record is always **narrated in words** when surfaced — "your own engine decision (`acme-eADR-0007`)" vs "the engine's founding law (`eADR-0017`)" — never the bare token alone. The concrete slug (the deployment's project identity, resolved at first-run) is a per-instance value — a build-spec leaf, like the literal path names.

  **Adjudications settled here.** (1) **Amending shipped canon eADR-0017 is a `fold`, not a supersession** — it *refines/extends* the namespacing law (adds a per-project layer) without reversing it, so per the canon-update rule (eadr-canon-manifest, [§18](../principles.md)) it is an in-place amendment, not a new linked eADR; an engine-side build-owe. (2) **The ontology law's scope broadens engine→engine** — the current law namespaces engine identifiers against the *product*; this adds an *intra-engine* (canon-vs-deployment) dimension, articulated in the ontology edit, not bolted on. (3) **Folder / `provides` membership stays authoritative; the identifier conforms** — if a filename prefix and its folder ever disagree, the folder governs (the overlay classifier keys on path/`provides`, never the token), so no new content-vs-path ambiguity replaces the bare-token one. (4) **Stream-worthiness is not relitigated** — whether the per-instance stream clears the contract threshold is locked ([D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md)); the fix rides the existing two-population design.

  **Propagation (non-locked, landed under this entry after the edits):** [glossary](../reference/glossary.md) (*Contract*, *Foundational eADR canon*, *Product ADR*, *Engine/product wall* — name the deployment scheme); wbs/eadr-canon-manifest (law **S2** + Authoring-metadata naming); wbs/eadr-canon/README (the "two seams" note — the distinct id makes stems structurally distinct); wbs/eadr-canon/S2-* (Decision + Significance name the deployment scheme; the fold-not-supersede note). **Verify-no-edit (recorded, no truthfulness change under the slug form):** [provisioning](../spec/systems/infrastructure/provisioning.md), [module-system](../spec/systems/grammar/module-system.md), [modules/core](../spec/modules/core.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md), [knowledge](../spec/systems/cognitive/knowledge.md), [control-plane](../spec/systems/infrastructure/control-plane.md)/CODEOWNERS, [engine-architecture](../architecture.md), [memory](../spec/systems/cognitive/memory.md) — each still truthful because the records remain eADRs and the overlay still classifies by path/`provides`.

  **Build-owe (engine-template):** the deployed scheme is realized in engine-template (filed via `.engine/tools/issue_author.py` + the `engine` label, reconciled against origin/main — PR #464/#422 already merged): widen the `contract.v1.json` `id` + `supersedes` patterns and the three `contract-*` check globs + `knowledge_gen`'s `deployment_contract_inventory()` glob to accept `<slug>-eADR-####`; **fold** the deployment scheme into shipped `eADR-0017`; discharge `instance/README.md`'s "won't clash" promise with the real scheme in plain language (no [§12](../principles.md) leak); migrate the `eADR` test fixtures; decide the slug source. The knowledge generator's `instance.<stem>` path-qualification becomes optional defense-in-depth (the distinct id de-collides structurally). This workspace lands the design of record; the build executes in engine-template. Findings are **COMMENTED** on issue #422; nothing on the live repo is closed or merged from here.

  **Id allocation:** tail was [D-297](0297-resolve-re-lock-audits-installs-the-standing-conditional-pro.md), no forward reservation above it; **D-298** (this litigation entry) allocated monotonically, with **D-299** (ontology re-lock) + **D-300** (contracts re-lock) forward-reserved here.

## Why

the collision is the exact failure eADR-0017 was written to prevent, one level inside its own wall, and it is locally certain the moment a deployment authors an eADR against an advancing canon — so it warrants the re-litigation, not a build-time patch. Retaining the `eADR` root is what makes the fix *conform* to eADR-0017 (an engine-namespaced identifier) rather than merely dodge the symptom, and it is what keeps the blast radius at two docs instead of six. The per-project namespace reads from the operator's seat as *their* project's first-class decision — the recursive application of the same law that already separates engine from product.

## What we ruled out

**A flat marker (`dADR`/`oADR`)** (rejected — drops the `e` engine-marker, so it is *not* an engine-namespaced identifier and does not inherit eADR-0017's guarantee: a product could reuse `dADR` (draft/design/database ADR), reopening a smaller collision; it also reads as *design*/*deployed* and courts `D-####` confusion (the engine's design-decision log, cited across the build), and it falsifies "per-instance eADR stream" across five locked docs — blowing the re-lock set to six incl. the heavier [modules/core](../spec/modules/core.md) module-doc gate). **The prime `eʹADR`** (rejected — non-ASCII, fragile in filenames, grep, commit messages, and the very id-references the wall must hold). **Path-only, accepting build's #464 knowledge-graph fix as sufficient** (rejected — eADR-0017's own text forecloses it: path-qualification does nothing for the bare token in free text). **Disjoint numeric ranges (canon low, deployment high / reserved band)** (rejected — the advancing frontier rots any boundary; only a distinct namespace is structurally safe). **Drop the per-instance stream, route deployment engine-decisions to the PR-body contract** (rejected — over-corrects and contradicts locked [contracts](../spec/systems/surfaces/contracts.md) more deeply; the two-population design is locked [D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md), and stream-worthiness is not what is being litigated). **Supersede shipped eADR-0017 rather than fold** (rejected — the law is refined, not reversed; a new linked eADR for a non-reversing extension is the ADR-explosion the canon-update rule prevents). **Re-lock ontology + contracts in this entry** (rejected — the landed-text cold audit is the mandatory gate before the irreversible re-lock; the re-locks land under [D-299](0299-resolve-re-lock-ontology-the-instance-identifier-law-gains-t.md)/[D-300](0300-resolve-re-lock-contracts-the-two-eadr-populations-named-can.md) after it).
