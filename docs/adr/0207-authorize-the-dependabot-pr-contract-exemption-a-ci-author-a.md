# Authorize the Dependabot PR-contract exemption: a CI-author applicability boundary on the PR-body completeness check (engine-template #116)

*Decided 2026-06-17 in the design workspace.*

## The decision

Authorize a re-litigation (litigation alarm) on explicit operator approval to exempt **GitHub Dependabot** pull requests from the **PR-body completeness** required check, by introducing a first-class **CI-author applicability boundary** to the [check](../spec/systems/surfaces/check.md) rule grammar. **The litigation alarm:** three Dependabot **security** PRs (engine-template #113/#114/#115 — bumps to python-multipart, starlette, cryptography) cannot merge. `main`'s ruleset requires two checks green with **no bypass actor**, and both go red on every Dependabot PR — `engine-ci` because `pr-body-completeness` finds none of the eight [control-plane](../spec/systems/infrastructure/control-plane.md) PR-contract sections (Dependabot writes its own changelog/release-notes body and never passes through the engine PR template), and `engine-guard` because each bump edits `.engine/uv.lock` (a guarded file) and demands the `guardrail-ack` label. **`engine-guard`/`guardrail-ack` is working as designed and stays fully load-bearing — a dependency-lockfile change is exactly where deliberate review belongs; this litigation does not touch it.** The grammar to express an actor-scoped exemption **does not exist** anywhere in the corpus (a check's `target` scopes by surface/path, never by PR author), so per "never invent structure on the fly" the grammar is decided here before the build realizes it.

  **The decision — exempt, realized as a disclosed not-applicable no-op (never a silent green).** The completeness check enforces the PR contract, which is the **Engine's own account-of-record** ([§11](../principles.md)/[§17](../principles.md)); an Engine build session produces it. A Dependabot PR is **not** an Engine build session — it is an external automation's PR carrying its own account — so the contract **binds contract-bearing (Engine-authored) PRs**, and a recognized external-automation author is **categorically outside its domain**. For such a PR the check is a **disclosed not-applicable result** — a stated pass naming why the rule does not bind this PR — consistent with the corpus's pervasive disclosed-no-op discipline ([glossary](../reference/glossary.md) *Slot*; [dependency-discipline](../spec/modules/dependency-discipline.md)'s checks), **never a silent skip** (which would mislead a reviewer into reading green as "eight sections verified"). **Auto-comply** (a workflow synthesizing the eight sections above Dependabot's body) was rejected by the operator and on principle: it would **manufacture a false Engine account** — a fabricated "Claude involvement"/"Review" record for a PR with no Engine review behind it, exactly the dressing-posture-as-substance [§7](../principles.md)/[§17](../principles.md) forbid (control-plane names Review's truthfulness as the one thing "the operator cannot independently corroborate"). Exempt is the *more honest* choice, not merely the lighter one.

  **The grammar (operator-chosen: a first-class facet, not buried in kind params).** The check rule record gains an **eighth, optional field — `ci_author_exempt`** — the pull-request author logins a rule **does not bind when evaluated in the `CI` suite** against a PR authored by one of them. It is **inert outside CI** (`pre-commit`/`pre-close` have no PR author; Dependabot never runs the engine's local hooks anyway), default-absent (true of every v1 rule except `pr-body-completeness`), and is the rule's declaration of an *applicability boundary* — the PR-context sibling of `target`. The **validation engine honors it as a disclosed not-applicable result, keeping the five closed kinds author-agnostic** (critical — `presence` is shared by the contract-anti-choice and close-disposition checks, which are not author-scoped); the boundary lives in **rule data**, never as logic in a kind or a conditional in the dumb CI harness. **Ownership ([§16](../principles.md)):** [control-plane](../spec/systems/infrastructure/control-plane.md) **owns the domain-boundary definition** (external-automation authorship is outside the PR-contract's domain), [validators-core](../spec/modules/validators-core.md)'s rule **realizes** it as data (declares `dependabot[bot]`), and `core`'s validation engine **honors** it. **Spoof-safety (a decided invariant, feasibility-confirmed below):** keyed on the **PR author** (`pull_request.user.login`), **never** `github.actor` (a re-run attributes that to the re-runner); `dependabot[bot]` is a non-registrable reserved GitHub-App identity (usernames cannot contain `[`/`]`) and a fork cannot author a PR as it. **Scope ([R6](../reference/risks.md)):** the facet is general (any rule may declare it — it is data, not new mechanism) but the applied value is one author on one rule; **no trusted-bot registry** and no arbitrary-predicate language. **§15:** narrowing a required check's coverage is a guardrail-weakening change ([§15](../principles.md) names "check definitions"); the PR that lands the exemption edits `.engine/check/`, so it trips both `engine-guard` and the §15 weakening-detection guard and lands only behind the operator's distinct acknowledgment — **the weakening is gated by the very gate we keep**, exactly as [dependency-discipline](../spec/modules/dependency-discipline.md)'s accepted-exception allow-list is. Any later widening is again §15-gated; the §15 guard itself never carries `ci_author_exempt`.

  **Reshaped by a four-lens cold plan-audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context). **Technical-feasibility PASS clean** — every platform fact verified against current GitHub docs + security research: `github.event.pull_request.user.login == 'dependabot[bot]'` is GitHub's own documented pattern; `dependabot[bot]` is spoof-safe (Synacktiv: a fork cannot force a Dependabot-authored PR); the "disclosed no-op = a genuine PASS result" is correct and **avoids the trap** that a job-level `if:` skip leaves a required check **Pending** (which blocks merge). **One BLOCKING (adversarial + architect, convergent):** the draft marked [modules/core](../spec/modules/core.md) verify-no-edit, but the validation engine is `core`'s, so honoring the boundary extends its locked dispatcher text — **`core` joins the re-lock set (4 → 5)**. **Serious, folded:** control-plane must *own* the domain boundary and its now-unqualified "fails the merge until the sections are present and non-empty" sentence must be neutralized to carry the boundary; the disclosed result must be a **real reported result**, not a silently-synthesized pass (realization — dispatcher-applies vs kind-emits — a build-spec leaf, the law being "a disclosed not-applicable result, kinds author-agnostic"); spoof-safety promoted from "verify at build" to a decided invariant; the **operator-presentation relay is BLOCKING from the operator seat** — the disclosure lands in CI output the operator never reads, so the AI must **relay in chat** why a Dependabot PR's completeness check is green (exempt, not verified) and why the lockfile `guardrail-ack` is the real protection; the landing PR's §15 acknowledgment must, in plain language, name what narrows and bound it truthfully (only Dependabot's own PRs; every other PR and the lockfile gate unchanged) and not imply the AI gained an unwatched path; maintainer jargon (`ci_author_exempt`, "dispatcher", "disclosed no-op") never surfaces to the operator. **Serious, partially declined (logged):** the adversarial push to move the exemption into the `presence` kind's `params` (to co-locate the no-op with the kind) — declined because applicability ("which PRs a rule binds") is a *rule property*, not a *kind parameter*, and `core` re-locks either way (the kinds are `core`'s too); the honesty concern it raises is met by the disclosed-result requirement, and the closed kinds stay author-agnostic regardless. **Architect, folded:** the check **governing schema** gains one optional field (value a build-spec leaf; optional/default-absent so schema-conformance still passes the other rules); the [glossary](../reference/glossary.md) *Check* field-list edit is **mandatory**, not optional, and **no new term** is minted ("disclosed no-op" already exists); **no new R24** — fold the residual into the existing [§15](../principles.md)-weakening clause of [R1](../reference/risks.md). The operator chose the first-class-facet form (5 re-locks) over the lighter params form on the basis above.

  **Scope. Re-lock set — 5** (all currently locked → re-locked, none added): [check](../spec/systems/surfaces/check.md) (the rule record gains the optional `ci_author_exempt` field; the governing schema gains one optional default-absent field, value a build-spec leaf), [validation](../spec/systems/guardrails/validation.md) (the engine honors a rule-declared CI-author boundary as a disclosed not-applicable result — CI-only, inert locally, "runs identically" preserved, kinds author-agnostic; narrowing/widening is §15-weakening), [validators-core](../spec/modules/validators-core.md) (the `provides` line notes `pr-body-completeness` declares the `dependabot[bot]` exemption, realizing control-plane's boundary), [control-plane](../spec/systems/infrastructure/control-plane.md) (own the domain boundary; neutralize the unqualified completeness sentence; the disclosed not-applicable reaches the operator via the relay; the exemption is §15-gated), [modules/core](../spec/modules/core.md) (the dispatcher seam bullet: the engine honors a rule-declared CI-author applicability boundary as a disclosed not-applicable result, kinds staying author-agnostic). **Carriers (non-locked):** [glossary](../reference/glossary.md) (*Check* field list), [risks](../reference/risks.md) [R1](../reference/risks.md) (the §15-weakening clause gains the check-coverage-narrowing sibling: introducing/widening an exempt-author set is a weakening change gated by the acknowledgment; the exempt check stays a disclosed not-applicable result so a green check is never silently "verified"). **Verify-no-edit (architect-confirmed):** [ontology](../spec/systems/grammar/ontology.md) (governs surfaces by record, not by a surface's internal field set), [engine-architecture](../architecture.md) (role+link index, no field list), all scenarios (none walks a Dependabot PR or a CI-suite author check — apparent hits are dependency-discipline links), [modules/README](../reference/module-catalog.md), [dependency-discipline](../spec/modules/dependency-discipline.md). The re-locks land under the **Resolve** entry (D-208) after the mandatory landed-text cold audit.

## Why

The litigation-alarm protocol authorizes a locked-doc change on explicit operator approval. The defect is real and the only legal fix is new grammar (no actor-scoping exists), so the grammar is decided here. Exempt-as-disclosed-no-op is the honest realization (auto-comply would fabricate an Engine account; a silent skip would mislead the reviewer). A first-class applicability facet puts the new concept in its conceptually-correct home (a rule property, sibling of `target`) rather than mis-filing it as a kind parameter, at the honest cost of one extra re-lock; it is optional/default-absent so it burdens no other rule, and is keyed on the authoritative, non-registrable `dependabot[bot]` author so it is spoof-safe. The change keeps `engine-guard`/`guardrail-ack` fully load-bearing, gates its own landing behind the §15 acknowledgment, and binds the disclosure to the operator-presentation relay so a non-engineer is never trained that a green check is uniformly "verified."

## What we ruled out

**Auto-comply** (synthesize the eight sections) — rejected: manufactures a false Engine account-of-record ([§7](../principles.md)/[§17](../principles.md)). **Silent skip** (exempt without disclosure) — rejected: a silent green misleads the reviewer; violates the disclosed-no-op discipline. **CI-harness conditional** (the workflow omits the rule for Dependabot) — rejected: violates "the harness owns neither check content nor membership" + "runs identically locally and in CI." **Bake into the `presence` kind's `params` / make the kind actor-aware** — rejected: special-cases a closed-core kind shared by three rules; applicability is a rule property, not a kind parameter. **Make `pr-body-completeness` a `custom/script` one-off** — rejected: downgrades a declarative `presence` rule to hidden script logic. **Overload `target` with an author dimension** — rejected: `target` is the subject (surface/path); PR-author is the PR context — keep the axes distinct. **A general trusted-bot registry / arbitrary `applies_when` predicate language** — rejected: scope creep ([R6](../reference/risks.md)); v1 needs one author on one rule. **Mark `modules/core` verify-no-edit** — rejected (the plan-audit BLOCKING): the validation engine is `core`'s, so honoring the boundary extends its locked dispatcher text. **Open a new R24** — rejected: the residual is the same §15-weakening class already housed in [R1](../reference/risks.md); minimize per [R6](../reference/risks.md). **Change `engine-guard` / weaken `guardrail-ack` on `.engine/uv.lock`** — rejected: out of scope; a lockfile change is where deliberate review belongs. **Treat the exemption as "not a weakening"** — rejected: it is a §15 weakening-direction diff; gate it honestly.
