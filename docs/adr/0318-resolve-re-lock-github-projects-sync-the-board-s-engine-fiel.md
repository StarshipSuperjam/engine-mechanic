# Resolve: re-lock `github-projects-sync` (the board's engine field is **`ranked work`**, not *"what's next"* — the label moves, the attribution stays) — a carrier of [D-314](0314-litigate-engine-template-394-attention-s-work-record-commiss.md)/[D-315](0315-amend-d-314-correct-its-operator-authorship-premise-the-buil.md)

*Decided 2026-07-16 in the design workspace.*

## The decision

Re-lock [github-projects-sync](../spec/modules/github-projects-sync.md), a carrier of [D-314](0314-litigate-engine-template-394-attention-s-work-record-commiss.md) as amended by [D-315](0315-amend-d-314-correct-its-operator-authorship-premise-the-buil.md)(6). [D-314](0314-litigate-engine-template-394-attention-s-work-record-commiss.md) deferred this doc to an adjudication *"before the re-locks land"*, framed as *"if the attribution moves"*. **The adjudication returns: the attribution does *not* move — the label does**, and D-314's framing was too narrow. **The attribution is true and stays.** Attention genuinely still produces the projected ordering: [control-plane](../spec/systems/infrastructure/control-plane.md):277 scopes this projection to the **engine-labeled** set, and `:59-61` confines the tool to *"only its own custom fields"* on *"its own already-labeled items"* — so `:45`'s *"attention prioritization/ordering"* is accurate post-`#394`. **The label is what is false.** `:45`, `:73`, `:170` and `:214` name that field **"what's next"** — the phrase [glossary](../reference/glossary.md):110 now pins, in this same pass, to a **different producer** (the accepted build Issue's next unchecked item, read not ranked). Two operator-facing surfaces, one phrase, two referents. **The field is relabelled `ranked work`** at all four sites, matching the status verb's dashboard field of the same name, so the two surfaces say one thing; `:45` additionally states that *"what's next"* is the plan's to answer and **no part of this projection**. `python3 lock.py --relock modules/github-projects-sync/README.md --decision D-318`.

## Why

this is the one site where the retired reading would have reached the operator **directly**, and it is the higher-risk surface by the module's own admission — `:143-144`: *"a non-engineer may come to **read the board instead of the Issues**"*. Worse, `:56-57` puts the operator's own **un-labeled backlog on that same board** whenever auto-add is on: a column labelled *"what's next"* that the engine never computes for those rows reads as a verdict that their backlog was **considered and ranked below** rather than **never ranked at all** — precisely the false belief [D-314](0314-litigate-engine-template-394-attention-s-work-record-commiss.md)'s own anti-choice rejected *"narrow 'what's next' to in-flight only"* to avoid. D-314 corrected the docs the operator never sees and would have left the defect on the one they do. The relabel costs nothing: *"ranked work"* is already operator-facing vocabulary at [glossary](../reference/glossary.md):110, so the [§12](../principles.md) leak guard `:170-172` invokes is satisfied for free — no new copy, no producer change, no design question opened, and the board face gains a name that is true of what is on it.

## What we ruled out

**Take D-314's conditional literally and leave the doc** (rejected — the conditional was mis-framed; "the attribution moves" is a narrower test than "the doc is wrong", and a locked module contradicting a freshly re-locked system doc is the unpropagated-residue class this pass exists to end, restaged one module over). **Re-source the board's *"what's next"* from the build-plan** (rejected — `:84` fixes `depends: core` with *"no edge to any optional module"*; reading [product-design](../spec/modules/product-design.md)'s build-plan would break it. Foreclosed by the module's own dependency law, which is why relabelling is the only honest move). **Argue the board is engine-scoped so it cannot mislead** (rejected on the module's own text — `:56-57`'s auto-add clause puts un-labeled operator Issues on the board; the defense fails without needing a hypothetical). **Relabel the *dashboard* instead** (rejected — the dashboard's read/ranked split is the correct one; the board is the divergent surface). **Leave `:214`** (rejected — the field list *"state / next / debt / last-synced"* is a fourth carrier of the same label; the sweep found it after the lenses named three).
