# Reconcile dependency-discipline to `depends: core` / L2 (the target-axis discriminator, applied)

*Decided 2026-05-29 in the design workspace.*

## The decision

Move [dependency-discipline](../spec/modules/dependency-discipline.md) from `depends: validators-core` (L3) to **`depends: core` (L2)** and reconcile the three module docs that held the contradiction plus the catalog, the build order, and the experimental stub — the remediation the [D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md) sweep adjudicated (all docs `designed`, so a reconciliation, **not** a litigation alarm). The discriminator is the workspace's own **target axis**, already stated by the sibling [migration-discipline](../spec/modules/migration-discipline.md): dependency-discipline's checks inspect the operator's **product** dependency manifests and presuppose **no** engine-self-validation corpus, so they need only `core`'s check engine (the kind dispatcher + the read-only `custom/script` or a presence-discovered conforming kind), never the engine-self-validation rule corpus [validators-core](../spec/modules/validators-core.md) consolidates. The "floor-holds" rationale dependency-discipline had borrowed is genuine only for the semantic self-audit [audit-library](../spec/modules/audit-library.md). Six edits: **(1)** dependency-discipline — manifest `depends: core`; opening rationale rewritten to the target-axis grounds; Status section follows `core` in dependency order, gated on a clean dry-run build-readiness precondition + a fresh cold-session audit. **(2)** validators-core — dependency-discipline dropped from the "feature modules … all three depend on validators-core" sentence and the Status dependents list, audit-library named the genuine floor-rester, the count-bearing phrasings made count-agnostic. **(3)** migration-discipline — the now-false contrast with dependency-discipline (`not validators-core … the difference … is deliberate`, and the parenthetical "dependency-discipline takes the validators-core edge … this one does not") **deleted**, its own target-axis rationale left standing alone. **(4)** [modules/README.md](../reference/module-catalog.md) — dependency-graph edge `validators-core → dependency-discipline` retargeted to `core → dependency-discipline`; catalog `depends` cell → `core`. **(5)** wbs/module-order.md — dependency-discipline moved from L3 to the L2 list, leaving L3 = {audit-library}. **(6)** [engine-knowledge-graph](../spec/modules/engine-knowledge-graph.md) (stub) — its catalogued `validators-core` edge **flagged** for the same target-axis re-test at its design session (flag, not resolve — its semantic recall runs over engine-internal memory, unlike the product-facing peers).

## Why

The [D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md) dry-run (contradiction-hunter upheld by the spec-completeness reviewer; orchestrator ground-truth) found the edge over-asserts presence ([§12](../principles.md)): three docs held a live prose contradiction with a real **L3-vs-L2 build-layer consequence** (the placement rested solely on the edge). The fix applies the discriminator the workspace already uses for the parallel `migration-discipline` and `external-contribution` cases — product target-axis ⇒ `core`. A two-lens cold-context plan audit (propagation-completeness/architect + faithfulness/adversarial, no shared session context) ran against the remediation plan before approval: it confirmed the edit set is exactly [D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md)'s mandate (no omission, no creep), the dependency graph stays acyclic with validators-core's out-edges reduced to {audit-library, engine-knowledge-graph}, no doc outside the set asserts the edge, and no locked doc is touched; and it folded three execution guards — the migration-discipline contrast is **deleted** (not inverted into "now shared" change-history cruft, authoring rule 1), all **three** validators-core count-bearing spots are corrected, and the dependency-discipline Status section is written **truthfully** (it does **not** assert "core is only `designed`" — `core` is locked, [D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md) — which a literal mirror of migration-discipline's stale status line would have minted). Propagation per the matrix: the six docs above; this entry. Verified no-change with rationale: [github-projects-sync](../spec/modules/github-projects-sync.md) (references dependency-discipline's *patterns / peer status*, not its depends edge), [audit-library](../spec/modules/audit-library.md) (the sole remaining L3 member — no fellow-L3 dependency-discipline reference in its body), [engine-architecture.md](../architecture.md) (a roster mention, no layer/depends claim; indexes systems not modules), [deviations/README.md](../reference/prototype-deviations.md) D24 (roster adjudication, no depends claim), [glossary.md](../reference/glossary.md) (no new/renamed term), [risks.md](../reference/risks.md) (no risk opened/closed). `python3 validate.py` green; graph acyclic. No locked doc edited.
