# Slim module status sections to one-line pointers (the prose status block was a rot-prone derivative)

*Decided 2026-05-29 in the design workspace.*

## The decision

Replace the prose **`## Status: designed, not locked`** section in all eight designed module docs ([validators-core](../spec/modules/validators-core.md), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md), [routine-mode](../spec/modules/routine-mode.md), [audit-library](../spec/modules/audit-library.md), [external-contribution](../spec/modules/external-contribution.md), [github-projects-sync](../spec/modules/github-projects-sync.md), [migration-discipline](../spec/modules/migration-discipline.md), [dependency-discipline](../spec/modules/dependency-discipline.md)) with a one-line **`## Status`** pointer. The convention going forward: a module doc carries **at most a one-line status pointer**, never a hand-narrated restatement of lock / WBS / dry-run state. The six build-ready modules point to the dry-run ledger for lock-readiness; the two blocked modules ([audit-library](../spec/modules/audit-library.md), [github-projects-sync](../spec/modules/github-projects-sync.md)) additionally carry the **one non-derivable signal** — a one-line "blocked pending [Q29](../reference/open-questions.md)/[Q28](../reference/open-questions.md)" pointer — which is why they are *slimmed to a pointer* rather than deleted outright. The `## Status: designed, not locked` heading (itself a restatement of the frontmatter `status:` field, and wrong the moment a module locks) becomes a neutral `## Status`.

## Why

Every factual claim the old prose sections made was **owned authoritatively elsewhere** — the module's maturity by the frontmatter `status:` field (which `validate.py` inventories), `core`'s lock by locks.yaml, the WBS by wbs/module-order.md, the build-readiness verdict by the dry-run ledger, and the blockers by [open-questions.md](../reference/open-questions.md). A per-module prose narration of all that is a hand-authored derivative of state it does not own — exactly what [principles §2/§3](../principles.md) (repo-authoritative truth; derive, don't hand-author — hand-authored structural state rots silently) forbid for the engine, and the same discipline applies to this workspace's own authoring. The evidence is direct: these sections fell **outside the change-propagation matrix** (nothing in CLAUDE.md said "lock a system / author the WBS / run a dry-run ⇒ update every dependent module's status prose"), so they rotted across three landings ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md) core lock, [D-107](0107-author-the-wbs-module-build-order-the-builder-crossover-reso.md) WBS authoring, the [D-123](0123-run-the-l2-dry-run-validators-core-memory-substrate-both-bui.md)–[D-127](0127-complete-the-module-by-module-dry-run-sweep-design-review-qa.md) dry-run sweep) and required two remediation passes ([D-128](0128-reconcile-routine-mode-s-stance-marker-framing-to-d-088-the.md) framing, [D-130](0130-reconcile-every-designed-module-status-section-to-current-tr.md) the full sweep) to true up — the rework was the smell. The operator weighed delete-entirely vs slim-to-pointer vs keep, and chose **slim**, preserving the blocked-on-Q signal while removing the rotting narration. This supersedes the per-module status-prose skeleton the early `designed` passes propagated ([D-089](0089-flesh-the-core-module-doc-to-designed-the-kernel-partition-t.md)/[D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md)/[D-091](0091-flesh-the-memory-substrate-sqlite-fts5-module-doc-to-designe.md)). Propagation per the matrix: the eight module docs; this entry. Verified no-change with rationale: no doc linked the old `#status-designed-not-locked` anchor (grep-confirmed), so the heading rename breaks nothing; [modules/README.md](../reference/module-catalog.md) (catalog already carries the authoritative `status` column), [glossary.md](../reference/glossary.md) / [engine-architecture.md](../architecture.md) / [risks.md](../reference/risks.md) (unaffected). `python3 validate.py` green; no locked doc edited.

## What we ruled out

**Delete the status sections entirely** (rejected — the operator chose slim; deletion would drop the non-derivable blocked-on-Q28/Q29 pointer, the one signal a reader of `audit-library`/`github-projects-sync` genuinely benefits from in-doc). **Keep the full prose sections** (rejected — they are the rot-prone derivative whose staleness drove [D-128](0128-reconcile-routine-mode-s-stance-marker-framing-to-d-088-the.md)/[D-130](0130-reconcile-every-designed-module-status-section-to-current-tr.md); keeping them keeps the recurring propagation tax). **Add "update module status sections" to the change-propagation matrix to keep them fresh** (rejected — that institutionalizes the hand-authored derivative, the opposite of [principles §3](../principles.md)'s derive-don't-hand-author; the fix is to stop restating, not to restate more diligently). **Edit the locked `core` doc now** (rejected — unjustified re-litigation for a cosmetic convention; deferred to its next relock). **Build a richer per-module readiness view** (rejected — if a consolidated readiness view is ever wanted it is derived once, in the dry-run ledger which already largely serves it, never re-scattered per doc).
