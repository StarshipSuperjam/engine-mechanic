# Resolve Q36: the engine release-cut / version-production process, as a standing maintainer-layer doc

*Decided 2026-06-14 in the design workspace.*

## The decision

Resolve [Q36](../reference/open-questions.md) by authoring wbs/release-process.md — the maintainer-layer **standing release-engineering process** that pins how an engine version is *produced* (the **bump rule** + the **release-cutting mechanism**), the complement to the locked version-*consumption* machinery ([D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md): manifest, tagged-release overlay, version-keyed migrations). It supersedes the implicit **"manual maintainer edit + tag"** premise [Q36](../reference/open-questions.md) named and **extends [D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)** as the consumption anchor, changing none of its contracts.

  **The design.** Two version levels stay exactly the locked [module-system](../spec/systems/grammar/module-system.md) grammar (per-package `version` = the non-derivable recorded migration "from" pointer; the single operator-facing engine version = the release identity). The **bump rule** is a **mechanical floor + evidenced, unconditional human confirmation**: auto-classified signals from the diff since the last release tag set a minimum (new `migrations` ⇒ package ≥ minor; module added ⇒ engine ≥ minor; module removed ⇒ engine ≥ major; engine = the max); a changed eADR/seam/[interface](../spec/systems/surfaces/interfaces.md)/wiring contract carries an **AI-authored plain-language impact statement** (what changed · which consumers depend · why breaking-vs-additive) plus, where one exists, a **break/no-break behavioral demonstration** — so the non-engineer maintainer consents on an *evidenced claim*, never a code-reading binary ([§17](../principles.md)); confirmation is **unconditional** against a plain-language **change inventory** (to catch a wrong floor or a *missing* signal, whose absence is otherwise invisible); the **contract-silent breaking change** (module-internal behavior altered with no migration/module-delta/contract edit) is the named honest residual — posture, not mechanical guarantee ([§7](../principles.md)). The **mechanism** is a `workflow_dispatch` GitHub Actions workflow (deliberate, not cron): diff → propose-with-evidence → maintainer confirm/raise → **release PR through the [control-plane](../spec/systems/infrastructure/control-plane.md) gate** (required-checks-only, the solo gate it inherits) → on merge a tag + Release **at the exact reviewed merge commit**, `concurrency` single-flighting the cut. **Every** tagged release gates on the acceptance-benchmark ("re-run before any later tagged release"; its "retires at v1" = not a *standing deployed* instrument, [Q31](../reference/open-questions.md), not "stops running"); the **v1 cut** is the first invocation, replacing the `0.0.0-dev` sentinel (stage-0-harness §6) with **1.0.0** on a benchmark PASS or a named/logged conscious sub-bar release ([D-152](0152-resolve-q15-author-the-pre-release-acceptance-benchmark-the.md)). The process is the **engine-mechanic bridge** ([D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md)): "released, ratified version N" is one a maintainer-merged cut produced; the post-v1 AI-cross-check gap beneath the merge gate is [Q31](../reference/open-questions.md), referenced not solved.

  **Reconciliations (audit-confirmed sound).** vs. module-system "non-derivable" — the rule derives the *increment* at cut time then **authors** the value; the recorded value stays non-derivable-from-source. vs. [§3](../principles.md) "derive don't hand-author" — the manifest is a *lockfile that records state*, not a *derived index that rots* (the stage-0-harness §6 hand-seed precedent).

  **Build-spec constraints pinned** (silent-failure traps, not loose leaves; verify against live GitHub docs): the **token decision tree** (`GITHUB_TOKEN`+`contents:write` *can* create a tag/Release — the contrary claim is false — but a `GITHUB_TOKEN`-opened PR does not trigger required checks and a `GITHUB_TOKEN`-created tag does not trigger downstream workflows, so the release PR / any future `on: release` automation needs a PAT / GitHub App / operator `gh`); `actions/checkout` **`fetch-depth: 0`** (else the bump-rule diff silently empties); `concurrency` **`cancel-in-progress: false`**. Plus the **silent-failure invariants**: the tagged commit *is* the reviewed merge commit; atomic-or-loudly-incomplete (no version/tag split-brain); the gate path (passed / consciously-sub-bar / errored) is legible; failures surface in plain language with a recovery action.

  **Process.** A four-lens cold audit (adversarial · technical-feasibility · non-engineer-maintainer · architect) ran against the plan and materially shaped the as-authored text: it caught that the corpus had advanced to [D-193](0193-resolve-the-d-192-conduct-surface-re-litigation-landed-text.md) under the session (so this is **D-194**, not D-192), reshaped the human gate to be §17-dischargeable (impact evidence + change inventory + unconditional confirmation), pinned the four GitHub constraints, corrected post-v1 gating to the every-release benchmark, and confirmed the home/seams/reconciliations sound.

  **Scope.** **New, no status (freely revisable, NOT locked):** wbs/release-process.md. **Non-locked carriers edited:** [open-questions.md](../reference/open-questions.md) (Q36 deleted), [glossary](../reference/glossary.md) (the *Release-cut (version production)* term), [risks](../reference/risks.md) (**R22** — the semantic-bump human-ceiling + the token-automation hazard, cross-referencing R14 which it relates to, not closes), wbs/README (release-process listed as a *standing* process, not a fourth construction-QA instrument), wbs/eadr-canon-manifest (D-194 added to the *excluded* build/workspace-instruments list — no new eADR; the versioned-template law is already C1). **Verified-no-edit (logged):** [engine-architecture](../architecture.md) (precedent: `wbs/` maintainer-process docs are not master-indexed), the locked consumption docs ([provisioning](../spec/systems/infrastructure/provisioning.md), [module-system](../spec/systems/grammar/module-system.md), [control-plane](../spec/systems/infrastructure/control-plane.md), [external-contribution](../spec/systems/lifecycle/external-contribution.md)) — no contract changed, so **no re-lock, no litigation alarm; still 41 locked**. `python3 validate.py` green.

## Why

Cutting a release as a manual semver hand-edit + tag is exactly the error-prone hand-step a non-engineer maintainer cannot own; Q36's own framing flags it. The mechanical floor removes the blind guess for the part of semver that is a fact; the part that is a judgment (major = breaking) is named and discharged on AI-authored evidence + a behavioral correlate where one exists, never on the maintainer reading code ([§17](../principles.md)) — and the residual it cannot mechanize (a contract-silent break) is stated as posture ([§7](../principles.md)), not dressed as coverage. Production is maintainer-side, so it homes in `wbs/` like its process siblings and binds one-directionally to the locked consumers, touching no contract — a `designed`-tier, no-lock pass under lock discipline. It is decided before v1 ships (its own first invocation is the v1 cut) but is non-gating for the current build, which runs on the `0.0.0-dev` sentinel until M1.

## What we ruled out

**Home it inside locked [provisioning](../spec/systems/infrastructure/provisioning.md)/[control-plane](../spec/systems/infrastructure/control-plane.md)** (rejected — production is maintainer-side, consumption deployed-engine-side; folding muddies Q36's own split and would force re-litigating a locked doc for a process that changes none of its contracts). **A `scenarios/` walkthrough** (rejected — scenarios are deployed-world *operator* runtime flows; the release-cut is a maintainer-layer act with no operator actor, so the sequence folds into the doc inline). **A pure-auto bump rule, no human** (rejected — major = breaking is a semantic consumer judgment a diff cannot decide; [§17](../principles.md) names the human call rather than hiding it in a black box). **Keep the status quo (manual edit + tag)** (rejected — the very hand-edit Q36 exists to remove). **Force a breaking/additive verdict on flagged signals with no impact evidence** (rejected at audit — that is a code-reading judgment in a plain-language costume, the [§17](../principles.md) violation, not its cure; the AI-authored impact statement + behavioral demo is what makes it dischargeable). **A new eADR for the release law** (rejected — the versioned-template law is already canon **C1**; release *production* is maintainer-layer build/workspace-instrument tooling, the excluded class in the eADR canon manifest, and does not ship).
