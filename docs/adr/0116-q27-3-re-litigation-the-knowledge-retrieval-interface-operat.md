# Q27 #3 re-litigation: the knowledge-retrieval interface operation set + the consumer-composed memory link

*Decided 2026-05-29 in the design workspace.*

## The decision

Resolve [Q27](../reference/open-questions.md) **instance #3** — the unowned knowledge-retrieval interface operation set and the knowledge-MCP minimum tool roster — across the locked [interfaces](../spec/systems/surfaces/interfaces.md) and [knowledge](../spec/systems/cognitive/knowledge.md) docs (the third locked-doc step of the closure wave, [D-112](0112-author-the-core-lock-closure-procedure-the-q24-q27-remediati.md)). The complete final-state op-set (not a minimal floor) is pinned on the interface: `get-entity(id)` (an entity + its declared edges), `find(selector)` (entities matching a selector), `neighbors(id, edge-filter?, direction?, depth?)` (adjacency traversal), and `relate(id-a, id-b)` (the relationship/path between two entities) — the structural query surface the fallback floor and any richer swap-in alike satisfy. Per the **protocol/implementation split**: the **op-set is the interface protocol**; the **MCP minimum tool roster** is [core](../spec/modules/core.md)'s graph-query MCP floor (the named conforming fallback), noted in core's `wires: mcp`. The per-operation JSON Schemas stay build-spec leaves; the op-set (form) is pinned (the laws-not-leaves form/contract convention, [D-113](0113-core-lock-closure-phase-0-the-build-spec-leaf-form-contract.md)). The **read-time knowledge→memory link is composed by the consumer** (knowledge returns entity-ids; the consumer queries [memory](../spec/systems/cognitive/memory.md)'s read-time join — which memory owns, keyed on memory's entity-id tags) — **not** a knowledge-retrieval operation; knowledge persists no reverse edges and exposes no memory operation, keeping the two swap seams independent and the [D-008](0008-memory-and-knowledge-are-distinct-substrates.md) structure/belief wall intact. This is the litigation-alarm re-litigation of the locked interfaces + knowledge docs ([D-064](0064-lock-the-interfaces-surface-final-wave-2-lock-single-active.md)/[D-082](0082-re-litigate-knowledge-honesty-r8-hub-explosion-is-deferred-b.md)), operator-approved this session; both re-locked. **Q27 instance #3 closes; [Q27](../reference/open-questions.md) stays open** until #2 (scent threshold), #4 (telemetry record), and #5 (ambient-cache) close. **Propagation:** the interfaces "v1 interfaces" entry pins the op-set and its Build-spec-leaves section narrows to the per-op schemas; knowledge's "Read-time link to memory" commitment is clarified to the consumer-composed framing; core (`designed`, no alarm) notes its graph-query MCP floor realizes the op-set. No glossary / engine-architecture / risks edit is owed — the `Interface`/`Knowledge` glossary terms sit above op-set granularity, the architecture index is unaffected, and [R8](../reference/risks.md) is **not** narrowed (the op-set is a retrieval contract agnostic to representation, so the swappable-representation seam stays deferred).

## Why

[D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)'s genesis dry-run found the op-set deferred to build-spec while `core` must ship a *conforming* MCP floor — the form a builder cannot proceed without. The complete-final-state op-set (operator-directed: no minimal/MVP floor) covers what locked attention (structural adjacency → `neighbors`) and boot (structure → `get-entity`/`find`) consume, plus `relate` for the "how they relate" half, with no write/mutation op (regeneration is knowledge's commit-boundary mutation, not an interface op). A **focused cold re-audit** (two independent lenses) ran on both as-edited docs before re-lock: it confirmed no contradiction with the locked interfaces laws (protocol-not-payload, single-active resolution, named-fallback), that the op-set is satisfiable by both the committed-JSON floor (incl. `relate` via BFS at one-project scale) and a richer swap-in **without narrowing R8's representation seam**, and that the knowledge memory-link clarification agrees with memory's locked read-time-join (memory owns the join) and tightens rather than alters the D-008 wall. Two nits were folded: `find`'s selector dimensions softened to illustrative (so which selectors exist stays a per-op schema leaf), and the interfaces memory-link parenthetical aligned to memory's precise "read-time join keyed on entity-id tags" framing (the knowledge wording was already exact). `python3 lock.py --relock` on interfaces and knowledge against D-116; `python3 validate.py` green.

## What we ruled out

A **minimal floor** op-set ({lookup, neighbors}) deferring the rest (rejected — operator-directed complete-final-state; there is no v2, and under-speccing the op-set is the gap the dry-run surfaced). Put the **read-time memory link in the knowledge-retrieval contract** as an operation (rejected — couples the two swap seams and breaches the [D-008](0008-memory-and-knowledge-are-distinct-substrates.md) structure/belief wall; the consumer composes it, memory owns the join). Home the **MCP tool roster on the interface** rather than the core floor (rejected — the op-set is the protocol, the roster is the implementation; the interfaces doc names core's graph-query MCP server as the conforming fallback — the protocol/implementation split). Pin the **per-op JSON Schemas** now (rejected — build-spec *values*; the convention pins the form/contract and defers the values). Enumerate `find`'s selectors as **definitive** (rejected — the entity-attribute model is a build-spec leaf; the dimensions are illustrative). Amend [R8](../reference/risks.md) (rejected — the op-set does not constrain representation; the seam's deferral is unchanged). Delete [Q27](../reference/open-questions.md) (rejected — five-instance umbrella; only #3 closes here).
