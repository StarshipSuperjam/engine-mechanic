# Open Q37: a post-v1 optional "hackathon" divergent-exploration module on the multi-agent workflow substrate

*Decided 2026-06-05 in the design workspace.*

## The decision

Open **[Q37](../reference/open-questions.md)** as a post-v1 parking-lot thread and record the framing settled in dialogue. The Engine has no organ that *generates and triages candidate intents* (it executes a known intent via [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) and self-monitors via [telemetry](../spec/systems/guardrails/telemetry.md)/[audits](../spec/systems/guardrails/audits.md)); the parked capability is an **optional, leaf** module that uses Claude Code's multi-agent **workflow** substrate to run a product-aimed "hackathon": *diverge into many product-context-grounded ideas → vet each through an **independent** adversarial/feasibility/utility gauntlet (the cold-audit/[design-review](../spec/modules/design-review.md) lens pattern turned generative) → rank → elaborate the leaders into rough, product-tailored **starting specs** → optionally feed [product-design](../spec/modules/product-design.md) (features) or the product backlog (bugs)*. Depth is one operator dial set at the kickoff plan-gate (scope → depth → cost-and-time estimate → consent), from shallow (operator picks finalists) to deep (unattended [routine](../spec/systems/lifecycle/modes.md) run), with all consent settled up front. **This entry changes nothing in v1** — it adds only [Q37](../reference/open-questions.md) and this record; no system is designed, edited, or locked. Design is deferred to a post-v1 session.

## Why

Opening it now preserves the use-case and the hard-won framing + anti-choices below while v1 stays build-ready and untouched. It is post-v1 because it rides a research-preview substrate (Dynamic Workflows) and adds no v1 capability. It is **leaf-no-law** ([§12](../principles.md)): it reuses existing grammar (the [agents](../spec/systems/surfaces/agents.md)/[operations](../spec/systems/surfaces/operations.md)/[skills](../spec/systems/surfaces/skills.md) surfaces, the review-lens machinery, and the existing product-side output channels) and creates no dependency edge anything else relies on, so it needs no foundation work and earns no new law. Platform facts were ground-truthed against primary Anthropic documentation on 2026-06-05 (workflows research-preview status; the script-orchestrated, no-peer-to-peer execution model; the experimental Agent-Teams alternative).

## What we ruled out

**Take it up for v1 / design it now** (rejected — post-v1; rides a preview substrate; v1 is build-ready and mid-build). **Coded prototypes as the competitor artifact** (rejected — the Engine builds from detailed spec, not iteration; a prototype yields a half-signal that still needs a full spec — double work). **Pie-in-the-sky ungrounded ideas** (rejected — ideas have utility only when grounded in the real product, which also bounds the feasibility verdict honestly). **Deepest rung chains into spec→build / "wake up to a built product"** (rejected — the terminus is rough starting specs; building stays the separate detailed spec→build process, holding the no-build line). **A structural module / new foundation / new grammar, or making [product-design](../spec/modules/product-design.md) depend on it** (rejected — leaf-no-law; one optional module that *feeds* product-design one-directionally and reuses existing surfaces, the [github-projects-sync](../spec/modules/github-projects-sync.md) self-contained-optional precedent). **Build collaborative-team grammar now** (rejected — the platform's team machinery (Agent Teams) is experimental and cannot nest or scale to many teams; keep teams a design-restraint that does not preclude a future collaborative-*generation* realization, the gauntlet independent always — design-for-don't-depend, [R12](../reference/risks.md) one level deeper). **Route product findings to the engine [debt register](../reference/glossary.md)** (rejected — that is engine self-monitoring; product findings route product-side; the engine debt register applies only in the engine-mechanic reflexive case).
