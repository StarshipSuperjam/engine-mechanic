# Surface-set completion: re-lock ontology and hooks to clear the resolved surface-set question

*Decided 2026-05-25 in the design workspace.*

## The decision

Under **explicit operator approval**, re-litigate two locked docs so the v1 surface-set question can fully close. [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md) settled the surface set (the six remaining surfaces designed; the set is complete), but its parking-lot deletion of [Q5](../reference/open-questions.md) was blocked because two locked docs still reference the surface-set *question* as open. This entry is the follow-on reconciliation D-042 anticipated. **(1)** [Ontology](../spec/systems/grammar/ontology.md): remove its `## Open questions` section, whose only entry was the resolved Q5 surface-membership pointer; the additive-membership stance it carried survives intact in the doc's design-commitment line ("stays sized to the v1 surface set by locking laws… surfaces attach additively without a re-lock"), so no law is lost. **(2)** [Hooks](../spec/systems/infrastructure/hooks.md): resolve the `Boundary` section's deferral — "whether a hook script is its own surface is left to the v1 surface-set question" becomes "a hook script is a [tool](../spec/systems/surfaces/tools.md) instance," entailed by the D-042 boundary law (deterministic engine code → `tool`, whose home holds hook script code); no hook law (event inventory, block budget, fail-open) is touched. Both are re-locked under this decision (`lock.py --relock`). With the locked references cleared, **Q5 and Q6 are deleted** from [open-questions](../reference/open-questions.md) and **Q7 is narrowed** to the v1 skill *membership* only. The two durable "surface set" law statements that are *not* pointers to the question — [ontology](../spec/systems/grammar/ontology.md) design-commitment line and [repository-topology](../spec/systems/infrastructure/repository-topology.md)'s "the surface set is the ontology's concern," plus [audits](../spec/systems/guardrails/audits.md)' "the surface set generically" — were adjudicated and **stand** (they mean the catalog of surfaces, not the open question). The append-only decision-log entries that mention Q5/Q6 ([D-016](0016-repository-topology-as-a-foundational-substrate-product-owns.md), [D-019](0019-authoring-grammar-locked-end-state-as-laws-not-leaves.md), [D-030](0030-memory-ledger-canonical-observe-don-t-predict-capture-lexica.md)) are left untouched as history.

## Why

Closing Q5 cleanly required removing its pointer from the locked ontology's own open-questions section; the cold audit then surfaced a *second* locked doc — the hooks `Boundary` deferral — that the settled surface set had also answered, so leaving it would fix one stale locked reference while leaving an identical one, the inconsistency the operator declined. Bundling both under one decision is correct because they are one semantic event (surface-set completion) downstream of D-042; `lock.py --relock` runs per-doc, both citing D-043. The cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran in two passes — the ontology removal, then the combined hooks edit plus two-doc coherence — across the four lenses; its findings were resolved before this entry: the adversarial "surface set incomplete" reading was a conflation of the *surface set* (complete) with *interface-instance membership* (check-kind, a deferred leaf); the hooks wording was softened to tie to the boundary law rather than over-claim D-042's exact words; and the reference-reconciliation list was confirmed complete (no third locked doc references the resolved question). Technical-feasibility verified the double re-lock mechanics (one decision may ratify two `locks.yaml` entries; re-locking the already-once-re-locked hooks doc is idempotent; bodies must be final before `--relock`).

## What we ruled out

Leave the locked references stale after deleting Q5/Q6 (rejected — a stale pointer in a locked doc is the exact drift the lock mechanism exists to forbid; the operator chose the clean end-state). Re-lock the ontology only and leave hooks stale (rejected — fixes one identical stale reference but not the other; inconsistent). Defer all of it to a future consolidated re-lock pass, keeping Q5 open as a tracker (rejected — the operator chose to complete it now). Two separate decisions, one per doc (rejected — they are one surface-set-completion event; splitting fractures the rationale). Treat additive cataloguing as the re-lock trigger (rejected — additive surface cataloguing needs no re-lock per [D-042](0042-procedural-content-grounding-surface-cluster-designed-the-bo.md); the genuine body changes here are the removed open-question and the resolved deferral, which do).
