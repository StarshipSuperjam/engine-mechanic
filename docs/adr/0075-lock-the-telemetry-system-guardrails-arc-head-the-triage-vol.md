# Lock the `telemetry` system (guardrails arc head): the triage-volume bound is structural, not a cap

*Decided 2026-05-26 in the design workspace.*

## The decision

Lock [telemetry](../spec/systems/guardrails/telemetry.md), the most-upstream of the three remaining `designed` systems (all its substrates — [control-plane](../spec/systems/infrastructure/control-plane.md), [memory](../spec/systems/cognitive/memory.md), [hooks](../spec/systems/infrastructure/hooks.md), [policies](../spec/systems/surfaces/policies.md), [validation](../spec/systems/guardrails/validation.md), [state](../spec/systems/cognitive/state.md), [attention](../spec/systems/cognitive/attention.md) — are locked), unblocking the [audits](../spec/systems/guardrails/audits.md) lock next. The lock resolves telemetry's sole lock-pass open question (a governing **bound on triage volume** so autonomous issue promotion cannot flood the tracker) and **deletes** that `## Open questions` block. **The resolution: no numeric cap — the bound is structural.** (1) The dedup **stable key is derived from the signal's *source identity*** (rule-id / surface-id / stream-id), **never** from per-occurrence material (file / run / parameter); combined with telemetry's **Engine-only** scope (it watches the engine's own surfaces, never product files), every recurrence collapses onto one issue and open low-severity volume is bounded above by the engine's own finite signal-source inventory — finite at any instant, growing only as the engine gains rules, not scaling with product size or recurrence. (2) A **`triage-pressure` stream** (count of open low-severity engine issues, threshold in the governed promotion policy instance) makes standing volume visible but is **render-only — crossing its threshold renders one plain-language boot line and promotes *nothing***, so the meter cannot feed the volume it measures. (3) Every engine-labeled issue telemetry opens carries a **plain-language operator contract** (self-identifies as the engine's own self-monitoring, not a product problem; backstage vocabulary never reaches the operator; the one-time "what engine-labeled issues are" teaching defers to [provisioning](../spec/systems/infrastructure/provisioning.md)'s first-run). The *Native and degradable* commitment is strengthened so the GitHub-outage boot line names the debt count *and* states detail is temporarily unreachable in plain language. `python3 lock.py systems/guardrails/telemetry/README.md --decision D-075`; ratified_by D-075.

## Why

A four-lens cold-session design audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran on the proposed design — adversarial, technical-feasibility, non-engineer-operator, architect — plus a targeted adversarial re-check of the revised resolution. A pre-lock seam-check first confirmed all eight of telemetry's cross-references to locked neighbors (including the [D-073](0073-lock-build-orchestration-wave-3-terminal-and-re-litigate-con.md) control-plane Review section) are consistent. The audit reshaped the resolution materially, not cosmetically: an earlier draft framed the bound as "observe + surface + adjudicate" with a `triage-pressure` *stream* and an **audits-retirement backstop** — the adversarial lens caught two **blocking** flaws (it dressed mere *observation* as a *bound* while issues still accumulated; and "audits will retire stale issues" is hand-waving, since audits fire on a missable cron and random-pick one artifact per run, [audits](../spec/systems/guardrails/audits.md) being explicit that a missed cron is expected degradation). The architect lens independently flagged the same audits-handoff as an undefined dependency that would also force editing the still-`designed` audits doc telemetry would then lock atop (a lock-discipline violation). The fixes: reframe to a **structural** bound and **drop the audits backstop as a named mechanism**. A second adversarial re-check then found the load-bearing **blocking** gap — the structural bound holds *only if* the dedup key is source-keyed, not per-occurrence — which the doc now pins explicitly (the Engine-only scope makes the source set the engine's own fixed inventory). The non-engineer-operator lens contributed the **blocking** operator-comprehension requirement (engine-opened issues must self-explain in plain language) and the degradability strengthening; the self-reference (a stream about issues that could itself promote to an issue) was closed by making `triage-pressure` render-only. Technical-feasibility cleared all of telemetry's own platform claims (gh merged-PR check reads, PostToolUse `tool_response.exit_code`, no-matcher `Stop` hook, gh issue CRUD) and surfaced one **serious** item — GitHub's 60-day scheduled-workflow auto-disable is documented for *public* repos and keys off `git push` — which concerns audit/control-plane cron cadence, **not** telemetry, and is **logged here for the audits lock pass**. Propagation per the matrix: telemetry (locked end-state), this entry; [glossary](../reference/glossary.md) gains *triage-pressure stream*; [risks.md](../reference/risks.md) R4 (the triage-pressure threshold is another in-policy, not in-code, threshold) and R3 (re-checked: no self-healing introduced). [engine-architecture.md](../architecture.md) verified still a truthful index (role line "health, surfaced for remediation" unchanged); [modules/README.md](../reference/module-catalog.md) + the `core` stub need no change (telemetry is a foundation, no module add/remove; the triage-pressure stream is foundation-shipped, no manifest line); no scenarios/ renders the debt register at boot in a way that must name the new line; [open-questions.md](../reference/open-questions.md) untouched (telemetry's question lived only in its own doc); [state](../spec/systems/cognitive/state.md) untouched (the triage-pressure count is a derived stream value, not a new committed pointer).

## What we ruled out

A **hard cap that drops or coalesces** low-severity signal once a limit is hit (rejected — it forces telemetry to decide *which* signals matter, a judgment that is audits' job, or to alter standing state autonomously toward self-healing, against telemetry's mechanical-only and report-never-heal commitments [D-009](0009-telemetry-is-a-remediation-loop-not-self-healing.md)/[§8](../principles.md); and it is unnecessary once the bound is shown to be structural). A **named "audits retire stale issues" backstop mechanism** (rejected — audits' missable cron and single-random-pick make it no real bound; a persistent benign signal keeping one issue open is *correct*, auto-resolve closes it when the signal goes absent, and retiring a now-irrelevant signal *source* is ordinary audits/Build work, not a telemetry mechanism). A **per-occurrence dedup key** (rejected — it would let one rule firing across N product files spawn N issues, scaling volume with product size and destroying the structural bound; source-identity keying is both correct for an Engine-only monitor and what makes the bound hold). **Editing the `designed` audits doc** to define the handoff (rejected — telemetry must not lock atop a churning neighbor; audits' existing general adversarial sweep already covers stale surfaces when audits locks). **Defer the telemetry lock** (rejected — it is the upstream-anchored head of the guardrails arc; deferring blocks the audits lock for no benefit).
