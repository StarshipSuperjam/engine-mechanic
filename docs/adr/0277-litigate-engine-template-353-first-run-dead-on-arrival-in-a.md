# Litigate engine-template #353: first-run dead-on-arrival in a deployed copy; restore the provisioned verdict to instantiator-presence (manifest demoted to checkpoint-conjunct), add a standing boot first-run onboarding surfacing, home the construction-repo suppression at L2 — re-litigate locked [provisioning](../spec/systems/infrastructure/provisioning.md) + [boot](../spec/systems/lifecycle/boot.md); coupled re-lock lands under D-278

*Decided 2026-06-30 in the design workspace.*

## The decision

A build session in engine-template hit a first-run defect, opened it as engine-authored [engine-template #353](https://github.com/StarshipSuperjam/engine-template/issues/353), and correctly routed it here because the fix "changes eADR-0023's grammar, so it must be litigated in engine-planning, not edited silently." **The symptom:** a repo created via "Use this template" is dead-on-arrival for setup — `/engine-setup` reports *"already set up… Nothing to do here"* and stops, leaving the repo un-provisioned but convinced it is finished (reproduced live on `StarshipSuperjam/engine-test`). **The diagnosis (the load-bearing reframe): the build diverged from canon — the issue misattributes the defect to canon, but the locked grammar already names the better signal.** `instantiator.is_provisioned()` keys the verdict on `.engine/engine.json` presence (instantiator.py:308), which "Use this template" copies into every generated repo. But the locked [provisioning](../spec/systems/infrastructure/provisioning.md) doc says the **opposite** signal — *"the instantiator's own **presence** is the signal that the repo is **unprovisioned**"* (:70; [glossary](../reference/glossary.md) *Gather/confirm/apply*; [scenarios/first-run.md](../architecture.md#first-run-provisioning)) — and the manifest's role is the **apply-resume checkpoint + upgrade source-of-truth** ([D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)), never the verdict. The eADR-canon recommendation S8 scopes the "single manifest grammar" to **module wiring (provides/requires)** and never pins the provisioned verdict on the manifest. So the build's eADR-0023 **conflated the apply-resume checkpoint with the provisioned verdict**; the canon's own signal (instantiator-presence) already classifies a fresh copy correctly. **This entry is the litigation alarm + operator authorization** (given in-session over a four-lens plan-stage cold audit) **and the design of record**; the **coupled re-lock of [provisioning](../spec/systems/infrastructure/provisioning.md) + [boot](../spec/systems/lifecycle/boot.md) lands under [D-278](0278-resolve-re-lock-provisioning-boot-provisioned-verdict-on-ins.md)** after the mandatory landed-text cold audit — the carriers **edited-but-not-relocked** until D-278 (the [D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md) authorize→resolve pattern; `validate.py` flags their lock fingerprints until the relock).

  **The ruling (operator-authorized — RESHAPED by the four-lens plan audit from the issue's "rekey on a new completion marker" framing and from this session's own first draft):**

  **(1) Restore the verdict in provisioning, three-state — manifest a conjunct, not the sole signal.** **instantiator present → unprovisioned** (offer setup — a fresh copy or an interrupted run; instantiator-presence **dominates**, so #353 is fixed); **instantiator absent AND manifest present → provisioned** (the clean post-retire repo); **instantiator absent AND no manifest → a broken/partial checkout** (botched copy, manual deletion) routed to the [operator-checkout strand detector](../spec/systems/infrastructure/provisioning.md)'s missing-engine-files arm, never silently read as done. The manifest stays the apply-resume checkpoint + upgrade source-of-truth + the **done-vs-broken disambiguator** — **not** the provisioned verdict on its own. Feasibility-confirmed: `is_provisioned()` lives **only** in the self-deleting instantiator and **no surviving module reads it**, so "absence = provisioned" is self-consistent; retire genuinely self-deletes the file.

  **(2) A standing boot first-run onboarding surfacing — a genuinely new (sixth) deferred surfacing.** Boot senses unprovisioned-and-fresh-copy (instantiator present, **not** the construction repo) and surfaces it **read-only**, **never gates** (surface+offer, the protected-branch precedent). It is **standing** — it persists every session until setup actually runs, routed through the [D-269](0269-litigate-q18-engine-template-313-resolve-cross-session-anti.md) collapse-when-unchanged presentation ledger — so a deferred "later" never silently reopens the false-confidence trap one layer up, and the recurrence never becomes nagging. The doc **pins the operator law** (not a bare build-spec-leaf placeholder, matching every other surfacing): framed as the operator's **own new project** (never an engine "copy"), names what setup does in one plain clause, an always-declinable offer, **self-correcting on ambiguity** ("if this is actually an existing project, just tell me and I'll stand down"), non-condescending register. Ranked below the governance-critical alarms beside the tool-runtime/checkout surfacings (an unprovisioned fresh copy cannot reach a protected branch — there is not one yet).

  **(3) Home the construction-repo suppression at L2 — drop the deployed identity machinery.** The construction/self-hosting repo carries the instantiator **machinery** (it ships it to generated repos) yet must not offer *itself* setup. This suppression is a **maintainer-layer degeneracy consequence** (stage-0 §6, the engine==product degeneracy home — freely revisable, no lock, retires at v1), recognized by the **existing construction sentinel** (root `CLAUDE.md` "construction governance"), **not** by an origin-slug/`templateRepository` identity check in the locked deployed doc (which would violate the [D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md) layer boundary and rests on a signal that is online-only, nullable, and fork/brownfield-absent). **Sequencing gate:** because a fresh copy carries the construction `CLAUDE.md` **byte-identical** to the workshop *until* first-run `apply` swaps in the deployed floor, the sentinel separates them cleanly only once the traveling construction residue (the committed manifest + construction `CLAUDE.md`) no longer rides a template copy — so **boot's onboarding surfacing ships gated behind that cleanup ([engine-template #323](https://github.com/StarshipSuperjam/engine-template/issues/323))**, mirroring the [D-213](0213-authorize-the-human-facing-front-door-re-litigation-the-root.md)/[D-214](0214-resolve-the-d-213-front-door-re-litigation-landed-text-cold.md) sequencing-gate precedent (R26) and matching the issue's own "post-v1, sibling of #323" schedule.

## Why

an engine that tells a brand-new operator their un-provisioned repo is "already set up" fails the very trust the burden-of-proof posture demands. The honest, minimal fix is **not** to rekey the verdict on a new completion marker (any *committed* marker travels via "Use this template" — the same disease; only instantiator-retirement and repo-identity do not travel) but to **realize the verdict signal the locked doc already names** — instantiator-presence — and close the conflation the build tripped on, refined three-state so absence is not silently trusted either. The construction-repo concern is the engine==product degeneracy stage-0 §6 / [D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md) already own at L2; homing an identity check in the locked deployed doc would import maintainer-layer vocabulary into a deployed-world law, and the #323 sequencing gate dissolves the need for fragile identity machinery entirely. The capability is provisioning's (it owns the instantiator + the standing-detector mechanism); boot relays and the sixth surfacing is a genuinely new lifecycle condition. The authorize→resolve-after-landed-text-audit split keeps the irreversible coupled re-lock behind its own clean gate ([D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md)).

## What we ruled out

**Rekey "provisioned" on a new positive completion marker / deployed-floor gating (the issue's framing)** (rejected — any committed marker travels via "Use this template," reintroducing the disease; a non-committed/identity-based marker just converges on instantiator-presence). **Build-owe only, no locked-doc edit (the [D-268](0268-adjudicate-engine-template-250-the-15-weakening-guard-s-guar.md) shape)** (rejected — the verdict conflation could be a pure conformance fix, but the three-state refinement, the standing boot onboarding surfacing, and the construction suppression are **unwritten in canon**; without homing them a cold builder repeats the error — the [D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md) reasoning). **An identity-based construction carve-out in the locked deployed provisioning doc + `templateRepository`/origin-slug provenance (this session's own first draft)** (rejected on convergent adversarial+architect+feasibility findings — violates [D-111](0111-resolve-q22-q23-the-construction-repo-carries-no-codeowners.md), and the signal is online-only/nullable/fork-absent; the L2 sentinel + #323 sequencing gate replace it with no fragile platform dependency). **A two-state verdict keyed on instantiator-absence alone** (rejected — absence is as spoofable as presence; a manually-deleted instantiator that never completed setup would read provisioned-and-done, the same dead-on-arrival class from the opposite cause; the three-state verdict routes it to the strand detector). **Fold first-run into an existing boot surfacing to keep "Five"** (rejected — first-run-needed is a distinct lifecycle condition, not a drifted/missing-files strand; forcing it into the strand bullet is the semantic shortcut the standing-oversight concern warns against). **Edit S8 to adjudicate verdict-vs-checkpoint** (rejected — S8 is the PROPOSED recommendation engine-template adjudicates; it is silent-not-wrong, and pre-resolving the distinction here does engine-template's adjudication for it, breaching the [D-272](0272-finalize-the-foundational-eadr-canon-membership-33-laws-and.md) boundary). **Mint a new glossary term or risk entry** (rejected — [R6](../reference/risks.md)/[D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) anti-sprawl; the existing terms + R20 carry it). **Write the [D-278](0278-resolve-re-lock-provisioning-boot-provisioned-verdict-on-ins.md) resolve entry now** (rejected — it records a landed-text cold audit that runs later; authoring it pre-audit would dress un-audited as audited, the [§7](../principles.md) violation this pattern prevents).
