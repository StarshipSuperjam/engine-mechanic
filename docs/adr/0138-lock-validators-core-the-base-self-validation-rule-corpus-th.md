# Lock `validators-core` (the base self-validation rule corpus): the second module lock

*Decided 2026-05-30 in the design workspace.*

## The decision

Ratify and **lock** [validators-core](../spec/modules/validators-core.md) (`status: designed → locked`) — the `required` module shipping the engine's base self-validation rule corpus (the concrete `check` data files that exercise [core](../spec/modules/core.md)'s validation engine against the engine's own surfaces), the **second module lock** after `core` ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)) and the first of the module packaging-lock passes. **Both module-lock gates are met.** The **build-readiness precondition** — a clean dry-run build over its build step — was met at the L2 run (dry-run-ledger: "validators-core — BUILD-READY, no blockers, no contradictions, no litigation alarms"), and its lone carry-forward nit (the stale Status section) was already cleared by [D-137](0137-clear-the-residual-dry-run-designed-doc-precision-nits-and-r.md). The **HARD cold-session design audit** (the CLAUDE.md gate) then ran four independent cold-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) against the finalized doc with **no blocking and no serious finding** — all four returned ratify. The lenses confirmed the two load-bearing seams: the [§16](../principles.md) fingerprint-coverage **detection relay** (knowledge owns the fingerprint *detection*; validators-core owns only the relaying `coverage`-kind rule — matching the locked [knowledge](../spec/systems/cognitive/knowledge.md) doc's own "a fingerprint coverage check — a check rule" phrasing) and the `depends` ≠ `wires` **orthogonality** (the inbound `audit-library`→`validators-core` edge is a presence assertion per [module-system](../spec/systems/grammar/module-system.md), imposing no wiring, so `wires: none` stands). The technical lens ground-truthed "active by presence" (the pattern this workspace's own `validate.py` already runs), the required-CI-check binding (no over-assumption of the default `GITHUB_TOKEN`), and the fingerprint backstop against the live engines + current Claude Code/GitHub docs; the operator lens confirmed the honest trust story (data not code → a plain-language `finding.v1`, never a traceback; install/uninstall never a hand-edit; no maintainer-vocabulary leak to an operator surface; the [R3](../reference/risks.md) over-promise stays clear); the architect lens confirmed scope ([R6](../reference/risks.md)) and floor-only propagation. **Nit dispositions (none blocking, none touching a locked doc):** (1) the fingerprint rule's `kind: coverage` reading more settled than the build-spec leaf warrants — **rejected** (already adjudicated at [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md); the concrete kind/params are a declared build-spec leaf contradicting no locked semantic, and the `coverage` label is grounded in the locked knowledge doc's own wording; re-deciding it is out-of-scope design churn); (2) the dense single-row `provides` cell (flagged by three lenses) — **left** (accurate, unpacked by the prose section below, and the single-row manifest-table is a cross-module convention matching `core` + every sibling; restructuring one cell breaks format symmetry for marginal gain); (3) `migrations: none (v1)` vs. the [check](../spec/systems/surfaces/check.md) `artifact` lifecycle — **value correct** (v1 ships no rule retirements, so the seam is genuinely empty); (4) the locked [hooks](../spec/systems/infrastructure/hooks.md) doc's `Stop`-block cap (=8) + env-var name being absent from public Claude Code docs — **out of scope for this lock** (validators-core relies only on "`Stop` *can* loop the model back," which is confirmed; the cap specifics belong to the hooks doc and are flagged separately for live-binary verification, not folded here). **Propagation (floor only, architect-confirmed):** the module doc's `status` (via `lock.py`) + the locks.yaml entry (ratified_by D-138) + this entry. **No edit owed** to [modules/README.md](../reference/module-catalog.md) (design-maturity not catalog-tracked, [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md); the catalog row and the `core`→validators-core / validators-core→audit-library graph edges are unchanged), [engine-architecture.md](../architecture.md) (indexes systems, not module lock-state), [glossary.md](../reference/glossary.md) (no term coined/renamed), [risks.md](../reference/risks.md) (the [R5](../reference/risks.md) containment story is unchanged), wbs/ (the L2 placement and the frozen ledger are unchanged), or the CLAUDE.md document map. **No locked-doc edit, no litigation alarm** — the lock *consumes* the locked validation/check/module-system/knowledge/core laws and changes none. `python3 lock.py modules/validators-core/README.md --decision D-138`; `python3 validate.py` green.

## Why

`validators-core` is the natural next lock after `core` — it is `required` spine, depends only on the now-locked `core` (upstream-anchored, so it sits atop no churning neighbor; its sole `designed` dependent `audit-library` adapts to it, the lock discipline governing dependencies not dependents), and its build-readiness precondition was met at the L2 dry-run. Both module-lock gates — buildability (the dry-run) and soundness (the cold-session audit) — are therefore satisfied, and the audit surfaced no blocking/serious finding, so ratification is warranted. The dry-run is the buildability *precondition*; it does not replace the cold audit, which every packaging lock owes in its own right ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)/[D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) precedent). The four nits are dispositioned in the decision (reject / leave / value-correct / out-of-scope), none requiring a doc edit and none touching a locked doc.

## What we ruled out

**Lock on the dry-run's BUILD-READY alone, skipping the cold-session audit** (rejected — the dry-run is the buildability precondition, not a substitute; every packaging lock owes its own fresh four-lens cold audit + operator go, the [D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)/[D-121](0121-lock-the-external-contribution-system-doc-reconcile-the-stal.md) precedent reinforced throughout the ledger; skipping ranks with a silent edit to a locked doc). **Change the fingerprint rule's `kind` from `coverage` to `presence`/`custom`** (rejected — adjudicated at [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md); the kind is a declared build-spec leaf, the `coverage` label is grounded in the locked knowledge doc's phrasing, and re-deciding it now is out-of-scope design churn against [R6](../reference/risks.md)). **Restructure the `provides` cell into a sub-list before locking** (rejected — the operator chose lock-as-is; the cell is accurate, the single-row manifest-table format is shared with `core` + every sibling, and the prose section already unpacks the corpus, so breaking symmetry for one cell is not worth it). **Fold the hooks `Stop`-cap verification into this entry** (rejected — it concerns the locked [hooks](../spec/systems/infrastructure/hooks.md) doc, not validators-core, which needs only that `Stop` *can* loop the model back; burying a locked-doc platform-fact concern inside a module lock would hide it, so it is flagged for separate live-binary verification). **Edit [modules/README.md](../reference/module-catalog.md)/[engine-architecture.md](../architecture.md)/glossary/risks to mark the lock** (rejected — no propagation owed: design-maturity is not catalog-tracked [D-090](0090-flesh-the-validators-core-module-doc-to-designed-the-engine.md), the lock coins no term, opens/closes no risk, and moves no WBS node — all confirmed by the architect lens).
