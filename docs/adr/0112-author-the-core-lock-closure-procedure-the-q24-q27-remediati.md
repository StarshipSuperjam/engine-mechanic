# Author the core-lock closure procedure (the Q24–Q27 remediation roadmap)

*Decided 2026-05-29 in the design workspace.*

## The decision

Author wbs/core-lock-closure.md, a maintainer-layer, freely-revisable **procedure** for closing the three `core`-lock blockers plus the systemic meta-pattern the genesis dry-run surfaced ([Q24](../reference/open-questions.md)–[Q27](../reference/open-questions.md), [D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)), so [core](../spec/modules/core.md) can take its first lock. The procedure: (1) a **coupling map** — each blocker → the locked doc(s) it edits → the decision it forces; (2) **Phase 0**, decide two cross-cuts first because they fix the content of multiple per-doc edits — the Q27 **meta-convention** (a build-spec leaf may defer values but must pin/home the form/contract those values inhabit) and the **finding/result shape** (adopt the already-locked agent `output-contract` `{severity,message,location}` as the canonical base, resolving the check-kind-result and telemetry-finding-record instances together and leaving [agents](../spec/systems/surfaces/agents.md) untouched); (3) **Phase 1**, re-litigate each affected locked doc **once**, batching all its items, in dependency order (policies → check+validation → interfaces+knowledge → skills → attention → telemetry → hooks → boot), with the homings that minimize alarms (the scent strong-match threshold → [attention](../spec/systems/cognitive/attention.md)'s policy, sparing a separate [boot](../spec/systems/lifecycle/boot.md) alarm; the `/engine-help` discovery contract likely a `core` build-spec leaf, sparing a [skills](../spec/systems/surfaces/skills.md) alarm); (4) **Phase 2**, update the `designed` [core](../spec/modules/core.md) to ship the pinned bodies and lock it **last** under the full cold-session audit; plus the per-step litigation-alarm gating, an audit strategy (focused-per-relock + full-for-core, or one compressed wave audit), and resumability markers. **The closure decisions themselves are deliberately not made here** — the operator chooses their content in the sessions that follow, and nothing is executed until the litigation-alarm gate runs per blocker.

## Why

The operator scoped this session to *defining the procedure*, reserving the actual closures for the next session — so this records the scoped deliverable, not a punt (the full analyzable work — coupling, cross-cuts, sequence, homings, gating — is done now; only the operator's content choices and the mechanical edit/audit/relock remain). The blockers are coupled: closing them piecemeal (one open-question and one isolated re-lock at a time) would redundantly re-audit and re-churn shared docs and risk one fix contradicting an already-relocked one (the finding-shape and scent-threshold cases cross doc boundaries), so the value is sequencing them as one coherent wave — cross-cuts first, batch-by-locked-doc, dependency order, `core` last. It touches **no locked doc** and makes **no closure decision**; it is a roadmap for litigation-alarm-gated work the operator authorizes per step. Placed under `wbs/` (outside the validator's frontmatter/coverage gates, freely revisable, the dry-run.md home) rather than a top-level doc, so no resume-order/document-map churn. It is **transient** — deleted when the blockers close (the deletion mandate). Propagation: wbs/core-lock-closure.md authored; wbs/README.md pointer (the remediation roadmap for the dry-run's findings); this entry. No locked doc, no glossary term, no [engine-architecture.md](../architecture.md) edit. `validate.py` green.

## What we ruled out

Close Q24–Q27 in this session (rejected — the operator reserved the closure content for the next session; the procedure is this session's scoped deliverable). Re-litigate each blocker's doc piecemeal as separate one-off events (rejected — redundant cold audits and repeated churn on shared docs, and a later cross-doc fix could contradict an already-relocked one; batch-by-doc with cross-cuts-first is the coherent, efficient shape). Decide the per-instance Q27 fixes before the meta-convention and finding-shape cross-cuts (rejected — the cross-cuts fix the content of multiple edits; deciding them after a relock forces re-opening it). Home the scent threshold in boot and the `/engine-help` contract in skills by default (rejected as the default — homing the threshold in attention's policy and the discovery contract in `core`'s build-spec spares two locked-doc alarms where honest; surfaced as determinations, not forced — and never weaken a design to dodge an alarm). Keep the procedure only in chat / as ephemeral notes (rejected — the operator acts on it next session, so it must be durable; no-silent-changes and finding-disposition both point to a committed artifact). Log nothing for it (rejected — authoring a maintainer-layer build-readiness artifact is a workspace-process change, the [D-108](0108-add-the-dry-run-build-simulation-instrument-the-workspace-s.md)/[D-037](0037-graveyard-exemption-the-append-only-decision-log-may-link-re.md) precedent). Lock `core` before the wave (rejected — that is exactly what the dry-run showed bakes in the unpinned forms; `core` locks last, [D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)).
