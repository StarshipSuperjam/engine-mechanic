# Resolve the D-209 ledger-compaction re-litigation: landed-text cold audit, four docs re-locked

*Decided 2026-06-17 in the design workspace.*

## The decision

The [D-209](0209-authorize-the-ledger-compaction-re-litigation-bound-the-appe.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with **five** independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect · **data-durability/storage**, the 5th added because the change rewrites the one canonical store) on the as-written edits in [memory](../spec/systems/cognitive/memory.md), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md), [boot](../spec/systems/lifecycle/boot.md), [audits](../spec/systems/guardrails/audits.md) plus the carriers. **Outcome: non-engineer-operator and architect PASS clean; technical-feasibility no blocking (two build-realization seriouses → build-owes); adversarial one blocking + one serious folded; data-durability two blocking + three serious folded.** Re-lock set: **4**.

  **The audit + dispositions.**
  - **Non-engineer-operator — PASS (no blocking/serious).** The four trust-critical properties hold in the as-written text: the Engine cannot autonomously shrink memory (the irreversible act sits on the operator's merge); boot no longer over-promises an undo on a permanent deletion; consent is single-purpose-PR + concrete-cost + keep-it (never laundered through bundled work); declining/never-adjudicating loses nothing. Two nits folded/noted — the "declining loses nothing, only disk reclaim deferred" line was added to memory's Trigger; the "open findings is where erasure proposals live" onboarding point is an operator-copy build-spec leaf. No jargon leak into any mandated operator-facing string.
  - **Architect — PASS (no blocking/serious); §16 coherent, propagation complete, re-lock set = 4 confirmed.** Memory owns mechanism+detection, [audits](../spec/systems/guardrails/audits.md) recommends-never-enacts (read-only persona), the merge is the gate, [boot](../spec/systems/lifecycle/boot.md) renders only the reversible readout — stated consistently across docs. [Telemetry](../spec/systems/guardrails/telemetry.md) genuinely untouched (the backlog stream was dropped). [Provisioning](../spec/systems/infrastructure/provisioning.md) verify-no-edit confirmed load-bearing (the ledger-generation stamp is memory extending its **own** manifest; the restore-contract shape is unchanged). The memory-substrate `provides` edit is necessary (compaction + the cross-session erasure observer are new shipped machinery, not subsumed). Two nits in the unlocked dry-run-ledger (manifest field-list + stale M5 undo citation) folded.
  - **Technical-feasibility — PASS (no blocking).** Every platform fact re-verified: atomic-rename + directory-fsync durability, generation-stamped full rebuild (anti-resurrection), merged-not-closed `gh` detection + merge-keyed idempotent marker + content-free record id, single-writer-lock + in-flight-marker ordering, frecency-as-recurrence, the public-repo 60-day cron auto-disable + "strands erasure only." **Two seriouses, both inside existing build-spec leaves → build-owes:** on Darwin the durability primitive is `F_FULLFSYNC`/`F_BARRIERFSYNC`, not bare `fsync` (folded as a named leaf in memory's crash-safe-swap law); and FTS5 `rebuild` is unavailable on a contentless table, so the ledger-fed rebuild must use an external-content/shadow table or drop-and-reinsert (the law "rebuilt from the ledger" is correct; the build must not ship a no-op `rebuild`).
  - **Adversarial — one blocking + one serious folded.** **Blocking (folded):** the "Active forgetting" step (3) enumerated the evidence classes (superseded/duplicate/contradicted/operator-directed/consolidated-raw) as *direct* erasure triggers — omitting the merge gate and the `operator-adjudicated erasure` class — contradicting the Compaction law below and re-opening autonomous erasure; reworded so evidence **flags/logically-retires** (reversible) and **physical erasure is never enacted by evidence alone, only via the merge-gated Layer-2 path.** **Serious (folded into this entry):** [D-209](0209-authorize-the-ledger-compaction-re-litigation-bound-the-appe.md)'s parenthetical "(validation enforces the bright Layer-1/Layer-2 boundary)" overclaimed a mechanism ([§7](../principles.md) — a "no code path reaches erasure" property is a build-conformance/test concern, not a check-kind); the landed docs correctly say **"build-conformance invariant"** ([memory](../spec/systems/cognitive/memory.md), wbs/memory-build-plan), and this entry supersedes the D-209 phrasing (the decision log is append-only, so the correction lands here, not as a D-209 edit). Other consistency checks passed (operator-adjudicated-erasure identical across docs; "archived = index-exclusion state" everywhere; boot drops the undo-on-deleted claim; no "closed" trigger anywhere).
  - **Data-durability — two blocking + three serious folded.** **Blocking 1 (folded):** the lock covered only the *swap*, not the *fold-read*, so a live append between fold and rename could be silently clobbered — the law now states compaction holds the single-writer lock across its **entire fold-and-swap critical section** (tail-replay a leaf that preserves the no-lost-append guarantee), which also closes the two-concurrent-compactions race. **Blocking 2 (folded):** the module's manifest field *tuple* omitted `ledger-generation` (in the contract-owning doc), defeating the resurrection guard — added to match the system doc. **Serious (folded):** recovery must bind to the **fixed canonical ledger name, never file recency** (orphaned-temp reaping); the frecency function **must be a recurrence on the carried snapshot** (a windowed/population-relative score is now explicitly out of bounds); the ledger-generation comparison is **independent of provisioning's engine-code-version check** (a same-version backup can still be an older generation). One nit logged-accepted (duplicate erasure markers for one merge identity are harmless — folded + idempotent-by-id).

  **Folds applied before re-lock:** [memory](../spec/systems/cognitive/memory.md) (step-3 reword; whole-critical-section lock + fixed-canonical-name reaping + Darwin-primitive leaf; frecency-recurrence constraint; generation-independence; declining-loses-nothing), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md) (manifest tuple gains `ledger-generation`), wbs/dry-run-ledger (manifest field-list + M5 undo citation). [boot](../spec/systems/lifecycle/boot.md) and [audits](../spec/systems/guardrails/audits.md) needed no post-audit fold (passed clean).

  **Re-lock set (4):** [memory](../spec/systems/cognitive/memory.md), [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md), [boot](../spec/systems/lifecycle/boot.md), [audits](../spec/systems/guardrails/audits.md). **Re-lock:** `python3 lock.py --relock` run on all four under this decision; `python3 validate.py` green. **Carriers edited (non-locked):** [glossary](../reference/glossary.md) (*Ledger compaction*, *operator-adjudicated erasure*; *Memory ledger* / *Frecency* reconciled), [risks](../reference/risks.md) [R24](../reference/risks.md), wbs/memory-build-plan (step 4), wbs/dry-run-ledger (two nits). **Verify-no-edit (logged):** [telemetry](../spec/systems/guardrails/telemetry.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [modules/README](../reference/module-catalog.md), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning), [scenarios/upgrade-the-engine](../architecture.md#upgrading-the-engine), [open-questions](../reference/open-questions.md). **No [open-questions.md](../reference/open-questions.md) opened/resolved; no [deviations](../reference/prototype-deviations.md) entry.** Still **42 docs locked** (4 re-locked, none added).

  **Build-owes (engine-template, downstream — not authored here):** on Darwin use `F_FULLFSYNC`/`F_BARRIERFSYNC` (not bare `fsync`) for the temp durability step; the FTS5 rebuild must read from a ledger-fed external-content/shadow table or drop-and-reinsert (not a bare `rebuild` on a contentless table); the erasure-enactment observer needs an explicit `gh` discovery query (by label/search) and must test `mergedAt != null` (merged, not merely closed); the concrete temp-naming/reaping, the generation-stamp + stable-record-id representations, and the trigger/observer cadence remain build-spec leaves; the operator-copy for the erasure-proposal Issue/PR (concrete-cost + keep-it, plus "declining is safe; only disk reclaim is deferred") is an operator-communication build-spec leaf.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious resolved before re-lock; it ran (five lenses), operator and architect passed clean, feasibility found no blocking (two build-realizations carried to build-owes), and the adversarial + durability blockers (the step-3 autonomous-erasure contradiction, the fold-read lock gap, the omitted manifest field) were folded before the re-locks. The landed text is faithful to [D-209](0209-authorize-the-ledger-compaction-re-litigation-bound-the-appe.md): append-only governs live writes while compaction (a self-directed restore-primitive rebuild-and-swap) bounds growth and realizes hard-delete; physical erasure is reachable only through the audit-adjudicated, single-purpose-PR-merge gate; the one canonical store stays crash-atomic and a resurrecting restore is surfaced; provisioning's restore contract is unwidened.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Edit [D-209](0209-authorize-the-ledger-compaction-re-litigation-bound-the-appe.md) to fix the "validation enforces" overclaim** (rejected — the decision log is append-only; the correction is recorded here and the landed docs already say "build-conformance invariant"). **Leave step (3) enumerating evidence as direct erasure triggers** (rejected — an as-written contradiction with the Compaction law that re-opens autonomous erasure; authoring-rule-1 / [§7](../principles.md)). **Treat fold-read concurrency as a build-spec leaf** (rejected — the lost-append window is a durability hole; the whole-critical-section lock is the law, tail-replay the leaf). **Ship the module manifest tuple without `ledger-generation`** (rejected — defeats the resurrection guard the law depends on). **Carry the Darwin-fsync / FTS5-rebuild facts only in this log** (rejected — they are build realizations, so they belong in the build-owes the fixing session reads).
