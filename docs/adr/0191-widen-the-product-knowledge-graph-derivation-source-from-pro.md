# Widen the product-knowledge-graph derivation source from product code to any committed canonical structural artifact

*Decided 2026-06-14 in the design workspace.*

## The decision

Re-scope the post-v1 [product-knowledge-graph](../spec/modules/product-knowledge-graph.md) stub (`status: stub`, name kept) by **generalizing what its derived graph derives *from*** — from "product code" ([D-105](0105-hold-a-post-v1-product-knowledge-graph-module-stub-product-s.md)) to **any committed canonical structural artifact the project has**: product code where it exists, and the product's authored structural model (e.g. [product-design](../spec/modules/product-design.md)'s C4 / structural model, which is product-owned and product-side of the [§13](../principles.md) wall) where it does not. The graph **stays derived and fingerprint-gated** — it is *not* flipped to hand-authored. Where both a code source and a design source exist, deriving from each and diffing them yields an **as-built ↔ as-designed drift check** (subsuming the old "walk product code" as one instance). The node/edge meta-model is restated as **domain-general**, not code-specific. Storage/representation stays a swappable [interface](../spec/systems/surfaces/interfaces.md) leaf with **no engine named**, and the concrete meta-model stays a deferred build-spec leaf — both owned by the module's own future design session. Propagated to the stub body and the [module catalog](../reference/module-catalog.md) paragraph (both non-locked); the [R8](../reference/risks.md) verb is corrected to *deferred behind the swappable seam* (per [D-082](0082-re-litigate-knowledge-honesty-r8-hub-explosion-is-deferred-b.md)) wherever it was carried as *bounds/mitigated*. **Supersedes only the derived-from-product-*code* premise of [D-105](0105-hold-a-post-v1-product-knowledge-graph-module-stub-product-s.md)**; D-105 otherwise stands as the founding stub decision.

## Why

D-105's "walks product code" premise silently assumed an introspectable codebase, too narrow for the North Star — the Engine cold-starts work on **any project**, not any *codebase*; for a multi-platform or non-code product a code-walking generator yields an empty graph, and leaving the premise uncorrected would hand the module's future design session a wrong starting point (the refactor a held stub exists to prevent). Widening the *source* rather than the operator-proposed flip-to-authored keeps the design principle-clean: [§3](../principles.md) holds (the graph is still derived and fingerprint-gated — no silently-rotting hand-authored structural state), [§2](../principles.md) holds (the index stays a replaceable derivative), the [D-008](0008-memory-and-knowledge-are-distinct-substrates.md) structure/belief wall holds (the graph is derived *structure*; beliefs stay in [memory](../spec/systems/cognitive/memory.md); the authored structural model the graph reads is product-design's product-owned artifact, [§13](../principles.md)), and [D-106](0106-elaborate-the-external-contribution-doc-with-the-cross-repo.md)'s engine-mechanic reasoning stays intact (the mechanic's product self-describes via its own derived knowledge graph). The locked [external-contribution](../spec/systems/lifecycle/external-contribution.md) text — "derived from the (un-owned) checkout" — **stays true and is not edited**: in that cross-repo case the checkout *is* the canonical structural artifact, so the graph necessarily derives from it. No locked doc is touched; this is a `stub`/`designed`-tier edit, not a lock.

## What we ruled out

**Flip the graph itself to authored-canonical with derivation demoted to optional** (the operator's original proposal) — rejected: a cold adversarial lens showed it violates [§3](../principles.md) ("hand-authored structural state rots silently" names structural state generally, and D-105 itself invoked the drift argument — "a committed code-graph drifts"), blurs the [D-008](0008-memory-and-knowledge-are-distinct-substrates.md) wall by housing a belief-about-structure under "knowledge" (defined as *purely derived*), and would silently rewrite [D-106](0106-elaborate-the-external-contribution-doc-with-the-cross-repo.md) — a principle-level re-litigation, not a stub edit. **Rename to `systems-knowledge-graph`** — rejected: "product" is the corpus's settled term for "the system the Engine builds" ([§13](../principles.md), [product-design](../spec/modules/product-design.md)); the name stays accurate after the fix, and renaming would force an edit to the **locked** external-contribution path link and leave append-only D-105 links dangling (a validate.py graveyard entry) for no clarity gain. **Decide storage/meta-model now (name a query store, e.g. Supabase/Postgres)** — rejected: the locked [knowledge](../spec/systems/cognitive/knowledge.md) foundation deliberately leaves its representation a swappable, unnamed leaf, so a downstream stub must not pin what its parent left open; naming one product's substrate would taint a domain-general module ([§13](../principles.md)/[§3](../principles.md)/[§4](../principles.md)) and would "mitigate" an [R8](../reference/risks.md) risk the corpus keeps *deferred*. **Minimal premise-correction only (graph a no-op where no code source exists)** — rejected: it leaves non-code products with no queryable structural graph, which is the actual North-Star gap.
