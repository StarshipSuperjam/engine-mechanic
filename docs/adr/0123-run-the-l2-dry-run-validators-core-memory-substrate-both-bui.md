# Run the L2 dry-run (validators-core + memory-substrate, both build-ready); harden the instrument with the calibration lessons it surfaced

*Decided 2026-05-29 in the design workspace.*

## The decision

Ran the dry-run build simulation over the two **L2** build steps that complete the M1 genesis stretch after the [core](../spec/modules/core.md) lock ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)): [validators-core](../spec/modules/validators-core.md) and [memory-substrate-sqlite-fts5](../spec/modules/memory-substrate-sqlite-fts5.md). Six independent cold-context agents in wave 1 (builder + contradiction-hunter + ordering-checker per module) and a spec-completeness reviewer per module in wave 2. **Verdict: both modules are BUILD-READY** — every artifact a cold builder needs is PINNED or a properly-owned NAMED build-spec leaf; ordering is clean for both (all inputs produced by L0 topology / the stage-0 seed / L1 core; no forward or circular edges); all six memory cross-system seams are clean [§16](../principles.md)/[§14](../principles.md) splits; **no blocker, no surviving contradiction, no litigation alarm.** The genesis [Q27](#) meta-pattern (a leaf whose presupposed form is itself unpinned) does **not** recur at L2. The L2 run is appended to the dry-run ledger. **Separately, harden the instrument** (wbs/dry-run.md, a no-status freely-revisable `wbs/` doc) with the two calibration lessons this run surfaced: (1) the **reviewer brief** now carries §2's deferred / build-spec-leaf doctrine explicitly (REJECT a named-but-deferred leaf; CONFIRM only a genuinely unowned form/contract) plus a self-check that a near-total confirm rate is the §2 over-tagging smell, not a result; (2) §4 now names the **orchestrator as final adjudicator** with two duties — **ground-truth any concrete defect-claim against the source before recording it** (binding hardest for litigation-class findings against `locked` docs), and **re-run a calibration-aware re-adjudicator when a reviewer signals over-tagging**; the builder brief's "deferred" carve-out and the §6 locked-doc routing gained the same ground-truth-first instruction.

## Why

This is the module-vs-system lock-gate discipline in motion — a clean dry-run over a module's build step is the **build-readiness precondition** for that module-packaging lock, distinct from and prior to the cold-session design audit every lock still passes ([D-110](0110-run-the-genesis-dry-run-through-complete-core-log-the-build.md)→[D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md) `core` precedent). The hardening is justified because the run **exposed real instrument fallibility**, not hypothetical: the first validators-core spec-completeness reviewer **over-confirmed (~20 findings, zero rejects)**, mistaking the build-spec leaves the locked docs name (`params`/`message`/`suites`/schema files) for gaps — the exact §2 failure mode — and it *and* the contradiction-hunter **misread the locked `tier` vocabulary in opposite directions**, manufacturing a phantom locked-doc contradiction. The orchestrator ground-truthed the source ([check](../spec/systems/surfaces/check.md) line 28 and [validation](../spec/systems/guardrails/validation.md) line 29 both use `hard`/`soft`; `hard-fail`/`soft-warn` are [principles §7](../principles.md)'s conceptual names) and ran an independent calibration-aware re-adjudicator, which reached BUILD-READY with no blocker. The original reviewer brief never carried the §2 doctrine the builder brief had — the root cause — so encoding it closes the gap at the source. **A self-correction is recorded for honesty:** the orchestrator's first ledger draft asserted a `"Reversibatlity"` typo at a locked-memory line that **does not exist** (the word is correctly spelled, [memory](../spec/systems/cognitive/memory.md) lines 135/145); it was caught by ground-truthing and removed before this entry — which is precisely why the §4 ground-truth-before-recording duty is now written into the instrument. This decision tunes the workspace's L1 build-readiness tooling ([D-108](0108-add-the-dry-run-build-simulation-instrument-the-workspace-s.md) created it, [D-109](0109-tune-the-dry-run-from-the-l0-calibration-a-deferred-disposit.md) tuned the `deferred` disposition); it edits **no** Engine design doc and touches no `locked` doc. **Propagation:** wbs/dry-run.md §2 builder-brief carve-out, §4 lens roster (new orchestrator-adjudicator subsection), §6 locked-doc routing, §8 reviewer brief; the dry-run ledger L2 section; this entry. No edit owed to wbs/README.md or CLAUDE.md — both reference the instrument's *role*, which is unchanged. `python3 validate.py` green. **Carry-forward (not acted on here):** both L2 module docs' "Status: designed, not locked" sections predate the dry-run instrument and name only the WBS + cold-audit gates; at their lock-prep pass they should also name the build-readiness precondition (a `designed`-doc nit), and the `validators-core`-vs-`memory-substrate` disagreement over whether the experimental stub [engine-knowledge-graph](../spec/modules/engine-knowledge-graph.md) blocks a lock is resolved then, not assumed.

## What we ruled out

**Treat the reviewer's CONFIRMs as the verdict** and record ~20 blockers + a litigation alarm (rejected — they were the §2 over-tagging failure and two misreads of locked text; relaying them would have wasted the human litigation gate on a phantom and frozen false blockers into the ledger). **Lock the L2 pair now** on the strength of build-readiness alone (rejected — build-readiness is the *precondition*, not the certification; each lock still owes its own fresh cold-session design audit and explicit operator go, per the module-vs-system lock gate and the CLAUDE.md HARD audit rule — and locking atop the still-`designed` neighbours would violate lock discipline). **Extend the dry-run to the rest of L2 / L3 before hardening** (rejected — the operator chose to fold the calibration lesson in first so subsequent runs are less reviewer-fallible; fixing the instrument before reusing it is the higher-leverage order). **Leave the instrument as-is and rely on orchestrator vigilance** (rejected — the reviewer brief's missing §2 doctrine was a structural gap, not a one-off lapse; a brief that does not carry the doctrine will reproduce the over-tagging on every future run). **Silently fix the ledger's fabricated typo** without recording the self-correction (rejected — finding-disposition and honesty: a fabricated finding that reached disk is itself a process defect, and the rule that prevents its recurrence is only credible if its origin is logged).
