# Litigate engine-template #367: a detached deployed repo resolves its engine-update source from the deployed repo's own `origin`, so it can never receive engine updates; the engine manifest records the engine's home repository (the single coordinate the updater and the escalate-upstream audit resolve the template repository from), §15-guarded — re-lock of `provisioning` lands under D-282

*Decided 2026-07-05 in the design workspace.*

## The decision

A build session in engine-template hit a divergence, opened it as engine-authored [engine-template #367](https://github.com/StarshipSuperjam/engine-template/issues/367), and correctly routed it here — "like #353, this changes a settled assumption, so it should be litigated in engine-planning rather than edited silently." **The symptom:** `module_manager.py upgrade` resolves the release source from the deployed repo's own `origin` remote (`boot.repo_slug()`; `_fetch_release_tree`/`_resolve_release_ref` do `slug = repo or boot.repo_slug()` and `upgrade()` never passes `repo=`), so a "Use this template" repo — whose own `origin` publishes no engine releases — has `upgrade` refuse (*"the engine repository has no published release to update to"*) and **can never receive engine updates**. Reproduced live on `StarshipSuperjam/engine-mechanic`, the first deployed copy; it blocks the engine-mechanic bootstrap. **The diagnosis (the [D-277](0277-litigate-engine-template-353-first-run-dead-on-arrival-in-a.md) shape): the build diverged from canon, which already forecloses `origin`.** The locked [glossary](../reference/glossary.md) *Update source* names the source *"the template repository's GitHub releases,"* and *Upstream (two senses)* ([D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)) keeps the engine-update channel **distinct** from the deployed repo's remotes — so `origin`-resolution was never canon. **What canon left unstated** is *how a detached repo resolves **which** repo "the template repository" is* — yet [glossary](../reference/glossary.md) *Escalate-upstream* already **promises** the answer lives in the manifest (*"the template repository (coordinates from the engine manifest)"*), a coordinate the built manifest does not yet carry and no code yet reads. So this **establishes** the resolution mechanism the manifest term already promises, grounded in **[D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md)** (which chose "the template repository's GitHub releases" but never specified the resolution) — a completion, **not** a re-litigation of D-024's anti-choices. **This entry is the litigation alarm + operator authorization** (given in-session over a four-lens plan-stage cold audit) **and the design of record**; the **re-lock of [provisioning](../spec/systems/infrastructure/provisioning.md) lands under [D-282](0282-resolve-re-lock-provisioning-the-engine-manifest-records-the.md)** after the mandatory landed-text cold audit — the carrier **edited-but-not-relocked** until D-282 (the [D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md) authorize→resolve pattern; `validate.py` flags its lock fingerprint until the relock).

  **The grammar (operator-authorized; RESHAPED by the four-lens plan audit from the issue's first-draft "release_home field / preserved-config" framing):** the engine manifest (`engine.json`) records the engine's **home repository** — the "template repository" coordinate that is the **single source of truth for both** (a) the **upgrade source** (the updater fetches releases from it) and (b) the **escalate-upstream target** (the same "template repository" the audit already files against). **One coordinate, two readers** ([R6](../reference/risks.md) anti-sprawl). Its laws: **(1) Preserved, not overlaid.** `engine.json` is **excluded from the upgrade overlay** (feasibility-confirmed against the code: `module_manager.py:527` lists the manifest among members "the overlay must NOT fetch-and-replace," and `_bump_engine_manifest` updates it **in place**, "PRESERVING … any other operator-owned keys"), so the home **persists** across upgrades — the sibling of `identity`/`handle`, not of the wholesale-overlaid engine code. **(2) Seeded and carried.** Seeded from the template's own committed manifest (ground-truth data, **never a code constant** — owned as a *choice*, since the repo already carries a `_TEMPLATE_LICENSE_HOLDER` constant elsewhere) and carried forward by the instantiator at `confirm()` via its own carry path (like `_existing_release`). **(3) Three-state resolution** (mirrors the [D-277](0277-litigate-engine-template-353-first-run-dead-on-arrival-in-a.md) two-state→three-state fix, one layer over): home recorded and **resolvable** → fetch; home recorded but **unresolvable** (the named repo publishes no release, or was renamed/removed) → **refuse loudly, naming the home**, never a generic "unreachable"; home **absent** → refuse and change nothing, surfacing — in plain language **matched to the cause** — why the update cannot proceed and the one concrete next step, **never a dead end**; **never falls back to `origin`**. The operator-facing refusal copy is a build-spec leaf held to the [§12](../principles.md) leak-guard, judged in review. **(4) Staleness bound named ([§7](../principles.md)/[§17](../principles.md)).** A preserved home can go **stale** (unlike the release version the overlay refreshes); the tag-pin and merge gate catch a malicious swap at review, but a non-engineer cannot themselves distinguish a right home from a look-alike — so the bound is named, not hidden (dropping the plan-draft's overclaimed "§15 cannot-weaken-silently"). **(5) §15-guarded (operator's call).** The home **selects where executable engine code is fetched from** — the tool-runtime lockfile's supply-chain sibling — so it is a [§15](../principles.md) guardrail-integrity file **by the existing property** ([D-268](0268-adjudicate-engine-template-250-the-15-weakening-guard-s-guar.md): the guarded set is property-derived, not a path list): a repoint is a **weakening-class change** blocked until the operator's **weakening acknowledgment**, surfaced as *"this changes where your engine's code is fetched from."* **Scope:** home = the engine's home repository (release source = escalate target); the fork-native **product-project upstream** (*Upstream (two senses)*) is a **distinct** coordinate, never the home, never the escalate target — reaffirmed, not muddied. **Fork-engine-lines are not opened as a designed release-cutting mode**; the home is merely a preserved coordinate a fork could repoint under its own gate (now a §15 acknowledgment). The **field name** is a build-spec leaf.

the `repo=` seam already exists so the build fix is small; the committed `engine.json` carries only `{engine_release, packages, identity}` today and **travels** via "Use this template"; GitHub copies no releases to a template-generated repo and `releases/latest` 404s on a release-less repo (the exact live symptom); ## Why

an engine whose deployed copies can never receive updates fails the upgradeability [D-024](0024-the-engine-is-upgradeable-versioned-packages-upgraded-by-ove.md) exists to guarantee. The honest, minimal fix is **not** to invent a new operator-tunable knob (the plan-draft "release_home / configurable source" that Agent-3 over-read into a D-024/D-102/D-103 re-litigation) but to **record, as ground-truth provenance the manifest already promises, which repo is the engine's home** — the one coordinate the updater and the escalate-upstream audit both need — and to fix the build's `origin`-resolution that canon already foreclosed. The manifest is the right home (it already carries the release + versions and the escalate-upstream coordinates), preserved across overlay so the value persists; three-state and refuse-with-remedy keep a non-engineer from a silent dead-end; the §15 guard makes a supply-chain repoint deliberate and plainly named, which also keeps the [D-102](0102-cross-repo-external-contribution-as-a-first-class-v1-operati.md)/[D-103](0103-cross-repo-design-cold-audit-resolutions-engine-clean-branch.md) engine-mechanic ratification gate honest (a repoint to un-ratified output is now a named weakening act, not a silent bypass) **without** re-litigating it. The authorize→resolve-after-landed-text-audit split keeps the irreversible re-lock behind its own clean gate ([D-273](0273-litigate-engine-template-332-ambient-turn-deltas-dominate-me.md)/[D-274](0274-resolve-re-lock-memory-ambient-turn-deltas-excluded-from-rec.md)).

## What we ruled out

**A new operator-configurable release-source knob / re-litigate D-024's "the template repository's GitHub releases"** (rejected — the source repo is unchanged; only its *resolution* was unstated. D-024's anti-choices — un-upgradeable foundations, git-remote merge, external registry — are untouched; this completes D-024, and Agent-3's "configurable source weakens trust" cascade was a strawman on a coordinate that is provenance, not a tunable). **Rekey resolution on the deployed repo's `origin`/`templateRepository` (the built behavior)** (rejected — a generated repo's origin is its own release-less repo; canon's *Upstream (two senses)* already forecloses it, and [D-277](0277-litigate-engine-template-353-first-run-dead-on-arrival-in-a.md) rejected origin-slug/`templateRepository` provenance — there as a spoofable *verdict* signal; the home is a coordinate, outside that, but origin-resolution is exactly the divergence). **A two-state verdict (present → fetch / absent → refuse)** (rejected — the [D-277](0277-litigate-engine-template-353-first-run-dead-on-arrival-in-a.md) "absence/presence is spoofable" finding recurs as present-but-wrong; a release-less or renamed home must refuse *loudly, naming the home*, not read as unreachable). **Frame the home as overlaid-wholesale, carried like engine code (the architect's premise)** (rejected on code ground-truth — `engine.json` is excluded from the overlay and bumped in place; overlaying it would reset a fork's home and clobber `handle`/`identity`). **Unify the upgrade-source and escalate-target as one field without fencing the product-project upstream** (rejected — the adversarial lens showed the prose invites conflating the engine home with the fork-native contribution target U; the scope clause fences U explicitly). **Open fork-engine-lines as a designed release-cutting mode** (rejected — [R6](../reference/risks.md) scope; the home merely permits a fork to repoint under its own §15 gate, no release infrastructure designed here). **Spec the absent-home refusal as a silent "refuses cleanly, changes nothing"** (rejected — the operator lens showed it reproduces the exact #367 stranding; it must carry a matched-to-cause reason + remedy, and pre-home repos get a boot detect-and-offer). **Mint a new glossary term or risk entry** (rejected — [R6](../reference/risks.md)/[D-261](0261-establish-the-artifact-warrant-discipline-a-7-17-application.md) anti-sprawl; the existing *Engine manifest*/*Update source*/*Engine updater*/*Escalate-upstream*/*Guardrail integrity* terms and R7 carry it). **Write the [D-282](0282-resolve-re-lock-provisioning-the-engine-manifest-records-the.md) resolve entry now** (rejected — it records a landed-text cold audit that runs later; authoring it pre-audit would dress un-audited as audited, the [§7](../principles.md) violation this pattern prevents).
