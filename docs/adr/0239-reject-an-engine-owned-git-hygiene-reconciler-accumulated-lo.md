# Reject an engine-owned git-hygiene reconciler: accumulated local worktrees/branches are Claude-Code harness exhaust (upstream gap), out of engine scope; record the boundary in [R20](../reference/risks.md)

*Decided 2026-06-22 in the design workspace.*

## The decision

The Engine will **not** own automatic cleanup of accumulated local git worktrees and branches. A deployed instance accrues a large pile of stale local session branches and worktree backings (observed in an engine-template checkout: **177 local `claude/*` branches vs 1 on the remote, 41 worktrees, the remote otherwise clean**, most local branches with no upstream). This is **exhaust of Claude Code's per-session worktree machinery** — Claude Desktop auto-creates a worktree + branch per session and only auto-cleans **clean, gracefully-exited** ones; crashed / interrupted / named / non-interactive sessions leave the worktree *and* its branch behind, and `cleanupPeriodDays` sweeps only *subagent* worktrees — a known, open upstream gap ([anthropics/claude-code#26725](https://github.com/anthropics/claude-code/issues/26725)). Because the pile is **local-only**, no Engine surface and no committed file is affected; remediation belongs at the **local / Claude layer**, not in an Engine surface: a one-time **rescue-aware** sweep (worktrees first — a branch is undeletable while a worktree backs it — then prune merged/stale local branches, rescue-branch any genuinely-unmerged work, **never a blanket `git branch -D`**) plus a small **operator-owned scheduled local routine**, with upstream [#26725](https://github.com/anthropics/claude-code/issues/26725) tracked so the routine retires when native GC ships. The **only** design-side change is a boundary note extending [R20](../reference/risks.md) to separate the Engine-owned *strand* residual (R20 proper) from *harness-exhaust accumulation* (platform-owned, out of scope). The native worktree-isolation reliance ([D-189](0189-authorize-the-operator-checkout-boundary-re-litigation-confi.md)) stands unchanged. **No locked doc is touched.**

## Why

A cold **four-lens** audit (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) of a proposed Engine reconciler — a boot-invoked, [provisioning](../spec/systems/infrastructure/provisioning.md)-owned, *lossless-or-it-does-not-run* auto-prune of branches/worktrees + return-to-trunk, with a tunable "auto" policy, plus a native `delete_branch_on_merge` bootstrap — returned **four convergent blocking findings**: **(1)** the branches are **squash-merged** (the documented Claude Code merge path), so after merge they are not ancestors of `main` — `git branch -d` refuses them and `git branch --merged` omits them (verified empirically); an offline boot reconciler is a **silent no-op against exactly the branches it exists to clean**, and the only effective detection is **online** `gh pr list --state merged`, which breaks the offline premise. **(2)** "accumulated local cruft" is already the **locked** [audits](../spec/systems/guardrails/audits.md) charter ([D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md); audits is the deployed Engine's anti-entropy tune-up that **reports and recommends, routes to engine-labeled Issues, and never remediates autonomously**) — a boot daemon that mutates state is precisely what [principles §8](../principles.md) forbids. **(3)** an "auto every boot" toggle has **no legal home** in the locked policy-override scope ([D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md): tuning values only, never enforcement/action config) and would force re-litigating the [policies](../spec/systems/surfaces/policies.md) surface ([D-168](0168-resolve-the-d-167-operator-policy-override-re-litigation-lan.md)) and the `core` never-strand-main floor. **(4)** it is a **layer violation** — the Engine building machinery to mop up version-contingent platform exhaust for a known upstream bug, against the deployed-instance lens and [R6](../reference/risks.md) scope discipline at a build-ready ([D-238](0238-resolve-the-d-237-memory-backup-shared-vault-flip-the-four-l.md)) line. The operator confirmed the remote carries none of these branches ("I don't see them in GitHub — it's a Claude issue"), corroborated by the repo measurement, which seals the layer call: the exhaust is **created by the harness and cleaned at the harness/local layer**, not by an Engine surface.

## What we ruled out

Build the boot/[provisioning](../spec/systems/infrastructure/provisioning.md) auto-reconciler (rejected — the four convergent blocking findings; chiefly squash-merge blindness makes it ineffective and the auto-mutation is a [§8](../principles.md)/[D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md) daemon with no policy-override home). Route git-hygiene cleanup through the [audits](../spec/systems/guardrails/audits.md) local-reconcile lane as an autonomous action (rejected — audits is recommend-only by lock; and branch/worktree deletion is git **metadata**, not a file diff a Build PR's merge can adjudicate, so it does not even fit the lane's merge-is-consent disposition). Add the native GitHub `delete_branch_on_merge` setting to the [control-plane](../spec/systems/infrastructure/control-plane.md) settings bootstrap (rejected for this problem — it deletes only the *remote* head branch on merge and the remote is already clean, so it does nothing for the local pile; it also crosses control-plane's locked "merge method / workflow is the product's choice" boundary — a separate decision if remote hygiene ever warrants it). Add a boot "offer to return to main when parked on a merged branch" (rejected in this pass — not the [R20](../reference/risks.md) strand class: clean tree, attached `HEAD`, nothing lost — so it would re-litigate locked [boot](../spec/systems/lifecycle/boot.md) ([D-210](0210-resolve-the-d-209-ledger-compaction-re-litigation-landed-tex.md)) + [provisioning](../spec/systems/infrastructure/provisioning.md) ([D-222](0222-resolve-the-d-221-first-run-license-clear-re-litigation-land.md)) for a low-harm, often-deliberate state; the offline "is it merged?" test is squash-fragile and a per-session offer risks [Q18](../reference/open-questions.md) habituation; available as a separate scoped re-litigation if the operator later wants it).
