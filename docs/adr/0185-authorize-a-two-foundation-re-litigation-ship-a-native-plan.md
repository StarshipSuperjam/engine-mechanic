# Authorize a two-foundation re-litigation: ship a native plan-mode default in the Engine that yields to an existing operator setting

*Decided 2026-06-08 in the design workspace.*

## The decision

On the operator's call, establish that the Engine ships a **recommended native plan-mode default** inside an Engine-managed repo — Claude Code's `permissions.defaultMode: "plan"` — that **yields to an operator who already has a different permission-mode setting and declines**, with install never clobbering existing user settings. This entry is the **litigation alarm + authorization**; it authorizes editing two locked foundations — [modes](../spec/systems/lifecycle/modes.md) and [provisioning](../spec/systems/infrastructure/provisioning.md) — and the **re-locks land under the resolve entry** after the mandatory cold audit on the landed text (the [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)→[D-168](0168-resolve-the-d-167-operator-policy-override-re-litigation-lan.md) / [D-169](0169-add-the-foundational-eadr-canon-the-engine-ships-its-own-why.md)→[D-170](0170-resolve-the-d-169-foundational-eadr-canon-re-litigation-land.md) pattern). A four-lens cold **plan**-audit (adversarial · technical-feasibility · non-engineer-operator · architect) reworked the design before this authorization; what is authorized is the audited design.
  **Design (final, post-plan-audit):**
  - **Two axes, never conflated.** The Engine *stance* ([modes](../spec/systems/lifecycle/modes.md): Explore/Build/Routine, the `PreToolUse` write-gate + merge wall) is the safety guarantee; Claude Code's native *permission mode* (`permissions.defaultMode`, read natively by the platform) is a separate axis. Plan-mode-default is the native-mode axis — **posture/ergonomics ([§7](../principles.md)), defense-in-depth layered atop the Explore gate**, never the guarantee.
  - **Nothing static ships.** `.claude/settings.json` continues to ship with **no** `defaultMode` key; a static project-level value would override the operator's user-level preference (precedence `user < project < local`, confirmed against the live settings schema) and defeat the yield.
  - **Provisioning writes it at install — the identity-tier pattern.** The instantiator **reads `~/.claude` read-only** to detect the operator's existing interactive `defaultMode` (it never *writes* `~/.claude`), then: *no existing pref, or already `plan`* → adopt by default, writing `defaultMode: "plan"` into the committed **project** settings as operator config with a plain-language disclosure; *existing pref ≠ `plan`* → the **only** added prompt (conflict-only) offers adopt-or-keep in outcome-in-this-repo terms — **keep writes nothing** (project unset → the operator's user-level mode governs) = the yield.
  - **Operator config, surgically preserved.** The written value is operator config preserved across overlays; the overlay edits settings.json **surgically** (re-applies only engine-keyed entries — hook/permission wiring — idempotently), leaving operator-owned top-level scalars in place. JSON carries no comment-fence, so preservation is by the keyed-edit scope **excluding** operator scalars ([repository-topology](../spec/systems/infrastructure/repository-topology.md) law 1 already owns this; made explicit in provisioning).
  - **Travel semantics named.** The yield is **deploying-operator-scoped**; the committed value then travels like any committed project setting (a deployment property, "this repo opens in plan mode"), not a per-clone re-decision (the instantiator self-deletes). A different user in that repo overrides locally via `settings.local.json` / `/config` — **not** a clobber (no `~/.claude` file is ever mutated).
  - **Routine never stalls.** Plan-mode-default is the **interactive** default; a Routine session establishes its own non-interactive posture **at launch** (which overrides the project default — launch posture beats project settings), consistent with [D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md); the override mechanism is a build-spec leaf verified at build. The clause lands in **modes**, so build-orchestration is **not** re-locked.
  - **§15 untouched.** No enforcement value changes; a later `defaultMode` change is **not** a weakening event ([§15](../principles.md)); the install write is **disclosed** in plain language as non-weakening ergonomics (the tool-runtime-consent disclosure pattern).
  - **No new surface ([R6](../reference/risks.md)).** The operator retunes via native `/config`; the design states this rather than inventing a command.
  **Authorized re-lock set (2, landing under the resolve entry):** [modes](../spec/systems/lifecycle/modes.md), [provisioning](../spec/systems/infrastructure/provisioning.md). **Assess; re-lock only if text changes:** [repository-topology](../spec/systems/infrastructure/repository-topology.md) (law 1 is expected to already cover the operator-scalar ownership — verify; no edit if so). **Non-locked propagation:** [scenarios/first-run.md](../architecture.md#first-run-provisioning) (the conditional step); [glossary](../reference/glossary.md) (a *native permission-mode default* term + the Mode-entry two-axis clarification); [engine-architecture](../architecture.md) (§4/§7 one-line); [risks](../reference/risks.md) (assess an adopter-confusion / platform-coupling clause). **Build-spec leaves (deferred):** the detection file-read/merge precision, the conflict-offer + disclosure copy (plain behavioral language, outcome-in-this-repo terms, names the `/config` change path), the routine-override mechanism, and the live-platform re-verification that `plan` is honored from repo settings (the [D-178](0178-resolve-the-d-177-plan-file-carve-out-landed-text-cold-audit.md)/[D-179](0179-augment-interactive-build-entry-with-plan-acceptance-correct.md) pattern; [D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md) records `defaultMode: auto` is ignored from repo settings, so the platform special-cases modes there). `python3 validate.py` green at each step (the two locked-doc edits fingerprint-fail by design until the resolve-entry re-lock).

## Why

The operator wants every Engine-managed repo to open in a safe first-touch (native plan mode), consistent for all adopters and robust against a clobbered user-level file — and the design has clean precedents (the identity-tier prompt writes operator config at first run; the [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)/[D-168](0168-resolve-the-d-167-operator-policy-override-re-litigation-lan.md) preserved-operator-config partition; provisioning's gather/confirm opt-out + non-clobber collision discipline). Seating it **now** is cheapest — both foundations are unbuilt and there are zero deployments to migrate (the [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md) timing argument). It is a **justified re-litigation, not silent drift** — the lock stops drift, not warranted edits — and the four-lens cold plan-audit reworked the design before this authorization (naming the clone/travel semantics, correcting a misread of [D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md) as forbidding committed permission config when it explicitly contemplates it, sharpening the [§15](../principles.md) tier to posture + an install-disclosure law, and making the settings.json surgical-overlay preservation explicit). Honest bound: plan-mode-default is **not** a new safety guarantee — Explore + the merge wall are — it is ergonomics + cross-adopter consistency.

## What we ruled out

**Ship a static `defaultMode: plan` in the template** (rejected — project>user precedence overrides the operator's existing setting; defeats the yield). **Model it as an operator-policy-override** (rejected — [policies](../spec/systems/surfaces/policies.md) excludes enforcement/guardrail config from override-eligibility, and Claude Code reads `defaultMode` natively with no engine consumer to merge at read time — the [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md) lane is the wrong vehicle). **Write the operator's `~/.claude` on install** (rejected — mutates global settings, violates the non-clobber requirement; engine writes to `~/.claude` are illegitimate per [modes](../spec/systems/lifecycle/modes.md)). **Explore-only, ship no native default** (rejected by the operator — loses cross-adopter consistency and the recommended safe first-touch; the operator declined this option). **§15-monitor `defaultMode`** (rejected — mis-names the enforcement tier [§7](../principles.md); the gate + merge wall are the enforcement, plan mode is posture over them). **Per-clone re-yield** (rejected — impossible; the instantiator self-deletes; the committed value is an intentional deployment property with a native local override). **Read [D-140](0140-lock-routine-mode-the-unattended-routine-entry-the-fourth-mo.md) as forbidding committed permission config** (rejected — a misread; D-140 placed the *routine non-interactive preset* operator-side because it was never routine-mode's to wire, and explicitly contemplated "were it committed, core/build-orchestration would own it" — it does not forbid a committed `defaultMode` written as operator config). **Defer post-v1** (rejected by the operator — the gap is present in every deployment and cheapest to seat before any deployment exists).
