# Flesh the `core` module doc to `designed`: the kernel partition, the validation engine/corpus seam, foundation-infra artifacts ride outside `provides`

*Decided 2026-05-27 in the design workspace.*

## The decision

Take the [`core`](../spec/modules/core.md) module doc from `stub` → `designed` (packaging-view depth, matching the four `designed` peers; **not** locked). `core` is the microkernel-*inspired* trusted root — the irreducible machinery surviving the *remove-every-module* test ([Slot](../reference/glossary.md), [§12](../principles.md)): the grammar (ontology catalog + schema + self-map, module-system manifest schema + the `.engine/tools/` wiring library), the regenerable cognitive floors (state, attention, knowledge — knowledge rides `core`'s `provides`, [D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md)), the guardrail foundations (templates, telemetry, and the **validation dispatcher + the five closed check-kinds**), the stand-up/enforcement infrastructure (hooks scripts, provisioning instantiator + module manager/updater), the full lifecycle spine (boot/modes/close/build-orchestration, the plan-review gate a no-op [Slot](../reference/glossary.md) filled by the [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) lenses), the v1-core policies + the control-plane PR contract + the `search`/knowledge-retrieval interface *protocols* + the agent persona-template grammar, and the two `operator-typed` skills (Build-entry, `/engine-help`, [D-087](0087-resolve-q7-v1-skill-membership-close-deviation-d2-the-wbs-de.md)). The doc fixes the **kernel partition**: what carves out to each sibling `required` package — `memory-substrate-sqlite-fts5` (the gitignored ledger + `search` *implementation* + memory MCP), `validators-core`, `adr-discipline`, `expression-contracts`, `routine-mode`, `audit-library`. Two partition points are settled here — the first a constrained **decision** (tightly bounded by locked docs, but a decision with alternatives, logged as such below), the second a forced consequence: **(1)** the **validation engine** (thin dispatcher + the five closed kinds `schema`·`shape`·`presence`·`coverage`·`coherence`) rides `core` and `validators-core` is a **rule-providing module on top** (the concrete `check` data files), the same presence-discovery shape as `audit-library`. The primary grounding is the locked [validation](../spec/systems/guardrails/validation.md) doc's *own* design: validation is "a thin dispatcher over a kind registry where **rules are data**," and modules extend it "by providing a conforming callable **discovered by presence — explicitly not a wiring seam**." That dissolves the apparent asymmetry an audit lens raised (*why does validation ride `core` while `memory` earns its own package?*): the validation foundation owns no non-regenerable per-instance store **and** exposes no bound seam (its extension is the §14 discovery axis, not a wiring seam), so the [Required-package rule](../reference/glossary.md) ([D-086](0086-cognitive-foundations-as-required-packages-reconciliation-me.md)) keeps it in `core` exactly as it keeps [knowledge](../spec/systems/cognitive/knowledge.md) there — `memory` is the exception because it satisfies *both* tests (the non-regenerable ledger + the bound `search` seam). Provisioning's locked direct `coherence` library call + the `core → validators-core` graph direction independently pin the engine to `core`. **(2)** per the locked [module-system](../spec/systems/grammar/module-system.md) coherence rule, the root `CLAUDE.md`, the engine manifest, and the engine-owned `.github/` control-plane files are **named foundation-infrastructure artifacts that are NOT surface-grouped in any `provides`** — they ship as the engine baseline and are unioned into coherence/CODEOWNERS, so `core`'s `provides` correctly omits them. The doc adds a [§16](../principles.md) **deferral-seams** section (core integrates — boot, telemetry surfacing, the validation dispatcher, provisioning — but relays; owners detect) and an **operator-voice** section (the maintainer vocabulary `core` carries never leaks; `/engine-help` derives its listing by presence and is degradation-proof). Also resolves a plan-stage open item: the **knowledge graph-query MCP server is a `core` `mcp` wire** (locked [knowledge](../spec/systems/cognitive/knowledge.md) "reached through a graph-query MCP server" + knowledge rides `core`).

## Why

A module doc is the packaging view; the design depth lives in the now-locked systems, so `core`'s doc maps locked machinery → the trusted-root bundle without restating laws (the depth bar is the `designed` peers, [D-065](0065-product-design-front-door-design-the-q14-intake-module-as-a.md)/[D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md)/[D-067](0067-operator-facing-module-packaging-industry-discipline-categor.md)). **Two four-lens cold-context audits** (adversarial / technical-feasibility / non-engineer-operator / architect) ran at the operator's request — neither is the lock-gate audit (this pass produces `designed`), but the operator asked for lock-grade rigor. **Audit 1 (against the plan):** blocking/serious findings discharged — the validation-engine-in-core "re-litigation" worry was checked against the locked validation doc and shown to be a forced consequence, not an edit (no lock touched); §16 seams and the wiring-library firewall became explicit sections; the operator jargon-leak guard, `/engine-help` degradation, and doc audiences became a named section; propagation was accounted target-by-target. **Audit 2 (against the finished doc + this entry):** both audits agreed the partition (validation engine/corpus, knowledge-in-core, foundation-infra off `provides`), the four hook events, and propagation are sound; four fixes were applied to [modules/core/README.md](../spec/modules/core.md) — the `mcp` wire reworded to name that the knowledge server reads *committed* entities + the *gitignored* index (entities are not gitignored); `/engine-help` degradation scoped to listing-plus-descriptions from committed skill files (not "never stranded" unqualified); the `permission` wire's concrete strings marked an explicit build-spec leaf; and the `validators-core` carve-out trimmed to cite this entry rather than re-derive the forced-consequence argument. One audit-2 recommendation was **rejected with rationale**: plain-languaging the doc's Deferral-seams section / marking the wires table operator-hidden — `modules/core/README.md` is a planning-workspace design doc, never shipped to a generated repo, so the §12/§14/§16 leak guard (which governs the Engine's *shipped* surfaces) does not require it; the doc already fences the shipped surfaces in its operator-surfaces section (layer discipline). **Audit 3 (a true plan-*approach* audit, run after the operator observed that the plan-stage audit had been blind — the plan lived outside the agents' sandbox, so the *plan-quality* gate was effectively skipped and the artifact audit cannot backfill it):** two lenses (adversarial, architect) judged the approach with the plan inlined. Its one valid catch is folded into (1) above — the partition was under-grounded (cited the weaker provisioning/graph leg) and left the validation/memory asymmetry unanswered; the fix grounds it in the locked validation doc's *rules-are-data / extend-by-presence-not-a-seam* design and states the asymmetry resolution. Its other findings are **rejected with rationale**: *lock leaves-first, core last* (rejected — the workspace locks **upstream-first**, dependents adapt to the locked foundation per CLAUDE.md; and this pass locks nothing); *lock `core` now since it has been audited* (rejected — lock-discipline forbids locking atop churning/stub neighbors, and `core`'s siblings are still stubs, so `designed` is correct); *author the WBS before designing `core`* (rejected — the dependency graph already exists in [modules/README.md](../reference/module-catalog.md); the WBS is downstream build-sequencing, not a design input to `core`, whose shape comes from the locked systems); *co-design `validators-core` with `core`* (rejected — the shared seam is already pinned by the locked validation doc, so `core`'s side follows the foundation rather than pre-deciding a free boundary). Coherence-closure under the split was confirmed to hold (each engine file still maps to exactly one `provides` — engine files → `core`, rule files → `validators-core` — no orphan or double-claim), so [modules/README.md](../reference/module-catalog.md) needs no edit. The validators-core = rule-corpus reading is consistent with `audit-library` depending on `validators-core` (no rework forced). The plan had listed the foundation-infra artifacts inside `provides`; reading the locked module-system coherence rule corrected this to the named non-`provides` set — a consistency fix. Propagation per the matrix: [modules/core/README.md](../spec/modules/core.md) authored to `designed`; this entry. Verified no-change with rationale: [modules/README.md](../reference/module-catalog.md) (catalog row, `required` runtime status, and graph edge for `core` already present — design-maturity is not catalog-tracked), wbs/README.md (unauthored; this pass feeds it and gates the eventual lock, not the `designed` state), [glossary.md](../reference/glossary.md) ("core" already defined via the *Slot* + *Required package* terms and "microkernel-inspired" via [D-025](0025-fault-containment-is-earned-at-the-seams-not-conferred-by-mo.md); "kernel" used as analogy, no new term), [engine-architecture.md](../architecture.md) (indexes via the catalog; §4/§6 stay truthful — core's role unchanged). No locked system doc edited.

## What we ruled out

Put the validation **engine** (dispatcher + closed kinds) in `validators-core` (rejected — inverts the locked `core → validators-core` graph and strands provisioning's direct `coherence` call). Make `core` depend on `validators-core` for coherence (rejected — dependency cycle). List the foundation-infra artifacts (root `CLAUDE.md`, engine manifest, control-plane `.github/`) in `core`'s `provides` (rejected — the locked module-system coherence rule names them as the non-`provides` infrastructure set unioned into coherence). Enumerate exhaustive `provides` file paths/`wires` directives now (rejected — build-spec-leaf, inconsistent with the `designed` peers). Lock `core` this pass (rejected — lock requires authored WBS + a fresh cold-session audit, per lock-in-dependency-order; `core` is the natural first lock but those gates are unmet). Coin "kernel" as a new glossary term (rejected — "core" is already defined and "microkernel-inspired" is established maintainer vocabulary).
