# Resolve the D-207 Dependabot PR-contract exemption: landed-text cold audit, five docs re-locked

*Decided 2026-06-17 in the design workspace.*

## The decision

The [D-207](0207-authorize-the-dependabot-pr-contract-exemption-a-ci-author-a.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with four independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written edits in [check](../spec/systems/surfaces/check.md), [validation](../spec/systems/guardrails/validation.md), [validators-core](../spec/modules/validators-core.md), [control-plane](../spec/systems/infrastructure/control-plane.md), [modules/core](../spec/modules/core.md), plus the carriers ([glossary](../reference/glossary.md), [risks](../reference/risks.md) [R1](../reference/risks.md)). **Outcome: technical-feasibility and non-engineer-operator PASS clean; two serious findings folded (one adversarial, one architect), both factual field-count staleness; four nits — one logged-accepted, three carried into the build-owes.** Re-lock set: **5**.

  **The audit + dispositions.**
  - **Technical-feasibility — PASS (no blocking/serious).** Every load-bearing GitHub fact re-verified against current docs + security research: author-keying on `dependabot[bot]` (the immutable `pull_request.user.login`, never the mutable `github.actor` — Synacktiv's Spring-Security attack flipped `github.actor` to `dependabot[bot]` via a force-push while the real author stayed the attacker, so the actor field is the spoofable one); `dependabot[bot]` non-registrable (usernames cannot contain `[`/`]`) and a fork cannot author a PR under it; the **disclosed-no-op-as-genuine-PASS** correctly avoids the trap that a job/workflow-level `if:` skip leaves a required check **Pending** (which blocks merge) — the landed text mandates a *reported result* inside the always-running engine, not a skip; the §15-guard-carries-no-exemption invariant present in all three load-bearing places. **Two nits → build-owes:** the `pull_request_target`/trusted-context premise is the unstated second leg of spoof-safety (the check must read the author from the trusted event context, not a fork-controlled `pull_request` run); and **"non-registrable ≠ spoof-safe" for every bot** — `github-actions[bot]` is also non-registrable but is assumable by any in-repo workflow, so any future widening of the exempt set must force a fresh spoof-safety re-confirmation (the §15-weakening gate already routes a widening through review; the build-spec note makes the caveat explicit).
  - **Non-engineer-operator — PASS (no blocking/serious); the plan-audit relay BLOCKING confirmed resolved.** The landed [control-plane](../spec/systems/infrastructure/control-plane.md) text binds the not-applicable disclosure to the operator-presentation relay ("a green required check otherwise reads to the operator as *verified* … surfaced to the operator through the AI's own reply … not only in CI output"), reinforced in [D-207](0207-authorize-the-dependabot-pr-contract-exemption-a-ci-author-a.md) and [R1](../reference/risks.md). The jargon quarantine holds — `ci_author_exempt`/"dispatcher"/"disclosed no-op"/"domain boundary" appear only in maintainer-facing design docs, never in an operator-facing string (the rule `message`, the §15 acknowledgment prompt, and the relay copy are plain-language build-spec leaves). The operator is told green = exempt-not-verified with `guardrail-ack` named as the live gate, is not stranded (the three security PRs merge on the label they already understand), and is not trained to wave through exempt greens (per-PR in-chat disclosure + §15-gated widening). **One nit → build-owes:** ship a plain-language *exemplar* for the relay sentence + §15 prompt so the builder does not improvise jargon into the one string the operator reads.
  - **Adversarial — one serious folded.** **Folded:** [validators-core](../spec/modules/validators-core.md)'s `provides` line — the bullet [D-207](0207-authorize-the-dependabot-pr-contract-exemption-a-ci-author-a.md) edited to add the `ci_author_exempt`/`dependabot[bot]` clause still opened "each carrying the **seven-field** rule record," a self-contradiction one clause apart and against the re-locked [check](../spec/systems/surfaces/check.md) ("seven fields, and may carry an optional eighth"); reconciled to "each carrying the **check rule record**" (the count is the check surface's authority; the generic phrasing does not rot). **All six attacks otherwise clean:** the unqualified control-plane "fails the merge until the sections are present and non-empty" sentence is correctly neutralized (the [validation](../spec/systems/guardrails/validation.md):136 and [build-orchestration](../spec/systems/lifecycle/build-orchestration.md) twins are Engine-build-PR tier descriptions, not universal-domain claims, and validation's authoritative tier-versus-context section carries the boundary); the disclosed-no-op is described consistently across all five docs; no authoring-rule-1 inline-history introduced; no overclaim (spoof-safety never escalated to absolute, solo never dressed airtight); §15 framing internally consistent (no doc says "not a weakening"); the field is stated optional/default-absent so existing rules validate.
  - **Architect — one serious folded; the 5-doc re-lock set confirmed correct and complete.** **Folded (missed carrier):** wbs/dry-run-ledger.md pinned "the seven-field rule record (`check/README.md`)" as a build-readiness fact, now stale against the re-locked check doc; reconciled to "the check rule record — seven fields plus the optional eighth `ci_author_exempt`" (a revisable WBS doc, no re-lock). **Confirmed clean:** the three-way [§16](../principles.md) ownership split is stated coherently and identically across the docs (control-plane **owns** the domain boundary, validators-core's rule **realizes** it, core's engine **honors** it, check **defines** the field, validation **states** the law), with "kinds stay author-agnostic" repeated in all four prose docs; both carriers are the minimal authorized form (no new R24 — folded into [R1](../reference/risks.md)'s §15 clause; no new glossary term — the *Check* field-list reconciled); the schema-optionality is stated; and the verify-no-edit claims for [ontology](../spec/systems/grammar/ontology.md), [engine-architecture](../architecture.md), [modules/README](../reference/module-catalog.md), and scenarios were ground-truthed clean. **Nit, logged-accepted (no edit):** the text uses "disclosed not-applicable **result**" and "disclosed not-applicable **no-op**" interchangeably; meaning-consistent and the glossary canonical term ("disclosed no-op") is unchanged, so unifying is cosmetic churn against [R6](../reference/risks.md).

## Why

The lock gate requires a landed-text cold audit with every blocking/serious finding resolved before re-lock; it ran (four lenses), feasibility and operator passed clean (the relay BLOCKING from the plan-audit confirmed resolved in the landed text), and the two serious findings were both factual field-count staleness (one inside a re-lock-set doc, one a missed non-locked carrier) folded before re-lock. The landed text is faithful to [D-207](0207-authorize-the-dependabot-pr-contract-exemption-a-ci-author-a.md): the exemption is a disclosed not-applicable result (never a silent green or a Pending-leaving skip), keyed on the authoritative non-registrable `dependabot[bot]` author, the closed kinds stay author-agnostic, control-plane owns the domain boundary the rule realizes and core's engine honors, the disclosure reaches the operator via the relay, `engine-guard`/`guardrail-ack` stays fully load-bearing, and the exemption's own landing is §15-gated.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Leave `validators-core` saying "seven-field" beside the eighth-field clause** (rejected — an as-written self-contradiction inside a doc being re-locked; authoring-rule 1). **Leave `wbs/dry-run-ledger.md` pinning "seven-field"** (rejected — a stale build-readiness fact contradicting the re-locked check doc; a missed carrier, fixed and logged). **Unify "disclosed not-applicable result" / "no-op" wording across the docs** (rejected — meaning-consistent, glossary canonical term unchanged; cosmetic churn against [R6](../reference/risks.md)). **Carry the feasibility/operator nits only in this log** (rejected — they are build realizations, so they belong in the #116 build-owes where the fixing session reads them).
