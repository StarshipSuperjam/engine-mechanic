# Memory: ledger-canonical, observe-don't-predict capture, lexical floor + semantic module, and the built-in-auto-memory boundary

*Decided 2026-05-23 in the design workspace.*

## The decision

Settle [memory](../spec/systems/cognitive/memory.md)'s workflow. **(1) Ledger-canonical:** the canonical store is an **append-only NDJSON ledger** (plain text); the SQLite/FTS5 store is a *derived, rebuildable index* ([principle §2](../principles.md)). **(2) Observe importance, don't predict it:** capture is cheap, generous, and **episodic** (a compact narrative record), never a write-time keep/discard gate; the in-context AI's judgment drives *typing and tagging*, not gatekeeping; **importance is derived from usage** (frecency + retrieval reinforcement). **(3) Durability:** ambient append of **session-id-tagged** turn deltas every `Stop`; deferred episodic **consolidation** at `PreCompact`/close; abandoned sessions recovered by **lease-gated** consolidation (sessions) — so close is best-effort, not the capture gate, and capture survives an ungraceful exit. **(4) Two-layer typing:** a closed, universal, Engine-shipped **role** vocabulary (decision, rationale/pushback, lesson, dead-end, preference, intent, observation) atop open project-emergent **entity/topic tags**. **(5) Retrieval:** FTS5 lexical recall is the **foundation floor** (offline, zero-dependency); **semantic recall is an optional module** behind a stable `search` interface, built from the same ledger — a swappable index, not a store migration; the foundation/module split is by *dependency weight* (no ChromaDB; at one-project scale brute-force exact similarity needs no ANN). **(6) Memory↔knowledge link** is a **read-time join** on entity-id tags in curated records; no persisted reverse edges. **(7) Active forgetting** (consolidation + tiered demotion + evidence-only hard deletion) that is **operator-visible and reversible**. **(8) Built-in-auto-memory boundary:** the Engine substrate is **authoritative for project recall**; the Engine never writes project content into Claude Code's built-in auto-memory and never cites it as fact (a memory-authority [policy](../spec/systems/surfaces/policies.md), routed via the committed root `CLAUDE.md`). **Firms [R2](../reference/risks.md)** and **narrows [Q3](../reference/open-questions.md)** (data shape settled; automatic operator-facing backup still open), and **adds a requirement to [Q6](../reference/open-questions.md)**.

## Why

Importance is a function of the future the capturing session cannot see, so a write-time salience gate bets on absent foresight — the honest design captures cheaply and lets relevance + reinforcement sort signal from noise (the mempalace lesson; mem0-style LLM fact-extraction is rejected as lossy and as colliding with the [D-008](0008-memory-and-knowledge-are-distinct-substrates.md) wall). Ledger-canonical unifies memory with knowledge's text-canonical/derived-index pattern and *solves backup/portability as a side effect*. The lexical floor honors degradability for a non-engineer; pushing embeddings to a module (behind a fixed interface, decided now) keeps the bolt-in a bolt-in rather than a later system migration, and the operator's prior operational experience with heavyweight vector engines justifies keeping them out of the foundation. Ambient append + deferred consolidation removes the prototype's fragile "close is the only capture" assumption; the two-layer typing applies the engine/product wall to classification (ship dimensions, not values). The cold-session review surfaced and fixed: the `additionalContext`-persistence fact, the manual/undiscoverable backup gap (Q3 narrowed), operator-invisible forgetting (made reversible), and the over-broad "embeddings strand the operator" framing (narrowed to dependency weight).

## What we ruled out

SQLite-as-canonical (rejected — a binary canonical store is a poor git/backup/portability surface; the index is the derivative, not the truth). Write-time LLM fact-extraction à la mem0 (rejected — lossy and wall-violating). Verbatim-everything à la mempalace with no structure (rejected — noise; episodic curation + roles is higher-signal). Embeddings in the foundation (rejected — strands a non-engineer on a dependency; it is a module). A heavyweight vector database as the semantic engine (rejected by the operator on prior operational experience). Write-time bidirectional memory↔knowledge columns (rejected — the prototype's unwired bridge; the read-time join on tags is what worked). Predictive/age-based forgetting (rejected — predicting future un-importance is the foresight trap inverted; demote-don't-delete, hard-delete only on evidence). Making close the sole capture point (rejected — loses abandoned-session context). Treating built-in auto-memory as the project record or ignoring it (rejected — ungoverned, unattributed, non-portable, and a cross-project leak surface; name the boundary).
