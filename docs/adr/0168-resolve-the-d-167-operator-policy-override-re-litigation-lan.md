# Resolve the D-167 operator-policy-override re-litigation: landed-text cold audit clean, six foundations re-locked

*Decided 2026-06-04 in the design workspace.*

## The decision

The [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md) operator-policy-override change-set is landed and **re-locked**. The mandatory landed-text cold audit (four independent lenses — adversarial · technical-feasibility · non-engineer-operator · architect) returned **no blocking or serious *design* findings**: the override is classified consistently as *operator config* (operator-owned, preserved across overlay) in every edited doc, with no residual foundation-infrastructure-artifact framing; [attention](../spec/systems/cognitive/attention.md)'s determinism law is untouched (the merged value is a static input); the [§15](../principles.md) boundary holds (no enforcement value is override-eligible); and the mechanism is feasible against the built `attention.py` (`load_policy_values` is a single merge seam, budgets already renormalize defensively, the stale-key check fits the existing `custom/script` kind, and a committed override needs no backup-first migration). **Findings resolved before re-lock:** *(serious — WBS propagation)* wbs/core-build-roadmap.md was updated — slice 26 gains the **policy-tuning** verb + its operation/tune tool, slice 12 `owes` the per-key override-merge read (a grouped-fix follow-up to the built slice), slice 18 reads the effective value, and the build-status note is reconciled to D-167; *(nits)* the [policies](../spec/systems/surfaces/policies.md) override section now states that tuning the triage-threshold adjusts only persistent-benign-debt *latency* (trust-critical signals promote immediately regardless, so no governance alarm can be suppressed), and the [audits](../spec/systems/guardrails/audits.md) carve-out crisps the stale-key division (validation catches a freshly-stale key at the merge; the audit re-surfaces a lingering one). **Accounting correction (supersedes [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md)):** D-167's text frames a "five-foundation" re-litigation and filed [modules/core](../spec/modules/core.md) under *non-locked propagation*; ground-truthing (and `validate.py`) confirmed `modules/core` is **locked** ([D-120](0120-lock-core-the-root-module-the-closure-wave-s-terminal-ratifi.md)) and was edited (the policy-tuning verb added to `provides` + the operator-verb count), so the re-lock set is **six**: [policies](../spec/systems/surfaces/policies.md), [repository-topology](../spec/systems/infrastructure/repository-topology.md), [provisioning](../spec/systems/infrastructure/provisioning.md), [module-system](../spec/systems/grammar/module-system.md), [audits](../spec/systems/guardrails/audits.md), [modules/core](../spec/modules/core.md). The locked **skills/operations/tools** surfaces D-167 also named were correctly **not** edited — they are grammar-only and the policy-tuning verb is an instance under existing grammar (no re-lock). **Re-lock:** `python3 lock.py --relock` run on the six under this decision; `python3 validate.py` green. **Propagation complete:** the six re-locks + the non-locked set (Q17 rewritten to "(a) designed-in, only (b) parked"; [R6](../reference/risks.md)/[R7](../reference/risks.md) reconciled; [glossary](../reference/glossary.md) term; [engine-architecture](../architecture.md) §3; [scenarios/upgrade-the-engine](../architecture.md#upgrading-the-engine); **`wbs/core-build-roadmap.md`** — the target D-167 omitted; this entry).

## Why

The lock gate requires a cold audit on the landed text with every blocking/serious resolved before re-lock; it ran, the design cleared with only propagation/accounting fixes, and those were applied. The count correction follows the append-only discipline (D-167 stands as authored; this entry supersedes its miscount — the [D-163](0163-correct-d-162-s-8-is-a-build-conformance-deviation-fix-the-b.md)-corrects-[D-162](0162-construction-scaffold-flexibility-for-ai-stepwise-build-fail.md) pattern): the `modules/core` edit was always necessary (a v1-required operator verb lives in a locked module doc) and operator-approved; only D-167's *accounting* of it was stale.

## What we ruled out

**Re-lock five and leave `modules/core` failing** (rejected — `validate.py` would hard-fail; the edit is necessary and approved, so the honest set is six). **Edit [D-167](0167-take-up-q17-component-a-authorize-a-five-foundation-re-litig.md) to fix the count** (rejected — append-only; this entry supersedes). **Re-lock before the WBS propagation** (rejected — the build map would under-count core's verbs against the re-litigated `modules/core`, a propagation-matrix violation; fixed first). **Edit the locked skills/operations grammar for the new verb** (rejected — grammar-only docs; the verb is an instance, no grammar change).
