# Q1 resolved: the v1 optional-module roster (4 cut, 2 kept)

*Decided 2026-05-26 in the design workspace.*

## The decision

Resolve the remaining (non-lens) part of [Q1](../reference/open-questions.md) — which prototype optional bundles survive into v1's end-state — under the inclusion bar **cross-cutting + no overlap** (a module earns a v1 design slot only if its use case recurs across many project types *and* it adds capability the foundations/decided modules don't already provide; serving none ⇒ scope creep, cut per [R6](../reference/risks.md)/[D-001](0001-restart-engine-template-in-a-blank-repo.md)). **Cut (4):** **`code-review-bundle`** — pre-submission code review is the [qa-review](../spec/modules/qa-review.md) lenses (`technical-integrity` + `security-governance`) and post-merge review is the [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md) `retroactive` lens; both have homes, and the bundle was never designed (no enumerated residual); **`quality-gates`** — metric thresholds are `check`-rule data dispatched by the validation foundation's `coverage`/`custom/script` check-**kinds** (distinct from the rejected wiring escape-hatch), so no module machinery is needed; **`github-collab-bundle`** — its concrete residual (issue/PR templates, CODEOWNERS, required-review) already travels as [control-plane](../spec/systems/infrastructure/control-plane.md) files and board/issue sync is `github-projects-sync` ([D-021](0021-github-projects-ships-as-an-optional-adopter-facing-module-p.md)); **`frontend-discipline`** — single-domain, *not* a cross-cutting SDLC discipline (it fit no recognized umbrella — the tell), its linting/accessibility/standards are `check` rules or a future per-need V&V lens, and generic UI standards are per-project knowledge, so no unique machinery is lost. **Kept, `status: optional` (both Software Configuration Management):** **`dependency-discipline`** (near-universal dependency governance beyond the control-plane Dependabot floor) and **`migration-discipline`** (data/schema change governance; no overlap). All cut bundles were bare `stub`s, so each cut rests on the surviving home, not on lost design. The kept modules are off by default (activation phrasing, not a status value); the operator's own MVP selection (activate `dependency-discipline`, exclude `migration-discipline`) is a separate workspace/instance concern, not recorded here. This **resolves [Q1](../reference/open-questions.md)** (the lens-membership half was [D-066](0066-the-4-4-review-lens-roster-two-stage-suites-mirroring-the-en.md); the residual deviation gate is clear — D8 KEEP, D15/D16 DECIDED, D2/[Q7](../reference/open-questions.md) is skills not bundles).

## Why

Q1 had to settle the *universe* of modules before core/module boundaries can be sorted, and the prototype's uncontrolled breadth is exactly what sank it ([D-001](0001-restart-engine-template-in-a-blank-repo.md)), so the lean "justify against a quality attribute or cut" bar (the open-question's own wording) governs. Each surviving module maps to a recognized SDLC discipline and a broad use case; each cut either overlaps already-decided capability (code-review, quality-gates, github-collab) or is single-domain content expressible through the extensible check/lens mechanism (frontend). A four-lens cold-session audit ([D-018](0018-cold-session-design-audit-required-before-any-lock.md)) ran against the plan; it corrected the code-review attribution (pre-submission qa-review lenses *plus* the `retroactive` lens, not a vague "qa-review suite"), kept the check-kind vs wiring-escape-hatch distinction explicit for quality-gates, and required the github-collab residual be named — all folded. Cutting `frontend-discipline` (re-examined after it fit no discipline umbrella) is a reduction within the audited envelope, not a new mechanism.

## What we ruled out

Keep all six bundles "to be safe" (rejected — re-imports the prototype breadth [D-001](0001-restart-engine-template-in-a-blank-repo.md) abandoned; over-coverage that serves no incremental quality attribute is scope creep). Keep `frontend-discipline` as an optional module (rejected — not a cross-cutting discipline; its capabilities are check rules or a future V&V lens, and generic UI standards are per-project knowledge, so a pre-shipped generic bundle is a guess that fits few projects). Demote the kept domain bundles to per-project content (rejected — dependency and migration governance are genuine cross-cutting *mechanisms* that should travel as modules, not be re-authored per project). Make `dependency-discipline` default-on (rejected — no default-on opinion for optional packages in v1; the operator selects, MVP is a separate axis). Cut all domain bundles to a pure-core v1 (rejected — loses real, near-universal SCM capability that maps to quality attributes).
