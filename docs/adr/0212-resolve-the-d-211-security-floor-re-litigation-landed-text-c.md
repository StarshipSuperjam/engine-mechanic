# Resolve the D-211 security-floor re-litigation: landed-text cold audit, two docs re-locked

*Decided 2026-06-18 in the design workspace.*

## The decision

The [D-211](0211-authorize-the-security-floor-re-litigation-add-native-code-s.md) change-set is landed and **re-locked**. The mandatory landed-text cold audit ran with **four** independent no-shared-context lenses (adversarial · technical-feasibility · non-engineer-operator · architect) on the as-written edits in [control-plane](../spec/systems/infrastructure/control-plane.md) and [provisioning](../spec/systems/infrastructure/provisioning.md) plus the carriers. **Outcome: no blocking on any lens; technical-feasibility PASS (every platform fact re-verified; three build-spec nits); adversarial one serious folded; non-engineer-operator two serious folded; architect two serious folded.** Re-lock set: **2**.

  **The audit + dispositions.**
  - **Technical-feasibility — PASS (no blocking/serious).** Re-verified against live GitHub docs: CodeQL default setup is `PATCH .../code-scanning/default-setup` `state=configured` (**not** PUT), repo-admin / Administration: write (the operator's `repo` qualifies), a clean **403** on free-private, works public + paid-private; default setup is GitHub-managed and **silently overrides a committed `codeql.yml`** (so shipping no workflow is correct); PVR is public-only, free, `PUT .../private-vulnerability-reporting`, admin-gated; a root `SECURITY.md` is auto-recognized (no setting), precedence `.github/`→root→`docs/`; the toggles reuse the ruleset-bootstrap capability (no new scope); enabling default setup adds **no** merge gate by itself. **Three build-spec nits folded/noted:** PVR's unsupported status on a private repo is **422** (not the code-scanning 403) — the per-toggle status keys are now pinned in the leaf; success is **200 or 202** (the "2xx/applied" bucket covers it); **409/422** on code scanning are concurrent/wrong-state (the "transient → retry" bucket absorbs them) — all build-spec precision, no design change.
  - **Adversarial — one serious folded; no fatal flaw.** Confirmed the [D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md) altitude conflict is genuinely avoided (a native setting-toggle, no check / CI / suite / committed workflow — not the bespoke style/lint module), "advisory not a merge gate" consistent across all docs, the [§5](../principles.md) asymmetry (code carries no traveling fallback) defended honestly (code scanning is an *enhancement* over the floor that *does* travel; its absence degrades a layer, never strands), and the `SECURITY.md` ownership story internally consistent. **Serious (folded):** the "every repo carries a disclosure channel" guarantee is technically "a root channel `.github/` can later shadow" — a clause now notes `.github/` precedence and that both files are operator-owned (the outcome is the operator's).
  - **Non-engineer-operator — two serious folded; no blocking.** Visibility-never-auto-switched and advisory-never-a-merge-gate both airtight; low-ceremony passes (one-time setup + advisory alerts). **Serious 1 (folded):** the disclosure law covered only "what's off," never that enabling **PVR** lets outsiders privately file security reports — the leaf law now requires the applied-PVR confirmation to name that consequence so the first report is expected, not a surprise (the scenario disclosure line says so too). **Serious 2 (folded):** "the paid Code Security tier" was unpriceable jargon — the leaf law now requires the unlock stated in evaluable terms (public is free; the alternative is a paid GitHub add-on with a per-seat cost), never a bare tier name or an HTTP status on the operator surface. **Nits noted (build-spec/accepted):** `403` appears only in maintainer-layer [risks](../reference/risks.md) (the operator wall holds); lead the confirmation with what *is* protecting them; verify at build that the default-setup check is never added to the required list (the "no required-check binding" law already forbids it).
  - **Architect — two serious folded; re-lock set = 2 confirmed; propagation complete.** Every verify-no-edit claim confirmed by reading the target: [modules/core](../spec/modules/core.md) (no committed workflow → nothing joins its artifact set; `SECURITY.md` seeded at root → not in core), [dependency-discipline](../spec/modules/dependency-discipline.md) (native first-party CodeQL ≠ a third-party scanner → stance untouched), [goals-and-quality](../reference/goals-and-quality.md) (no security attribute exists; fold under #1/#5 sound), [clean-code](../spec/modules/clean-code.md) / [modules/README](../reference/module-catalog.md) (style/lint ≠ security scanning; disclosure stays true). Contract/mechanism split clean. **Serious 1 (folded):** the Secrets pillar reused "secret scanning" for both the committed open-source floor and the native feature — now disambiguated ("a committed open-source secret-scan workflow — distinct from GitHub's own native secret scanning"). **Serious 2 (folded):** the first-run mermaid attributed the native-scanning enablement to a `CP->>CP` self-action — re-attributed to the instantiator-driven `INST->>CP` bootstrap (the mechanism is provisioning's), with the disclosure as `INST-->>NE`.

  **Folds applied before re-lock:** [control-plane](../spec/systems/infrastructure/control-plane.md) (Secrets-pillar disambiguation), [provisioning](../spec/systems/infrastructure/provisioning.md) (the leaf law — both-directions disclosure incl. the PVR consequence + evaluable unlock terms + per-toggle 403/422 status keys; the seed bullet — `.github/` precedence + an explicit first-run seed disclosure), [scenarios/first-run](../architecture.md#first-run-provisioning) (mermaid re-attribution + the PVR consequence in the disclosure line).

  **Re-lock set (2):** [control-plane](../spec/systems/infrastructure/control-plane.md), [provisioning](../spec/systems/infrastructure/provisioning.md). **Re-lock:** `python3 lock.py --relock` run on both under this decision; `python3 validate.py` green. **Carriers edited (non-locked):** [constraints](../reference/constraints.md), [glossary](../reference/glossary.md) (*Security floor*, *Protection floor*), [risks](../reference/risks.md) ([R25](../reference/risks.md)), [engine-architecture](../architecture.md), [scenarios/first-run](../architecture.md#first-run-provisioning) + [scenarios/upgrade-the-engine](../architecture.md#upgrading-the-engine). **Verify-no-edit (logged, architect-confirmed):** [modules/core](../spec/modules/core.md), [modules/dependency-discipline](../spec/modules/dependency-discipline.md), [goals-and-quality](../reference/goals-and-quality.md), [modules/clean-code](../spec/modules/clean-code.md), [modules/README](../reference/module-catalog.md), [telemetry](../spec/systems/guardrails/telemetry.md), [audits](../spec/systems/guardrails/audits.md). **No [open-questions](../reference/open-questions.md) opened/resolved; no [deviations](../reference/prototype-deviations.md) entry** (no security-coverage deviation). Still **42 docs locked** (2 re-locked, none added).

  **Build-owes (engine-template, downstream — not authored here):** key each toggle's status-branch to the right code (code scanning **403** = no Code Security; PVR **422** = public-only), treat 200/202 as success and 409/422-on-code-scanning as retry; the default-setup call must **never** be added to the ruleset's required-check list (alerts stay advisory); the operator-facing disclosure copy (PVR-consequence naming, evaluable unlock terms, lead-with-what's-protecting) is build-spec leaf copy under the plain-language law; the `SECURITY.md` seed file's default content; re-verify all endpoints against live GitHub at build.

## Why

The lock gate requires a landed-text cold audit with every blocking/serious resolved before re-lock; it ran (four lenses), feasibility passed clean (three build-spec nits), and the five seriouses (the `.github/`-precedence guarantee, the PVR-consequence and evaluable-unlock disclosure gaps, the Secrets-pillar naming ambiguity, the first-run actor mis-attribution) were folded before the re-locks. The landed text is faithful to [D-211](0211-authorize-the-security-floor-re-litigation-add-native-code-s.md): the floor extends along its own native-where-supported / disclose-never-downgrade grain; code scanning is native CodeQL, advisory-not-gating, absent-and-disclosed on free-private with no bespoke scanner; disclosure is a seeded root operator-owned `SECURITY.md` + native PVR on public; the two locked decisions it might have touched ([D-095](0095-cut-expression-contracts-disposition-prose-organization-cove.md), dependency-discipline) and the framing rubric stand untouched.

## What we ruled out

**Re-lock without the landed-text audit** (rejected — HARD lock gate). **Leave the PVR-enabled consequence undisclosed** (rejected — a non-engineer surprised by a stranger's private report is the never-surprise failure; the applied-PVR confirmation names the consequence). **Leave "Code Security tier" as the unlock wording** (rejected — unpriceable jargon; the unlock is stated in evaluable terms). **Carry the per-toggle status codes only in this log** (rejected — they are build realizations; pinned in the leaf as build-owes). **Treat the Secrets-pillar naming ambiguity as out of scope** (rejected — the re-litigation rewrote and re-locks that section, so the ambiguity is in scope and folded). **Leave the first-run diagram attributing the toggles to the control-plane lane** (rejected — it inverts the contract/mechanism split the re-lock keeps clean).
