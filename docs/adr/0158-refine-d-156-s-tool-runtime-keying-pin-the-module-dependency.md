# Refine D-156's tool-runtime keying: pin the module→dependency-group binding convention (group named by module id, normalized); fold two contained nits; re-lock `provisioning` only

*Decided 2026-05-31 in the design workspace.*

## The decision

An independent pressure-test of the [D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md)/[D-157](0157-comprehensive-cold-audit-of-the-d-156-tool-runtime-change-se.md) change-set (five cold-context lenses — adversarial, uv technical-feasibility, non-engineer-operator, architect, genesis-buildability — plus orchestrator ground-truth at source and a fresh live re-verification of the uv facts against current Astral docs) confirmed the change fundamentally sound but surfaced one **serious** gap the single comprehensive [D-157](0157-comprehensive-cold-audit-of-the-d-156-tool-runtime-change-se.md) audit missed: the crux of group-scoped `uv sync` — "install only the [dependency-group](../reference/glossary.md)s **derived** from the installed module set" — never pinned the **key** tying a present manifest (`.engine/modules/<id>/`) to a `[dependency-groups]` entry in `.engine/pyproject.toml`. [glossary.md](../reference/glossary.md) said the mapping is "derived, not a manifest field" without stating the derivation rule, so a builder had to invent the join. **Pin it:** a dep-carrying module's Python dependencies are declared as a `pyproject.toml` `[dependency-groups]` entry **whose name is the module's `id`** (which is also its `.engine/modules/<id>/` directory name); the [module manager](../spec/systems/infrastructure/provisioning.md) derives the `uv sync` group selection from the present manifest ids, **matched by PEP 735 normalized name**; a module with no Python dependencies declares no group. This introduces **no new manifest field** — the join reuses the `id` the manifest already carries — so the [module-system](../spec/systems/grammar/module-system.md) manifest grammar and glossary's "not a manifest field" stay true and **untouched**. **Home: [provisioning](../spec/systems/infrastructure/provisioning.md)** (the group-scoped `uv sync` mechanism owner) **+ [glossary.md](../reference/glossary.md)** (the term); **module-system is not re-litigated** — the convention is a `pyproject.toml` property, not manifest grammar (the [check-suite](../spec/systems/guardrails/validation.md) roster precedent keys by in-file self-declaration, not by id, so it is invoked only at the derived-not-registered principle level, never as dictating the home). **Two contained nits fold into the same pass, both provisioning-local:** **(F2)** the engine-offered **retry** is reattributed to the runtime-present degradation path (the [boot](../spec/systems/lifecycle/boot.md) pack) and the interpreter-independent `CLAUDE.md` floor is described as **orienting-only**, while the same passage still states that a **fully-absent** runtime degrades to that orient-only floor (the fresh-clone / deleted-`.venv` case must not go undescribed), the auto-heal clause staying on the runtime-present side and the "honest, named bound … inoperable" sentence un-orphaned; **(F3)** the foundation `.engine/.venv/` ignore is named a **distinct, separately-keyed** comment-fenced block from module `gitignore` *wires* (the coherence carve-out at [module-system](../spec/systems/grammar/module-system.md) already handles the coherence side; this homes the reversal/identity side in the mechanism doc). Plus cosmetic provisioning clarifications (`:183` "universal" → "universal across platforms and all groups"; `:426` add `pyproject` to the forbidden-terms list). **Non-locked propagation:** [glossary.md](../reference/glossary.md) (id-keying + normalized-match + "reuses the existing `id`, no new field"; `group-scoped` added to the uv-sync CI clause); [scenarios/first-run.md](../architecture.md#first-run-provisioning) (the consent gloss gains the *why* element); wbs/stage-0-harness.md (`:189` anchors the genesis instance — a dep-carrying module's pyproject group is **maintainer-hand-seeded append-as-built** per the §6 engine-manifest precedent, named by `id`; the bare/pre-core seed has no groups so its `uv sync` is trivial; group-selection is the module manager's job once [core](../spec/modules/core.md) lands). **This refines [D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md)** ("one dependency-group per dep-carrying module") by pinning the keying it left unstated; it supersedes nothing and re-litigates no decision. **Re-lock set: [provisioning](../spec/systems/infrastructure/provisioning.md) only.** After a single comprehensive cold-session design audit over the D-158 change-set (≥4 lenses, the [D-153](0153-clear-the-deferred-nit-backlog-one-batched-re-litigation-of.md)/[D-157](0157-comprehensive-cold-audit-of-the-d-156-tool-runtime-change-se.md) batched instrument), `python3 lock.py --relock systems/infrastructure/provisioning/README.md --decision D-158`; `python3 validate.py` green. **Build-ready stays provisional** ([D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md)) pending the genesis dry-run re-run (§3/§4/§8) and a clean validate — the next and final step.

## Why

The execution substrate is foundational grammar ([D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md)), group-scoped sync is its crux, and a crux whose join key is unstated is exactly the build-time landmine [D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md) exists to remove — the kind a reader passes but a builder hits (the [memory-substrate](../spec/modules/memory-substrate-sqlite-fts5.md) module is the first concrete exerciser). The fix is small and additive — a naming convention plus a derivation rule — and the natural join key is the `id` the manifest already carries, so it adds no field and changes no manifest grammar. PEP 735 normalized-name matching makes the match robust against a future non-kebab id at zero cost today (all v1 module ids verified valid, collision-free group keys). A four-lens cold plan-audit run *before* approval cut the re-lock set from two locked docs to one by establishing that the convention is a `pyproject.toml` property rather than manifest grammar, added the normalization guard, mandated the explicit "no new manifest field" reconciliation, required F2 to keep naming the fully-absent floor case, and routed the genesis authoring-owner / pre-core-sync residuals to the stage-0 anchor and the dry-run backstop. F2 and F3 ride the same pass because they are contained provisioning-local clarifications already adjacent to [D-157](0157-comprehensive-cold-audit-of-the-d-156-tool-runtime-change-se.md) dispositions; pinning F1 now (rather than letting the dry-run re-discover it) means the genesis re-run executes against the corrected corpus.

## What we ruled out

**Home the keying in [module-system](../spec/systems/grammar/module-system.md)** (rejected — the group name is a `pyproject.toml` property, not manifest grammar; the check-roster precedent keys by in-file self-declaration, not by id, so it does not dictate that home; editing it would re-litigate a third locked doc for no coherence gain — the plan-audit's blast-radius cut). **Match group-name to id by raw string equality** (rejected — a future non-kebab/uppercase id, still a valid PEP 735 group key, would silently mismatch and install nothing for that module, violating "installed means present" in the dependency direction; normalized-name match closes it at zero v1 cost). **Add a `dependency`/group manifest field** (rejected — re-litigates the closed-seam/manifest grammar [D-156](0156-name-the-engine-s-execution-substrate-a-group-scoped-uv-mana.md) already declined; the `id` is the join key already). **Pull locked [boot](../spec/systems/lifecycle/boot.md) into the F2 fix** (rejected — the boot double-fault floor-copy enhancement is a separately-logged [D-157](0157-comprehensive-cold-audit-of-the-d-156-tool-runtime-change-se.md) deferred build-session item; F2 only makes provisioning honest about today's floor behavior, touching no second locked doc). **Defer F1 to the dry-run re-run to re-discover** (rejected — the operator elected to pin it now so the genesis dry-run runs on the corrected corpus; foundational grammar is named in the design, never discovered at build, [D-003](0003-specify-the-full-end-state-before-the-first-build-pr.md)). **Bundle the cosmetic [repository-topology](../spec/systems/infrastructure/repository-topology.md) `:26` "bootstrap" overload or the pre-existing stage-0 `:352-355` authoring cruft into this pass** (rejected — the first would expand the re-lock set for a cosmetic term; the second predates D-156 and belongs to a separate cleanup, not this change-set).
