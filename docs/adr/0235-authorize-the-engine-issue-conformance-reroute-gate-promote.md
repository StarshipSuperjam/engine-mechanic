# Authorize the engine-Issue conformance reroute gate: promote engine-labeled-channel helper-routing from posture to a block-eligible, minimal-work-loss redirect (re-opens locked [control-plane](../spec/systems/infrastructure/control-plane.md) D-212, [modes](../spec/systems/lifecycle/modes.md) D-188, [hooks](../spec/systems/infrastructure/hooks.md) D-180, [modules/core](../spec/modules/core.md) D-208 — the engine-Issue body-contract posture of [D-073](0073-lock-build-orchestration-wave-3-terminal-and-re-litigate-con.md)/[D-183](0183-authorize-the-issue-authoring-grammar-correction-build-issue.md)/[D-184](0184-resolve-the-d-183-issue-authoring-grammar-correction-landed.md))

*Decided 2026-06-22 in the design workspace.*

## The decision

Authorize re-opening four locked docs to close a real, recurring operational failure the operator surfaced: engine sessions — in both this planning workspace and the deployed engine-template repo — author engine-labeled Issues with free-text bodies, bypassing the shared issue-authoring helper, unless the operator names it every single time. That is the designed-for failure of the *"authoring-via-the-helper is posture"* tier ([D-073](0073-lock-build-orchestration-wave-3-terminal-and-re-litigate-con.md)/[D-183](0183-authorize-the-issue-authoring-grammar-correction-build-issue.md)/[D-184](0184-resolve-the-d-183-issue-authoring-grammar-correction-landed.md)): ambient grounding read at session start loses to the moment of action. Promote routing-through-the-helper, **for the engine-labeled channel only**, from posture to a **block-eligible PreToolUse reroute gate**. **Five changes.** **(1) [control-plane](../spec/systems/infrastructure/control-plane.md) — body-contract enforcement tier:** the engine-authored-issue body contract's *routing* gains a **channel-scoped conformance floor** — a PreToolUse gate **denies** a `gh issue create`/issue-creating `gh api` whose Issue is destined for the engine-labeled channel and whose body lacks the contract's structural markers, **redirecting** to the helper; the contract's *shape* is what the gate keys on, its *truthfulness* stays posture (the PR-contract tiering, unchanged). The by-construction helper stays — the gate is the floor *beneath* it, never a replacement. The *"costs legibility, never a guardrail, so §15 does not bite"* framing is superseded: bypassing now meets a redirect — but the gate is **not** dressed as the unbypassable wall (it has none), it is the honest [§7](../principles.md) tier *between* posture and the merge wall. The **escalate-upstream draft stays exempt** (un-owned upstream, [external-contribution](../spec/systems/lifecycle/external-contribution.md)-governed, not engine-labeled). The CI backstop (below) is added to the CI-harness section. **(2) [modes](../spec/systems/lifecycle/modes.md) — Explore gate:** the gate that today *allows* all `gh issue` calls now **denies** a non-conforming **engine-channel** creation and redirects; reads/`list`/`view`/`comment`/`--add-label`/`close` and **every unlabeled or human Issue** stay allowed (the operator is never stranded, [§5](../principles.md)). The honest-fallibility framing carries over verbatim (aliases/`eval`/stdin/`--body-file`/`gh api` payloads evade a shell-string check; fail-open); what differs from the build-gate is that the Issue channel has **no merge wall** behind it, so this gate is the **primary lever**, not a nudge-behind-a-wall, with the CI backstop its only catch-all. **(3) [hooks](../spec/systems/infrastructure/hooks.md) — block-budget law:** register the engine-Issue-conformance reroute into the block-eligible set, additively. The [§6](../principles.md) reservation (*hard-block only for governance-critical invariants; hard-block buys friction without proportional trust*) is **honored, not weakened**: a reroute **loses no work** — the Issue still gets filed, via the helper — so it imposes only minimal, deterministically-resolvable friction (one extra call), categorically below a work-blocking refusal, which is precisely why it clears admission where a blanket Issue-blocker would not. **(4) [modules/core](../spec/modules/core.md) — provides:** the helper *"(posture)"* gains the **reroute-gate hook** (core-provided, registered by modes into the hooks block budget) + the **`on:issues` CI backstop** workflow. **(5) CI backstop:** an `on:issues` workflow flags a non-conforming engine-labeled Issue (label + comment the conforming skeleton); the slip feeds the engine's own detect→surface→remediate loop ([telemetry](../spec/systems/guardrails/telemetry.md)/[audits](../spec/systems/guardrails/audits.md)), **never a silent rewrite and never an operator chore** — the soft-warn backstop for the gate's known fallibility, which does *not* gate creation (consistent with *GitHub cannot gate Issue creation*). **Propagation:** [glossary](../reference/glossary.md) (the body-contract + Engine-label-scheme entries gain the gate + channel-scope, plus a reroute-gate gloss). [modules/core](../spec/modules/core.md)'s `provides` and grounding-floor binding gain the gate hook + CI workflow; [modules/README](../reference/module-catalog.md) (the status/deps/graph catalog) and the module-granular wbs need **no edit** — no module, dependency, or build-order change, and core's slice detail is the engine-template build-owe (below), the workspace's transient core roadmap having been deleted at core completion. [risks](../reference/risks.md) needs no entry — the *engine-Issues-bypass-the-contract* exposure is now gated, and the residual gate-fallibility is self-disclosing and CI-surfaced. **Verify-and-decide, edit only if a sentence is now false:** [build-orchestration](../spec/systems/lifecycle/build-orchestration.md):429, [telemetry](../spec/systems/guardrails/telemetry.md), [audits](../spec/systems/guardrails/audits.md) (escalate-upstream) — each claims *"authors via the helper"* / owns an exempt lane; the gate is **transport-neutral to a caller**, so the claims stay true (logged, not edited, unless a tier-word is now false). [engine-architecture](../architecture.md) needs no edit (the gate is a mechanism *within* existing systems, not a new system). The four re-locks land at the resolving entry in dependency order (control-plane → hooks → modes → modules/core) after a landed-text cold re-check (the [D-233](0233-authorize-the-audit-over-audit-re-litigation-feed-the-period.md)/[D-234](0234-resolve-the-d-233-audit-over-audit-re-litigation-landed-text.md) pattern).

## Why

The failure is real, recurring, and reported across both repos — and it is the designed-for failure of the posture tier, not a design weakened to fit current work (CLAUDE.md justified-re-litigation bar): the original *"by construction, posture only"* choice ([D-073](0073-lock-build-orchestration-wave-3-terminal-and-re-litigate-con.md)) rested on a **true** platform fact (*GitHub cannot gate Issue creation server-side*) but never considered the **client-side PreToolUse hook** as an authoring-time lever — the very lever the engine already uses to gate `gh pr create`/`git commit` in Explore ([modes](../spec/systems/lifecycle/modes.md)). The honest limit is stated, not papered over: a client-side gate is fallible (a shell string is not fully parseable) and, unlike the build-gate, has **no merge wall** behind it — so it is the primary lever and the CI backstop is the catch-all, named as such, never dressed as a wall. The **plan-stage four-lens cold audit** (adversarial · technical-feasibility · non-engineer-operator · architect, no shared context) ran against the proposal and reshaped it: it struck an early §17-*governance-critical* overclaim (the case is the narrower [§6](../principles.md) minimal-work-loss-redirect + no-backstop argument, *not* a reclassification of issue prose), surfaced the **engine-labeled-channel scoping** that exempts the operator's own Issues, free-form notes, and the escalate-upstream draft in one move, established the gate can be **self-contained** (a body-marker check, no helper dependency — so it needs no venv), and confirmed the four-doc propagation and dependency-ordered re-lock. The **workspace counterpart gate** (engine-planning/.claude, non-binding, no re-litigation) is already built and unit-tested (12/12 cases — denies free-text engine Issues, exempts unlabeled/human/read/PR calls, fails open on unparseable input) as the working proof before the Engine locks move.

## What we ruled out

**Stay posture + a just-in-time nudge** (rejected — the operator weighed it: a nudge that *allows* leaves the bad body created, and the after-the-fact rewrite loop wastes operator time and tokens; prevention has no such loop). **CI backstop as the primary mechanism** (rejected — same reason; CI is detection-plus-remediation, the loop the operator rejected; retained as the fallibility backstop only). **Reclassify Issue-channel integrity as governance-critical via [§17](../principles.md) to justify the block** (rejected — §17 governs the human *trust gate*, not issue prose; [control-plane](../spec/systems/infrastructure/control-plane.md):299's *legibility-not-a-guardrail* stands for the *truthfulness* claim; the gate is justified by the minimal-work-loss-redirect property, not a reclassification). **Make the helper active** (file the Issue + apply the label itself, so the gate keys on provenance) (rejected — would re-litigate the locked *passive-formatter, no-network-calls* property, [§14](../principles.md)/§16; the gate keys on body *content* instead, so a hand-matched conforming body also passes — correct, the contract is about body shape). **Gate all `gh issue create`, not just the engine-labeled channel** (rejected — would block the operator's own quick Issues and the human web-template path, stranding a non-engineer at a native capability, [§5](../principles.md); and would catch the escalate-upstream draft external-contribution governs by the host's conventions). **Dress the gate as the wall / claim it unbypassable** (rejected — it is fallible and backed only by CI; modes' honest-fallibility framing and *"the only wall is the merge"* carry over unchanged; the engine never dresses a local gate as the wall).
